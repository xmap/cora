2

7StreamableHTTPSessionManager raises if the same instance's `.run()` is

310def _enforce_production_principal_policy(settings: Settings) -> None: 

311 """Refuse to boot deployments where the principal-fallback would 

312 silently grant admin to header-less callers. 

313 

314 THREE numbered conditions, plus the F11 transport-security check 

315 below, all producing the same fail-fast: 

316 

317 1. `app_env in {prod, production, staging}` without 

318 `require_authenticated_principal=True`. The legacy Phase-3e 

319 gate: header-less prod requests would otherwise run as 

320 SYSTEM_PRINCIPAL_ID under whichever Authorize port is wired. 

321 `staging` is treated as production-tier (see `_PROD_LIKE_APP_ENVS`). 

322 

323 2. `trust_policy_id is not None` without 

324 `require_authenticated_principal=True`, when `app_env` is 

325 NOT `test`. Post-Phase-A: the seeded bootstrap policy permits 

326 SYSTEM_PRINCIPAL_ID to call DefinePolicy + RegisterActor. 

327 Without the principal-header check, ANY caller spoofing 

328 `X-Principal-Id: 00000000-0000-0000-0000-000000000000` 

329 becomes SYSTEM and gets standing admin. Staging/local 

330 deployments with only TRUST_POLICY_ID set (forgetting the 

331 second flag) would ship a wide-open API — gate-review F1. 

332 

333 Test env (`app_env=test`) is exempt because legitimate test 

334 fixtures exercise "operator misconfigured" + "SYSTEM-fallback 

335 under real policy" scenarios that REQUIRE this combo to be 

336 constructible. The exemption is safe because `app_env=test` 

337 is never operator-set in deployment configs. 

338 

339 3. `app_env in {prod, production, staging}` with `trust_policy_id is 

340 None` and `allow_permissive_authz` not set. A None `trust_policy_id` 

341 wires `AllowAllAuthorize`, which permits every command; shipping 

342 that permit-everyone stub to production is almost always a 

343 misconfiguration. Refuse boot unless the operator consciously 

344 opts in via `ALLOW_PERMISSIVE_AUTHZ=true`, the same conscious- 

345 choice shape as the per-IdP `allow_insecure_*` opt-ins. 

346 

347 Bootstrap workflow stays clean: a fresh non-prod deploy wanting 

348 AllowAll leaves `trust_policy_id` unset (today's default); a prod 

349 deploy points `TRUST_POLICY_ID` at the seeded bootstrap policy (or 

350 sets `ALLOW_PERMISSIVE_AUTHZ=true` to stay permissive on purpose). 

351 A deploy wanting real authz sets `TRUST_POLICY_ID` + 

352 `REQUIRE_AUTHENTICATED_PRINCIPAL=true` together, and operates 

353 behind an auth proxy that strips/sets `X-Principal-Id` per the 

354 routing.py contract. 

355 """

365 "REQUIRE_AUTHENTICATED_PRINCIPAL=true). The permissive " 

366 "SYSTEM_PRINCIPAL_ID fallback is not safe for a " 

367 "production-tier environment (prod / production / staging)." 

368 )

373 and not settings.require_authenticated_principal 

374 ):

377 "require_authenticated_principal=True (set " 

378 "REQUIRE_AUTHENTICATED_PRINCIPAL=true). Without the " 

379 "principal-header check, any caller can spoof " 

380 "X-Principal-Id and become SYSTEM under the configured " 

381 "Policy — bypassing the authz gate you just turned on. " 

382 "See memory/project_bootstrap_policy_design.md (F1)." 

383 ) 

384 raise RuntimeError(msg)

386 # exist for localhost test fixtures. Under prod posture an operator 

387 # (or an attacker with env-var-write access) could flip one IdP to

403 "memory/project_edge_auth_design.md gate-review F11."

430def _enforce_run_witness_recording_gate(settings: Settings) -> None: 

431 """Refuse to boot with run_witness_recording_enabled=True unless both 

432 prerequisites it depends on are also set. 

433 

434 run_witness_recording_enabled promotes a BEGUN capture observation to 

435 a real witnessed Run; that promotion needs (a) the shadow witness 

436 itself running (run_witness_enabled) to ever see an observation, and 

437 (b) a target Plan (capture_watch_plan_id) to bind the promoted Run 

438 to. Catching the misconfiguration at boot is cheaper than discovering 

439 it the first time a real capture begins and record_witnessed_run has 

440 nowhere to point. 

441 

442 Also refuses to boot with capture_progress_recording_enabled=True 

443 unless run_witness_recording_enabled is itself True (slice 10): with 

444 no promoted Run there is nothing for a progress reading to attach to. 

445 

446 Also refuses to boot with capture_baseline_recording_enabled=True 

447 unless run_witness_recording_enabled is itself True (slice 12): the 

448 baseline read happens exactly once, at the instant a capture 

449 promotes to a Run, so with no promotion there is nothing to attach 

450 a baseline reading to either. 

451 

452 Also refuses to boot with capture_path_recording_enabled=True unless 

453 run_witness_recording_enabled is itself True (slice 13): the write 

454 happens at a promoted Run's terminal, so with no promotion there is 

455 no run_id to write the observed path against either. 

456 

457 Also refuses to boot with capture_experiment_identity_recording_enabled=True 

458 unless run_witness_recording_enabled is itself True (slice 14a): the 

459 read happens exactly once, at the instant a capture promotes to a Run 

460 (mirroring the baseline read's timing), so with no promotion there is 

461 no run_id to vault a reading against either. 

462 

463 Also refuses to boot with capture_scan_ingestor_enabled=True unless 

464 capture_path_recording_enabled is itself True (slice 17): the sweep's 

465 only candidate signal is a resolved run_capture_path row, so with no 

466 path ever written there is nothing to ingest. 

467 

468 Also refuses to boot with capture_probe_recording_enabled=True unless 

469 run_witness_enabled is itself True (slice 16) -- an INDEPENDENT check 

470 from the four above, deliberately not chained off 

471 run_witness_recording_enabled: the capture-probe trail scopes on 

472 capture_code, not run_id (see entries_run_capture_probes' migration 

473 header), so its value is realized precisely while recording is off. 

474 It needs only the shadow observer running to have anything to write 

475 from. 

476 

477 Also refuses to boot with capture_orchestrator_ref_recording_enabled=True 

478 unless run_witness_recording_enabled is itself True: the attachment 

479 happens at promotion (a second `external_refs` entry on the 

480 genesis), so with no promoted Run there is no genesis to attach it 

481 to. 

482

488 so with no remote host there is no way to find a durable copy at

490 marked durable (with none, the sweep can never find a copy to 

491 record); and every durable root is a member of 

492 scan_probe_allowed_roots SPECIFICALLY, not merely the union of it and

496 refuse.

635def _enforce_production_signing_posture( 

636 settings: Settings, 

637 *, 

638 signature_port_factory: object, 

639 signer_factory: object, 

640 publish_port_factory: object, 

641) -> None: 

642 """Refuse to boot a production deployment wired to in-memory signing. 

643 

644 The signing seam ships with in-memory adapters by default (see 

645 `Settings.allow_insecure_inmemory_signing`): `InMemorySignaturePort` 

646 does NO cryptography and rubber-stamps every federation verify; 

647 `InMemorySigner` signs with an ephemeral per-process key whose 

648 signatures cannot be verified across a restart. Both are correct for 

649 dev / test and are the documented stubs kept until the rule-of-two 

650 wire-tier trigger fires, but under a production-tier `app_env` 

651 ({prod, production, staging}, see `_PROD_LIKE_APP_ENVS`) they would 

652 silently ship a false integrity guarantee. This is the 

653 in-memory-default footgun the `make_inmemory_kernel` fitness test 

654 guards for the Kernel; here it guards the signing factories. 

655 

656 Sibling to `_enforce_production_principal_policy`, and keyed on the 

657 same `_PROD_LIKE_APP_ENVS` set so staging runs the hardened posture 

658 too: fail at boot, which is cheaper than discovering crypto-free 

659 signing in production. `allow_insecure_inmemory_signing=True` is the 

660 explicit per-environment escape hatch. 

661 """ 

662 if settings.app_env not in _PROD_LIKE_APP_ENVS: 

663 return 

664 if settings.allow_insecure_inmemory_signing: 

665 return 

666 offenders = [ 

667 f"{label}={_signing_factory_display_name(factory)}" 

668 for label, factory in ( 

669 ("signature_port_factory", signature_port_factory), 

670 ("signer_factory", signer_factory), 

671 ("publish_port_factory", publish_port_factory), 

672 ) 

673 if _is_insecure_signing_stub(factory) 

674 ] 

675 if offenders: 

676 joined = ", ".join(offenders) 

677 msg = ( 

678 f"app_env={settings.app_env!r} is wired to in-memory signing " 

679 f"stubs: {joined}. InMemorySignaturePort does no cryptography " 

680 "and accepts every federation artifact; InMemorySigner uses an " 

681 "ephemeral key whose signatures do not verify across restarts. " 

682 "Wire the wire-tier adapters (DSSE / COSE / SCITT plus a durable " 

683 "KMS / Sigstore signer) before production, or set " 

684 "ALLOW_INSECURE_INMEMORY_SIGNING=true for a staging environment " 

685 "that is intentionally exercising the prod posture. See " 

686 "memory/project_federation_port_design.md (rule-of-two trigger)." 

687 ) 

688 raise RuntimeError(msg)
