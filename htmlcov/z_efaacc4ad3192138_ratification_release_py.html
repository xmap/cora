1"""Reaction (consequence gate, Gate IV): a settled Ratification -> resume the run. 

2 

3Reacts to BOTH RatificationGranted and RatificationDenied and un-parks the run 

4this enforcer held: Granted means the co-sign arrived (the operator can re-issue 

5the now-covered stop, which the gate admits); Denied means the co-sign was refused 

6(the run returns to Running and the stop stays un-admitted, since coverage is never 

7Granted). Leaving a denied run Held forever would make the "reversible hold" 

8un-reversible, so denial auto-resumes symmetrically. 

9 

10CORRELATION (the load-bearing guard): the release discharges ONLY this gate's own 

11hold claim, and resumes the run only when no other claim is active. Because 

12several concerns can hold one run (the kill-switch on a revoked grant, an 

13operator, the supervisor on an envelope breach), a settled ratification has three 

14outcomes, not one: resume (this gate was the last holder), release-and-stay-held 

15(others remain), or stand down (this gate never held it). 

16 

17This replaced a backward scan for the most recent `RunHeld` comparing envelope 

18principals. That guard was correct for the case it covered and blind to the one 

19that mattered: every holder used to no-op on an already-held run, so a hold 

20arriving during this gate's co-signature wait left NO event to be found, and the 

21grant resumed the run with that concern's cause unenforced. 

22 

23Pattern C write (not the resume_run slice): loads the run, guards, authorizes 

24ResumeRun as its own principal, appends RunResumed with optimistic concurrency. 

25Granted/Denied carry only ratification_id, so it loads the Ratification aggregate 

26(the sole reason cora.agent depends on cora.trust.aggregates) to resolve the 

27target run. Kind-blind; idempotent + fail-safe (already-Running / foreign-hold / 

28lost-race / Deny are logged no-ops). 

29"""
