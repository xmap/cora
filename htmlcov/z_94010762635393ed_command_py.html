1"""The `ResumeRun` command — intent dataclass for this slice. 

2 

3Resume transition: `Held -> Running`, discharging ONE hold claim and 

4only when it is the last one active. The inverse of hold_run. No reason 

5field — resume is just permission to proceed — but the command carries 

6`cause` so the decider knows WHOSE claim is being discharged. 

7 

8When other concerns still hold the Run the decider emits 

9`HoldClaimReleased` instead and the Run stays Held; when the caller's own 

10claim is not active at all it raises rather than resuming past a hold it 

11did not place. 

12""" 

13 

14from dataclasses import dataclass 

15from uuid import UUID 

16 

17from cora.run.aggregates.run import HOLD_CAUSE_OPERATOR 

18 

19 

20@dataclass(frozen=True) 

21class ResumeRun: 

22 """Resume a held Run (Held → Running). 

23 

24 `decided_by_decision_id` (mirrors HoldRun): optional Decision BC 

25 reference to the record that justified this resume. The operator- 

26 facing route leaves it None (routine resumes need no justification); 

27 the in-process RunSupervisor sets it to link an autonomous, safety- 

28 gated resume to its Decision. NO existence check at the decider per 

29 the cross-BC eventual-consistency stance. 

30 

31 `cause` names whose claim this resume discharges, and must match the 

32 `cause` the hold was placed under. Defaults to `operator`, which is 

33 what the operator route and tool mean. 

34 """ 

35 

36 run_id: UUID 

37 decided_by_decision_id: UUID | None = None 

38 cause: str = HOLD_CAUSE_OPERATOR
