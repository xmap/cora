82 # Authorization — Trust BC wiring 

83 # When None, `build_kernel` wires `AllowAllAuthorize` and every 

84 # command is permitted (legacy default; matches dev/test). When 

85 # set to a UUID, `TrustAuthorize` is wired and gates every command 

86 # through that single Policy aggregate. Multi-policy resolution 

87 # via projections lands in a later phase; until then this is one 

88 # policy per deployment. 

89 # 

90 # The bootstrap migration seeded the System Bootstrap Policy at a 

91 # fixed UUID so production deployments can enable real authz with 

92 # a single env var instead of the old 3-step dance: 

93 # 

94 # TRUST_POLICY_ID=00000000-0000-0000-0000-000000000002 

95 # 

96 # The seed permits SYSTEM_PRINCIPAL_ID to call DefinePolicy + 

97 # RegisterActor on the nil conduit, bound to the seeded HTTP 

98 # Surface — the minimum needed to register a real admin Actor and 

99 # promote a real admin Policy. 

100 # The default stays None (AllowAllAuthorize) for now because 

101 # ~2400 tests pass arbitrary principal_ids; flipping the default 

102 # is gated on a test-fixture audit (memory: 

103 # project_bootstrap_policy_design.md, WI8). 

104 trust_policy_id: UUID | None = None

108 # header are then rejected with 401 instead of silently falling 

109 # back to `SYSTEM_PRINCIPAL_ID`. Default false matches the 

110 # dev / test posture where the fallback is convenient. 

111 # The startup check in `create_app()` refuses to boot when 

112 # `app_env` is production-tier ({"prod", "production", "staging"}) and 

113 # this is False, so a production-tier deployment cannot accidentally

129 # Escape hatch for booting against a schema this build does not 

130 # expect. Default false: `build_kernel` refuses to start when the 

131 # applied migration version is not `EXPECTED_SCHEMA_VERSION`, which 

132 # is the state a restore leaves behind (see 

133 # `cora.infrastructure.schema_version`). 

134 # 

135 # Setting it True does NOT restore normal service. The process boots 

136 # with its event store wrapped in `ReadOnlyEventStore`, so a restored 

137 # database can be read and nothing can be appended to it. That 

138 # asymmetry is the whole point: the event log is append-only, so a 

139 # write against the wrong schema is history rather than a row to fix, 

140 # while a read costs nothing. 

141 # 

142 # It does not cover a database with NO schema. An override meant for 

143 # reading a restored database has nothing to offer an empty one, and 

144 # letting it through would boot a process that reports an empty 

145 # database as fine. 

146 allow_schema_version_mismatch: bool = False

148 # Federation / event-signing posture. 

149 # The signing seam ships with in-memory adapters by default: the 

150 # crypto-free `InMemorySignaturePort` (federation envelope sign / 

151 # verify), the dict-backed `InMemoryPublishPort`, and the real-but- 

152 # ephemeral-key `InMemorySigner` (event provenance). These are the 

153 # documented test-tier stubs per memory: 

154 # project_federation_port_design.md, kept until the rule-of-two 

155 # adapter trigger fires; the wire-tier DSSE / COSE / SCITT verifiers 

156 # are deliberately deferred. 

157 # 

158 # The startup check in `create_app()` refuses to boot when 

159 # `app_env` is production-tier ({"prod", "production", "staging"}, 

160 # the same set the authz guards key on) and any signing factory

162 # deployment cannot silently ship crypto-free signing (the 

163 # federation SignaturePort) or non-durable signatures (the 

164 # ephemeral-key event Signer). Set this true only for an environment 

165 # intentionally exercising the prod posture before the wire-tier 

166 # adapters land (e.g. a staging deployment).

169 # Projection worker 

170 # `projection_use_listen_notify=True` (default) wires the worker's 

171 # wake-up signal to LISTEN on the `events` channel emitted by the 

172 # AFTER INSERT trigger from migration 20260509120000. Latency from 

173 # event commit to projection write is ~tens of ms under normal load. 

174 # Flip to False to fall back to polling-only when LISTEN/NOTIFY's 

175 # global commit lock causes contention (per Recall.ai July 2025 

176 # incident; trigger documented in `memory/project_deferred.md` under 

177 # the NATS deferred entry). Polling fallback latency is bounded by 

178 # `projection_poll_interval_seconds`. 

179 projection_use_listen_notify: bool = True 

180 # Safety-net poll interval when NOTIFY mode is on (catches missed 

181 # signals from listener disconnect). Becomes the primary signal 

182 # when NOTIFY is off — recommended values are very different 

183 # between the two modes (5s with NOTIFY, 1-2s without). Floor of 

184 # 0.1s prevents accidental tight-loop misconfiguration. 

185 projection_poll_interval_seconds: float = 5.0

187 # `llm_enabled` is the SWITCH; `anthropic_api_key` below is the 

188 # CREDENTIAL. Both are required before CORA calls an external model, 

189 # and this one defaults OFF. 

190 # 

191 # Why a switch at all, when a key is already needed: the key is often 

192 # present in an environment for an unrelated reason, and its mere 

193 # presence used to be enough to auto-register RunDebriefer + 

194 # CautionDrafter, which call an external API on EVERY terminal Run. 

195 # That is experiment metadata leaving the facility (EGRESS) and money 

196 # being spent (SPEND), switched on by a side effect. Every one of the 

197 # ~13 sibling subscribers carries its own `*_enabled` default-off 

198 # flag; this seam was the outlier. 

199 # 

200 # Egress and spend are a DIFFERENT axis from actuation (the 

201 # ControlPort write gate and the ComputePort exec allowlist, see 

202 # `control_writes_enabled`). A facility told "read-only, CORA cannot 

203 # touch my hardware" hears a claim about actuation, and would still 

204 # be unhappy to discover CORA phoned its data out. Both promises 

205 # belong to the observe-only posture; neither subsumes the other. 

206 # 

207 # Turning this off is graceful, never a crash: `build_llm` returns 

208 # None, and every consumer already treats `llm=None` as a supported 

209 # state because the key-absent case always produced it. The 

210 # LLM-backed subscribers log-and-skip and `regenerate_run_debrief` 

211 # answers unavailable. The `llm` decide substrate is not selectable 

212 # over the wire at all, so its factory guard is an internal-caller 

213 # guard rather than a request-reachable path. 

214 llm_enabled: bool = False

218 # wires no LLM and the Kernel carries `llm=None`; the LLM-backed 

219 # subscribers log-and-skip rather than refusing to boot, so a 

220 # deployment may defer Agent rollout. The dev / test default of None

239 # `idempotency_ttl_hours` is read by the pruner background task

241 # Stripe's industry default is 24h; clients are expected to retry 

242 # within that window or accept that a duplicate request will hit

416 # probe (shared across the flag-only watchers + the acting agents). Each tick 

417 # a watcher issues an authz-gated list read; under a real Authorize policy a

426 # `liveness_posture` governs whether the authorization gate reads 

427 # `Actor.active` for the calling principal, the switch an operator flips 

428 # with deactivate_actor / reactivate_actor. Three states, because 

429 # measuring must be possible without refusing: 

430 # - "off" (default) the gate performs no liveness read at all, and 

431 # `Conjunct.LIVENESS` never appears in a result. 

432 # - "shadow" resolve and log every non-active caller WITHOUT denying. 

433 # This is the adoption measurement: how many live requests 

434 # would enforcement have refused, and which remedy each 

435 # would have needed. Run it for a full beamtime cycle 

436 # before "enforce". 

437 # - "enforce" a deactivated or unregistered principal is denied even 

438 # where the Policy permits it. 

439 # Default "off" because turning this on refuses requests that succeed 

440 # today, and the human-envelope design requires the measurement to 

441 # precede the enforcement rather than follow it. 

442 liveness_posture: Literal["off", "shadow", "enforce"] = "off"

445 # `identity_providers` is the list of IdPs CORA accepts tokens 

446 # from. Empty (default) keeps the legacy X-Principal-Id-with-

452 # "jwks_url":"https://idp.example.com/jwks.json", 

453 # "audiences":{"00000000-0000-0000-0000-000000000020":"https://cora.example/http"}, 

454 # "allowed_algorithms":["RS256"]}]' 

455 #

581 # Exactly what the `local_process` substrate may spawn. Empty 

582 # (default) permits NOTHING, so selecting local_process without 

583 # naming an executable yields a port that refuses every job rather 

584 # than one that runs any. The CHECK matches command[0] exactly: no

597 # re-opens arbitrary execution via `-c`, and the check cannot tell. 

598 # This bounds WHAT runs; it does not authorize the conduct path (no 

599 # Trust policy gates the spawn). See `cora_allow_raw_conduct` below
