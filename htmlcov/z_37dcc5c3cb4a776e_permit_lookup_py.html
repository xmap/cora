1"""PermitLookup port: cross-BC query for Federation BC's permit projection. 

2 

3Used by per-BC publish/pull slice handlers to resolve the matching 

4outbound-direction or inbound-direction Permit at command time, 

5before composing a `FederationTrustContext` for SignaturePort calls 

6or assembling the cross-BC `append_streams` over the Permit stream. 

7 

8## Convention 

9 

10Mirrors the existing CredentialLookup precedent: cross-BC port 

11shaped around the CONSUMER's need ("what permit authorizes this 

12publication / pull?"), Federation BC ships the 

13`PostgresPermitLookup` adapter reading 

14`proj_federation_permit_summary`, and the in-memory adapter at 

15`cora.federation.adapters.in_memory_permit_lookup` is the test 

16default until real federation peers connect. 

17 

18## No BC imports in the port 

19 

20`direction` and `status` are typed as `str` so this port stays 

21inside `cora.infrastructure`'s `depends_on = []` tach contract. 

22The string values match the BC-tier `Direction` and `PermitStatus` 

23StrEnums (`Outbound | Inbound`, `Defined | Active | Suspended | Revoked`). 

24Consumers compare via literal equality on the strings. 

25 

26`peer_facility_id` (both on the lookup method parameter and on the 

27`PermitLookupResult` dataclass) is typed `FacilityCode` (not bare `str`) 

28per the locked two-tier facility identity design 

29([[project-structural-scope-design]] Slice 3 "FacilityCode VO + 

30port-surface migration"). The VO is the cross-deployment convergent 

31identity for a facility; handlers construct 

32`FacilityCode(command.peer_facility_id)` at the port edge, and the 

33projection-row adapter constructs the VO from the raw `TEXT` column. 

34Event payloads on disk remain bare strings; the VO is in-memory only 

35at the port surface. 

36 

37## Why outbound/inbound on a single port 

38 

39The per-BC publish slice needs an outbound permit; the per-BC pull 

40slice needs an inbound permit. The two lookups share the same 

41projection table and almost-identical resolution logic (key on 

42peer_facility_id + artifact_kind + direction); collapsing onto one 

43port keeps both slice handlers reading from one shipped adapter 

44instead of two. Per consumer-shaped port discipline, both shapes 

45land here. 

46""" 

47

55@dataclass(frozen=True) 

56class PermitLookupResult: 

57 """Summary row from `proj_federation_permit_summary` for slice handlers. 

58 

59 Carries the minimal columns a per-BC publish / pull handler needs 

60 to compose a FederationTrustContext and stage the cross-BC 

61 `append_streams` over the Permit stream. The loaded version is 

62 surfaced as `current_version` so the handler can pass it as the 

63 expected_version to `append_streams` without re-loading the 

64 full Permit stream. 

65 

66 `peer_facility_id` is a `FacilityCode` value object per the two-tier 

67 facility-identity design; the adapter constructs the VO from the 

68 raw `TEXT` column. A malformed code at the projection-row tier 

69 raises `InvalidFacilityCodeError` at adapter construction time, 

70 which surfaces upstream as a port-level integrity error. 

71 """ 

72 

73 permit_id: UUID 

74 peer_facility_id: FacilityCode 

75 direction: str 

76 status: str 

77 abi_tier_floor: str 

78 current_version: int

81@runtime_checkable 

82class PermitLookup(Protocol): 

83 """Cross-BC port: query Federation's permit projection by direction. 

84 

85 `lookup_outbound` is the publish-side query (matches a peer- 

86 facility id + artifact kind to the outbound Permit that 

87 authorizes publishing to that peer); `lookup_inbound` is the 

88 pull-side query (matches a peer-facility id + artifact kind to 

89 the inbound Permit that authorizes pulling from that peer). 

90 Both return None when no matching active permit exists. 

91 

92 `peer_facility_id` takes a typed `FacilityCode`; handlers construct 

93 `FacilityCode(command.peer_facility_id)` at the port edge. 

94 """ 

95 

96 async def lookup_outbound( 

97 self, peer_facility_id: FacilityCode, artifact_kind: str 

98 ) -> PermitLookupResult | None: ... 

99 

100 async def lookup_inbound( 

101 self, peer_facility_id: FacilityCode, artifact_kind: str 

102 ) -> PermitLookupResult | None: ... 

103 

104
