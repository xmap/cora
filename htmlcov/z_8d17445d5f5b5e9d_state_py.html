1"""Method aggregate state, value objects, status enum, and domain errors. 

2 

3`Method` is the abstract recipe — the technique class as published 

4by the vendor or scientific community. Examples: "X-ray Fluorescence 

5Mapping", "Step Tomography", "Ptychography". Equipment-agnostic 

6(refers to `Family` ids only, not specific Asset instances). 

7 

8Per the BC map's recipe ladder, Method ≈ ISA-88 General Recipe. The 

9facility's adapted version lives in `Practice`, and the 

10concrete Asset binding lives in `Plan`. 

11 

12 

13Minimal Method: 

14 - `id` + `name` 

15 - `needed_family_ids: frozenset[UUID]` — the Family ids this 

16 Method requires. Composable: a "Fly Tomography" Method has 

17 needed_family_ids = {Tomography_id, FlyScan_id}. At Plan 

18 binding time, the operator picks an Asset whose 

19 families ⊇ method.needed_family_ids. 

20 - `status` (defaults `Defined`). 

21 

22`Versioned` and `Deprecated` transitions land in the lifecycle 

23slices. Description / owner / additional facets defer to enrichment. 

24 

25## Needed_family_ids: eventual-consistency stance 

26 

27The decider does NOT verify each Family id refers to a real 

28Family stream in the event store. Same precedent as Trust's 

29Conduit zone refs and Asset parent refs. Typos produce 

30"dangling" Methods; downstream Plan binding is where the 

31mismatch will surface (Asset can't satisfy the requirement). For 

32day-one ergonomics this is fine; structural validation can be 

33layered on at the API boundary later if pilot demand emerges. 

34 

35Empty `needed_family_ids` is allowed (a Method that needs no 

36specific equipment family — rare but operationally valid for 

37purely procedural Methods like "Sample Cleaning"). 

38 

39## Status as enum-in-state, derived-from-event-type-in-evolver 

40 

41`MethodStatus` is a `StrEnum` so the values would serialize 

42naturally as JSON-friendly strings IF carried in an event payload. 

43Today they aren't: state holds the enum (typed) and the evolver 

44derives the new status from the event TYPE — same precedent as 

45`FamilyStatus`, `SubjectStatus`, `AssetLifecycle`. 

46 

47## Eighth bounded-name VO 

48 

49`MethodName` is the **eighth** trimmed-bounded-name VO after 

50`ActorName`, `ZoneName`, `ConduitName`, `PolicyName`, `SubjectName`, 

51`FamilyName`, `AssetName`. The shared trim+length-check logic was 

52hoisted to `cora.infrastructure.bounded_text.validate_bounded_text` 

53once the 10th VO (PlanName) landed; MethodName now calls that 

54helper while keeping its own frozen dataclass type and per-aggregate 

55error class. See the helper module's docstring for the design 

56rationale. 

57 

58## Frozensets in state, lists in payloads 

59 

60`needed_family_ids` is `frozenset[UUID]` in domain state 

61(deduplicated, hashable, set-membership in O(1) for Plan-binding 

62checks) and `list[UUID]` in event payloads (JSON-friendly, sorted 

63for determinism). Same precedent as Trust's Policy 

64`permitted_principal_ids` / `permitted_commands`. The evolver bridges 

65the two. Sorting in `to_payload` keeps the persisted bytes 

66deterministic — same logical family set, same payload, same 

67idempotency hash. 

68"""

132class MethodCannotVersionError(Exception): 

133 """Attempted to version a method not in `Defined` or `Versioned`. 

134 

135 Multi-source guard: `version_method` accepts both `Defined` 

136 (first revision) and `Versioned` (subsequent revisions — 

137 operators bump v1 → v2 → v3 over time as the recipe's 

138 parameters or step list are refined). Only `Deprecated` is 

139 rejected (you can't revise a deprecated method — un-deprecate 

140 first if you want to bring it back, though that slice doesn't 

141 exist today). 

142 

143 Mirrors `FamilyCannotVersionError` shape and semantics 

144 (Equipment BC). Same deliberate divergence from strict-not- 

145 idempotent: re-versioning with the same tag succeeds and emits a 

146 fresh event (re-attestation is a legitimate audit moment). 

147 Pinned by tests/unit/recipe/test_version_method_decider.py. 

148 """ 

149

151 super().__init__( 

152 f"Method {method_id} cannot be versioned: currently in status " 

153 f"{current_status.value}, version requires " 

154 f"{MethodStatus.DEFINED.value} or {MethodStatus.VERSIONED.value}" 

155 ) 

156 self.method_id = method_id 

157 self.current_status = current_status

252@dataclass(frozen=True) 

253class Method: 

254 """Aggregate root: an abstract technique-class recipe. 

255 

256 `needed_family_ids` is a frozenset of Family ids the Method 

257 requires. Eventual-consistency stance: existence is not verified 

258 at decide time; mismatch surfaces at Plan binding. 

259 

260 `version` is the operator-supplied label of the most recent 

261 `version_method` call (None until first version). State always 

262 holds the latest tag — past tags live in the event stream as 

263 `MethodVersioned` events. No `current_` prefix because state by 

264 definition holds current values (same convention as `status`, 

265 `name`). Free-text validated at API boundary + defensively in the 

266 decider; no VO. Default None keeps MethodDefined-only legacy 

267 streams folding cleanly (additive-state pattern). Mirrors 

268 Family's `version` semantics (Equipment BC): preserved 

269 across deprecation as an audit signal of the last revision before 

270 deprecation. 

271 

272 `parameters_schema` is the optional JSON Schema (Draft 2020-12, 

273 constrained subset) declaring the shape of parameter dicts that 

274 Plans and Runs carry for this Method. Defaults to 

275 None for legacy Methods (additive-state pattern); None means 

276 "this Method declares no parameter contract, accept any dict". 

277 Distinct from `{}` (empty schema, "operator explicitly said no 

278 parameters"). Subset shared with Family.settings_schema via 

279 `cora.infrastructure.json_schema_subset`. See 

280 [[project_run_parameters_design]] for the full parameter-family layout. 

281 """ 

282 

283 id: UUID 

284 name: MethodName 

285 needed_family_ids: frozenset[UUID] = field(default_factory=frozenset[UUID]) 

286 status: MethodStatus = MethodStatus.DEFINED 

287 version: str | None = None 

288 # content_hash captures the SHA-256 of the canonical body bytes for 

289 # the most recently versioned content subset (`name + 

290 # parameters_schema + capability_id + needed_family_ids + 

291 # needed_supplies`). None until first MethodVersioned (Defined-only 

292 # streams have no attested revision yet) AND for pre-rollout legacy 

293 # MethodVersioned events that predate the content-hash field 

294 # (additive-state pattern; same posture as `version`, `capability_id`). 

295 # Preserved across MethodDeprecated and MethodParametersSchemaUpdated: 

296 # the hash represents the LAST ATTESTED revision, so post-rollout 

297 # schema updates intentionally leave the hash pointing at the prior 

298 # version — see [[project_content_addressed_identity_design]]. 

299 content_hash: str | None = None 

300 parameters_schema: dict[str, Any] | None = field(default=None) 

301 # Method.capability_id points to the universal Capability 

302 # template (Recipe BC) this Method realizes as a Method-shaped 

303 # executor. REQUIRED at define_method now; defaults None at the 

304 # STATE level for evolver-back-compat with older streams (additive- 

305 # state pattern; same shape as Method.parameters_schema). 

306 # Distinct from `needed_family_ids` (hardware compatibility, what 

307 # Family classes the Method needs available), both fields stay, 

308 # answering DIFFERENT questions per [[project-capability-aggregate-design]] 

309 # see [[project-capability-aggregate-design]] watch item 10. The cross-BC validation that 

310 # `Method.parameters_schema ⊂ Capability.parameters_schema` runs at 

311 # define_method time via the capability_loader port (STRICT per 

312 # [[project-asset-settings-design]] cross-BC anchor). 

313 capability_id: UUID | None = field(default=None) 

314 # needed_supplies references Supply.kind STRINGS (not 

315 # UUIDs). Asymmetric with needed_family_ids (frozenset[UUID]) by 

316 # design: Family is a TYPE registry (one global definition, 

317 # referenced by UUID); Supply is an INSTANCE aggregate (multiple 

318 # per facility, each with its own availability state, sharing a 

319 # `kind` label). Methods are facility-portable so they reference 

320 # the abstract kind, not a per-facility instance UUID. Defaults 

321 # to empty frozenset (additive-state pattern; legacy 

322 # MethodDefined-only streams fold cleanly via payload.get default). 

323 # See [[project_supply_design]] §"Method.needed_supplies consumer" 

324 # for the full design lock. 

325 needed_supplies: frozenset[str] = field(default_factory=frozenset[str]) 

326 # needed_assembly_ids references Assembly aggregates (Equipment BC) 

327 # by UUID. Declares "this Method needs a specific composition 

328 # blueprint" (e.g., the MCTOptics microscope fixture), not just N 

329 # independent Assets of the Families in needed_family_ids. Plan 

330 # binding consults this set at bind time: each id in 

331 # Method.needed_assembly_ids must be materialized as a Fixture among 

332 # the Plan's Assets, where Fixture.assembly_id matches. Affordance-cover (Capability) check is 

333 # unchanged because Assembly.presents_as_family_id provides the 

334 # Family-typed unit the Capability binds against. Defaults to empty 

335 # frozenset (additive-state pattern; legacy MethodDefined-only 

336 # streams fold cleanly via payload.get default). See 

337 # [[project-assembly-aggregate-design]] Locks section for the cross-BC 

338 # contract. 

339 needed_assembly_ids: frozenset[UUID] = field(default_factory=frozenset[UUID]) 

340 

341 def content_subset(self) -> dict[str, object]: 

342 """Canonical content subset hashed into MethodVersioned.content_hash. 

343 

344 Pins identity per [[project_content_addressed_identity_design]]: 

345 `name + parameters_schema + capability_id + needed_family_ids + 

346 needed_supplies + needed_assembly_ids`. Identity-bearing fields 

347 excluded: `id` (identity, not content); `status` and `version` 

348 (lifecycle, derived in evolver from event type and version_tag). 

349 UUIDs render as strings (json-serializable); frozensets render 

350 as sorted lists (canonical_body_bytes would sort either way but 

351 the explicit materialization keeps "what's hashed" readable as 

352 a spec, not a black-box dump). Lives on the aggregate so any 

353 future field addition forces an explicit decision about whether 

354 it participates in content identity (anti-hook #10) at the same 

355 site as the field itself; deciders and drift-detection helpers 

356 call this rather than re-listing the subset. 

357 """ 

358 return { 

359 "name": self.name.value, 

360 "parameters_schema": self.parameters_schema, 

361 "capability_id": str(self.capability_id) if self.capability_id is not None else None, 

362 "needed_family_ids": sorted(str(f) for f in self.needed_family_ids), 

363 "needed_supplies": sorted(self.needed_supplies), 

364 "needed_assembly_ids": sorted(str(a) for a in self.needed_assembly_ids), 

365 }
