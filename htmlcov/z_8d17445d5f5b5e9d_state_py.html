1"""Method aggregate state, value objects, status enum, and domain errors. 

2 

3`Method` is the abstract recipe — the technique class as published 

4by the vendor or scientific community. Examples: "X-ray Fluorescence 

5Mapping", "Step Tomography", "Ptychography". Equipment-agnostic 

6(refers to `Family` ids only, not specific Asset instances). 

7 

8Per the BC map's recipe ladder, Method ≈ ISA-88 General Recipe. The 

9facility's adapted version lives in `Practice` (6d), and the 

10concrete Asset binding lives in `Plan` (6e). 

11 

12## Phase 6a scope 

13 

14Minimal Method: 

15 - `id` + `name` 

16 - `needed_families: frozenset[UUID]` — the Family ids this 

17 Method requires. Composable: a "Fly Tomography" Method has 

18 needed_families = {Tomography_id, FlyScan_id}. At Plan 

19 binding time (6e), the operator picks an Asset whose 

20 families ⊇ method.needed_families. 

21 - `status` (defaults `Defined`). 

22 

23`Versioned` and `Deprecated` transitions land in 6b. Description / 

24owner / additional facets defer to 6c. 

25 

26## needed_families — eventual-consistency stance 

27 

28The decider does NOT verify each Family id refers to a real 

29Family stream in the event store. Same precedent as Trust's 

30Conduit zone refs (3b) and Asset parent refs (5b). Typos produce 

31"dangling" Methods; downstream Plan binding (6e) is where the 

32mismatch will surface (Asset can't satisfy the requirement). For 

33day-one ergonomics this is fine; structural validation can be 

34layered on at the API boundary later if pilot demand emerges. 

35 

36Empty `needed_families` is allowed (a Method that needs no 

37specific equipment family — rare but operationally valid for 

38purely procedural Methods like "Sample Cleaning"). 

39 

40## Status as enum-in-state, derived-from-event-type-in-evolver 

41 

42`MethodStatus` is a `StrEnum` so the values would serialize 

43naturally as JSON-friendly strings IF carried in an event payload. 

44Today they aren't: state holds the enum (typed) and the evolver 

45derives the new status from the event TYPE — same precedent as 

46`FamilyStatus`, `SubjectStatus`, `AssetLifecycle`. 

47 

48## Eighth bounded-name VO 

49 

50`MethodName` is the **eighth** trimmed-bounded-name VO after 

51`ActorName`, `ZoneName`, `ConduitName`, `PolicyName`, `SubjectName`, 

52`FamilyName`, `AssetName`. Phase 6e-1 hoisted the shared 

53trim+length-check logic to `cora.infrastructure.bounded_text.validate_bounded_text` 

54once the 10th VO (PlanName) landed; MethodName now calls that helper 

55while keeping its own frozen dataclass type and per-aggregate error 

56class. See the helper module's docstring for the design rationale. 

57 

58## Frozensets in state, lists in payloads 

59 

60`needed_families` is `frozenset[UUID]` in domain state 

61(deduplicated, hashable, set-membership in O(1) for Plan-binding 

62checks) and `list[UUID]` in event payloads (JSON-friendly, sorted 

63for determinism). Same precedent as Trust's Policy 

64`permitted_principals` / `permitted_commands`. The evolver bridges 

65the two. Sorting in `to_payload` keeps the persisted bytes 

66deterministic — same logical family set, same payload, same 

67idempotency hash. 

68"""

132class MethodCannotVersionError(Exception): 

133 """Attempted to version a method not in `Defined` or `Versioned`. 

134 

135 Multi-source guard: `version_method` accepts both `Defined` 

136 (first revision) and `Versioned` (subsequent revisions — 

137 operators bump v1 → v2 → v3 over time as the recipe's 

138 parameters or step list are refined). Only `Deprecated` is 

139 rejected (you can't revise a deprecated method — un-deprecate 

140 first if you want to bring it back, though that slice doesn't 

141 exist today). 

142 

143 Mirrors `FamilyCannotVersionError` shape and semantics 

144 (Equipment 5f-2). Same deliberate divergence from strict-not- 

145 idempotent: re-versioning with the same tag succeeds and emits a 

146 fresh event (re-attestation is a legitimate audit moment). 

147 Pinned by tests/unit/recipe/test_version_method_decider.py. 

148 """ 

149 

150 def __init__(self, method_id: UUID, current_status: "MethodStatus") -> None: 

151 super().__init__( 

152 f"Method {method_id} cannot be versioned: currently in status " 

153 f"{current_status.value}, version requires " 

154 f"{MethodStatus.DEFINED.value} or {MethodStatus.VERSIONED.value}" 

155 ) 

156 self.method_id = method_id 

157 self.current_status = current_status

253@dataclass(frozen=True) 

254class Method: 

255 """Aggregate root: an abstract technique-class recipe. 

256 

257 `needed_families` is a frozenset of Family ids the Method 

258 requires. Eventual-consistency stance: existence is not verified 

259 at decide time; mismatch surfaces at Plan binding (6e). 

260 

261 `version` is the operator-supplied label of the most recent 

262 `version_method` call (None until first version). State always 

263 holds the latest tag — past tags live in the event stream as 

264 `MethodVersioned` events. No `current_` prefix because state by 

265 definition holds current values (same convention as `status`, 

266 `name`). Free-text validated at API boundary + defensively in the 

267 decider; no VO. Default None keeps pre-6b MethodDefined-only 

268 streams folding cleanly (additive-state pattern). Mirrors 

269 Family's `version` semantics (Equipment 5f-2): preserved 

270 across deprecation as an audit signal of the last revision before 

271 deprecation. 

272 

273 `parameters_schema` is the optional JSON Schema (Draft 2020-12, 

274 constrained subset) declaring the shape of parameter dicts that 

275 Plans (6g-b) and Runs (6g-c) carry for this Method. Defaults to 

276 None for legacy Methods (additive-state pattern); None means 

277 "this Method declares no parameter contract — accept any dict". 

278 Distinct from `{}` (empty schema, "operator explicitly said no 

279 parameters"). Subset shared with Family.settings_schema via 

280 `cora.infrastructure.json_schema_subset`. See 

281 [[project_run_parameters_design]] for the full 6g family layout. 

282 """ 

283 

284 id: UUID 

285 name: MethodName 

286 needed_families: frozenset[UUID] = field(default_factory=frozenset[UUID]) 

287 status: MethodStatus = MethodStatus.DEFINED 

288 version: str | None = None 

289 parameters_schema: dict[str, Any] | None = field(default=None) 

290 # Phase 6l: Method.capability_id points to the universal Capability 

291 # template (Recipe BC 6k) this Method realizes as a Method-shaped 

292 # executor. REQUIRED at define_method post-6l; defaults None at the 

293 # STATE level for evolver-back-compat with pre-6l streams (additive- 

294 # state pattern; same shape as Method.parameters_schema 6g). 

295 # Distinct from `needed_families` (hardware compatibility, what 

296 # Family classes the Method needs available) — both fields stay, 

297 # answering DIFFERENT questions per [[project-capability-aggregate-design]] 

298 # DLM-B watch item 10. The cross-BC validation that 

299 # `Method.parameters_schema ⊂ Capability.parameter_schema` runs at 

300 # define_method time via the capability_loader port (STRICT per 

301 # [[project-asset-settings-design]] 5g-c anchor). 

302 capability_id: UUID | None = field(default=None) 

303 # Phase 10b: needed_supplies references Supply.kind STRINGS (not 

304 # UUIDs). Asymmetric with needed_families (frozenset[UUID]) by 

305 # design: Family is a TYPE registry (one global definition, 

306 # referenced by UUID); Supply is an INSTANCE aggregate (multiple 

307 # per facility, each with its own availability state, sharing a 

308 # `kind` label). Methods are facility-portable so they reference 

309 # the abstract kind, not a per-facility instance UUID. Defaults 

310 # to empty frozenset (additive-state pattern; pre-10b 

311 # MethodDefined-only streams fold cleanly via payload.get default). 

312 # See [[project_supply_design]] §"Phase 10b — Method.needed_supplies 

313 # consumer" for the full design lock. 

314 needed_supplies: frozenset[str] = field(default_factory=frozenset[str])

327 [[project_schema_validated_values_pattern]] + 

328 [[project_asset_settings_design]] 5g-c cross-BC anchor. 

329 

330 `reason` is a descriptive string with the offending JSON Pointer 

331 so operators can pinpoint the conflict (e.g. 

332 `properties.energy.maximum`). 

333 """

336 super().__init__( 

337 f"Method {method_id} parameters_schema is not a subset of "

339 ) 

340 self.method_id = method_id 

341 self.capability_id = capability_id 

342 self.reason = reason
