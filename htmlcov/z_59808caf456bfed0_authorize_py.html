1"""TrustAuthorize: production adapter for the cross-BC `Authorize` port. 

2 

3Implements `cora.infrastructure.ports.Authorize` by loading a single 

4configured Policy aggregate and delegating to `decide_authorization` 

5in `cora.trust._authorization_decision`, the one place a decision is 

6reached. This is the structural moment where the Trust BC's pure domain 

7logic (Zone / Conduit / Policy + define + evaluate) gates real commands 

8across every BC. 

9 

10This adapter supplies a `ResolvedContext`: it resolved every input the 

11decision consults, so the answer is the system's real one. The query 

12slices supply a `PolicyOnlyContext` for hypotheticals and get an answer 

13stamped as partial. Adding a conjunct means changing the decision 

14module, not this adapter, which is the point of routing through it. 

15 

16## Shape: single configured policy 

17 

18The constructor takes one `policy_id`. Every `authorize(...)` call 

19loads that policy via `load_policy` (fold-on-read; O(events-per-stream) 

20per request) and evaluates against it. 

21 

22This deliberately ships the smallest useful gating wire-up: 

23- One policy per deployment (set via `Settings.trust_policy_id`) 

24- No projection / cross-stream resolution 

25- No caching (each request hits the event store) 

26 

27Multi-policy resolution + caching + LISTEN/NOTIFY invalidation land 

28in later phases when projection-worker infrastructure exists. 

29 

30## A second, optional rulebook for the in-process door 

31 

32`in_process_policy_id` adds exactly one exception to "one policy per 

33deployment": when set, a call whose `surface_id` is 

34`SYSTEM_IN_PROCESS_SURFACE_ID` (CORA's own background agents, never a 

35human, never an external caller) is evaluated against THAT policy 

36instead of `policy_id`. Every other surface, and an in-process call 

37when this is left unset, resolves to `policy_id` exactly as before -- 

38`_effective_policy_id` is the single place this is decided, mirroring 

39`_effective_conduit_id`. This is deliberately not a general multi- 

40surface widening of `Policy` itself (`Policy.surface_id` stays a single 

41scalar); it is the smallest change that lets the front door and the 

42backdoor be governed by two different rulebooks on one deployment. 

43 

44## Conduit semantics 

45 

46The port passes `conduit_id: UUID`. TrustAuthorize forwards the 

47caller's `conduit_id` to `evaluate`, which means a policy bound 

48to one conduit naturally denies calls on another via evaluate's 

49existing conduit-mismatch check. 

50 

51Operational consequence: deployments wire `Settings.trust_policy_id` 

52to a Policy whose `conduit_id` matches what handlers pass. Every 

53handler passes `UUID(int=0)` (nil sentinel; the ~180-call-site sweep 

54that would let a handler pass a real conduit_id of its own is 

55deferred, per `project_conduit_injection_design.md` WI10, until a 

56real multi-zone need exists), so the gating policy must use 

57`conduit_id=UUID(int=0)` unless a deployment configures 

58`Settings.trust_conduit_id`. 

59 

60`trust_conduit_id` resolves the UNSPECIFIED case: when the caller 

61passes the nil sentinel AND a conduit is configured, that conduit is 

62used for both the Policy evaluation and the Verdict write, never one 

63without the other, so the row that gets written can never disagree 

64with the decision that produced it (`_effective_conduit_id` is the 

65single place this is decided). A caller that passes a real, 

66non-nil conduit_id of its own is never overridden — configuration is 

67a default for "unspecified", not an override for "specified". Once 

68HTTP / MCP / A2A surfaces start injecting their own conduit_ids, 

69deployments will define one Policy per conduit (single-policy-per- 

70deployment shape stays; the operator picks which conduit to gate 

71first, others fall through to deny). 

72 

73## Bootstrap problem (closed) 

74 

75Without a seed, the configured policy must already permit 

76`DefinePolicy` for someone to define new policies through the API — 

77chicken-and-egg. The Atlas migration 

78`20260519200000_seed_default_surfaces_and_v2_policy.sql` seeds the 

79System Bootstrap Policy at a fixed UUID 

80(`cora.trust._bootstrap.SYSTEM_BOOTSTRAP_POLICY_ID`) permitting 

81`SYSTEM_PRINCIPAL_ID` to call `{DefinePolicy, RegisterActor}` on the 

82nil conduit, bound to the seeded HTTP Surface. Production deployments 

83collapse the prior 3-step dance to a single env var: 

84 

85 TRUST_POLICY_ID=00000000-0000-0000-0000-000000000002 

86 

87Operators then register a real admin Actor and promote a real admin 

88Policy via the API, and (optionally) re-point `TRUST_POLICY_ID` at 

89the new policy. Design lock + anti-hooks: 

90`memory/project_bootstrap_policy_design.md`. The Settings default 

91flip to non-None is deferred (WI8) pending a test-fixture audit; 

92~2400 tests rely on AllowAllAuthorize today. 

93 

94## Caller authz vs evaluation result 

95 

96`Authorize.authorize` returns `Allow` or `Deny`. From the caller's 

97perspective there's no distinction between "the policy permits you" 

98(Allow) and "no policy applies / always Allow" (Allow); both gate 

99through. Same for Deny — the reason string carries the diagnostic 

100("Principal X not in policy Y's permitted set" vs "Configured 

101TrustAuthorize policy Y not found in event store"). 

102 

103If the configured policy is missing from the event store, this 

104adapter returns Deny — fail-closed. A Settings-time check that the 

105policy exists at startup would surface this earlier; deferred. 

106 

107## Optional verdict entry emission 

108 

109When constructed with a `VerdictStore`, every Allow / Deny 

110decision additionally writes one `Verdict` entry row 

111to the per-Conduit verdict logbook. This is the per-Conduit 

112authz audit log — every command that traverses a Conduit is 

113captured with actor, command, decision, reason, and timestamps. 

114 

115Wiring is opt-in (constructor param defaults to None) so existing 

116test paths and the AllowAllAuthorize fallback don't accumulate 

117entries. When `verdict_store` is provided, `clock` and 

118`id_generator` are required (for `occurred_at` and `event_id`); the 

119constructor enforces this so missed wiring fails loud at app 

120startup, not at the first authz call. 

121 

122Logbook id resolution: TrustAuthorize loads the target Conduit 

123aggregate via `load_conduit` and reads `conduit.logbooks[ 

124LOGBOOK_KIND_VERDICT]`. The Conduit stream is short (genesis + 

125logbook-open, ~handful of events) so per-call fold cost is small; 

126per-process caching keyed on `conduit_id` is the natural future 

127optimization. If the Conduit doesn't exist (typical for 

128`UUID(int=0)` sentinel until conduit-routing lands) or has no 

129verdict logbook open, the entry write is silently skipped with 

130a warn log — the authz decision itself is unaffected. 

131 

132`correlation_id` for the entry row comes from 

133`current_correlation_id()` (the active OTel span's trace_id encoded 

134as a UUID); same source the calling handler uses for its event 

135envelope, so entry rows correlate naturally with the events that 

136triggered them. 

137"""

180 self, 

181 event_store: EventStore,

183 policy_id: UUID,

185 clock: Clock | None = None, 

186 id_generator: IdGenerator | None = None,

193 if liveness_enforced and liveness_lookup is None: 

194 msg = "TrustAuthorize: liveness_enforced requires a liveness_lookup to be wired" 

195 raise ValueError(msg) 

196 if verdict_store is not None and (clock is None or id_generator is None): 

197 msg = "TrustAuthorize: verdict_store requires both clock and id_generator to be wired" 

198 raise ValueError(msg) 

199 self._event_store = event_store 

200 self._policy_id = policy_id 

201 # The configured conduit a caller's UNSPECIFIED (nil) conduit_id 

202 # resolves to. None leaves every caller's conduit_id exactly as 

203 # passed, which for every handler today means nil — today's 

204 # behaviour, unchanged. See `_effective_conduit_id`. 

205 self._conduit_id = conduit_id 

206 # The second, optional rulebook: governs calls that arrive through 

207 # the in-process Surface (`SYSTEM_IN_PROCESS_SURFACE_ID`) when set, 

208 # leaving every other surface -- and an in-process call when this 

209 # is unset -- resolved to `policy_id` exactly as before. See 

210 # `_effective_policy_id`. 

211 self._in_process_policy_id = in_process_policy_id 

212 # Defaults to True so that adding this knob cannot weaken a 

213 # deployment that already gates: an existing config that sets 

214 # `trust_policy_id` and nothing else keeps enforcing exactly as it 

215 # did. Only an explicit `policy_posture=shadow` downgrades, and the 

216 # boot path refuses that combination without a policy id. 

217 # 

218 # There is no third "off" state here on purpose. Off is already 

219 # spelled `trust_policy_id is None`, which returns 

220 # `AllowAllAuthorize` from `build_authorize` before this class is 

221 # constructed at all, and two ways to say the same thing is how a 

222 # deployment ends up believing it is gated when it is not. 

223 self._policy_enforced = policy_enforced 

224 self._verdict_store = verdict_store 

225 self._clock = clock 

226 self._id_generator = id_generator 

227 # Two knobs, not one, because measuring must be possible without 

228 # refusing. A wired lookup with `liveness_enforced=False` is SHADOW 

229 # mode: every non-active caller is logged and none is denied, which 

230 # is the adoption measurement the human-envelope design requires 

231 # before any conjunct depends on it. Enforcement without a lookup is 

232 # rejected at construction rather than silently degrading to "off", 

233 # because a deployment that asked for enforcement and got none is 

234 # exactly the failure this arrangement exists to prevent. 

235 self._liveness_lookup = liveness_lookup 

236 self._liveness_enforced = liveness_enforced

238 async def _resolve_liveness( 

239 self, principal_id: UUID, command_name: str 

240 ) -> PrincipalLiveness | None: 

241 """Resolve the CALLER's liveness, or None when the conjunct cannot run. 

242 

243 `principal_id` is the caller, never a command target. Passing the 

244 wrong id here would silently authorize against a different 

245 principal's switch, so `test_liveness_is_resolved_for_the_caller` 

246 pins the argument rather than trusting the call site. 

247 

248 None means the conjunct is not evaluated, for any of FOUR 

249 reasons: no lookup wired, the command is exempt, the read 

250 failed, or the posture is "shadow" (resolved and logged, then 

251 deliberately withheld from the decision). All four must leave 

252 `Conjunct.LIVENESS` absent from `evaluated` so no verdict claims 

253 a check that did not run. Shadow is the easy one to forget when 

254 editing this, because it is the only case that DOES resolve a 

255 value and then discards it. 

256 

257 A failed read FAILS OPEN, loudly. Fail-closed would turn a 

258 transient event-store fault into a site-wide lockout mid-beamtime, 

259 which is worse than briefly not enforcing a switch an operator 

260 flips by hand. The warning is the ONLY compensating control: the 

261 `Verdict` row carries no conjunct column, so a reader of the 

262 logbook cannot tell a fail-open request from an enforced one. 

263 """ 

264 if self._liveness_lookup is None or is_liveness_exempt(command_name): 

265 return None 

266 try: 

267 liveness = await self._liveness_lookup.liveness_of(principal_id) 

268 except Exception: 

269 _log.warning( 

270 "trust_authorize.liveness_unresolved", 

271 principal_id=str(principal_id), 

272 command_name=command_name, 

273 correlation_id=str(current_correlation_id()), 

274 exc_info=True, 

275 ) 

276 return None 

277 if liveness is not PrincipalLiveness.ACTIVE: 

278 # Emitted in BOTH postures. In shadow this is the entire 

279 # deliverable (how much would enforcement have refused, and 

280 # which remedy each case needed); under enforcement it is the 

281 # operator-facing record of a refusal that already happened. 

282 _log.info( 

283 "trust_authorize.liveness_not_active", 

284 principal_id=str(principal_id), 

285 command_name=command_name, 

286 liveness=liveness.value, 

287 enforced=self._liveness_enforced, 

288 correlation_id=str(current_correlation_id()), 

289 ) 

290 return liveness if self._liveness_enforced else None

292 def _effective_conduit_id(self, conduit_id: UUID) -> UUID: 

293 """Resolve an UNSPECIFIED conduit_id to the configured one. 

294 

295 Called exactly once per `authorize()` call, and the single result 

296 feeds BOTH the Policy evaluation and the Verdict write below, so 

297 the two can never disagree about which conduit a command 

298 traversed -- the row that gets written always describes the 

299 conduit the decision was actually evaluated against. 

300 

301 `NIL_SENTINEL_ID` is documented (`infrastructure.routing`) as 

302 meaning "unspecified", not "none", so resolving it to the 

303 deployment's one configured conduit is a default for the 

304 unspecified case, not a fabrication. A caller that already 

305 passes a real, non-nil conduit_id is never overridden -- this 

306 only fills in what the caller left blank. 

307 """ 

308 if self._conduit_id is not None and conduit_id == NIL_SENTINEL_ID: 

309 return self._conduit_id 

310 return conduit_id

312 def _effective_policy_id(self, surface_id: UUID) -> UUID: 

313 """Resolve which configured Policy governs this call. 

314 

315 The backdoor rulebook applies only when BOTH hold: the call 

316 arrived through the in-process Surface, and a backdoor policy is 

317 actually configured. Every other surface -- and an in-process 

318 call when no backdoor policy is set -- resolves to the one front 

319 policy, today's single-rulebook behaviour unchanged. 

320 """ 

321 if self._in_process_policy_id is not None and surface_id == SYSTEM_IN_PROCESS_SURFACE_ID: 

322 return self._in_process_policy_id 

323 return self._policy_id

325 async def authorize( 

326 self, 

327 principal_id: UUID, 

328 command_name: str, 

329 conduit_id: UUID, 

330 surface_id: UUID = NIL_SENTINEL_ID, 

331 ) -> AuthzResult: 

332 conduit_id = self._effective_conduit_id(conduit_id) 

333 policy_id = self._effective_policy_id(surface_id) 

334 liveness = await self._resolve_liveness(principal_id, command_name) 

335 policy = await load_policy(self._event_store, policy_id) 

336 if policy is None: 

337 _log.warning( 

338 "trust_authorize.policy_missing", 

339 policy_id=str(policy_id), 

340 principal_id=str(principal_id), 

341 command_name=command_name, 

342 conduit_id=str(conduit_id), 

343 surface_id=str(surface_id), 

344 correlation_id=str(current_correlation_id()), 

345 ) 

346 result: AuthzResult = Deny( 

347 reason=(f"Configured TrustAuthorize policy {policy_id} not found in event store") 

348 ) 

349 else: 

350 # Forward the EFFECTIVE conduit_id (was policy.conduit_id 

351 # previously). evaluate's conduit-mismatch check now 

352 # meaningfully gates calls — a policy bound to one conduit 

353 # denies calls on another instead of being evaluated as if 

354 # it were governing. 

355 # Forward surface_id; defaults to nil where the route 

356 # layer hasn't been swept to inject the real Surface ID. 

357 result = decide_authorization( 

358 AuthorizationRequest( 

359 principal_id=principal_id, 

360 command_name=command_name, 

361 conduit_id=conduit_id, 

362 surface_id=surface_id, 

363 ), 

364 ResolvedContext(policy=policy, liveness=liveness), 

365 ) 

366 

367 result, shadow_reason = self._apply_policy_posture( 

368 result, 

369 policy_id=policy_id, 

370 principal_id=principal_id, 

371 command_name=command_name, 

372 surface_id=surface_id, 

373 ) 

374 self._log_decision( 

375 result, 

376 policy_id=policy_id, 

377 principal_id=principal_id, 

378 command_name=command_name, 

379 surface_id=surface_id, 

380 shadow_reason=shadow_reason, 

381 ) 

382 

383 if self._verdict_store is not None: 

384 await self._emit_verdict( 

385 principal_id=principal_id, 

386 command_name=command_name, 

387 conduit_id=conduit_id, 

388 result=result, 

389 shadow_reason=shadow_reason, 

390 ) 

391 

392 return result

394 def _log_decision( 

395 self, 

396 result: AuthzResult, 

397 *, 

398 policy_id: UUID, 

399 principal_id: UUID, 

400 command_name: str, 

401 surface_id: UUID, 

402 shadow_reason: str | None, 

403 ) -> None: 

404 """One line per call, naming what the gate DID. 

405 

406 Runs AFTER `_apply_policy_posture`, for the same reason the verdict 

407 row is written after it. A `trust_authorize.deny` line beside a 

408 command that went on to succeed makes every refusal count taken from 

409 the log wrong, and taking a refusal count is the entire job of a 

410 shadow period. The first live shadow window emitted both lines for 

411 each near-miss and was exactly that misleading. 

412 

413 The counterfactual is not lost by moving the line: it rides on the 

414 allow as `shadowed_reason`, beside the `policy_shadow_near_miss` 

415 warning the posture already emits. Both fields are chosen the same 

416 way `_emit_verdict` chooses the row's decision and reason, so a 

417 reader cannot find the log and the record disagreeing about a call. 

418 """ 

419 if isinstance(result, Deny): 

420 _log.info( 

421 "trust_authorize.deny", 

422 policy_id=str(policy_id), 

423 principal_id=str(principal_id), 

424 command_name=command_name, 

425 surface_id=str(surface_id), 

426 reason=result.reason, 

427 correlation_id=str(current_correlation_id()), 

428 ) 

429 return 

430 _log.info( 

431 "trust_authorize.allow", 

432 policy_id=str(policy_id), 

433 principal_id=str(principal_id), 

434 command_name=command_name, 

435 surface_id=str(surface_id), 

436 shadowed_reason=shadow_reason, 

437 correlation_id=str(current_correlation_id()), 

438 )

440 def _apply_policy_posture( 

441 self, 

442 result: AuthzResult, 

443 *, 

444 policy_id: UUID, 

445 principal_id: UUID, 

446 command_name: str, 

447 surface_id: UUID, 

448 ) -> tuple[AuthzResult, str | None]: 

449 """In shadow, turn a refusal into a recorded near-miss. 

450 

451 Runs BEFORE `_emit_verdict` deliberately, so the Verdict row says 

452 what the system actually did. A row reading `Deny` beside a command 

453 that went on to succeed would make the record false in the one place 

454 a reader goes to find out whether something was refused, and no 

455 amount of surrounding log context repairs that. 

456 

457 The counterfactual is not thrown away: it rides in the row's own 

458 `reason`, prefixed, so the shadow log is queryable from the record 

459 rather than only from stdout. That is what makes a shadow period 

460 usable as the INVENTORY for the eventual policy: every principal and 

461 command an enforcing gate would have refused is retrievable 

462 afterwards, with its reason, from the verdict logbook. 

463 

464 `evaluated` is carried across unchanged. The conjuncts really were 

465 consulted; posture governs what is done with the answer, never 

466 whether the question was asked. 

467 """ 

468 if self._policy_enforced or not isinstance(result, Deny): 

469 return result, None 

470 _log.warning( 

471 "trust_authorize.policy_shadow_near_miss", 

472 policy_id=str(policy_id), 

473 principal_id=str(principal_id), 

474 command_name=command_name, 

475 surface_id=str(surface_id), 

476 would_deny_reason=result.reason, 

477 correlation_id=str(current_correlation_id()), 

478 ) 

479 return Allow(evaluated=result.evaluated), f"{_SHADOW_REASON_PREFIX}{result.reason}"

481 async def _emit_verdict( 

482 self, 

483 *, 

484 principal_id: UUID, 

485 command_name: str, 

486 conduit_id: UUID, 

487 result: AuthzResult, 

488 shadow_reason: str | None = None, 

489 ) -> None: 

490 """Best-effort write of one Verdict entry per call. 

491 

492 Skipped silently with a warn log if the Conduit doesn't exist 

493 or has no currently-open verdict logbook. The authz 

494 decision itself is unaffected. 

495 """ 

496 # Type-narrowed: __init__ enforces that these are non-None 

497 # whenever verdict_store is set. 

498 assert self._verdict_store is not None 

499 assert self._clock is not None 

500 assert self._id_generator is not None 

501 

502 conduit = await load_conduit(self._event_store, conduit_id) 

503 if conduit is None: 

504 _log.warning( 

505 "trust_authorize.skip_traversal", 

506 conduit_id=str(conduit_id), 

507 reason="conduit_not_found", 

508 correlation_id=str(current_correlation_id()), 

509 ) 

510 return 

511 logbook_id = conduit.logbooks.get(LOGBOOK_KIND_VERDICT) 

512 if logbook_id is None: 

513 _log.warning( 

514 "trust_authorize.skip_traversal", 

515 conduit_id=str(conduit_id), 

516 reason="no_open_verdict_logbook", 

517 correlation_id=str(current_correlation_id()), 

518 ) 

519 return 

520 

521 decision_str: VerdictDecision = "Allow" if isinstance(result, Allow) else "Deny" 

522 # `shadow_reason` is set only on an Allow that a shadow posture 

523 # downgraded from a Deny, so the two are never both present: the 

524 # row reports the decision that was ACTED ON, and carries the 

525 # refusal that did not happen as its reason. 

526 reason = result.reason if isinstance(result, Deny) else shadow_reason 

527 

528 await self._verdict_store.append( 

529 [ 

530 Verdict( 

531 event_id=self._id_generator.new_id(), 

532 conduit_id=conduit_id, 

533 logbook_id=logbook_id, 

534 actor_id=principal_id, 

535 command_name=command_name, 

536 decision=decision_str, 

537 reason=reason, 

538 correlation_id=current_correlation_id(), 

539 causation_id=None, 

540 occurred_at=self._clock.now(), 

541 ) 

542 ] 

543 )
