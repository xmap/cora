1"""Authorize port: gate every command behind authz.authorize(principal, command, conduit, surface). 

2 

3`principal_id` (not `actor_id`) names the invoker because the Access BC 

4already owns an `Actor` aggregate; using `actor_id` for both the Actor 

5aggregate's id and the calling-party's id was a real bug vector at 

6handler call sites where commands target an Actor aggregate (for example, 

7DeactivateActor). 

8 

9`conduit_id: UUID` names the ISA-99/IEC-62443 inter-zone 

10channel — comms path between two trust zones — through which the 

11command would flow. Operationally inert at v1: every handler passes 

12`UUID(int=0)` nil-sentinel. Reactivation tracked as 

13project_conduit_injection_design.md WI10. 

14 

15`surface_id: UUID` names the process-level arrival point (HTTP / 

16MCP stdio / MCP streamable-http) through which the request entered 

17CORA. Closed-StrEnum kind sits on the 

18`cora.trust.aggregates.surface.Surface` aggregate; surface adapters 

19resolve concrete IDs per request, and edge-auth layers OAuth `aud` 

20validation on top. 

21 

22Defaults: both `conduit_id` and `surface_id` default to nil 

23`UUID(int=0)` so existing handler call sites work unchanged. As real 

24routing arrives at the HTTP / MCP / A2A boundaries, routes inject 

25concrete IDs and stop using the nil sentinel — the architecture 

26fitness test pins the no-nil-leak invariant. 

27 

28`AllowAllAuthorize` is the no-op stub used for dev/test and the 

29documented bootstrap workflow; `TrustAuthorize` 

30(in `cora.trust.authorize`) is the production adapter. 

31"""

55class Authorize(Protocol): 

56 """Authorization gate: called before every command. 

57 

58 Named-method (not `__call__`) per Python typing-community guidance 

59 (PEP 544 + typing spec + mypy docs): `__call__` Protocols are for 

60 callback signatures `Callable[...]` can't express (variadic, 

61 overloaded, complex generic). A single-operation domain port uses 

62 a regular method, matching CORA's other ports (`Clock.now`, 

63 `EventStore.load`, `TokenVerifier.verify`, …) and the broader 

64 authorization-library corpus (Spring Security 6's 

65 `AuthorizationManager.authorize`, Pundit's `authorize`, Cedar's 

66 `is_authorized`, Casbin's `enforce`). 

67 

68 The seam: `Kernel.authz: Authorize` with call sites reading 

69 `await deps.authz.authorize(...)` — "use the authz port to 

70 authorize this command." Factory protocols (`AuthorizeFactory`, 

71 `LLMFactory`) DO use `__call__` because they ARE construction 

72 functions; this port is not. 

73 """
