1"""The back-door grant table: which in-process principal needs which command. 

2 

3CORA gates every command through the `Authorize` port. Two doors reach 

4it: the HTTP front door (people and external agents), and 

5`SYSTEM_IN_PROCESS_SURFACE_ID`, the back door CORA's own background 

6runtimes use to act on themselves. This table is the ground truth for 

7the back door: for every principal that issues a command through it, 

8the exact set of command names a `TrustAuthorize` Policy must grant that 

9principal so the runtime keeps working once a deployment leaves shadow 

10mode and starts enforcing a real Policy instead of `AllowAllAuthorize`. 

11 

12## Inert by design 

13 

14Nothing in the running app imports this module. It is consumed by two 

15things only: 

16 

17 - `tests/architecture/test_hardcoded_command_lists_track_wire_surface.py`, 

18 which AST-parses (never imports) this file's `IN_PROCESS_GRANTS` 

19 literal and checks every granted command name against the real wire 

20 surface, the same way it already checks every other hand-typed 

21 command-name list in the repo. 

22 - `tools/gen_policy_grants.py`, which imports this table to emit the 

23 `POST /policies` request body an operator pipes into the API to 

24 seed the deployment's real back-door Policy. 

25 

26Nothing here changes what any runtime does; changing this table has no 

27effect until an operator re-runs the generator and posts the result. A 

28future sweep (out of scope here) is what will make the ~35 in-process 

29call sites that still pass `NIL_SENTINEL_ID` for `surface_id` actually 

30land on this door; today the table already reflects the commands those 

31sites issue, so that sweep does not have to re-derive them. 

32 

33## How every entry was derived 

34 

35Not copied from a design memo: each entry comes from reading the 

36call site itself, for every principal drawn from two populations, 

37`grep -rl SYSTEM_IN_PROCESS_SURFACE_ID src/cora/` and 

38`grep -rl "surface_id=NIL_SENTINEL_ID" src/cora/`. Every command name 

39below is confirmed present in the real wire surface via 

40`grep -rn 'command_name=' src/cora/*/wire.py`. 

41 

42## Deliberate omissions 

43 

44 - `cora.agent.promote_seeded_fleet.promote_seeded_fleet`: rebinds the 

45 kernel through `AllowAllAuthorize` before calling `version_agent` 

46 (see that module's own docstring, "Bypasses the deployment's 

47 configured gate, on purpose"). It never consults a real Policy, so 

48 there is nothing for a Policy to grant it. 

49 - Eight synthetic Decision-envelope labels (`CampaignWatcherTick`, 

50 `ClearanceWatcherTick`, `ClearanceExpirerTick`, `ProcedureWatcherTick`, 

51 `CalibrationWatcherTick`, `ExperimentSteererTurn`, 

52 `CautionPromoterSubscriber`, `AuthorityRevocationHolderSubscriber`): 

53 these are `command_name=` values written directly via 

54 `to_new_event(...)` + `event_store.append(...)`, audit labels on a 

55 Decision record, never arguments to `authorize()`. They carry no 

56 grant because there is no gate that checks one. 

57 

58## Overridable principals 

59 

60`RUN_DEBRIEFER_EXTERNAL_AGENT_ID` and `CAUTION_DRAFTER_EXTERNAL_AGENT_ID` are the default 

61principals only: `Settings.run_debriefer_agent_id` and 

62`Settings.caution_drafter_agent_id` let a deployment designate a 

63different Agent for either LLM subscriber. A deployment that overrides 

64either one must grant the designated Agent the same command below 

65instead (or in addition). 

66 

67## Not currently wired 

68 

69`SIM_OBSERVATION_FEEDER_AGENT_ID` (`cora.run.adapters.sim_observation_feeder`) 

70is not a member of `SEEDED_FLEET` and nothing in `cora.api.main` 

71instantiates it; it ships as an optional sim harness a deployment can 

72wire in. Its entry documents what that deployment would need to grant, 

73not a principal already active anywhere. 

74"""
