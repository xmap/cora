1"""Operation BC factory: materialise a `DecidePort` from a config. 

2 

3`build_decide_port(config)` returns a `DecidePort` for the configured 

4decider substrate: 

5 

6 - `InMemoryDecidePort` (no config / `in_memory` substrate; the default + 

7 test convenience; replays seeded advice then advises Stop) 

8 - `GridWalkDecidePort` (`grid_walk` substrate; a deterministic, stateless 

9 grid/sweep decider over the SteeringSpace, no external optimizer) 

10 - `SobolDecidePort` (`sobol` substrate; a deterministic, stateless Sobol 

11 initial-design seeder; needs the optional `bo` dependency group) 

12 - `BoTorchDecidePort` (`botorch` substrate; a Gaussian-process Bayesian- 

13 optimization brain; forward-runs-only, needs the optional `bo` group) 

14 - `StagedDecidePort` (`staged` substrate; a two-phase composite that seeds 

15 with `sobol` then hands off to `botorch` on a successful-observation 

16 count; needs the optional `bo` group) 

17 

18These arms mirror `build_compute_port`, and a routing registry is earned only 

19when the substrate count makes the if-chain unwieldy, exactly as ControlPort 

20earned its registry from a third substrate and ComputePort deferred its. 

21 

22## Wire-selectable vs internally-selectable substrates 

23 

24`DecideSubstrate` is the FULL set of substrates the factory can build. 

25`WireDecideSubstrate` is the SUBSET a remote caller may select over the 

26HTTP/MCP wire. They are deliberately decoupled: a new substrate becomes 

27factory-buildable (and usable by in-process composition such as the staged 

28decider or a deployment config) the moment it is added to `DecideSubstrate`, 

29WITHOUT silently becoming selectable over the wire, where its config fields 

30may have no wire representation yet. A substrate is promoted to the wire only 

31when its wire config is deliberately designed. The wire request model 

32(`DecideConfigRequest` in `_advise_wire`) types its `substrate` field with 

33`WireDecideSubstrate`, so the two sets cannot drift by accident. 

34 

35## Lifecycle 

36 

37The returned port owns the lifecycle of any decider resource it holds: 

38`aclose()` is a no-op for the in-CORA deciders and would release a model 

39client / optimizer subprocess for a real external adapter. The caller 

40`aclose()`s it at teardown without branching on type. 

41"""

57DecideSubstrate = Literal["in_memory", "grid_walk", "sobol", "botorch", "staged"] 

58"""The full set of decider substrates `build_decide_port` can materialise. 

59 

60`in_memory` is the deterministic fake; `grid_walk` is the in-CORA grid/sweep 

61decider; `sobol` is the Sobol initial-design seeder; `botorch` is the GP 

62Bayesian-optimization brain; `staged` is the two-phase sobol-then-botorch 

63composite (the last three need the optional `bo` group). Adding an arm here 

64makes it factory-buildable for in-process composition + deployment config; 

65promoting it to the wire is a separate, deliberate step (see 

66`WireDecideSubstrate`). 

67""" 

68 

69WireDecideSubstrate = Literal["in_memory", "grid_walk"] 

70"""The subset of substrates a remote caller may select over the HTTP/MCP wire. 

71 

72Narrower than `DecideSubstrate` on purpose: a substrate is wire-selectable 

73only once its config has a designed wire representation. `sobol` (and later 

74the GP brain) are factory-buildable but NOT wire-selectable yet, so widening 

75`DecideSubstrate` never silently exposes an unconfigurable substrate on the 

76live route. The wire request model types its `substrate` with this Literal. 

77""" 

78

80@dataclass(frozen=True) 

81class DecidePortConfig: 

82 """Deployment config for the DecidePort substrate. 

83 

84 `substrate` selects the adapter. `points_per_axis` is the grid-walk 

85 resolution for continuous axes. `min_observations` / `num_restarts` / 

86 `raw_samples` / `seed` tune the BoTorch brain (the `botorch` substrate, 

87 and the brain child of the `staged` substrate). `staged_threshold` is the 

88 successful-observation count at which the `staged` composite hands off 

89 from the Sobol seeder to the brain; it must be >= `min_observations`. A 

90 full route table is deferred, mirroring `ComputePortConfig`. 

91 """ 

92 

93 substrate: DecideSubstrate = "in_memory" 

94 points_per_axis: int = 5 

95 min_observations: int = 5 

96 num_restarts: int = 10 

97 raw_samples: int = 256 

98 seed: int = 0 

99 staged_threshold: int = 5 

100 

101 

102def build_decide_port(config: DecidePortConfig | None = None) -> DecidePort: 

103 """Materialise the DecidePort the conduct loop talks to. 

104 

105 None or the `in_memory` substrate returns an `InMemoryDecidePort` (the 

106 default + test convenience). `grid_walk` returns a `GridWalkDecidePort` 

107 at the configured resolution. `sobol` / `botorch` return the seeder / 

108 GP brain (both probe the optional `bo` dependency at construction, raising 

109 `ValueError` if it is missing). `staged` composes a Sobol seeder + a 

110 BoTorch brain into the two-phase composite. New arms are added here as 

111 they are earned, exactly as `build_compute_port` grew its `local_process` 

112 arm. 

113 """ 

114 resolved = config if config is not None else DecidePortConfig() 

115 if resolved.substrate == "in_memory": 

116 return InMemoryDecidePort() 

117 if resolved.substrate == "grid_walk": 

118 return GridWalkDecidePort(points_per_axis=resolved.points_per_axis) 

119 if resolved.substrate == "sobol": 

120 return SobolDecidePort() 

121 if resolved.substrate == "botorch": 

122 return _build_botorch(resolved) 

123 if resolved.substrate == "staged": 

124 return StagedDecidePort( 

125 seeder=SobolDecidePort(), 

126 brain=_build_botorch(resolved), 

127 threshold=resolved.staged_threshold, 

128 brain_min_observations=resolved.min_observations, 

129 ) 

130 raise ValueError( # pragma: no cover 

131 f"unsupported decide substrate: {resolved.substrate!r}" 

132 ) 

133 

134 

135def _build_botorch(config: DecidePortConfig) -> BoTorchDecidePort: 

136 """Construct the BoTorch brain from config (shared by the botorch + staged arms).""" 

137 return BoTorchDecidePort( 

138 min_observations=config.min_observations, 

139 num_restarts=config.num_restarts, 

140 raw_samples=config.raw_samples, 

141 seed=config.seed, 

142 )
