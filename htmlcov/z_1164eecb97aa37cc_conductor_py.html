1"""Operation BC `Conductor`: walks Procedure steps via ControlPort + actions + checks. 

2 

3The Conductor is the Operation BC's Layer-2 runtime per 

4[[project_edge_runtime_design]]. It receives a sequence of `Step` 

5operations (a discriminated union over `SetpointStep | ActionStep | 

6CheckStep`), dispatches each through the right primitive 

7(`ControlPort.write` for setpoints, an action body looked up in the 

8`ActionRegistry` for actions, `ControlPort.read` followed by 

9criterion evaluation for checks), and records every outcome as a 

10step entry in the Procedure's steps logbook via the existing 

11`append_activities` handler. 

12 

13The Conductor is a single-process asyncio walker; per-call state 

14lives on the returned `ConductorResult`. Substrate-agnostic on the 

15setpoint + check paths (address parses inside the routed 

16`ControlPort` adapter); body-agnostic on the action path (the 

17registry maps a free-form name to a callable the deployment 

18supplies). 

19 

20## Failure mode 

21 

22The first step that raises any `Control*Error`, first action whose 

23name is not registered, OR first check whose criterion did not match 

24(or whose reading was non-Good quality) halts execution. The failing 

25step IS recorded in the logbook (payload's `result="failed"` + 

26`error_class` + `message`) before the call returns; subsequent steps 

27are NOT attempted. The Procedure's FSM is NOT advanced by the 

28Conductor; the caller decides abort vs retry vs hand-off after 

29inspecting `ConductorResult.failure`. 

30 

31Non-`Control*Error` exceptions raised by an action body (programmer 

32errors, `KeyboardInterrupt`, `CancelledError`, third-party-library 

33crashes) are NOT caught: they propagate to the caller so signals + 

34cancellation behave normally and bugs surface. Action bodies that 

35want to signal a domain-level "this didn't work out" without throwing 

36can return a result dict carrying their own status (e.g. `{"ok": 

37False, "reason": "out_of_range"}`); the Conductor treats any return 

38from a body as success-shaped at this tier. 

39 

40## Check semantics 

41 

42A `CheckStep` carries an address + an acceptance criterion. The 

43Conductor reads from the address via `ControlPort.read`, requires 

44`Reading.quality == "Good"` (Uncertain or Bad fails the check), and 

45evaluates the criterion against the observed value. The closed 

46criterion union (`EqualsCriterion | WithinToleranceCriterion`) keeps the wire shape 

47JSON-clean while leaving room for future variants (`OneOf`, 

48`Matches`, `Within` range) to land as additive code edits without a 

49migration. Non-numeric values land in `WithinToleranceCriterion` as a clean 

50mismatch (no coercion exception escapes); criterion handling tolerates 

51substrate value-type drift. 

52 

53## Cancellation handling 

54 

55`execute()` lets `CancelledError` propagate untouched: it is the 

56lower-level primitive that does not own FSM transitions. `conduct()` 

57catches `CancelledError` raised mid-`execute`, attempts a best-effort 

58`abort_procedure(reason="cancelled mid-execute")` so the Procedure 

59FSM lands in Aborted rather than orphaned in Running, then re-raises 

60so the caller's task still sees the cancellation. Cancellation 

61during the start / complete handler calls themselves propagates as-is 

62(those boundaries are single-handler-atomic; abort cleanup would race 

63the in-flight transition). 

64 

65## Out of scope at this iteration 

66 

67The executor arc continues; the following land in subsequent iters: 

68 

69 - pre-write reading capture (`verify` only does post-write today; 

70 a `capture_pre` flag would land additively when an undo / rollback 

71 pattern surfaces) 

72 - additional check criteria (`OneOf`, `Matches`, `Within` range) 

73 - concurrent / pipelined setpoint dispatch (sequential at v1) 

74 - `Capability`-driven step-list resolution (caller supplies the list) 

75 - action-body discovery from disk / config (registry is hand-built today) 

76 - acceptance of Uncertain quality (today only Good passes; an opt-in 

77 `allowed_qualities` field on CheckStep would land additively) 

78 

79## Why call the handler not the store directly 

80 

81`append_activities` is the slice handler that owns lazy-open of 

82the steps logbook + status guard (Procedure must be `Running`) + 

83authorization. The Conductor calls the handler, not the underlying 

84`ActivityStore`, so those concerns stay caged inside the existing slice 

85and the Conductor stays a thin orchestrator. The dependency is the 

86handler's `Handler` Protocol, not a concrete binding, so tests inject 

87a fake without standing up the full handler machinery. 

88"""

393@dataclass(frozen=True) 

394class ConductorResult: 

395 """Outcome of a `Conductor.execute` call. 

396 

397 `completed_count` is the number of steps that fully ran AND 

398 recorded a success entry. The failing step (if any) is NOT 

399 counted in `completed_count`; its failure IS recorded in the 

400 logbook AND surfaced in `failure`. 

401 

402 `actuation_kind` is the provenance fact the producing Dataset 

403 snapshots: `Physical` / `Simulated` / `Hybrid` when the conduct 

404 touched a routing table that declares simulated routes, else 

405 `None` (no routing table to consult, e.g. an opt-out in-memory 

406 deployment) which leaves the promotion gate inactive. It reflects 

407 routes ATTEMPTED, not only successfully actuated: a dispatch that 

408 resolves a simulated route and then raises still taints the conduct 

409 (any simulator touch is disqualifying), so the failure-path result 

410 still reports the kind. Do not "fix" the observe-before-dispatch 

411 ordering in `_ActuationObserver` without revisiting this contract. 

412 """ 

413 

414 procedure_id: UUID 

415 completed_count: int 

416 failure: ConductorFailure | None = None 

417 actuation_kind: ActuationKind | None = None 

418 

419 @property 

420 def succeeded(self) -> bool: 

421 return self.failure is None

424class _ActuationObserver: 

425 """Per-conduct `ControlPort` decorator that records actuation provenance. 

426 

427 Wraps the Conductor's `ControlPort` for the duration of one 

428 `execute` call so every dispatch (setpoint write, verify/check 

429 read, and action-body IO) passes through one seam. For each touched 

430 address it asks the inner port whether the address routes to a 

431 simulated adapter, then collapses the observations to an 

432 `ActuationKind`. 

433 

434 When the inner port does not expose `route_is_simulated` (a bare 

435 adapter or an opt-out in-memory deployment with no routing table), 

436 nothing is recorded and `actuation_kind` stays `None`, leaving the 

437 promotion gate inactive. The simulated determination is the 

438 inner port's declared per-route flag, never inferred here from the 

439 adapter class: a soft IOC speaks real Channel Access yet is a 

440 simulator. 

441 """ 

442 

443 def __init__(self, inner: ControlPort) -> None: 

444 self._inner = inner 

445 self._route_is_simulated: Callable[[str], bool] | None = getattr( 

446 inner, "route_is_simulated", None 

447 ) 

448 self._simulated_flags: set[bool] = set() 

449 

450 def _observe(self, address: str) -> None: 

451 if self._route_is_simulated is None: 

452 return 

453 # A routing miss surfaces on the real read/write below; here it 

454 # just means there is nothing to observe for this address. 

455 with contextlib.suppress(NoAdapterForAddressError): 

456 self._simulated_flags.add(bool(self._route_is_simulated(address))) 

457 

458 async def read(self, address: str) -> Reading: 

459 self._observe(address) 

460 return await self._inner.read(address) 

461 

462 async def write( 

463 self, 

464 address: str, 

465 value: int | float | bool | str | tuple[Any, ...], 

466 *, 

467 wait: bool = True, 

468 timeout_s: float = 30.0, 

469 ) -> None: 

470 self._observe(address) 

471 await self._inner.write(address, value, wait=wait, timeout_s=timeout_s) 

472 

473 def subscribe(self, address: str) -> AsyncIterator[Reading]: 

474 self._observe(address) 

475 return self._inner.subscribe(address) 

476 

477 @property 

478 def actuation_kind(self) -> ActuationKind | None: 

479 if not self._simulated_flags: 

480 return None 

481 if self._simulated_flags == {True}: 

482 return ActuationKind.SIMULATED 

483 if self._simulated_flags == {False}: 

484 return ActuationKind.PHYSICAL 

485 return ActuationKind.HYBRID

488class Conductor: 

489 """Operation BC Layer-2 runtime: walks `Step`s via ControlPort + action registry. 

490 

491 Stateless walker. Construct once at app wire-up time; call 

492 `execute` per Procedure execution. Per-call state lives on the 

493 returned `ConductorResult`. 

494 

495 The Conductor calls the `append_activities` handler (not the 

496 underlying `ActivityStore`) so lazy-open + status guard + authorization 

497 stay inside that slice. See module docstring for failure mode + 

498 out-of-scope. 

499 """ 

500 

501 def __init__( 

502 self, 

503 *, 

504 control_port: ControlPort, 

505 append_step: AppendProcedureActivitiesHandler, 

506 clock: Clock, 

507 id_generator: IdGenerator, 

508 action_registry: ActionRegistry | None = None, 

509 start_procedure: StartProcedureHandler | None = None, 

510 complete_procedure: CompleteProcedureHandler | None = None, 

511 abort_procedure: AbortProcedureHandler | None = None, 

512 ) -> None: 

513 self._control_port = control_port 

514 self._append_step = append_step 

515 self._clock = clock 

516 self._id_generator = id_generator 

517 self._action_registry: ActionRegistry = action_registry or InMemoryActionRegistry({}) 

518 self._start_procedure = start_procedure 

519 self._complete_procedure = complete_procedure 

520 self._abort_procedure = abort_procedure 

521 

522 async def execute( 

523 self, 

524 *, 

525 procedure_id: UUID, 

526 principal_id: UUID, 

527 correlation_id: UUID, 

528 steps: Sequence[Step], 

529 causation_id: UUID | None = None, 

530 surface_id: UUID = NIL_SENTINEL_ID, 

531 ) -> ConductorResult: 

532 """Walk `steps` in order; dispatch per kind + record outcome. 

533 

534 Halts on the first `Control*Error`, `UnknownActionError`, or 

535 `CheckFailedError` (criterion mismatch or non-Good quality). 

536 The failing step is recorded in the logbook (`result="failed"`) 

537 BEFORE this returns; subsequent steps are NOT attempted. The 

538 Procedure's FSM is unchanged. 

539 

540 Non-port, non-UnknownAction exceptions (programmer errors, 

541 KeyboardInterrupt, CancelledError) are NOT caught: they 

542 propagate to the caller so signals + cancellation behave 

543 normally and bugs surface. 

544 """ 

545 envelope = _Envelope( 

546 procedure_id=procedure_id, 

547 principal_id=principal_id, 

548 correlation_id=correlation_id, 

549 causation_id=causation_id, 

550 surface_id=surface_id, 

551 ) 

552 observer = _ActuationObserver(self._control_port) 

553 completed = 0 

554 for index, step in enumerate(steps): 

555 # Bind correlation_id to the ContextVar scoped per dispatch so 

556 # ControlPort adapters can emit `controlport.dispatch` events 

557 # without taking a kwarg. See `_control_dispatch_context` for 

558 # the why; contextvars survive each `await` inside `_dispatch` 

559 # and reset cleanly on exception. 

560 with with_dispatch_correlation_id(correlation_id): 

561 failure = await self._dispatch(step, index=index, envelope=envelope, port=observer) 

562 if failure is not None: 

563 return ConductorResult( 

564 procedure_id=procedure_id, 

565 completed_count=completed, 

566 failure=failure, 

567 actuation_kind=observer.actuation_kind, 

568 ) 

569 completed += 1 

570 return ConductorResult( 

571 procedure_id=procedure_id, 

572 completed_count=completed, 

573 actuation_kind=observer.actuation_kind, 

574 ) 

575 

576 async def conduct( 

577 self, 

578 *, 

579 procedure_id: UUID, 

580 principal_id: UUID, 

581 correlation_id: UUID, 

582 steps: Sequence[Step], 

583 causation_id: UUID | None = None, 

584 surface_id: UUID = NIL_SENTINEL_ID, 

585 ) -> ConductorResult: 

586 """Drive the full Procedure lifecycle: start -> execute -> complete | abort. 

587 

588 Three-phase wrapper around `execute()`: 

589 

590 1. Issue `start_procedure` (transitions Procedure Defined -> 

591 Running). If the start handler rejects (Procedure not 

592 in Defined, target Asset Decommissioned, Supply gate 

593 unmet, authz deny), return a lifecycle ConductorFailure 

594 without attempting any steps. 

595 2. Call `self.execute(steps)`. Step-level failures land in 

596 the result.failure as already documented. 

597 3. On execute success: issue `complete_procedure` 

598 (Running -> Completed). On execute failure: issue 

599 `abort_procedure` with a reason derived from the failed 

600 step. The abort is best-effort: if it ALSO fails, the 

601 original execute failure is what surfaces on the result 

602 (the Procedure stays Running and the operator must 

603 reconcile via state inspection). 

604 

605 Requires `start_procedure` + `complete_procedure` + 

606 `abort_procedure` handlers to have been supplied at __init__. 

607 Raises `RuntimeError` if any of the three is missing; this 

608 is a wiring bug, not a runtime failure, so it propagates. 

609 

610 Lifecycle failures (start rejected, complete rejected) carry 

611 `step_index=None`, `source_kind="lifecycle"`, `target` in 

612 `{"start", "complete", "abort"}`. 

613 """ 

614 if ( 

615 self._start_procedure is None 

616 or self._complete_procedure is None 

617 or self._abort_procedure is None 

618 ): 

619 raise RuntimeError( 

620 "Conductor.conduct() requires start_procedure + complete_procedure + " 

621 "abort_procedure handlers at __init__; only execute() is available " 

622 "without them." 

623 ) 

624 envelope_kwargs: dict[str, Any] = { 

625 "principal_id": principal_id, 

626 "correlation_id": correlation_id, 

627 "causation_id": causation_id, 

628 "surface_id": surface_id, 

629 } 

630 try: 

631 await self._start_procedure( 

632 StartProcedure(procedure_id=procedure_id), **envelope_kwargs 

633 ) 

634 except _LIFECYCLE_RERAISE: 

635 raise 

636 except Exception as exc: 

637 return ConductorResult( 

638 procedure_id=procedure_id, 

639 completed_count=0, 

640 failure=ConductorFailure( 

641 step_index=None, 

642 source_kind=_SOURCE_KIND_LIFECYCLE, 

643 target=_LIFECYCLE_TARGET_START, 

644 error_class=type(exc).__name__, 

645 message=str(exc), 

646 ), 

647 ) 

648 try: 

649 result = await self.execute( 

650 procedure_id=procedure_id, 

651 principal_id=principal_id, 

652 correlation_id=correlation_id, 

653 steps=steps, 

654 causation_id=causation_id, 

655 surface_id=surface_id, 

656 ) 

657 except asyncio.CancelledError: 

658 # The execute() call was cancelled mid-flight (caller cancelled 

659 # the conducting task or the loop is shutting down). The 

660 # Procedure is now in `Running` with partial step history; if 

661 # we let the cancellation propagate untouched, the FSM would 

662 # be orphaned. Best-effort transition to Aborted so operator 

663 # state reflects what happened. Re-raise so the caller's task 

664 # still sees the cancellation - this keeps signals + shutdown 

665 # behaving normally. 

666 with contextlib.suppress(Exception): 

667 # No ConductorResult is available on cancellation (execute() 

668 # raised before returning), so the observed actuation kind is 

669 # unrecoverable here: abort records None. Conservative residual 

670 # documented in the activation design; a Dataset off a 

671 # cancelled conduct carries no proven kind. 

672 await self._abort_procedure( 

673 AbortProcedure(procedure_id=procedure_id, reason="cancelled mid-execute"), 

674 **envelope_kwargs, 

675 ) 

676 raise 

677 if result.succeeded: 

678 try: 

679 await self._complete_procedure( 

680 CompleteProcedure( 

681 procedure_id=procedure_id, 

682 # The bridge: the observed kind rides the terminal 

683 # event the Conductor already issues, where the Data 

684 # BC reads it back at Dataset registration. Raw 

685 # ActuationKind value or None (no instrumented actuation). 

686 actuation_kind=( 

687 result.actuation_kind.value 

688 if result.actuation_kind is not None 

689 else None 

690 ), 

691 ), 

692 **envelope_kwargs, 

693 ) 

694 except _LIFECYCLE_RERAISE: 

695 raise 

696 except Exception as exc: 

697 return ConductorResult( 

698 procedure_id=procedure_id, 

699 completed_count=result.completed_count, 

700 failure=ConductorFailure( 

701 step_index=None, 

702 source_kind=_SOURCE_KIND_LIFECYCLE, 

703 target=_LIFECYCLE_TARGET_COMPLETE, 

704 error_class=type(exc).__name__, 

705 message=str(exc), 

706 ), 

707 ) 

708 return result 

709 # execute failed; attempt abort with a derived reason. Best-effort: 

710 # if abort itself fails, surface the original step failure since 

711 # that is what the caller needs to triage. 

712 failure = result.failure 

713 assert failure is not None # not result.succeeded implies failure 

714 reason = _derive_abort_reason(failure) 

715 with contextlib.suppress(Exception): 

716 await self._abort_procedure( 

717 AbortProcedure( 

718 procedure_id=procedure_id, 

719 reason=reason, 

720 # Honest provenance for a Dataset off an aborted conduct: 

721 # routes attempted before the failing step still taint it. 

722 actuation_kind=( 

723 result.actuation_kind.value if result.actuation_kind is not None else None 

724 ), 

725 ), 

726 **envelope_kwargs, 

727 ) 

728 return result

731 self, 

732 step: Step, 

733 *, 

734 index: int, 

735 envelope: "_Envelope", 

736 port: ControlPort, 

737 ) -> ConductorFailure | None: 

738 """Run one step + record outcome; return ConductorFailure on halt-condition. 

739 

740 `port` is the per-conduct observing wrapper around the 

741 Conductor's ControlPort; every dispatch goes through it so 

742 actuation provenance is captured once for the whole conduct. 

743 """ 

744 if isinstance(step, SetpointStep): 

745 return await self._run_setpoint(step, index=index, envelope=envelope, port=port) 

746 if isinstance(step, ActionStep): 

747 return await self._run_action(step, index=index, envelope=envelope, port=port) 

748 return await self._run_check(step, index=index, envelope=envelope, port=port)

779 **payload_body,

996def _criterion_to_dict(criterion: CheckCriterion) -> dict[str, Any]: 

997 """Serialize a criterion into a JSON-clean dict for the step payload.""" 

998 if isinstance(criterion, EqualsCriterion): 

999 return {"kind": "equals", "expected": criterion.expected} 

1000 return { 

1001 "kind": "within_tolerance", 

1002 "expected": criterion.expected, 

1003 "tolerance": criterion.tolerance, 

1004 }

1006 

1007def _criterion_matches(criterion: CheckCriterion, value: Any) -> bool: 

1008 """True iff `value` satisfies `criterion`. 

1009 

1010 `WithinToleranceCriterion` tolerates non-numeric values: a `TypeError` or 

1011 `ValueError` from `float(value)` is treated as a clean mismatch 

1012 rather than escaping. This is the right shape because a reading 

1013 that isn't numerically comparable IS a failed check, not a bug. 

1014 """ 

1015 if isinstance(criterion, EqualsCriterion): 

1016 return value == criterion.expected 

1017 try: 

1018 return abs(float(value) - criterion.expected) <= criterion.tolerance 

1019 except (TypeError, ValueError): 

1020 return False 

1021

1023def _mismatch_reason(criterion: CheckCriterion, value: Any) -> str: 

1024 """Operator-friendly explanation for a failed criterion.""" 

1025 if isinstance(criterion, EqualsCriterion): 

1026 return f"value {value!r} did not equal expected {criterion.expected!r}" 

1027 return f"value {value!r} not within {criterion.tolerance} of expected {criterion.expected}"

1030def _derive_abort_reason(failure: ConductorFailure) -> str: 

1031 """Build a Procedure-aggregate-compliant abort reason from a step failure. 

1032 

1033 Truncates to `REASON_MAX_LENGTH` so the AbortProcedure 

1034 handler does not reject the cleanup call. The format leads with 

1035 the step pointer (kind + index + target) so an operator scanning 

1036 the abort reason knows immediately which step in the conducted 

1037 sequence killed the Procedure. 

1038 """ 

1039 if failure.step_index is None: 1039 ↛ 1040line 1039 didn't jump to line 1040 because the condition on line 1039 was never true

1040 prefix = f"{failure.source_kind} {failure.target}" 

1041 else: 

1042 prefix = f"{failure.source_kind}[{failure.step_index}] {failure.target}" 

1043 reason = f"{prefix} failed: {failure.error_class}: {failure.message}" 

1044 return reason[:REASON_MAX_LENGTH]

1058 "quality_detail": reading.quality_detail, 

1059 "sampled_at": reading.sampled_at.isoformat(),
