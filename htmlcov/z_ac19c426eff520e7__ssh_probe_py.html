1"""Shared SSH transport for the two remote scan-ingest adapters. 

2 

3`SshDataExchangeScanReader` and `SshPosixChecksumComputer` both need the 

4same thing: run `cora.data._remote_scan_probe` on a host that holds bytes 

5CORA's own host cannot reach in time (see that module's docstring for the 

6measured reasoning), ship it a request over stdin, and read one JSON 

7verdict back over stdout. Splitting that mechanism across two copies is 

8how the two adapters would drift on the one property that actually 

9matters here -- how the untrusted locator reaches the far side -- so it 

10lives once, here, mirroring `_file_uri.py`'s reason for existing. 

11 

12## The locator is untrusted; this is the module's whole reason to exist 

13 

14`full_file_name` (the source of every locator this ever runs against) 

15comes from `2bmSP2:HDF1:FullFileName_RBV`, writable by anyone with 

16Channel Access. `run_probe` NEVER lets it reach a shell or an argv 

17element: the ssh argv is fixed at call time (host, a pinned interpreter 

18path, `-m`, the probe module name) and the request -- including the 

19locator -- travels as one JSON line over the child's stdin. `ssh 

20host cmd arg` would otherwise be re-parsed by the remote shell, turning a 

21crafted PV value into remote code execution on the detector host; stdin 

22is not re-parsed by anything. 

23 

24Two more guards run before any process is ever spawned, both refusing 

25rather than probing: 

26 

27- `_charset_ok`: the decoded path must be printable, control-character 

28 and NUL free. Cheap, and it means a malformed PV value never even 

29 reaches the network. 

30- `_prefix_allowed`: the raw (unresolved) path must start with one of the 

31 deployment's configured roots. This is NOT the authoritative 

32 confinement check -- it cannot be, since `..` and symlinks resolve on 

33 the REMOTE host's filesystem, which this process cannot see. The 

34 authoritative check is `resolve_confined_file_uri`, run inside 

35 `_remote_scan_probe.py` on the host that actually owns the path. This 

36 is only the early refusal that saves a network round trip on an 

37 obviously-wrong value. 

38 

39## Never raises 

40 

41Mirrors every port this feeds (`ScanReader.describe`, `ChecksumComputer.compute`): 

42a dead host, a timed-out probe, a malformed response, or a refused 

43locator all return a `{"kind": "ProbeError", ...}` dict, never an 

44exception. The two adapter classes translate that into the shape their 

45own port expects (`Unreadable` / `Unreachable`). 

46 

47Every `ProbeError` this module itself produces carries an `origin` (see 

48`cora.shared.probe_error`) saying whether the transport was touched. 

49Responses relayed from the remote process carry none, and correctly so: 

50they arrived over a transport that demonstrably works. 

51 

52## No `detail` this module writes can carry a path 

53 

54Callers log `detail` verbatim, and the trees these probes walk are 

55organized into directories named for people. So every `detail` 

56constructed here is built only from a fixed literal, a configured 

57value (the timeout), an exit code, or an exception TYPE name. Nothing 

58interpolates an exception message, the remote's stderr, or its stdout, 

59all three of which have carried a path at some point in this module's 

60history. Keep it that way: the property holds only because each site 

61holds it, and one `{exc}` puts it back. 

62 

63The property is about what THIS module writes. A `detail` relayed from 

64the remote process is that module's to guarantee, and it does so for 

65the `locate` op only; see `_remote_scan_probe`. 

66"""

87@dataclass(frozen=True) 

88class SshProbeConfig: 

89 """Deployment-declared transport parameters for one remote host. 

90 

91 `allowed_roots` are roots as valid ON `host`, never on CORA's own 

92 filesystem; see `Settings.scan_probe_allowed_roots`. 

93 

94 `max_walk_seconds` bounds a remote `checksum` op's digest walk (see 

95 `SshPosixChecksumComputer.compute`); it has no bearing on `describe` 

96 or `locate`. No default: the composition root always sources it from 

97 `Settings.posix_checksum_max_walk_seconds`, the same setting the 

98 local (non-SSH) `PosixChecksumAdapter` already uses, so a deployment 

99 with tens-of-gigabytes files raises one setting rather than two 

100 drifting copies of it. 

101 """

105 allowed_roots: tuple[str, ...]

111def raw_path_from_file_uri(uri: str) -> str | None: 

112 """Decode a `file://` URI's path with NO filesystem resolution. 

113 

114 Unlike `cora.data.adapters._file_uri.resolve_confined_file_uri`, this 

115 never calls `os.path.realpath`: that would resolve against THIS 

116 process's filesystem, which is the wrong host. Returns `None` for a 

117 non-`file` scheme or a non-local netloc, mirroring that module's own 

118 scheme rule. 

119 """ 

120 parsed = urlparse(uri) 

121 if parsed.scheme != "file" or parsed.netloc not in ("", "localhost"): 

122 return None 

123 raw_path = unquote(parsed.path) 

124 return raw_path or None

127def _charset_ok(path: str) -> bool: 

128 """Printable, control-character and NUL free.""" 

129 return path.isprintable() and "\x00" not in path 

130 

131 

132def _prefix_allowed(path: str, allowed_roots: tuple[str, ...]) -> bool: 

133 """Early, non-authoritative refusal; see the module docstring.""" 

134 return any(path == root or path.startswith(root.rstrip("/") + "/") for root in allowed_roots)

136 

137def _refuse(reason: str) -> dict[str, Any]: 

138 # NEVER embeds the locator: this detail string is what 

139 # `SshDataExchangeScanReader.describe` / `SshPosixChecksumComputer.compute` 

140 # log verbatim on refusal (`reason=` / `error_detail=`), and the 

141 # locator is the same personal-data value 

142 # `run.aggregates.run.capture_path` vaults rather than logs. 

143 # 

144 # `origin` separates "this ONE request was malformed" from "the hop 

145 # is down", which a sweeping caller must not conflate: the first 

146 # says skip this item, the second says stop trying. A refusal here 

147 # has not touched the transport at all, so it says nothing about 

148 # the next request. 

149 return { 

150 "kind": "ProbeError", 

151 "origin": PROBE_ERROR_ORIGIN_CLIENT, 

152 "detail": f"refused before probing: {reason}", 

153 } 

154 

155 

156def _transport_failure(detail: str) -> dict[str, Any]: 

157 """A failure of the hop itself, which the next request will hit too.""" 

158 return {"kind": "ProbeError", "origin": PROBE_ERROR_ORIGIN_TRANSPORT, "detail": detail}

161async def run_probe(request: dict[str, Any], *, config: SshProbeConfig) -> dict[str, Any]: 

162 """Validate, then run one request against `config.host`; never raises. 

163 

164 `request` must carry `locator_uri`; `allowed_roots` is filled in from 

165 `config` here (the caller never supplies it), so the SAME allowlist 

166 the client-side guard checked is the one the remote probe enforces. 

167 """ 

168 locator_uri = request.get("locator_uri") 

169 if not isinstance(locator_uri, str): 

170 return _refuse("no locator_uri in request") 

171 raw_path = raw_path_from_file_uri(locator_uri) 

172 if raw_path is None: 

173 return _refuse("not a recognizable file:// URI") 

174 if not _charset_ok(raw_path): 

175 return _refuse("path contains non-printable or control characters") 

176 if not _prefix_allowed(raw_path, config.allowed_roots): 

177 return _refuse("path is outside the configured allowed roots") 

178 

179 return await _invoke({**request, "allowed_roots": list(config.allowed_roots)}, config=config)

182async def run_locate_probe( 

183 *, 

184 root: str, 

185 months: tuple[str, ...], 

186 directory_suffix: str, 

187 filename: str, 

188 subdirectory: str | None, 

189 config: SshProbeConfig, 

190) -> dict[str, Any]: 

191 """Run one `locate` request against `config.host`; never raises. 

192 

193 The odd one out: `locate` carries no `locator_uri`, because its job 

194 is to find a path CORA cannot yet name, so `run_probe`'s 

195 locator-shaped guard does not apply and this validates the 

196 locate-shaped request instead. Both go through the same transport 

197 and both fill `allowed_roots` from `config` here rather than from 

198 the caller, so the allowlist the client checked is the one the 

199 remote enforces. 

200 

201 Every segment is checked against the same `is_safe_path_segment` 

202 rule the remote applies. Checking on both sides is deliberate 

203 duplication, not redundancy: the values come from PVs writable by 

204 anyone with Channel Access, and the two processes are separately 

205 reachable. The remote also caps how many months one request may 

206 scan; the client does not duplicate that bound, since it is a 

207 resource limit on the side that pays for it. 

208 """ 

209 if matched_storage_root(root, config.allowed_roots) is None: 

210 return _refuse("root is outside the configured allowed roots") 

211 if not months: 

212 return _refuse("no months to search") 

213 unsafe = [ 

214 value for value in (*months, directory_suffix, filename) if not is_safe_path_segment(value) 

215 ] 

216 if unsafe or (subdirectory is not None and not is_safe_path_segment(subdirectory)): 

217 return _refuse("request carries a value that is not one safe path segment") 

218 

219 payload: dict[str, Any] = { 

220 "op": "locate", 

221 "root": root, 

222 "months": list(months), 

223 "directory_suffix": directory_suffix, 

224 "filename": filename, 

225 "allowed_roots": list(config.allowed_roots), 

226 } 

227 if subdirectory is not None: 

228 payload["subdirectory"] = subdirectory 

229 return await _invoke(payload, config=config)

232async def _invoke(payload: dict[str, Any], *, config: SshProbeConfig) -> dict[str, Any]: 

233 """Transport only: ssh out, one JSON line in, one JSON line back. 

234 

235 Shared by both entry points so the timeout handling, the never-raise 

236 contract and the response parsing cannot drift apart between them. 

237 """ 

238 # `max(1, ...)`: OpenSSH reads `ConnectTimeout=0` as "no timeout 

239 # configured here, use the default" -- silently removing the bound 

240 # for a sub-1s config value instead of enforcing a very short one. 

241 # `--` before `config.host`: operator-configured, never 

242 # attacker-reachable, but a host string starting with `-` would 

243 # otherwise be parsed by `ssh` as an option rather than a hostname. 

244 argv = [ 

245 "ssh", 

246 "-o", 

247 "BatchMode=yes", 

248 "-o", 

249 f"ConnectTimeout={max(1, int(config.connect_timeout_seconds))}", 

250 "--", 

251 config.host, 

252 config.remote_python, 

253 "-m", 

254 _PROBE_MODULE, 

255 ] 

256 try: 

257 process = await asyncio.create_subprocess_exec( 

258 *argv, 

259 stdin=asyncio.subprocess.PIPE, 

260 stdout=asyncio.subprocess.PIPE, 

261 stderr=asyncio.subprocess.PIPE, 

262 ) 

263 except OSError as exc: 

264 return _transport_failure(f"could not launch ssh: {type(exc).__name__}") 

265 

266 try: 

267 stdout, stderr = await asyncio.wait_for( 

268 process.communicate(json.dumps(payload).encode("utf-8") + b"\n"), 

269 timeout=config.command_timeout_seconds, 

270 ) 

271 except TimeoutError: 

272 process.kill() 

273 with contextlib.suppress(ProcessLookupError): 

274 await process.wait() 

275 return _transport_failure(f"timed out after {config.command_timeout_seconds}s") 

276 

277 if process.returncode != 0: 

278 # The exit code, NOT the tail of the remote's stderr. That tail 

279 # is arbitrary text from a process walking a tree whose 

280 # directories are named for people, and this string is logged 

281 # verbatim by every caller. Carrying it would have been a path 

282 # in a log line reachable from any failing probe. 

283 # 

284 # Yes, this costs diagnosis: `Permission denied` and `Host key 

285 # verification failed` came through here. They are recoverable 

286 # by running the probe by hand, which an operator with access to 

287 # the host can do; a surname in an append-only log sink is not 

288 # recoverable by anyone. `255` is OpenSSH's own "the connection 

289 # or authentication failed" code and says which half to look at. 

290 _ = stderr 

291 return _transport_failure(f"ssh exited {process.returncode}") 

292 

293 # No origin on either of these. The hop carried the request and the 

294 # remote exited 0, so calling it a transport failure would be false, 

295 # and it is the one origin a sweeping caller stops on. Leaving it 

296 # unset falls to the fail-safe reading: this response is unusable, 

297 # the next one may be fine. 

298 try: 

299 parsed: Any = json.loads(stdout.decode("utf-8").splitlines()[0]) 

300 except (IndexError, UnicodeDecodeError, json.JSONDecodeError) as exc: 

301 # The exception TYPE, not its message. None of the three types 

302 # caught here renders the input it choked on, so this is 

303 # defense in depth rather than a fix for a live leak: it keeps 

304 # the rule uniform across every `detail` in the module, so a 

305 # reader does not have to re-derive per site which exceptions 

306 # happen to be safe to render. 

307 return { 

308 "kind": "ProbeError", 

309 "detail": f"unparseable probe response: {type(exc).__name__}", 

310 } 

311 if not isinstance(parsed, dict): 

312 return {"kind": "ProbeError", "detail": "probe response is not a JSON object"} 

313 return cast("dict[str, Any]", parsed)
