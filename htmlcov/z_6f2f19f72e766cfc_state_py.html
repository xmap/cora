1"""Plan aggregate state, value objects, status enum, and domain errors. 

2 

3`Plan` is the recipe ladder's binding layer (ISA-88 Master/Control 

4Recipe analog). A Plan binds a `Practice` (which itself adapts a 

5`Method` for a site) to a specific set of `Asset` instances at the 

6facility. Plan is what `Run` ultimately executes. 

7 

8Per the BC map's recipe ladder: Method (≈ General Recipe, equipment- 

9agnostic) → Practice (≈ Site Recipe, facility-localized) → Plan 

10(≈ Master/Control Recipe, equipment-bound) → Run (≈ batch execution). 

11 

12## Aggregate scope 

13 

14Plan state: 

15 - `id` + `name` 

16 - `practice_id: UUID` — the Practice this Plan binds (eventual- 

17 consistency ref; existence verified at handler-load time, not 

18 in the decider) 

19 - `asset_ids: frozenset[UUID]` — the Assets this Plan is bound 

20 to (multi-asset binding; gate-review Q3) 

21 - `status: PlanStatus` (Defined → Versioned → Deprecated FSM) 

22 - `version: str | None` — operator-supplied label of the most 

23 recent `version_plan` call (None until first version) 

24 

25Field addition follows the additive convention: the `version` 

26field landed when the first mutating event (`PlanVersioned`) 

27arrived, not speculatively. Same precedent as Method and Practice. 

28 

29Audit data captured at bind time (`method_id`, snapshots of the 

30Method's needed_family_ids and each bound Asset's families) 

31lives in the `PlanDefined` event payload only — NOT in state. 

32Slim Aggregate principle (gate-review Q4): state holds only what 

33future deciders need to validate invariants. version_plan and 

34deprecate_plan don't re-validate families, so the snapshots 

35stay payload-only. 

36 

37Additional facets defer to a later sub-phase if pilot demand emerges: 

38 - `wiring` (which Asset.ports are connected to what; depends on 

39 Asset.ports landing first, currently deferred) 

40 - calibrations 

41 - per-Plan parameter overrides 

42 

43## Cross-aggregate validation at bind time (gate-review Q5) 

44 

45The `define_plan` handler pre-loads Practice, Method (via 

46`practice.method_id`), and each bound Asset, then hands the loaded 

47entities to the pure decider as a `PlanBindingContext`. The decider 

48treats them as opaque domain data and validates: 

49 

50 - Practice not Deprecated → `PlanBoundPracticeDeprecatedError` 

51 - Method not Deprecated → `PlanBoundMethodDeprecatedError` 

52 - No bound Asset is Decommissioned → `PlanAssetDecommissionedError` 

53 - `union(asset.family_ids) ⊇ method.needed_family_ids` → 

54 `PlanFamiliesNotSatisfiedError` 

55 

56Handler-side load misses become `PracticeNotFoundError` / 

57`MethodNotFoundError` / `AssetNotFoundError` (defined on the 

58respective aggregates) before reaching the decider. The four 

59errors above are Plan-domain errors specific to "you tried to bind 

60to something whose state forbids binding"; they live in this 

61module. 

62 

63This is the first decider in the codebase that takes cross- 

64aggregate state as input. The pattern is documented in 

65CONTRIBUTING.md as the canonical approach for cross-validating 

66deciders. Second instance shipped in `start_run` with 

67`RunStartContext` of the same shape. 

68 

69## Status as enum-in-state, derived-from-event-type-in-evolver 

70 

71Same precedent as Method and Practice and Family. 

72The lifecycle mirrors theirs: Defined → Versioned → 

73Deprecated. Approval/governance is a separate concern handled by 

74the future Decision BC with `RecipeApproval` context (gate-review 

75Q2). 

76 

77## Tenth bounded-name VO + helper extraction 

78 

79`PlanName` is the **tenth** bounded-name VO. The Family gate-review 

80parked extraction at "first per-VO divergence OR ~10 instances". 

81We hit 10 with no divergence pressure, so the trim+length-check 

82helper got hoisted to `cora.shared.bounded_text.validate_bounded_text` 

83(see that module's docstring). PlanName uses the helper from day 

84one; the prior 9 VOs were refactored in the same hoist commit. 

85"""

348@dataclass(frozen=True) 

349class Plan: 

350 """Aggregate root: a Practice bound to specific Asset instances. 

351 

352 `practice_id` is the Practice this Plan binds (eventual- 

353 consistency ref). `asset_ids` is the set of Assets this Plan 

354 binds (multi-asset; at least one required, validated at decide 

355 time). `status` defaults to `Defined`. 

356 

357 `version` is the operator-supplied label of the most recent 

358 `version_plan` call (None until first version). State always 

359 holds the latest tag — past tags live in the event stream as 

360 `PlanVersioned` events. No `current_` prefix because state by 

361 definition holds current values (same convention as `status`, 

362 `name`). Free-text validated at API boundary + defensively in 

363 the decider; no VO. Default None keeps legacy PlanDefined- 

364 only streams folding cleanly (additive-state pattern). Mirrors 

365 Method/Practice/Family `version` semantics: preserved across 

366 deprecation as an audit signal of the last revision before 

367 deprecation. 

368 

369 `method_id` is the Method ultimately implemented by this Plan 

370 (originally captured in PlanDefined.method_id payload as audit- 

371 only data; promoted to state because the 

372 `update_plan_default_parameters` decider needs it to look up 

373 `Method.parameters_schema` for validation). Legacy PlanDefined 

374 streams fold cleanly: the evolver reads `method_id` from the 

375 payload field that was present from day one. Default-defaults to 

376 a sentinel via the constructor; in practice every well-formed 

377 stream sets it explicitly via PlanDefined. Mirrors the 

378 "state holds what future deciders need" precedent in the 

379 docstring above. 

380 

381 `default_parameters: dict[str, Any]` is the 

382 operator-set defaults for parameters that downstream Runs 

383 merge with their per-run overrides. Validated against 

384 the owning Method's `parameters_schema` at decide time 

385 (STRICT when Method declares no schema: non-empty defaults 

386 rejected; operators wanting "no parameters" Methods declare 

387 `parameters_schema={}` explicitly. Mirrors Asset.settings's 

388 "no Capabilities + non-empty settings → reject" anchor; see 

389 [[project_run_parameters_design]] §audit-correction). 

390 Defaults to empty dict for legacy Plans (additive-state pattern). 

391 The full dict is persisted; PATCH semantics handled by the slice 

392 via RFC 7396 `merge_patch`. Mirrors `Asset.settings` shape. 

393 

394 `wires: frozenset[Wire]` is the typed graph of port- 

395 to-port connections between bound Assets. Each `Wire` carries 

396 a 4-tuple identifying source/target ports across two Assets. 

397 Mutated via `add_plan_wire` / `remove_plan_wire` slices (mirrors 

398 Asset.ports's add/remove_asset_port pattern). Direction is enforced 

399 (source=OUTPUT, target=INPUT), `signal_type` must match exactly, 

400 fan-out allowed (one source port → many target ports), fan-in 

401 forbidden (one target port = at most one incoming Wire). See 

402 [[project_plan_wiring_design]] for the locked design memo. 

403 Defaults to empty frozenset for legacy Plans (additive-state 

404 pattern). 

405 

406 `content_hash: str | None` is the SHA-256 (64-char lowercase hex) 

407 of the canonical body bytes for this Plan revision's content 

408 subset (`name + method_id + practice_id + asset_ids + 

409 default_parameters + wires`), captured by the version_plan 

410 decider per the non-determinism principle and folded by the 

411 evolver from MethodVersioned PlanVersioned event payloads. None 

412 for legacy Plans that never reached Versioned status and for 

413 pre-rollout PlanVersioned events that landed before the 

414 content-hash field was added (additive-state pattern per 

415 [[project_content_addressed_identity_design]]). 

416 

417 PRESERVATION semantics across non-version transitions: 

418 - PlanDeprecated preserves content_hash (the hash represents 

419 the LAST ATTESTED revision and stays a valid equivalence 

420 anchor for the deprecated binding). 

421 - PlanDefaultParametersUpdated preserves content_hash (Bazel 

422 input/output split semantics: schema-side updates between 

423 Versioned events leave the hash pointing at the prior 

424 attested revision; the drift between current 

425 default_parameters and the hashed snapshot IS the intended 

426 signal that the Plan has uncommitted changes). 

427 - PlanWireAdded / PlanWireRemoved preserve content_hash (same 

428 Bazel input/output split rationale: wiring is a 

429 content-bearing field, so changes between Versioned events 

430 leave the hash dangling against the prior revision; operators 

431 re-version to anchor a new hash). 

432 """ 

433 

434 id: UUID 

435 name: PlanName 

436 practice_id: UUID 

437 asset_ids: frozenset[UUID] 

438 status: PlanStatus = PlanStatus.DEFINED 

439 version: str | None = None 

440 method_id: UUID | None = None 

441 default_parameters: dict[str, Any] = field(default_factory=dict[str, Any]) 

442 wires: frozenset["Wire"] = field(default_factory=frozenset["Wire"]) 

443 content_hash: str | None = None 

444 # role_bindings declares which Asset fills each of the bound 

445 # Method's required_roles (positional role-tagging; IEC 81346 

446 # Function aspect). Each `RoleBinding` is a (role_name, 

447 # asset_id) pair; uniqueness within the set is keyed on role_name 

448 # (enforced by the bind_plan_role decider, not the VO). The 

449 # role_name links to a `RoleRequirement` declared on the Plan's 

450 # Method (state.method_id). Empty by default; legacy PlanDefined- 

451 # only streams fold cleanly via the additive-state pattern. See 

452 # [[project-plan-role-bindings-design]] for the full design lock 

453 # and [[project-method-required-roles-design]] for the upstream 

454 # vocabulary. 

455 role_bindings: frozenset["RoleBinding"] = field(default_factory=frozenset["RoleBinding"]) 

456 

457 def content_subset(self) -> dict[str, object]: 

458 """Canonical content subset hashed into PlanVersioned.content_hash. 

459 

460 Pins identity per [[project_content_addressed_identity_design]]: 

461 `name + method_id + practice_id + asset_ids + default_parameters 

462 + wires`. Excluded: `id` (identity, not content); `status` and 

463 `version` (lifecycle, derived in evolver from event type and 

464 version_tag); `content_hash` itself (a Plan's content cannot 

465 contain its own hash). UUIDs render as strings (json-serializable), 

466 frozensets render as sorted lists (canonical_body_bytes would sort 

467 either way but explicit materialization keeps the subset readable 

468 as a spec). Wires render as sorted 4-tuples-of-strings to give 

469 determinism over the rendered tuple form (anti-hook #12). method_id 

470 is Optional in state (additive-state default for legacy Plans) but 

471 always concrete for any Plan that has reached Versioned status, 

472 because PlanDefined carries it; rendered as None when absent. 

473 Lives on the aggregate so any future field addition forces an 

474 explicit decision about whether it participates in content 

475 identity (anti-hook #10) at the same site as the field itself. 

476 """ 

477 return { 

478 "name": self.name.value, 

479 "method_id": str(self.method_id) if self.method_id is not None else None, 

480 "practice_id": str(self.practice_id), 

481 "asset_ids": sorted(str(a) for a in self.asset_ids), 

482 "default_parameters": self.default_parameters, 

483 "wires": sorted( 

484 ( 

485 str(w.source_asset_id), 

486 w.source_port_name, 

487 str(w.target_asset_id), 

488 w.target_port_name, 

489 ) 

490 for w in self.wires 

491 ), 

492 # role_bindings participates in content identity: 

493 # rendered as a sorted list of (role_name, asset_id) 

494 # tuples for byte-stable serialization (matches the wires 

495 # sort convention). 

496 "role_bindings": sorted( 

497 (b.role_name.value, str(b.asset_id)) for b in self.role_bindings 

498 ), 

499 }

521@dataclass(frozen=True) 

522class Wire: 

523 """A typed port-to-port connection between two bound Assets. 

524 

525 Tuple `(source_asset_id, source_port_name, target_asset_id, 

526 target_port_name)` describes one connection. The 4-tuple IS the 

527 identity; `frozenset[Wire]` deduplicates on the tuple. 

528 

529 `source` / `target` labels match OPC UA SourceNode/TargetNode 

530 + Argo Workflows dependency direction (clearer than `from`/`to`, 

531 avoids collision with `PortDirection.{INPUT, OUTPUT}` that the 

532 `out`/`in` labels would create). 

533 

534 Validation rules enforced at the decider level (NOT here): 

535 - source port must have `direction=OUTPUT` 

536 - target port must have `direction=INPUT` 

537 - `source_port.signal_type == target_port.signal_type` (exact match) 

538 - both endpoint asset_ids must be in the Plan's `asset_ids` set 

539 - both endpoint port_names must exist on their respective Asset.ports 

540 - target port can be the destination of at most one Wire (fan-in 

541 forbidden); fan-out (one source → many targets) is allowed 

542 - self-loops allowed iff `source_port_name != target_port_name` 

543 

544 `__post_init__` validates only structural shape (port-name lengths 

545 + canonicalization via trim); the cross-aggregate validations 

546 above need a `PlanWireContext` and live in the slice deciders. 

547 

548 See [[project_plan_wiring_design]] for the locked design memo. 

549 """ 

550 

551 source_asset_id: UUID 

552 source_port_name: str 

553 target_asset_id: UUID 

554 target_port_name: str 

555 

556 def __post_init__(self) -> None: 

557 trimmed_source = self.source_port_name.strip() 

558 if not trimmed_source or len(trimmed_source) > WIRE_PORT_NAME_MAX_LENGTH: 

559 raise InvalidWireError(self.source_port_name) 

560 trimmed_target = self.target_port_name.strip() 

561 if not trimmed_target or len(trimmed_target) > WIRE_PORT_NAME_MAX_LENGTH: 

562 raise InvalidWireError(self.target_port_name) 

563 # Frozen dataclasses block normal assignment in __post_init__; 

564 # use object.__setattr__ to install canonicalized names. 

565 object.__setattr__(self, "source_port_name", trimmed_source) 

566 object.__setattr__(self, "target_port_name", trimmed_target)
