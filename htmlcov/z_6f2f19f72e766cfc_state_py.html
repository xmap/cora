1"""Plan aggregate state, value objects, status enum, and domain errors. 

2 

3`Plan` is the recipe ladder's binding layer (ISA-88 Master/Control 

4Recipe analog). A Plan binds a `Practice` (which itself adapts a 

5`Method` for a site) to a specific set of `Asset` instances at the 

6facility. Plan is what `Run` ultimately executes. 

7 

8Per the BC map's recipe ladder: Method (≈ General Recipe, equipment- 

9agnostic) → Practice (≈ Site Recipe, facility-localized) → Plan 

10(≈ Master/Control Recipe, equipment-bound) → Run (≈ batch execution). 

11 

12## Aggregate scope 

13 

14Plan state: 

15 - `id` + `name` 

16 - `practice_id: UUID` — the Practice this Plan binds (eventual- 

17 consistency ref; existence verified at handler-load time, not 

18 in the decider) 

19 - `asset_ids: frozenset[UUID]` — the Assets this Plan is bound 

20 to (multi-asset binding; gate-review Q3) 

21 - `status: PlanStatus` (Defined → Versioned → Deprecated FSM) 

22 - `version: str | None` — operator-supplied label of the most 

23 recent `version_plan` call (None until first version) 

24 

25Field addition follows the additive convention: the `version` 

26field landed when the first mutating event (`PlanVersioned`) 

27arrived, not speculatively. Same precedent as Method and Practice. 

28 

29Audit data captured at bind time (`method_id`, snapshots of the 

30Method's needed_family_ids and each bound Asset's families) 

31lives in the `PlanDefined` event payload only — NOT in state. 

32Slim Aggregate principle (gate-review Q4): state holds only what 

33future deciders need to validate invariants. version_plan and 

34deprecate_plan don't re-validate families, so the snapshots 

35stay payload-only. 

36 

37Additional facets defer to a later sub-phase if pilot demand emerges: 

38 - `wiring` (which Asset.ports are connected to what; depends on 

39 Asset.ports landing first, currently deferred) 

40 - calibrations 

41 - per-Plan parameter overrides 

42 

43## Cross-aggregate validation at bind time (gate-review Q5) 

44 

45The `define_plan` handler pre-loads Practice, Method (via 

46`practice.method_id`), and each bound Asset, then hands the loaded 

47entities to the pure decider as a `PlanBindingContext`. The decider 

48treats them as opaque domain data and validates: 

49 

50 - Practice not Deprecated → `PlanBoundPracticeDeprecatedError` 

51 - Method not Deprecated → `PlanBoundMethodDeprecatedError` 

52 - No bound Asset is Decommissioned → `PlanAssetDecommissionedError` 

53 - `union(asset.family_ids) ⊇ method.needed_family_ids` → 

54 `PlanFamiliesNotSatisfiedError` 

55 

56Handler-side load misses become `PracticeNotFoundError` / 

57`MethodNotFoundError` / `AssetNotFoundError` (defined on the 

58respective aggregates) before reaching the decider. The four 

59errors above are Plan-domain errors specific to "you tried to bind 

60to something whose state forbids binding"; they live in this 

61module. 

62 

63This is the first decider in the codebase that takes cross- 

64aggregate state as input. The pattern is documented in 

65CONTRIBUTING.md as the canonical approach for cross-validating 

66deciders. Second instance shipped in `start_run` with 

67`RunStartContext` of the same shape. 

68 

69## Status as enum-in-state, derived-from-event-type-in-evolver 

70 

71Same precedent as Method and Practice and Family. 

72The lifecycle mirrors theirs: Defined → Versioned → 

73Deprecated. Approval/governance is a separate concern handled by 

74the future Decision BC with `RecipeApproval` context (gate-review 

75Q2). 

76 

77## Tenth bounded-name VO + helper extraction 

78 

79`PlanName` is the **tenth** bounded-name VO. The Family gate-review 

80parked extraction at "first per-VO divergence OR ~10 instances". 

81We hit 10 with no divergence pressure, so the trim+length-check 

82helper got hoisted to `cora.infrastructure.bounded_text.validate_bounded_text` 

83(see that module's docstring). PlanName uses the helper from day 

84one; the prior 9 VOs were refactored in the same hoist commit. 

85"""

356@dataclass(frozen=True) 

357class Plan: 

358 """Aggregate root: a Practice bound to specific Asset instances. 

359 

360 `practice_id` is the Practice this Plan binds (eventual- 

361 consistency ref). `asset_ids` is the set of Assets this Plan 

362 binds (multi-asset; at least one required, validated at decide 

363 time). `status` defaults to `Defined`. 

364 

365 `version` is the operator-supplied label of the most recent 

366 `version_plan` call (None until first version). State always 

367 holds the latest tag — past tags live in the event stream as 

368 `PlanVersioned` events. No `current_` prefix because state by 

369 definition holds current values (same convention as `status`, 

370 `name`). Free-text validated at API boundary + defensively in 

371 the decider; no VO. Default None keeps legacy PlanDefined- 

372 only streams folding cleanly (additive-state pattern). Mirrors 

373 Method/Practice/Family `version` semantics: preserved across 

374 deprecation as an audit signal of the last revision before 

375 deprecation. 

376 

377 `method_id` is the Method ultimately implemented by this Plan 

378 (originally captured in PlanDefined.method_id payload as audit- 

379 only data; promoted to state because the 

380 `update_plan_default_parameters` decider needs it to look up 

381 `Method.parameters_schema` for validation). Legacy PlanDefined 

382 streams fold cleanly: the evolver reads `method_id` from the 

383 payload field that was present from day one. Default-defaults to 

384 a sentinel via the constructor; in practice every well-formed 

385 stream sets it explicitly via PlanDefined. Mirrors the 

386 "state holds what future deciders need" precedent in the 

387 docstring above. 

388 

389 `default_parameters: dict[str, Any]` is the 

390 operator-set defaults for parameters that downstream Runs 

391 merge with their per-run overrides. Validated against 

392 the owning Method's `parameters_schema` at decide time 

393 (STRICT when Method declares no schema: non-empty defaults 

394 rejected; operators wanting "no parameters" Methods declare 

395 `parameters_schema={}` explicitly. Mirrors Asset.settings's 

396 "no Capabilities + non-empty settings → reject" anchor; see 

397 [[project_run_parameters_design]] §audit-correction). 

398 Defaults to empty dict for legacy Plans (additive-state pattern). 

399 The full dict is persisted; PATCH semantics handled by the slice 

400 via RFC 7396 `merge_patch`. Mirrors `Asset.settings` shape. 

401 

402 `wires: frozenset[Wire]` is the typed graph of port- 

403 to-port connections between bound Assets. Each `Wire` carries 

404 a 4-tuple identifying source/target ports across two Assets. 

405 Mutated via `add_plan_wire` / `remove_plan_wire` slices (mirrors 

406 Asset.ports's add/remove_asset_port pattern). Direction is enforced 

407 (source=OUTPUT, target=INPUT), `signal_type` must match exactly, 

408 fan-out allowed (one source port → many target ports), fan-in 

409 forbidden (one target port = at most one incoming Wire). See 

410 [[project_plan_wiring_design]] for the locked design memo. 

411 Defaults to empty frozenset for legacy Plans (additive-state 

412 pattern). 

413 

414 `content_hash: str | None` is the SHA-256 (64-char lowercase hex) 

415 of the canonical body bytes for this Plan revision's content 

416 subset (`name + method_id + practice_id + asset_ids + 

417 default_parameters + wires`), captured by the version_plan 

418 decider per the non-determinism principle and folded by the 

419 evolver from MethodVersioned PlanVersioned event payloads. None 

420 for legacy Plans that never reached Versioned status and for 

421 pre-rollout PlanVersioned events that landed before the 

422 content-hash field was added (additive-state pattern per 

423 [[project_content_addressed_identity_design]]). 

424 

425 PRESERVATION semantics across non-version transitions: 

426 - PlanDeprecated preserves content_hash (the hash represents 

427 the LAST ATTESTED revision and stays a valid equivalence 

428 anchor for the deprecated binding). 

429 - PlanDefaultParametersUpdated preserves content_hash (Bazel 

430 input/output split semantics: schema-side updates between 

431 Versioned events leave the hash pointing at the prior 

432 attested revision; the drift between current 

433 default_parameters and the hashed snapshot IS the intended 

434 signal that the Plan has uncommitted changes). 

435 - PlanWireAdded / PlanWireRemoved preserve content_hash (same 

436 Bazel input/output split rationale: wiring is a 

437 content-bearing field, so changes between Versioned events 

438 leave the hash dangling against the prior revision; operators 

439 re-version to anchor a new hash). 

440 """ 

441 

442 id: UUID 

443 name: PlanName 

444 practice_id: UUID 

445 asset_ids: frozenset[UUID] 

446 status: PlanStatus = PlanStatus.DEFINED 

447 version: str | None = None 

448 method_id: UUID | None = None 

449 default_parameters: dict[str, Any] = field(default_factory=dict[str, Any]) 

450 wires: frozenset["Wire"] = field(default_factory=frozenset["Wire"]) 

451 content_hash: str | None = None 

452 

453 def content_subset(self) -> dict[str, object]: 

454 """Canonical content subset hashed into PlanVersioned.content_hash. 

455 

456 Pins identity per [[project_content_addressed_identity_design]]: 

457 `name + method_id + practice_id + asset_ids + default_parameters 

458 + wires`. Excluded: `id` (identity, not content); `status` and 

459 `version` (lifecycle, derived in evolver from event type and 

460 version_tag); `content_hash` itself (a Plan's content cannot 

461 contain its own hash). UUIDs render as strings (json-serializable), 

462 frozensets render as sorted lists (canonical_body_bytes would sort 

463 either way but explicit materialization keeps the subset readable 

464 as a spec). Wires render as sorted 4-tuples-of-strings to give 

465 determinism over the rendered tuple form (anti-hook #12). method_id 

466 is Optional in state (additive-state default for legacy Plans) but 

467 always concrete for any Plan that has reached Versioned status, 

468 because PlanDefined carries it; rendered as None when absent. 

469 Lives on the aggregate so any future field addition forces an 

470 explicit decision about whether it participates in content 

471 identity (anti-hook #10) at the same site as the field itself. 

472 """ 

473 return { 

474 "name": self.name.value, 

475 "method_id": str(self.method_id) if self.method_id is not None else None, 

476 "practice_id": str(self.practice_id), 

477 "asset_ids": sorted(str(a) for a in self.asset_ids), 

478 "default_parameters": self.default_parameters, 

479 "wires": sorted( 

480 ( 

481 str(w.source_asset_id), 

482 w.source_port_name, 

483 str(w.target_asset_id), 

484 w.target_port_name, 

485 ) 

486 for w in self.wires 

487 ), 

488 }

510@dataclass(frozen=True) 

511class Wire: 

512 """A typed port-to-port connection between two bound Assets. 

513 

514 Tuple `(source_asset_id, source_port_name, target_asset_id, 

515 target_port_name)` describes one connection. The 4-tuple IS the 

516 identity; `frozenset[Wire]` deduplicates on the tuple. 

517 

518 `source` / `target` labels match OPC UA SourceNode/TargetNode 

519 + Argo Workflows dependency direction (clearer than `from`/`to`, 

520 avoids collision with `PortDirection.{INPUT, OUTPUT}` that the 

521 `out`/`in` labels would create). 

522 

523 Validation rules enforced at the decider level (NOT here): 

524 - source port must have `direction=OUTPUT` 

525 - target port must have `direction=INPUT` 

526 - `source_port.signal_type == target_port.signal_type` (exact match) 

527 - both endpoint asset_ids must be in the Plan's `asset_ids` set 

528 - both endpoint port_names must exist on their respective Asset.ports 

529 - target port can be the destination of at most one Wire (fan-in 

530 forbidden); fan-out (one source → many targets) is allowed 

531 - self-loops allowed iff `source_port_name != target_port_name` 

532 

533 `__post_init__` validates only structural shape (port-name lengths 

534 + canonicalization via trim); the cross-aggregate validations 

535 above need a `PlanWireContext` and live in the slice deciders. 

536 

537 See [[project_plan_wiring_design]] for the locked design memo. 

538 """ 

539 

540 source_asset_id: UUID 

541 source_port_name: str 

542 target_asset_id: UUID 

543 target_port_name: str 

544 

545 def __post_init__(self) -> None: 

546 trimmed_source = self.source_port_name.strip() 

547 if not trimmed_source or len(trimmed_source) > WIRE_PORT_NAME_MAX_LENGTH: 

548 raise InvalidWireError(self.source_port_name) 

549 trimmed_target = self.target_port_name.strip() 

550 if not trimmed_target or len(trimmed_target) > WIRE_PORT_NAME_MAX_LENGTH: 

551 raise InvalidWireError(self.target_port_name) 

552 # Frozen dataclasses block normal assignment in __post_init__; 

553 # use object.__setattr__ to install canonicalized names. 

554 object.__setattr__(self, "source_port_name", trimmed_source) 

555 object.__setattr__(self, "target_port_name", trimmed_target)
