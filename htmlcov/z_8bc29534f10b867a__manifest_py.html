1"""The export manifest: git commit, watermark, both profile hashes, and 

2the per-kind / per-event-type / per-run facts a reader needs before 

3trusting the bundle. 

4 

5Per `project_record_export_build_brief.md` step 4 and 

6`project_record_export_v3.md` F8. All THREE of F5's hashes are namable 

7here now: `record_hash` (H1, the whole unredacted bundle, step 3), 

8`redaction_profile_hash` (H2, every table that decides what a published 

9record discloses, widened to both tiers by step 7's security review), 

10and `published_record_hash` (H3, the redacted projection's own hash, 

11added with the bundle writer). H3 is optional because an unredacted 

12bundle genuinely has none; see the field's own docstring for why its 

13absence is a signal rather than a default. 

14 

15`build_manifest` is pure: every input it needs (`git_commit`; 

16`source_row_count_by_logbook_kind`, S2b's independent per-kind count; the 

17watermark comes off `record` itself) is captured by the caller first and 

18passed in, so the function itself does no I/O and is trivial to test 

19with synthetic `ExportedRecord`s. 

20"""

41"""Versions the registered logbook-kind SET a manifest was built 

42against: literally "which universe of kinds the claim was made 

43against", `project_record_completeness_design.md`'s "Two authorities, 

44two times" in its own words. Bump this, together with 

45`registered_kinds_hash` and the pin in 

46`tests/architecture/test_manifest_registered_kinds_pin.py`, only when 

47that SET changes (a tenth `EntriesTableSpec`, or one retired). 

48 

49Bumped 1 -> 2 for the `supply_probe` kind (the BLEPS supply observer's 

50probe trail), the tenth `EntriesTableSpec` this docstring names as the 

51trigger case by number. 

52 

53Adding an unrelated field to `Manifest` itself does not need a bump, 

54and neither does a kind's status moving between `included` / `excluded` 

55/ `untraversed`: `extent_by_logbook_kind` already carries that fact 

56per-export, in band, for every kind the set pin below enumerates, so a 

57reader comparing two bundles sees the difference directly and needs no 

58second version axis to notice it. (A prior draft of this docstring 

59named status graduation as a second bump trigger; S5a, S5b and S5c each 

60moved a kind's status without bumping, correctly under this reading, 

61so that draft was naming the wrong trigger, not describing a missed 

62bump.) The set pin also freezes each kind's CURRENT status, so a status 

63change still cannot land silently -- it fails that test and forces a 

64deliberate look here -- it just does not by itself force a version 

65bump. 

66 

67S2b (`project_record_completeness_design.md`) removed the top-level 

68`row_count_by_logbook_kind` map and folded it into 

69`extent_by_logbook_kind[kind].exported_row_count`, alongside the new 

70`source_row_count`: a real change to the manifest's JSON shape, not an 

71addition, and this constant did not bump for it. Consistent with the 

72"kind SET only" reading above: no kind's set membership or status moved, 

73and the fact `row_count_by_logbook_kind` carried is still present, in a 

74new location, so a reader who could compute one map can compute the 

75other. A future removal that actually drops information a reader could 

76not otherwise recover would be a different case this docstring does not 

77yet cover; decide it when it happens rather than by extrapolation now."""

80class LogbookKindExtentStatus(StrEnum): 

81 """Whether the exporter can account for one registered logbook kind. 

82 

83 `INCLUDED` means the exporter's traversal reads that kind's rows, 

84 regardless of how many it finds this export: an envelope-driven 

85 kind is reached by the full, unbounded stream walk whether or not 

86 any instance of its envelope occurred in this particular database, 

87 so zero rows is a genuine zero, not a coverage gap. `EXCLUDED` is a 

88 still-open, registry-level policy decision (see 

89 `project_record_completeness_design.md`'s S4); nothing in the 

90 registry sets it today, so no kind currently resolves to it. 

91 `UNTRAVERSED` means no code path reads that kind's table at all yet. 

92 """ 

93 

94 INCLUDED = "included" 

95 EXCLUDED = "excluded" 

96 UNTRAVERSED = "untraversed"

99class LogbookKindRowCountMismatchError(RuntimeError): 

100 """An `included` kind's two independent row counts disagree, or its 

101 `source_row_count` was never captured. 

102 

103 `source_row_count` (an unscoped `count(*)` against the kind's table, 

104 sharing no predicate with any reader) and `exported_row_count` 

105 (`len(record.logbooks[kind])`, the render-stage tally) must agree for 

106 any kind whose extent status is `included`. Disagreement usually means 

107 the exporter's traversal omitted rows the database actually holds, or 

108 its render step lost or duplicated rows it did read -- the omission- 

109 at-origin scenario `project_record_completeness_design.md` exists to 

110 catch. A missing `source_row_count` (the kind absent from the caller's 

111 `source_row_count_by_logbook_kind` mapping) is treated the same way, 

112 never as "skip the check": see 

113 `project_independent_check_principle.md`'s closing anti-hook against a 

114 coverage field silently switched off by writing `null`. 

115 

116 One benign cause worth knowing before treating every occurrence as a 

117 code defect: for an envelope-scoped kind, ordinary concurrency 

118 elsewhere in the database can pin the stream walk's xmin watermark 

119 below this transaction's own snapshot cutoff (see 

120 `capture_source_row_count_by_logbook_kind`'s docstring), excluding an 

121 envelope the snapshot itself would otherwise show. A fresh export 

122 retry captures a fresh watermark and will not reproduce that specific 

123 cause; a divergence that reproduces across a retry is the real signal 

124 to investigate as an actual omission. This error does not distinguish 

125 the two causes -- it cannot, from inside one export -- so retrying 

126 once before escalating is a reasonable first response, not "ignoring" 

127 the finding. 

128 """

142@dataclass(frozen=True, slots=True) 

143class LogbookKindExtent: 

144 """One `extent_by_logbook_kind` slot. 

145 

146 `source_row_count` is an unscoped `count(*)` against the kind's table 

147 (`_export.py`'s `capture_source_row_count_by_logbook_kind`), sharing no predicate with 

148 any reader. `exported_row_count` is `len(record.logbooks[kind])`, the 

149 render-stage tally of what this export actually carries. For an 

150 `included` kind the two must agree -- `_extent_by_logbook_kind` raises 

151 `LogbookKindRowCountMismatchError` before they can land here disagreeing. 

152 For `excluded` / `untraversed` both are populated and reported but never 

153 compared. `source_row_count` is `None` only when the kind is absent from 

154 the caller's mapping; per the design memo's own wording that is 

155 permitted only for `untraversed` (a kind with no reader at all has 

156 nothing forcing its table to be counted either). `excluded` is a 

157 registry-level policy status nothing sets today, so this is unexercised 

158 in production; a future `excluded` spec should still get a real, 

159 non-`None` `source_row_count`, since `capture_source_row_count_by_logbook_kind` 

160 counts every registered spec's table unconditionally. 

161 """ 

162 

163 status: LogbookKindExtentStatus 

164 source_row_count: int | None 

165 exported_row_count: int

168@dataclass(frozen=True, slots=True) 

169class Manifest: 

170 """One export's provenance and shape, independent of its bytes on disk. 

171 

172 `max_schema_version_by_event_type` is a reader-facing sanity check: a 

173 reader can recompute it from the bundle itself and compare, catching 

174 truncation or a stale generator without needing to trust this manifest 

175 blindly. The equivalent per-kind row-count check lives inside 

176 `extent_by_logbook_kind` now (`exported_row_count`, cross-checked 

177 against `source_row_count` at build time) rather than as its own 

178 top-level field; see that field's docstring for why the two were never 

179 allowed to coexist as separate coverage maps. 

180 """ 

181 

182 git_commit: str 

183 watermark: int 

184 record_hash: str 

185 redaction_profile_hash: str 

186 max_schema_version_by_event_type: dict[str, int] 

187 is_simulated: bool 

188 expansion_digest_presence_by_run: dict[str, bool] 

189 extent_by_logbook_kind: dict[str, LogbookKindExtent] 

190 """One mandatory slot per kind registered in `_registry.all_specs()`, 

191 present even at zero rows. Iterated from the registry at build time, 

192 NEVER from `record.logbooks` alone: an earlier version of this field 

193 carried only a `row_count_by_logbook_kind` map that WAS computed from 

194 `record.logbooks`, agreed-by-construction with the traversal it was 

195 meant to check, and missed 53,499 rows across two kinds while 

196 reporting `{}`. That field is gone; `exported_row_count` here is its 

197 replacement, cross-checked at build time against the independent 

198 `source_row_count` (S2b, `project_record_completeness_design.md`'s 

199 "The independent count"). See 

200 `project_independent_check_principle.md`.""" 

201 registered_kinds_hash: str 

202 """`hash_registered_kinds` over the sorted kind set this export's 

203 checkout has registered, so a reader can tell whether their own 

204 checkout's registry has since grown a kind this bundle's manifest 

205 never had a slot for.""" 

206 manifest_schema_version: int 

207 published_record_hash: str | None = None 

208 """H3, present only on a manifest built alongside a redacted record. 

209 

210 `None` means "this manifest describes an unredacted bundle", NOT 

211 "redaction produced nothing". A reader seeing `None` beside a bundle 

212 someone called published should treat the bundle as unverified: the 

213 absence is the signal. 

214 

215 Safe to carry inside the bundle despite H3 covering that bundle, 

216 because H3 hashes the two tiers only. The manifest is not in its own 

217 hashed body, so there is no circularity to resolve. 

218 """ 

219 unfired_tier2_clearances: tuple[str, ...] | None = None 

220 """Declared tier-2 jsonb clearances (`"kind/column/pointer"`) that 

221 never matched a row in a kind this export carried. `None` means "no 

222 redaction happened", the same absence-is-the-signal convention as 

223 `published_record_hash`; an empty tuple means redaction happened and 

224 every clearance fired. 

225 

226 This is a COMPLETENESS fact, not a safety finding. Tier 2's 

227 dispositions are an allowlist, so an unfired clearance means a field 

228 was published less often than the profile permits, never more -- 

229 see `unfired_clearances`'s own docstring for the full argument and 

230 the denylist-shaped mistake this field replaces (an earlier version 

231 aborted the export instead of reporting this). A reviewer reading a 

232 non-empty list here learns "this export was too narrow to exercise 

233 every rule the profile declares", which is a caveat about coverage, 

234 not a leak. 

235 """ 

236 unfired_tier1_fields: tuple[str, ...] | None = None 

237 """The same completeness fact as `unfired_tier2_clearances`, one tier 

238 up: `"event_type/field"` pairs declared in the generated disposition 

239 table for an event type this export carried, whose field never 

240 appeared on any row of that type. Same `None`/empty-tuple convention. 

241 

242 Almost always empty in practice: tier 1's table is exhaustively 

243 generated, and a declared field is normally present (even as `null`) 

244 on every row of an event type the current dataclass produces. A 

245 field appearing here means EVERY row of that event type in this 

246 export predates the `schema_version` that added the field -- one 

247 surviving row with the key present would have marked it fired -- a 

248 narrowness caveat about THIS export, not a leak; see 

249 `RedactionResult.unfired_tier1_fields`'s docstring for why a 

250 build-time guard cannot see this and a per-export field can. 

251 """

254def capture_git_commit(*, cwd: Path | str | None = None) -> str: 

255 """The exporting checkout's HEAD commit SHA. 

256 

257 No caching, no fallback: a failure here (detached submodule, no 

258 `.git`, corrupt repo) should stop the export rather than write a 

259 manifest that lies about provenance.

267 )

282def _extent_by_logbook_kind( 

283 record: ExportedRecord, source_row_count_by_logbook_kind: dict[str, int] 

284) -> dict[str, LogbookKindExtent]: 

285 """Every registered kind, status derived from the registry alone, both 

286 row counts cross-checked for every `included` kind. 

287 

288 Status: the predicate is "does ANY reader reach this kind": either 

289 `spec.envelope_class is not None` (the six envelope-driven kinds) or 

290 `spec.unscoped_reader is not None` (`heartbeat` S5a, `capture_probe` 

291 S5b, `permit_probe` S5c). Both are structural, registry-level facts 

292 about whether the exporter's traversal CAN reach that kind's table 

293 at all; neither says anything about what THIS export happened to 

294 find, which is the whole point (see 

295 `Manifest.extent_by_logbook_kind`'s docstring). Every registered 

296 kind now sets one or the other, so no kind resolves `untraversed` in 

297 production today; the status stays in the enum as the exporter-level 

298 coverage gap it exists to catch, exercised deliberately rather than 

299 incidentally (see `test_manifest.py`'s own construction of the case). 

300 

301 Counts: `exported_row_count` is `len(record.logbooks[kind])`, measured 

302 here at the RENDER stage rather than at fetch time inside `_export.py`'s 

303 read loop, so a row `render_row` drops or duplicates after the fetch 

304 still shows up as a divergence. `source_row_count` comes from the 

305 caller's `source_row_count_by_logbook_kind` (`_export.py`'s 

306 `capture_source_row_count_by_logbook_kind`, an unscoped `count(*)` 

307 sharing no predicate with any reader), keyed by `spec.kind`; a kind 

308 absent from that mapping reads as `None`. For an 

309 `included` kind the two must agree -- `None` counts as disagreement, 

310 since a coverage field silently switched off by omission is exactly the 

311 failure this check exists to prevent (`project_independent_check_principle.md`). 

312 `excluded` and `untraversed` kinds get both counts populated and 

313 reported, never compared: see `project_record_completeness_design.md`'s 

314 "The independent count". 

315 """ 

316 extents: dict[str, LogbookKindExtent] = {} 

317 for spec in all_specs(): 

318 status = ( 

319 LogbookKindExtentStatus.INCLUDED 

320 if spec.envelope_class is not None or spec.unscoped_reader is not None 

321 else LogbookKindExtentStatus.UNTRAVERSED 

322 ) 

323 source_row_count = source_row_count_by_logbook_kind.get(spec.kind) 

324 exported_row_count = len(record.logbooks.get(spec.kind, ())) 

325 if status == LogbookKindExtentStatus.INCLUDED and source_row_count != exported_row_count: 

326 raise LogbookKindRowCountMismatchError( 

327 kind=spec.kind, 

328 source_row_count=source_row_count, 

329 exported_row_count=exported_row_count, 

330 ) 

331 extents[spec.kind] = LogbookKindExtent( 

332 status=status, 

333 source_row_count=source_row_count, 

334 exported_row_count=exported_row_count, 

335 ) 

336 return extents

339def _max_schema_version_by_event_type(record: ExportedRecord) -> dict[str, int]: 

340 versions: dict[str, int] = {} 

341 for row in record.streams: 

342 event_type = row["event_type"] 

343 schema_version = row["schema_version"] 

344 assert isinstance(event_type, str) 

345 assert isinstance(schema_version, int) 

346 if schema_version > versions.get(event_type, 0): 

347 versions[event_type] = schema_version 

348 return versions

351def _is_simulated(record: ExportedRecord) -> bool: 

352 """False unless an observation row explicitly says otherwise. 

353 

354 Matches the Run BC's own fold of this exact column 

355 (`postgres_run_channel_lookup.py`'s `coalesce(bool_or(is_simulated), false)`): 

356 an observation asserts simulated by being present and True, so the 

357 identity element for "no observations at all" is False, the same as 

358 `bool_or` over an empty set. The manifest previously used `all(...)`, 

359 whose empty-set identity is True, so a record with zero observation 

360 rows -- including the pilot's first genuine beamline-attached export, 

361 which had none -- was reported as simulated. A published record 

362 cannot carry that flag by an accident of aggregation identity. 

363 

364 A mixed result (some True, some False) reports as True: ANY row 

365 asserting simulated is enough to call the whole export simulated, 

366 mirroring `bool_or`'s semantics exactly rather than requiring 

367 unanimity in either direction. 

368 """ 

369 observations = record.logbooks.get("observation", ()) 

370 return any(row["is_simulated"] is True for row in observations)

373def _expansion_digest_presence_by_run( 

374 record: ExportedRecord, *, token_map: TokenMap | None = None 

375) -> dict[str, bool]: 

376 """Per F8: a run has a pinned expansion digest iff at least one of its 

377 child Procedures was registered via `register_procedure_from_recipe` 

378 (carries a `RecipeExpansionRecorded` on its own stream). A Procedure 

379 registered directly, or a run recorded by observing an external 

380 scan, has no digest to compare against; that is correct, not a gap. 

381 

382 Without `token_map`, this dict is keyed by the RAW `stream_id` values 

383 pulled straight from the unredacted `record` -- harmless on a full 

384 bundle, but on a published one it would republish in plaintext 

385 exactly the Run identifiers tier-1 redaction already replaced with 

386 per-export surrogates in the streams body. Pass the SAME 

387 `RedactionResult.token_map` tier-1 redaction used (via `token_uuid`, 

388 memoized by source) so a run's key here always equals the surrogate 

389 a reader finds on that run's rows. 

390 """ 

391 run_ids = { 

392 _require_str(row["stream_id"]) for row in record.streams if row["stream_type"] == "Run" 

393 } 

394 

395 parent_run_by_procedure: dict[str, str | None] = {} 

396 expanded_procedures: set[str] = set() 

397 for row in record.streams: 

398 if row["event_type"] == "ProcedureRegistered": 

399 payload = _payload(row) 

400 parent_run_id = payload["parent_run_id"] 

401 parent_run_by_procedure[_require_str(payload["procedure_id"])] = ( 

402 None if parent_run_id is None else _require_str(parent_run_id) 

403 ) 

404 elif row["event_type"] == "RecipeExpansionRecorded": 

405 expanded_procedures.add(_require_str(_payload(row)["procedure_id"])) 

406 by_raw_run_id = { 

407 run_id: any( 

408 parent_run_id == run_id and procedure_id in expanded_procedures 

409 for procedure_id, parent_run_id in parent_run_by_procedure.items() 

410 ) 

411 for run_id in run_ids 

412 } 

413 if token_map is None: 

414 return by_raw_run_id 

415 return { 

416 _require_str(token_map.token_uuid(run_id)): value for run_id, value in by_raw_run_id.items() 

417 }

428def build_manifest( 

429 record: ExportedRecord, 

430 *, 

431 git_commit: str, 

432 source_row_count_by_logbook_kind: dict[str, int], 

433 redaction: RedactionResult | None = None, 

434) -> Manifest: 

435 """Assemble the manifest for one already-exported, already-rendered record. 

436 

437 `watermark` is read from `record.watermark`, the value `export_record` 

438 itself captured and bounded its query by, rather than taken as a 

439 separate parameter: no caller could otherwise produce "the SAME value 

440 the query used" without calling `capture_watermark` a second time, 

441 which returns a different snapshot. 

442 

443 `source_row_count_by_logbook_kind` is required, deliberately with no default: it is 

444 `_export.py`'s `capture_source_row_count_by_logbook_kind`, called by the shell inside 

445 the SAME transaction as `export_record` so both describe one snapshot. 

446 There is no bypass here -- a caller cannot omit this and get a manifest 

447 that silently skips the independent check; see 

448 `LogbookKindRowCountMismatchError` and `_extent_by_logbook_kind`. Raises 

449 that error before returning if any `included` kind's two counts 

450 disagree, which means it also raises before either `write_bundle` call 

451 a caller might make next. 

452 

453 Pass `redaction` (the `RedactionResult` `redact_record` returned) when 

454 the bundle being written is the published projection, so the manifest 

455 carries H3 and its per-run map is keyed by the same surrogates tier-1 

456 redaction already put on the streams body. The shape counts 

457 (`extent_by_logbook_kind`, including S2b's two row counts) stay derived 

458 from the UNREDACTED `record` regardless: `redact_record` maps each 

459 kind's rows 1:1 (`tuple(redact_tier2_row(...) for row in rows)`), 

460 never adding or removing one, so the counts describe both bundles 

461 today. That is a property of `redact_record`'s current implementation, 

462 not something checked here: if a future redaction pass ever starts 

463 suppressing whole rows, the PUBLISHED manifest built by this branch 

464 would keep reporting the unredacted counts, over-claiming what its own 

465 `published/` bundle actually contains, and nothing in this function 

466 would notice. Closing that gap belongs with whatever change first 

467 makes redaction row-dropping possible, not guarded against 

468 speculatively here. 

469 

470 `redaction` carries `redacted_record`, `token_map`, 

471 `unfired_tier2_clearances` and `unfired_tier1_fields` together as one 

472 object, deliberately, not as four independently-omittable parameters: 

473 a caller could otherwise supply a `token_map` from an unrelated 

474 redaction (or none at all) alongside a genuinely redacted record, 

475 producing a manifest whose per-run keys disagree with the surrogates 

476 actually on the streams body; or supply `redacted` while omitting one 

477 of the completeness fields, silently reporting a false "everything 

478 fired" instead of the true count. All become structurally impossible 

479 once every one of them comes from the one `RedactionResult` a real 

480 redaction pass produced. 

481 """ 

482 if redaction is None: 

483 redacted: TwoTierRecord | None = None 

484 token_map: TokenMap | None = None 

485 unfired_tier2: frozenset[tuple[str, str, str]] = frozenset() 

486 unfired_tier1: frozenset[tuple[str, str]] = frozenset() 

487 else: 

488 redacted = redaction.redacted_record 

489 token_map = redaction.token_map 

490 unfired_tier2 = redaction.unfired_tier2_clearances 

491 unfired_tier1 = redaction.unfired_tier1_fields 

492 return Manifest( 

493 git_commit=git_commit, 

494 watermark=record.watermark, 

495 record_hash=hash_record(record), 

496 redaction_profile_hash=hash_redaction_profile(), 

497 max_schema_version_by_event_type=_max_schema_version_by_event_type(record), 

498 is_simulated=_is_simulated(record), 

499 expansion_digest_presence_by_run=_expansion_digest_presence_by_run( 

500 record, token_map=token_map
