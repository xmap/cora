1"""Process-wide dependency kernel. 

2 

3`Kernel` carries the cross-BC primitives (settings, clock, 

4id_generator, authorize, event_store, idempotency_store) plus the 

5asyncpg `pool` (None for `app_env=test`). It's the "Shared Kernel" 

6in the DDD sense: a deliberately-shared set of dependencies every 

7bounded context's `wire_<bc>(deps)` function pulls from. 

8 

9## Why this lives in its own module 

10 

11This module has **zero BC imports**. That's the point: every BC's 

12wire / handler / route imports `Kernel` from here without 

13transitively pulling in any other BC. Phase-8d hardening: the 

14prior `Kernel` (then `SharedDeps`) lived alongside the production- 

15construction logic that lazy-imported `cora.trust` for the 

16authorize factory. That lazy import was tagged `deprecated = true` 

17in tach.toml because tach couldn't tell that the import was 

18control-flow-guarded. Splitting the data class out of the 

19construction module breaks the cycle at the namespace level: 

20`cora.infrastructure.kernel` knows about ports, not adapters, with two 

21deliberate carve-outs: the `canonicalization_registry` and 

22`signing_registry` fields are concrete version-dispatch containers 

23(`CanonicalizationRegistry` / `SigningRegistry`) because version 

24selection needs the registry container, not a single port instance. 

25 

26## BC-specific stores stay BC-internal 

27 

28`Kernel` carries cross-BC primitives only. BC-specific entry 

29stores (Trust BC's `VerdictStore`, Decision BC's `InferenceStore`, 

30etc.) are constructed inside each BC's own `wire_<bc>(deps)` from 

31`deps.pool` and live BC-internal. This keeps the kernel clean as 

32more BCs adopt the logbook-and-entries pattern. 

33"""

93@dataclass(frozen=True) 

94class Kernel: 

95 """Process-wide dependencies. Immutable after construction. 

96 

97 `pool` is the asyncpg connection pool (None when 

98 `app_env=test`). BCs that need additional Postgres-backed 

99 adapters (entry stores, projections, etc.) construct them in 

100 their own `wire_<bc>(deps)` from this pool, keeping BC-specific 

101 stores out of the kernel. 

102 

103 `clearance_lookup`: cross-BC port consumed by 

104 Run BC's `start_run` handler to gate Run.start on the presence 

105 of an Active Safety Clearance covering the Run's scope. Safety 

106 BC ships `PostgresClearanceLookup` as the production adapter 

107 (reads `proj_safety_clearance_summary`). Test environments 

108 default to `AlwaysCoveredClearanceLookup` (synthetic Active 

109 clearance bypass) so existing Run tests don't have to seed 

110 real clearances; gate-specific tests override with the real 

111 adapter explicitly. Mirrors the `Authorize` / `AllowAllAuthorize` 

112 test-default pattern. 

113 

114 `clearance_template_lookup`: cross-aggregate port consumed by 

115 Safety BC's own `version_clearance_template` handler to validate 

116 the supersedes_template_id parent chain stays within one 

117 facility (per the cross-facility identity lock). 9E extends the 

118 consumer set with `register_clearance` / `amend_clearance`. 

119 Safety BC ships `PostgresClearanceTemplateLookup` as the 

120 production adapter (reads `proj_safety_clearance_template_summary`). 

121 Test environments default to `InMemoryClearanceTemplateLookup`; 

122 chain-validation tests seed parent templates via the adapter's 

123 `register(...)` helper. 

124 

125 `caution_lookup`: cross-BC port consumed by Run 

126 BC's `start_run` handler to snapshot operator-authored cautions 

127 onto the `RunStarted` event payload. Caution BC ships 

128 `PostgresCautionLookup` as the production adapter (reads 

129 `proj_caution_summary`). Test environments default to 

130 `AlwaysQuietCautionLookup` (returns `[]`) so existing Run tests 

131 don't have to seed cautions; snapshot-specific tests override 

132 with the real adapter explicitly. NON-BLOCKING by construction 

133 (see `cora.infrastructure.ports.caution_lookup` module 

134 docstring): the snapshot informs the payload but the decider 

135 never gates on it. 

136 

137 `capability_lookup`: cross-BC port consumed by Equipment BC's 

138 `get_asset_integration_view` handler to fetch the set of 

139 Recipe Capabilities whose `required_affordances` are covered 

140 by an Asset's combined Family affordances. Recipe BC ships 

141 `PostgresCapabilityLookup` as the production adapter (reads 

142 `proj_recipe_capability_summary`). Test environments default 

143 to `AlwaysEmptyCapabilityLookup` (returns `[]`) so existing 

144 Equipment tests do not have to seed Capability projection 

145 rows; surface-specific tests override with a fake that returns 

146 seeded references or with the real adapter explicitly. The 

147 port preserves Family's vocabulary discipline ("Capability" 

148 stays a Recipe word) by isolating the Recipe reference type 

149 behind a Protocol the handler maps onto the local 

150 `CapabilityView` response shape. 

151 

152 `supply_lookup`: cross-BC port consumed by Run BC's `start_run` 

153 handler and Operation BC's `start_procedure` handler to gate 

154 start on Method.needed_supplies satisfaction (at least one 

155 AVAILABLE Supply per required kind). Supply BC ships 

156 `PostgresSupplyLookup` as the production adapter (reads 

157 `proj_supply_summary`, excludes Decommissioned rows per the 

158 partial UNIQUE INDEX semantics in 

159 [[project_deregister_supply_design]]). Test environments default 

160 to `AllSatisfiedSupplyLookup` (synthetic Available per kind) so 

161 existing Run / Procedure tests don't have to seed real Supplies; 

162 gate-specific tests override with the real adapter or with 

163 `NoSuppliesRegisteredLookup` for the missing-kind path. Mirrors 

164 the `ClearanceLookup` / `CautionLookup` test-default pattern. 

165 See [[project_supply_preflight_gate_design]]. 

166 

167 `spend_guard`: the pre-call half of budget enforcement, consulted by 

168 the steering brain before each LLM call; see the field docstring. 

169 

170 `spend_lookup`: cross-BC port consumed by the budget gate at the 

171 LLM subscribers' seams (RunDebriefer / CautionDrafter) to sum an 

172 agent's recorded spend in a cap window before permitting the next 

173 call. Planned consumers, not wired today: the regenerate slice and 

174 the Operation BC steering brain at the per-call pre-estimate tier. 

175 Decision BC ships `PostgresSpendLookup` as the production adapter 

176 (sums `entries_decision_inferences`). Test environments default 

177 to `AlwaysZeroSpendLookup` (nothing spent) so a declared cap 

178 never blocks tests that don't exercise budget gating. 

179 

180 `language_model_lookup`: cross-cutting port consumed by Agent BC's 

181 `define_agent` handler to gate agent registration on the target 

182 model identity holding an Approved catalog entry (the shipped 

183 fleet's defaults are pinned against the seeds by a unit 

184 consistency test, not by any startup check). Agent BC ships 

185 `PostgresLanguageModelLookup` as the production adapter (reads 

186 `proj_agent_language_model_summary`). 

187 Defaults to `AlwaysApprovedLanguageModelLookup` (every identity 

188 Approved) so tests and catalog-less deployments keep the 

189 pre-catalog behavior; standing up a real catalog is what arms the 

190 gate. Mirrors the `spend_lookup` opt-in posture. 

191 

192 `model_usage_lookup`: cross-BC port consumed by Agent BC's 

193 `list_at_risk_results` read slice to enumerate the Decisions whose 

194 recorded LLM calls touched a catalog entry's model identity (the 

195 at-risk-results surface a vendor retirement announcement lights 

196 up). Decision BC ships `PostgresModelUsageLookup` as the production 

197 adapter (reads `entries_decision_inferences`, the same durable fact 

198 `spend_lookup` sums). Test environments default to 

199 `AlwaysEmptyModelUsageLookup` (no recorded call touched any model) so 

200 tests that don't exercise the at-risk surface stay inert; 

201 slice-specific tests inject a fake returning seeded rows or the 

202 real adapter. 

203 

204 `run_actor_involvement_lookup`: cross-BC port consumed by the 

205 authority-revocation holder subscriber (K3) to resolve the 

206 in-flight Runs a revoked principal drives and hold each. Run BC 

207 ships `PostgresRunActorInvolvementLookup` as the production adapter 

208 (reads `proj_run_actor_involvement`). Test environments default to 

209 `NoInvolvementLookup` (returns `[]`) so existing tests don't have 

210 to seed runs; kill-switch tests override with the real adapter. 

211 Mirrors the `ClearanceLookup` / `CautionLookup` test-default pattern. 

212 

213 `consequence_lookup`: cross-BC port consumed by Run BC's `stop_run` 

214 handler for the consequence gate (Gate IV): is this action covered 

215 by a GRANTED Ratification (a second, independent principal's 

216 co-signature)? Trust BC ships `PostgresConsequenceLookup` as the 

217 production adapter (reads `proj_trust_ratification_coverage`). Test 

218 environments default to `AlwaysRatifiedConsequenceLookup` (coverage 

219 always present) so existing stop_run tests stay green with stop_run 

220 in the ratification allowlist; consequence-gate tests override with 

221 `NeverRatifiedConsequenceLookup` (refuse-and-hold path) or the real 

222 adapter (end-to-end). 

223 

224 `dataset_distribution_lookup`: cross-BC port consumed by Run BC's 

225 `start_run` handler to gate a reconstruction Run on each declared 

226 input Dataset (`StartRun.input_dataset_ids`) having a Verified 

227 Distribution (genesis-only). Data BC ships 

228 `PostgresDatasetDistributionLookup` as the production adapter (reads 

229 `proj_data_distribution_summary`, excludes Discarded rows). Test 

230 environments default to `NoDatasetDistributionsLookup` (every Dataset 

231 has no Distribution), the conservative default: a Run that declares an 

232 input but seeds nothing fails the gate. Gate-specific tests override 

233 with `SeededDatasetDistributionLookup`. Ordinary acquisition Runs 

234 declare no inputs, so the handler skips the lookup and the gate is 

235 dormant. See [[project_run_input_dependency_design]]. 

236 

237 `compute_reachability_lookup`: cross-BC-style port consumed by Run BC's 

238 `start_run` handler to resolve `StartRun.compute_resource_code` to the 

239 set of Storage Supply ids the named compute resource can read, so the 

240 decider can require each declared input's Verified Distribution to sit on 

241 a reachable tier. The production adapter (a deployment-config map resolved 

242 by Supply name) is deferred; test environments default to 

243 `NoComputeReachabilityLookup` (every code unknown), the conservative 

244 default: a Run naming a compute resource fails with 

245 `RunComputeResourceUnknownError` unless the test seeds a mapping with 

246 `SeededComputeReachabilityLookup`. A Run naming no compute resource never 

247 calls the lookup, so the reachability arm stays dormant. 

248 

249 `credential_lookup`: cross-BC port consumed by Federation BC's 

250 seal handlers (`initialize_seal`, `rotate_seal_online_key`) to 

251 validate cross-aggregate purpose binding (the referenced 

252 Credential's purpose must match the seal slot: 

253 `SealOnlineSigning` for `online_credential_id`, `SealOfflineRoot` for 

254 `offline_credential_id`) and the status-Active invariant (Rotating or 

255 Revoked secrets cannot back a Seal). Federation BC ships 

256 `PostgresCredentialLookup` as the production adapter (reads 

257 `proj_federation_credential_summary` keyed by `credential_id`). 

258 Test environments default to `InMemoryCredentialLookup`; seal 

259 handler / decider tests seed credentials explicitly via the 

260 adapter's `register(...)` helper. The handler does the async 

261 lookup and threads the result through to the decider as part of 

262 the slice's context dataclass, keeping the decider pure (mirrors 

263 the start_run -> ClearanceLookup pattern). 

264 

265 `facility_lookup`: cross-aggregate port consumed by Federation BC's 

266 `register_facility` handler to validate parent.kind=Site at 

267 cross-stream boundary (per [[project-slice6-design]] L2; closes the 

268 Slice 5 deferral). Future Slice 6 Sub-Slice B consumers 

269 (`add_facility_trust_anchor_credential` decider) will also consume 

270 this port. Federation BC ships `PostgresFacilityLookup` as the 

271 production adapter (reads `proj_federation_facility_summary` shipped 

272 Slice 5 Sub-Slice B, keyed by `facility_id`). Test environments 

273 default to `InMemoryFacilityLookup`; register_facility handler / 

274 decider tests seed facilities explicitly via the adapter's 

275 `register(...)` helper. Mirrors the credential_lookup pattern: the 

276 handler does the async lookup and threads the result through to the 

277 decider as the slice's parent-lookup parameter, keeping the decider 

278 pure. 

279 

280 `asset_lookup`: cross-aggregate port consumed by cross-BC 

281 consumers that hold an `AssetId` from the wire and need to 

282 validate the Asset exists before committing a command. First 

283 consumer is Supply BC's `register_supply` handler (Session 5 

284 Slice 7B): it resolves `command.containing_asset_id` to an 

285 `AssetLookupResult` and threads the result into the decider. 

286 Future Slice 8 (Asset.facility_id back-binding) and potential 

287 Safety / Caution BC consumers will also consume this port. 

288 Equipment BC ships `PostgresAssetLookup` as the production 

289 adapter (reads `proj_equipment_asset_summary` shipped Phase 

290 8e-3a). Test environments default to `InMemoryAssetLookup`; 

291 cross-BC binding tests seed assets via the adapter's 

292 `register(...)` helper. 

293 

294 `family_lookup`: cross-aggregate port consumed by Layer-3 sub-slice 

295 3D's `bind_plan_role` handler (per 

296 [[project-role-aggregate-design]] Lock 17). Walks 

297 Asset.family_ids -> FamilyLookup.lookup -> presents_as ∩ 

298 affordance-superset using the ANY-single-family disjunction 

299 semantic. Equipment BC ships `PostgresFamilyLookup` as the 

300 production adapter (reads `proj_equipment_family_summary` with 

301 the Layer-3 sub-slice 3B presents_as + affordances columns). 

302 Test environments default to `InMemoryFamilyLookup`; 3D consumer 

303 tests seed Families via the adapter's `register(...)` helper. 

304 

305 `assembly_lookup`: cross-aggregate port consumed by 3D's 

306 `bind_plan_role` handler for the Assembly satisfaction branch. 

307 When the candidate Asset carries `fixture_id`, the handler 

308 loads the Fixture, then `AssemblyLookup.lookup(fixture.assembly_id)`, 

309 and the decider ORs-in `role_kind in assembly.presents_as` on 

310 top of the Family disjunction (closes the Microscope-Assembly 

311 worked example from the design memo). Equipment BC ships 

312 `PostgresAssemblyLookup` as the production adapter (reads 

313 `proj_equipment_assembly_summary` with the 3C presents_as 

314 column). Test environments default to `InMemoryAssemblyLookup`. 

315 

316 `role_lookup`: cross-aggregate port consumed by Layer-3 sub-slices 

317 of [[project-role-aggregate-design]]. 3B `add_family_presents_as` 

318 decider validates role_id resolves AND that the Family's 

319 Affordances superset Role.required_affordances. 3C 

320 `add_assembly_presents_as` decider validates role_id resolves 

321 (affordance-superset deferred to register_fixture layer). 3D 

322 `bind_plan_role` handler walks Asset.family_ids -> 

323 a gather of FamilyLookup.lookup (one per family) -> RoleLookup.lookup 

324 for the role_kind satisfaction path (Lock 17 ANY-single-family 

325 disjunction). 3E 

326 `update_capability_suggested_roles` handler validates every 

327 proposed RoleId resolves (Lock 10 documentation-only event). 

328 Equipment BC ships `PostgresRoleLookup` as the production adapter 

329 (reads `proj_equipment_role_summary` shipped Layer-3 sub-slice 

330 3A). Test environments default to `InMemoryRoleLookup`; consumer 

331 tests seed Roles via the adapter's `register(...)` helper or 

332 leave the registry empty for the missing-role path. 

333 

334 `llm`: optional LLM-chat port consumed by Agent BC subscribers 

335 (RunDebriefer, CautionDrafter). Production wires 

336 `AnthropicLLM` when both `Settings.llm_enabled` and 

337 `Settings.anthropic_api_key` are set; otherwise this is `None` 

338 and the subscribers that depend on it skip registration with a 

339 warning. Tests use 

340 `FakeLLM` (zero network) when an LLM is needed and leave 

341 this `None` otherwise. 

342 

343 `logbook_mirror`: optional mirror to operator-facing logbook 

344 systems (Olog / SciLog / SciCat). No production implementor 

345 yet; the field exists to reserve the wiring slot and let the 

346 RunDebriefer subscriber short-circuit cleanly on `is None`. An 

347 adapter lands when a pilot facility's logbook is wired. 

348 

349 `token_verifier`: process-singleton 

350 `TokenVerifier` (concretely `IdentityProviderRegistry`) built 

351 from `Settings.identity_providers`. `None` when no IdPs are 

352 configured (today's default): the legacy 

353 `X-Principal-Id`-with-`SYSTEM`-fallback path stays in effect. 

354 Non-`None` is the production-edge-auth posture: middleware 

355 extracts `Authorization: Bearer <token>`, verifies via this 

356 port, stores the resulting `VerifiedPrincipal` on the request 

357 state. Typed as the port (not the registry adapter) so the 

358 kernel-construction primitives can stay in 

359 `cora.infrastructure.deps` without `cora.infrastructure.kernel` 

360 importing `cora.infrastructure.auth` (kernel boundary: ports 

361 only, no adapters). 

362 

363 `profile_store`: process-singleton `ProfileStore` for the 

364 `actor_profile` PII vault. Required (not optional) because 

365 BOTH Access BC (`register_actor`) AND Agent BC (`define_agent`) 

366 upsert through it on the genesis path — a missing 

367 profile_store breaks the cross-BC atomic write. Constructed in 

368 `make_*_kernel` as `PostgresProfileStore(pool)` (production) 

369 or `InMemoryProfileStore()` (tests / `app_env=test`). The 

370 Protocol lives in `cora.infrastructure.ports.profile_store`; 

371 adapters in `cora.access.aggregates.actor.profile`. Sibling- 

372 BC instances all read this one field so the in-memory dict is 

373 shared across slices, mirroring how `EventStore` and 

374 `IdempotencyStore` are shared.

411 beam_availability_lookup: BeamAvailabilityLookup = field(default_factory=AllBeamOpenLookup) 

412 """Cross-BC port consumed by Run BC's `start_run` and Operation 

413 BC's `start_procedure` to read live beam-availability state (the 

414 front-end + station `BeamBlockingM` shutters and the ACIS FES-permit 

415 composite) at the start instant and gate the start (BEAM-1). 

416 

417 UNIQUE among the cross-BC lookups in carrying a default: every other 

418 lookup reads a projection and is built at Kernel-construction time, 

419 but the production beam adapter (`ControlPortBeamAvailabilityLookup`) 

420 reads LIVE through the Operation BC's `ControlPort`, which is not on 

421 the Kernel and is only materialised during wiring. So the Kernel 

422 defaults to the always-open `AllBeamOpenLookup` stub (preserving the 

423 pre-BEAM-1 no-gate behavior + the test default) and the composition 

424 root overrides it post-construction via `dataclasses.replace` with a 

425 `ControlPortBeamAvailabilityLookup` over the shared ControlPort when 

426 `BEAM_AVAILABILITY_PVS` is configured. Gate-specific tests likewise 

427 `replace` it with a stub returning the reading under test."""

430 per-call pre-estimate enforcement tier). Defaults to the always-pass 

431 stub so tests and non-steering deployments are unaffected; the 

432 composition root binds the Agent BC's `BudgetSpendGuard` in 

433 production, which reads the caller's declared caps and the recorded 

434 spend the `spend_lookup` sums."""

445 `NullInferenceRecorder` so unwired kernels and unit tests stay inert; the
