1"""Reconstruct a steered loop's observation history from the recorded outcomes. 

2 

3The crux of RESUME: rebuild the `tuple[SteeringObservation, ...]` the brain saw 

4across the already-closed passes of an interrupted steered conduct, from the 

5recorded `Outcome` rows alone, so a resumed loop re-conditions the brain from 

6the record instead of re-measuring hardware (strategy A per the resume-semantics 

7research: recorded results are replayed, side effects are not re-run). 

8 

9## Self-describing rows: no join, no off-by-one 

10 

11Each `Outcome` row carries BOTH the coordinate it measured at (`point`, the x) 

12and the measured values there (`measurements`, the y). So reconstruction is a 

13plain sort-by-`iteration_index` then map: row -> observation. There is no join 

14to `ProcedureIterationEnded.advised_next_point` and no pass-k-to-pass-(k-1) 

15pairing, which removes the off-by-one and, critically, survives an abandoned 

16pass: a mid-crash pass leaves an index gap (no outcome row was written for it, 

17or a stale one under a now-unused index), and a sort tolerates gaps where a 

18positional pairing could not. 

19 

20The brain does not depend on the index being dense: every shipped decider reads 

21its cursor from `len(evidence.observations)` (the count of prior measurements), 

22not from any iteration number, so a gapped `iteration_index` never mis-cues the 

23brain. The index is retained only as the stable sort key + an audit 

24cross-reference to the FSM iteration that produced the row. 

25"""

43def reconstruct_observations( 

44 outcomes: Sequence[RecordedOutcome], 

45) -> tuple[SteeringObservation, ...]: 

46 """Rebuild the observation history the brain saw, from recorded outcomes. 

47 

48 `outcomes` are the recorded `RecordedOutcome` rows for the procedure, in any 

49 order; this sorts them ascending by `iteration_index` (the recorded pass 

50 order) and maps each self-describing row to a `SteeringObservation`. Index 

51 gaps (from an abandoned mid-crash pass) are tolerated: the sort preserves 

52 pass order regardless, and the brain reads its cursor from the observation 

53 count, not the index. Returns observations in pass order, ready to seed a 

54 resumed loop's evidence and to re-condition the brain at the frontier. 

55 """ 

56 ordered = sorted(outcomes, key=lambda row: row.iteration_index) 

57 return tuple( 

58 SteeringObservation( 

59 point=SteeringPoint(coordinates=dict(row.point)), 

60 measurements=tuple(_measurement_from_dict(m) for m in row.measurements), 

61 artifact_ref=None, 

62 actuation_kind=( 

63 ActuationKind(row.actuation_kind) if row.actuation_kind is not None else None 

64 ), 

65 succeeded=row.succeeded, 

66 ) 

67 for row in ordered 

68 )

71def _measurement_from_dict(raw: dict[str, Any]) -> Measurement: 

72 """Rebuild a `Measurement` from an Outcome row's recorded measurement dict. 

73 

74 Symmetric with `conductor._outcome_measurement_to_dict`: reads back name, 

75 value, kind, quality, quality_detail, units, and the ISO-8601 produced_at. 

76 Defensive on the optional fields so a leaner recorded shape still rebuilds. 

77 """ 

78 produced_at_raw = raw.get("produced_at") 

79 produced_at = ( 

80 datetime.fromisoformat(produced_at_raw) if isinstance(produced_at_raw, str) else _EPOCH 

81 ) 

82 kind: MeasurementKind = raw.get("kind", "Scalar") 

83 quality: Quality = raw.get("quality", "Good") 

84 return Measurement( 

85 value=raw.get("value"), 

86 kind=kind, 

87 quality=quality, 

88 produced_at=produced_at, 

89 quality_detail=raw.get("quality_detail", ""), 

90 name=raw.get("name", ""), 

91 units=raw.get("units"), 

92 )
