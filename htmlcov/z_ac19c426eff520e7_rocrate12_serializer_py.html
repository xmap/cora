1"""`RoCrate12Adapter`: first `EditionSerializer` implementation. 

2 

3Produces RO-Crate-flavored JSON-LD, modeled on the RO-Crate 1.2 + 

4Workflow Run Crate profiles (per the Edition design memo L10). It is 

5not yet a conformant RO-Crate; see "Known gaps blocking first 

6publication" below. The serializer is deterministic: 

7given the same logical inputs, the output bytes (and therefore the 

8sha256 `content_hash`) are byte-identical. All set-semantic fields 

9sort their entries on the wire; ordered fields (`creators`) preserve 

10input order; numeric keys serialize as canonical JSON via 

11`cora.shared.canonical_json`. 

12 

13The resulting bytes are returned via a `data:` URL inline today; a 

14production deployment that writes to object storage swaps the adapter 

15or extends this one with an upload step. 

16 

17## Publish-once discipline 

18 

19This artifact gets registered under a DOI once sealed, and a DOI-bearing 

20document is unretractable. Every field it carries must therefore be a 

21HISTORICAL STATEMENT ("this was so when published"), never a LIVE 

22PROMISE ("follow this and it will work"). A live promise rots the 

23moment the world moves, and CORA has no mechanism to revise bytes that 

24already carry a checksum a third party may have copied. Fields that 

25would only ever be a live promise (a fetch location, an access 

26procedure, an internal identifier the outside world cannot resolve) 

27are omitted outright rather than published in a form that will go 

28stale. 

29 

30## What ships 

31 

32 - Top-level JSON-LD with `@context` = the RO-Crate 1.2 context (the 

33 released Recommendation, not the superseded 1.2-DRAFT constant 

34 this adapter shipped with before RO-Crate 1.2 was finalized) plus 

35 the Workflow Run Crate profile. 

36 - Root `Dataset` entity for the Edition itself (`@id="./"`) with: 

37 - `name`: the Edition title 

38 - `datePublished`: the publication year (ISO 8601 reduced 

39 precision, year only; RFC 3339 has no year-only production) 

40 - `license`: the SPDX identifier when present 

41 - `publisher`: a reference to the Organization entity below 

42 - `creator`: list of `Person` entities (one per Creator, in 

43 input order in the JSON array; RO-Crate does not treat this 

44 as semantically ordered and may render the entries content- 

45 free, see "Known gaps" below) 

46 - `hasPart`: opaque list of `@id` references, one per DatasetRef 

47 - `identifier`: the `external_pid` value when published, absent 

48 entirely otherwise (no pre-DOI fallback value is emitted) 

49 - `conformsTo`: list of profile URIs 

50 - One `Organization` entity for the publisher, carrying: 

51 - `@id`: a document-local blank node 

52 - `identifier`: the Facility code, an internal code under no 

53 registered scheme (same class of gap as the creator id; ROR 

54 is the eventual fix, not built here) 

55 - One `Dataset` entry per `DatasetRef`, carrying: 

56 - `@id`: `urn:uuid:<dataset_id>` (stable; cross-system safe) 

57 - `sha256`: from the Distribution checksum (algorithm pinned to 

58 sha256 in the Dataset BC today) 

59 - `contentSize`: byte size as integer 

60 - `encodingFormat`: media type 

61 - `conformsTo`: encoding's `conforms_to` profile URIs (sorted) 

62 

63 `contentUrl` is deliberately NOT emitted. The Distribution URI is 

64 either an internal `cora-capture-path://` locator that resolves 

65 for nobody outside CORA, or a real filesystem path that embeds 

66 operator-identifying detail (a lead scientist's surname has shown 

67 up in these paths). No value this field could hold is safe to 

68 publish permanently, and omitting it only for some rows would be 

69 worse than omitting it always: a reader could not tell "restricted" 

70 from "forgotten". The `@id` (`urn:uuid`) plus `sha256` already let 

71 anyone who obtains a candidate file prove it is this dataset; that 

72 is the stronger of the two links anyway; a path only says where to 

73 look and proves nothing about what you find. Do not add 

74 `conditionsOfAccess` or any other field describing how to obtain 

75 the bytes: an access mechanism is exactly the same live-promise 

76 shape and rots the same way (this project has already watched one 

77 storage tier carry three different names in a few months). 

78 

79Creators are published without an `identifier`. `Creator.actor_id` 

80(see `cora.data.aggregates.edition.state.Creator`) is CORA's internal- 

81opaque Actor id, useless for external attribution since no outside 

82reader can resolve it, and dangerous to publish anyway: it is a stable 

83pseudonymous person-identifier that would let anyone correlate every 

84Edition credited to the same individual forever without ever learning 

85who that is. Pseudonymous is not anonymous, and nobody consented to 

86that linkage. Keeping it out is still correct; that harm outweighs the 

87one below, and no Edition has ever been published. 

88 

89But the honest accounting stops there, and BLOCKS the first real 

90publication. The pinned RO-Crate 1.2 context declares no `@container` 

91for `creator`, so it maps to plain `schema:creator`: the JSON array is 

92an unordered RDF `@set`, not an ordered `@list`. Order is not carried. 

93The Person entity's `@id` is a document-scoped blank node 

94(`_:creator-0`), which is not an identifier a consumer may rely on for 

95anything, including position. And `affiliation` is optional on 

96`Creator`, so a Person with none serializes to exactly `{"@id": 

97"_:creator-0", "@type": "Person"}`: a content-free node indistinguishable 

98from any other creator with no affiliation. Four co-authors at one 

99institution are four identical, unordered, contentless nodes. The 

100artifact cannot credit anyone. The intended resolution is to resolve 

101`actor_id` to a name / ORCID via an `ActorLookup` port before 

102serializing (`Creator`'s own docstring already says so); that port has 

103not been built, and building it is a separate slice with its own 

104design. Until it ships, this adapter has no attribution to offer, and 

105that is a publication blocker, not a nicety. 

106 

107External-pid awareness: when `external_pid is None` the artifact omits 

108`identifier` entirely (pre-DOI bytes). When `external_pid` is 

109supplied, the root entity gains `identifier` carrying the 

110scheme-prefixed value (e.g. `doi:10.5281/zenodo.1234567`). The sha256 

111of the two byte streams differs by design (this is the two-content-hash 

112model). The root `identifier` no longer falls back to `edition:<uuid>` 

113when no DOI is present: that value was an internal id under an 

114unregistered scheme, unresolvable outside CORA, the exact shape this 

115module's rule at the top says to omit rather than publish. 

116 

117## Known gaps blocking first publication 

118 

119Two things must ship before this adapter's output should back a real 

120DOI: 

121 

122 1. Attribution (above): no name/ORCID resolution exists yet, so 

123 `creator` carries no information a reader can use. 

124 2. Validity: this module emits an RO-Crate `@graph` with a root 

125 `Dataset`, a publisher `Organization`, per-creator `Person` 

126 entities, and per-part `Dataset` entities, but RO-Crate requires 

127 a self-describing metadata descriptor entity (`@id` = 

128 `ro-crate-metadata.json`) carrying an `about` reference to the 

129 root entity, and it is the ROOT ENTITY's `conformsTo` (not 

130 `@context`) that a consumer reads to learn which profile version 

131 applies. Neither exists here. The output is RO-Crate-flavored 

132 JSON-LD, not a conformant RO-Crate. Adding the descriptor is its 

133 own slice; this module docstring recorded the gap, not a fix. 

134"""

136import base64 

137import hashlib 

138from uuid import UUID

140from cora.data.aggregates.edition.state import ( 

141 Creator, 

142 EditionKind, 

143 SpdxIdentifier, 

144) 

145from cora.data.ports.edition_serializer import ( 

146 DatasetRef, 

147 SerializedEdition, 

148) 

149from cora.shared.canonical_json import canonical_json_bytes 

150from cora.shared.facility_code import FacilityCode 

151from cora.shared.identifier import PersistentIdentifier

153_ROCRATE_12_CONTEXT = "https://w3id.org/ro/crate/1.2/context" 

154_WORKFLOW_RUN_CRATE_PROFILE = "https://w3id.org/ro/wfrun/workflow/0.5" 

155_PROCESS_RUN_CRATE_PROFILE = "https://w3id.org/ro/wfrun/process/0.5" 

156_CONTENT_TYPE = "application/ld+json" 

157 

158 

159def _dataset_id_uri(dataset_id: UUID) -> str: 

160 return f"urn:uuid:{dataset_id}" 

161 

162 

163def _external_pid_uri(external_pid: PersistentIdentifier) -> str: 

164 return f"{external_pid.scheme.value}:{external_pid.value}" 

165 

166 

167def _dataset_part(ref: DatasetRef) -> dict[str, object]: 

168 return { 

169 "@id": _dataset_id_uri(ref.dataset_id), 

170 "@type": "Dataset", 

171 "sha256": ref.checksum.value, 

172 "contentSize": ref.byte_size, 

173 "encodingFormat": ref.encoding.media_type, 

174 "conformsTo": sorted(ref.encoding.conforms_to), 

175 } 

176 

177 

178def _creator_entity(creator: Creator, index: int) -> dict[str, object]: 

179 person_id = f"_:creator-{index}" 

180 entity: dict[str, object] = { 

181 "@id": person_id, 

182 "@type": "Person", 

183 } 

184 if creator.affiliation is not None: 

185 entity["affiliation"] = creator.affiliation 

186 return entity 

187 

188 

189def _publisher_entity(publisher_facility_code: FacilityCode) -> dict[str, object]: 

190 return { 

191 "@id": f"_:facility-{publisher_facility_code.value}", 

192 "@type": "Organization", 

193 "identifier": publisher_facility_code.value, 

194 }

197class RoCrate12Adapter: 

198 """`EditionSerializer` implementation for `EditionKind.ROCRATE`. 

199 

200 Pure in-process serializer; no IO. `serialize` returns a 

201 `SerializedEdition` carrying the sha256 hash + an inline 

202 `data:application/ld+json;base64,...` URI + the IANA content type. 

203 """ 

204 

205 async def serialize( 

206 self, 

207 *, 

208 edition_id: UUID, 

209 kind: EditionKind, 

210 title: str, 

211 dataset_refs: tuple[DatasetRef, ...], 

212 publisher_facility_code: FacilityCode, 

213 creators: tuple[Creator, ...], 

214 publication_year: int, 

215 license: SpdxIdentifier | None, 

216 external_pid: PersistentIdentifier | None, 

217 ) -> SerializedEdition: 

218 _ = kind # routed by caller; verified by precondition 

219 _ = edition_id # no internal-id fallback published; see module docstring 

220 sorted_dataset_refs = sorted(dataset_refs, key=lambda r: r.dataset_id) 

221 

222 creator_entities = [ 

223 _creator_entity(creator, index) for index, creator in enumerate(creators) 

224 ] 

225 publisher_entity = _publisher_entity(publisher_facility_code) 

226 

227 root_entity: dict[str, object] = { 

228 "@id": "./", 

229 "@type": "Dataset", 

230 "name": title, 

231 "datePublished": str(publication_year), 

232 "publisher": {"@id": publisher_entity["@id"]}, 

233 "creator": [{"@id": entity["@id"]} for entity in creator_entities], 

234 "hasPart": [{"@id": _dataset_id_uri(ref.dataset_id)} for ref in sorted_dataset_refs], 

235 "conformsTo": [ 

236 {"@id": _PROCESS_RUN_CRATE_PROFILE}, 

237 {"@id": _WORKFLOW_RUN_CRATE_PROFILE}, 

238 ], 

239 } 

240 if license is not None: 

241 root_entity["license"] = license.value 

242 if external_pid is not None: 

243 root_entity["identifier"] = _external_pid_uri(external_pid) 

244 

245 graph: list[dict[str, object]] = [root_entity] 

246 graph.append(publisher_entity) 

247 graph.extend(creator_entities) 

248 graph.extend(_dataset_part(ref) for ref in sorted_dataset_refs) 

249 

250 document: dict[str, object] = { 

251 "@context": _ROCRATE_12_CONTEXT, 

252 "@graph": graph, 

253 } 

254 

255 canonical_bytes = canonical_json_bytes(document) 

256 content_hash = hashlib.sha256(canonical_bytes).hexdigest() 

257 bytes_uri = f"data:{_CONTENT_TYPE};base64," + base64.b64encode(canonical_bytes).decode( 

258 "ascii" 

259 ) 

260 return SerializedEdition( 

261 content_hash=content_hash, 

262 bytes_uri=bytes_uri, 

263 content_type=_CONTENT_TYPE, 

264 ) 

265 

266 

267__all__ = ["RoCrate12Adapter"]
