1"""Recipe bounded context. 

2 

3Owns the recipe-and-procedure concerns of CORA. Five aggregates per 

4[[project-recipe-aggregate-design]] (SHIPPED on main 2026-06-03 via 

5PR #24); the ladder mirrors ISA-88's Recipe type hierarchy (General -> Site -> 

6Master -> Control) with Capability as the operations-layer contract 

7that Methods and Recipes bind to: 

8 

9 - `Capability` -- operations-layer contract. Declares 

10 `executor_shapes`, `parameters_schema`, and 

11 `required_affordances`. Templates that Methods and Recipes refer 

12 to by `capability_id` for the lifetime of the dependent. 

13 - `Method` ~= ISA-88 General Recipe -- the technique class, vendor 

14 / scientific-community level. Equipment-agnostic (refers to 

15 `Family` ids). `Method.parameters_schema` is a STRICT subset of 

16 the bound Capability's schema. 

17 - `Practice` ~= ISA-88 Site Recipe -- a facility's adapted version 

18 of a Method (institutional constraints, default parameter 

19 envelopes, safety overlay), still abstract over which Asset 

20 performs it. 

21 - `Plan` ~= ISA-88 Master / Control Recipe -- concrete binding of 

22 a Method (or Practice) to specific Asset instances + wiring, 

23 ready to schedule or execute. `define_plan` checks the 

24 family-superset invariant via the `PlanBindingContext` pattern. 

25 - `Recipe` -- the executable parameterized step sequence. Pins an 

26 immutable `capability_id`; carries templated steps with 

27 `BindingRef` sentinels; instantiated into a runtime Procedure 

28 via the Operation BC's `register_procedure_from_recipe`. 

29 

30`Run` (the actual execution) lives in the Run BC, not here, but 

31binds back to Plan + Subject. 

32 

33## Versioning-contract divergence 

34 

35Two versioning semantics span the ladder (intentional, load-bearing, 

36see [[project-recipe-aggregate-design]]): 

37 

38 - **Capability is REPLACE-WHOLESALE.** `version_capability` accepts 

39 the full declarative contract (`executor_shapes`, 

40 `parameters_schema`, `description`) on every call; each 

41 `CapabilityVersioned` event carries a complete new contract. 

42 Bindings point at the Capability aggregate, not at a specific 

43 version-tag; re-versioning replaces the contract in-place. 

44 - **Method / Plan / Practice / Recipe are INCREMENTAL-LABEL.** 

45 `version_*` slices accept a new `version_tag` plus the 

46 delta-bearing fields (Plan: `wires` + `default_parameters`; 

47 Recipe: `steps`; Method: `parameters_schema` + 

48 `needed_family_ids`; Practice: parameter overrides). Each 

49 version is content-addressed; the upstream binding 

50 (`capability_id`, `method_id`, `practice_id`) stays IMMUTABLE 

51 across versions of the binding aggregate. 

52 

53The asymmetry is deliberate: Capability is a contract whose identity 

54is its name + lineage; Method / Plan / Practice / Recipe each carry 

55an evolving body whose changes operators want to track by labeled 

56version. Operator-facing wire shapes follow suit: Capability's 

57version events redeclare the contract; the rest carry deltas. 

58 

59## Genesis-event convention 

60 

61All five aggregates emit `<X>Defined` at registration per 

62[[project-defined-vs-registered-genesis]]: each is a template / 

63contract / blueprint. Distinct from the Operation BC's 

64`ProcedureRegistered` (records that a runtime Procedure instance 

65exists, possibly bound to a Recipe via the recipe-replay path). 

66 

67Track-A BC: depends on `Equipment.Family` (referenced by 

68`Method.needed_family_ids`) and `Equipment.Asset` (referenced by 

69`Plan` binding). Cross-aggregate refs use the eventual-consistency 

70stance: the decider does NOT verify the referenced Family / Asset 

71exists; the precedent comes from Trust BC's Conduit zone refs. 

72 

73Layout (mirrors Equipment / Trust / Subject): 

74 aggregates/<aggregate>/ -- aggregate state, events union, evolver, read 

75 features/<verb>_<noun>/ -- vertical slice: command/query + decider? + handler + route + tool 

76 wire.py -- RecipeHandlers bundle + wire_recipe(deps) 

77 routes.py -- register_recipe_routes(app) 

78 tools.py -- register_recipe_tools(mcp, *, get_handlers) 

79"""
