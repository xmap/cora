1"""Practice aggregate state, value objects, status enum, and domain errors. 

2 

3`Practice` is the **facility-adapted Method** — the institution's 

4curated version of a technique class, ready to bind to specific 

5Asset instances at Plan time. ISA-88 maps it to **Site Recipe**: 

6the Method (≈ General Recipe) gets adapted at the Site level with 

7facility-specific equipment, constraints, and operational defaults, 

8but is still abstract over which specific batch run it serves. 

9 

10Per the BC map's recipe ladder: 

11 - Method ≈ General Recipe (vendor / scientific community) 

12 - **Practice ≈ Site Recipe** (this aggregate) 

13 - Plan ≈ Master / Control Recipe (concrete Asset binding) 

14 - Run ≈ batch execution 

15 

16 

17Minimal Practice: 

18 - `id` + `name` 

19 - `method_id: UUID` — the Method this Practice adapts (eventual- 

20 consistency stance: existence is NOT verified at decide time; 

21 same precedent as Method.needed_family_ids and Trust Conduit zone refs) 

22 - `site_id: UUID` — the Site-level Asset this Practice belongs to 

23 (institutional ownership; eventual-consistency: not verified) 

24 - `status: PracticeStatus` (Defined → Versioned → Deprecated FSM) 

25 - `version: str | None` (None until first version_practice) 

26 

27Additional facets are deferred if pilot demand emerges: 

28 - `additional_families: frozenset[FamilyId]` (facility- 

29 specific Family requirements that go beyond Method's 

30 needed_family_ids — for example a facility that always pairs 

31 Tomography with FlyScan) 

32 - `default_parameters` (parameter envelope dict) 

33 - `safety_overlay` (free-text or structured operator instructions) 

34 - `owner` (Actor id; institutional sanctioning authority) 

35 

36## Why Practice and not just Method.facility_id 

37 

38ISA-88's Site Recipe layer exists for a reason: a single General 

39Recipe can have multiple facility-adapted Practices (different 

40sites, different vendors, different operational defaults), and they 

41evolve independently. Pinning facility constraints onto Method 

42itself would force a 1-Method-per-facility model that doesn't 

43generalize. 

44 

45## Eventual-consistency stance for cross-aggregate refs 

46 

47Same precedent as everywhere else (Trust Conduit zone refs, 

48Method needed_family_ids, Asset.family_ids entries): 

49the decider does NOT verify `method_id` refers to a real 

50Method or `site_id` refers to a real Site-level Asset. Typos 

51produce "dangling" Practices; downstream Plan binding is where 

52the mismatch surfaces. 

53 

54## Status as enum-in-state, derived-from-event-type-in-evolver 

55 

56Same precedent as Method and Family. The lifecycle 

57mirrors Method's: Defined → Versioned → Deprecated. 

58 

59## Ninth bounded-name VO 

60 

61`PracticeName` is the **ninth** trimmed-bounded-name VO after 

62Actor / Zone / Conduit / Policy / Subject / Family / Asset / 

63Method. The shared trim+length-check logic was hoisted to 

64`cora.shared.bounded_text.validate_bounded_text` once the 

6510th VO (PlanName) landed; PracticeName now calls that helper 

66while keeping its own frozen dataclass type and per-aggregate 

67error class. 

68"""

80class PracticeStatus(StrEnum): 

81 """The Practice's lifecycle state. 

82 

83 Mirrors Method's lifecycle (and Family's). Transitions land 

84 per-slice: 

85 - Defined -> Versioned (version_practice) 

86 - (Defined | Versioned) -> Deprecated (deprecate_practice) 

87 

88 `Defined` is the genesis state set by `define_practice`. The 

89 enum values are PascalCase strings (matching the BC-map status 

90 vocabulary) so log lines and DTOs read naturally without 

91 additional mapping. 

92 """

95 VERSIONED = "Versioned"

126class PracticeCannotVersionError(Exception): 

127 """Attempted to version a practice not in `Defined` or `Versioned`. 

128 

129 Multi-source guard: `version_practice` accepts both `Defined` 

130 (first revision) and `Versioned` (subsequent revisions). Only 

131 `Deprecated` is rejected. Same divergence from strict-not- 

132 idempotent as version_method / version_family: 

133 re-versioning with the same tag succeeds (re-attestation is a 

134 legitimate audit moment). 

135 

136 Per-transition error class — same naming convention as 

137 `MethodCannotVersionError` (Recipe BC) and 

138 `FamilyCannotVersionError` (Equipment BC). 

139 """ 

140 

141 def __init__(self, practice_id: UUID, current_status: "PracticeStatus") -> None: 

142 super().__init__( 

143 f"Practice {practice_id} cannot be versioned: currently in status " 

144 f"{current_status.value}, version requires " 

145 f"{PracticeStatus.DEFINED.value} or {PracticeStatus.VERSIONED.value}" 

146 ) 

147 self.practice_id = practice_id 

148 self.current_status = current_status 

149

200@dataclass(frozen=True) 

201class Practice: 

202 """Aggregate root: a facility-adapted Method (ISA-88 Site Recipe analog). 

203 

204 `method_id` is the Method this Practice adapts. `site_id` is the 

205 Site-level Asset (per Equipment's hierarchy) this Practice 

206 belongs to. Both are eventual-consistency refs: the decider does 

207 NOT verify they refer to real aggregates. Mismatch surfaces at 

208 Plan binding. 

209 

210 `version` mirrors Method's pattern: None until the first 

211 version_practice call; preserved across deprecation as the audit 

212 signal of the last revision before deprecation. State always holds 

213 the latest tag — past tags live in the event stream as 

214 `PracticeVersioned` events. No `current_` prefix because state by 

215 definition holds current values (same convention as `status`, 

216 `name`). 

217 """
