1"""ComputePort: domain-shaped job submission for the Operation BC executor. 

2 

3`ComputePort` is the async Protocol a Run-conducting runtime uses to 

4submit a compute job, await its terminal state, and fetch a reference 

5to the artifact it produced. Substrate details (a local subprocess, 

6a Slurm REST scheduler, Globus Compute) live behind concrete adapters; 

7the runtime never touches substrate-specific symbols directly. 

8 

9This is the CONDUCT sibling of `ControlPort`. ControlPort generalises 

10value-IO across control-system substrates; ComputePort generalises 

11job submission across compute substrates. They sit in the same BC home 

12(`cora.operation.ports`) because both are seams the executor reaches 

13across to actuate the outside world: ControlPort drives hardware, 

14ComputePort drives a compute job. Per the seam model 

15([[project_seam_model]]) invoking an external compute substrate is the 

16same posture as invoking EPICS, not a competition with it. 

17 

18## Earned, not minted 

19 

20This port ships with exactly ONE real adapter (a local-process 

21executor) plus a test fake, following the adapter-first lesson behind 

22ControlPort ([[project_adapter_naming_research]], 

23[[feedback_port_generalization_trigger]]): a port surface is distilled 

24from a concrete adapter, never speculated ahead of one. The surface 

25below is what a local subprocess genuinely needs. When a second real 

26substrate arrives (Slurm REST, Globus Compute), generalise the surface 

27and introduce a routing registry then, exactly as ControlPort earned 

28its registry from a third substrate. No registry ships now. 

29 

30## Domain vocabulary (substrate-neutral) 

31 

32- **`JobSpec`** is the substrate-neutral description of the work: 

33 the command to run, its input and output URIs, validated parameters, 

34 and the resource shape it needs. Adapters translate it into a 

35 substrate launch (an argv + cwd for local-process; a batch script + 

36 `#SBATCH` directives for Slurm; a function payload for Globus). 

37- **`ComputeStatus`** is the closed terminal-state enum. A submitted 

38 job ends in exactly one of `Succeeded | Failed | Cancelled | 

39 TimedOut`. There is no in-flight value: `await_terminal_state` 

40 returns only when the job is done. 

41- **`ArtifactRef`** is a reference to the produced output, shaped to 

42 feed `RegisterDataset` 1:1 (uri + checksum + byte_size + media_type 

43 + conforms_to). The runtime captures it for provenance; a later 

44 `register_dataset` call records the resulting Dataset + Distribution. 

45- **`ComputeResult`** is the captured-once result the runtime 

46 snapshots onto the Run's terminal event for replay determinism 

47 ([[project_non_determinism_principle]]): job id, terminal status, 

48 the output artifacts and measurements, and the `ActuationKind` the 

49 adapter declares. 

50 

51## Two output arms, one walker 

52 

53ComputePort exposes two output arms, both now driven by the Procedure 

54`Conductor`'s `ComputeStep` (`cora.operation.conductor`). A step 

55selects its arm by whether it names an output file: 

56 

57- the file-artifact arm (a step with an `output_uri`): submit -> await 

58 -> `fetch_artifact_ref` -> `provide_result(artifacts=...)`, surfacing 

59 an `ArtifactRef` a Dataset registers against (a reconstruction); 

60- the value arm (a step without an `output_uri`): submit -> await -> 

61 `fetch_measurements` -> `provide_result(measurements=...)`, recording 

62 each `Measurement` on the Procedure's activity log so an 

63 align-resolution routine yields a structured value (a detector pixel 

64 size) that homes to a Calibration. 

65 

66The two arms ride one port surface because both are the same 

67submit/await posture over a compute substrate; which arm a step 

68populates is the step's choice (its `output_uri`), not a port split. A 

69single-job compute Run is the degenerate one-step file-arm case the 

70composition root walks through this same Conductor. 

71 

72## Actuation kind 

73 

74ComputePort reuses Operation's existing `ActuationKind` 

75(`Physical | Simulated | Hybrid`) rather than minting a parallel enum. 

76A real subprocess running a real solver is `Physical`; the in-memory 

77fake is `Simulated`. The adapter is the authority (mirroring how the 

78ControlPort registry's per-route `is_simulated` flag, not the adapter 

79class, decides): `provide_result` lets the adapter stamp 

80the kind onto the result, which rides the Run terminal 

81event so simulator-origin data can never be promoted to Production. 

82 

83## Out of scope (deferred) 

84 

85- **A routing registry / multi-substrate dispatch.** Triggers at the 

86 second real adapter, like ControlPort's registry. 

87- **Fire-and-reconcile submission** (submit returns immediately, a 

88 separate reconciler awaits the terminal state). The single blocking 

89 `submit` + `await_terminal_state` shape fits a local subprocess; 

90 the split is the Slurm-style second-adapter trigger. 

91- **Streaming / progress events** mid-job. A future `ComputeEventPort` 

92 sibling, by analogy to ControlPort's deferred `EventPort`. 

93- **Mid-job cancellation by handle.** Today the runtime cancels by 

94 cancelling the awaiting task; an explicit `cancel(job_id)` lands 

95 when a substrate needs server-side kill. 

96 

97## Exceptions 

98 

99Six exception families mirror CORA's standard shape and ControlPort's 

100posture: ComputePort is not REST-accessible; the conducting runtime 

101captures these as event-payload metadata, never surfacing them as HTTP 

102errors. A raised exception means the conduct failed; the runtime 

103records an aborted Run with the failure detail. 

104 

105`ComputeExecutableNotPermittedError` subclasses 

106`ComputeSubmitRejectedError` rather than standing beside it, so it 

107reaches the runtime's closed catch tuples without either being edited. 

108Prefer that shape for any future CORA-side refusal that is a NARROWING 

109of an existing family: a sibling would have to be threaded into every 

110`except` tuple by hand, and the one nobody remembers is the one that 

111strands a Procedure in `Running`. 

112"""

122JobId = NewType("JobId", str) 

123"""Opaque substrate job handle returned by `submit`. 

124 

125A local-process adapter mints a process-scoped token; Slurm would use 

126its numeric job id; Globus Compute its task UUID. The runtime treats 

127it as an opaque correlation key it passes back to `await_terminal_state` 

128and `fetch_artifact_ref`, and snapshots onto the Run terminal event as 

129`producing_job_id` for audit. 

130"""

133class ComputeStatus(StrEnum): 

134 """Closed terminal-state enum for a submitted compute job. 

135 

136 A job that has reached `await_terminal_state` is in exactly one of 

137 these. There is no `Running` / `Pending` value: the port models 

138 submission-to-terminal, not in-flight polling, so the surface 

139 cannot represent a non-terminal job by construction. 

140 

141 `Succeeded`: the job exited cleanly and produced its artifact. 

142 `Failed`: the job ran but exited non-zero / errored. 

143 `Cancelled`: the conduct was cancelled before the job finished. 

144 `TimedOut`: the job exceeded its allotted wall-clock budget. 

145 

146 Only `Succeeded` warrants `fetch_artifact_ref`; the other three are 

147 failure terminals the runtime maps to an aborted Run. 

148 """ 

149 

150 SUCCEEDED = "Succeeded" 

151 FAILED = "Failed" 

152 CANCELLED = "Cancelled" 

153 TIMED_OUT = "TimedOut" 

154 

155 @property 

156 def is_success(self) -> bool: 

157 """True only for `Succeeded`; the three failure terminals are False.""" 

158 return self is ComputeStatus.SUCCEEDED

201@dataclass(frozen=True) 

202class ArtifactRef: 

203 """Reference to the artifact a succeeded job produced. 

204 

205 Shaped to feed `RegisterDataset` 1:1 so the runtime (or a later 

206 register-dataset call) can record the output Dataset + Distribution 

207 without reshaping: `uri` is where the bytes landed, `checksum_*` 

208 and `byte_size` verify them, `media_type` and `conforms_to` describe 

209 them. The adapter computes the checksum + size from the produced 

210 file on `fetch_artifact_ref`; `media_type` / `conforms_to` default 

211 to "unknown" when the substrate cannot infer them. 

212 

213 The artifact may be a single file OR a directory of files (a default 

214 tomopy reconstruction writes a per-slice stack into a `{stem}_rec/` 

215 directory). For a single file, `checksum_algorithm` is `sha256` and 

216 `entry_count` is None. For a directory, `checksum_algorithm` is 

217 `sha256-tree` (a deterministic digest over the whole tree, see 

218 `_tree_hash.sha256_tree`), `byte_size` is the summed file sizes, and 

219 `entry_count` is the number of files. The 64-hex `checksum_value` 

220 format is identical for both, so it feeds `RegisterDataset` unchanged. 

221 """ 

222 

223 uri: str 

224 checksum_algorithm: str 

225 checksum_value: str 

226 byte_size: int 

227 media_type: str | None = None 

228 conforms_to: tuple[str, ...] = () 

229 entry_count: int | None = None

232@dataclass(frozen=True) 

233class ComputeResult: 

234 """Captured-once result a compute conduct produced: provenance + outputs. 

235 

236 Assembled by the adapter's `provide_result` so the adapter owns the 

237 `actuation_kind` determination (a real subprocess is `Physical`, the 

238 fake is `Simulated`). A conduct's outputs are a SET: zero or more file 

239 `artifacts` (each an `ArtifactRef` that feeds `RegisterDataset` 1:1) 

240 and zero or more structured `measurements` (each a `Measurement`, the 

241 value arm that homes to a Calibration). A reconstruction populates 

242 `artifacts`; an alignment measurement populates `measurements`; a 

243 quality-reporting reconstruction populates both. The runtime threads 

244 `actuation_kind` + `job_id` + the outputs onto the terminal event so a 

245 replay folds the same provenance without re-running the job 

246 ([[project_non_determinism_principle]]). 

247 

248 The Conductor's file-arm ComputeStep populates `artifacts` from 

249 `fetch_artifact_ref`; the value-arm ComputeStep populates 

250 `measurements` from `fetch_measurements`. 

251 

252 `is_simulated` is derived, not stored: any simulator touch 

253 disqualifies promotion, so `actuation_kind in {Simulated, Hybrid}` 

254 is the single source of truth, mirroring the ControlPort promotion 

255 gate's treatment of `Hybrid` as `Simulated`. 

256 """ 

257 

258 job_id: JobId 

259 status: ComputeStatus 

260 actuation_kind: ActuationKind 

261 artifacts: tuple[ArtifactRef, ...] = () 

262 measurements: tuple[Measurement, ...] = () 

263 

264 @property 

265 def is_simulated(self) -> bool: 

266 """True when any part of the conduct touched a simulator. 

267 

268 Derived from `actuation_kind`: `Simulated` and `Hybrid` both 

269 count (any simulator touch is disqualifying for promotion); 

270 only `Physical` is False. 

271 """ 

272 return self.actuation_kind is not ActuationKind.PHYSICAL

275class ComputeSubmitRejectedError(Exception): 

276 """The job was refused at submission time, before it ran. 

277 

278 Covers both directions of refusal: a substrate saying no (a 

279 scheduler rejecting the spec on a bad resource request or an 

280 exhausted quota) and an adapter's own pre-flight saying no (a 

281 malformed launch, an executable the deployment does not permit). 

282 Distinct from `ComputeNotAvailableError` (the substrate itself is 

283 reachable; it is the specific job it rejected). 

284 

285 `ComputeExecutableNotPermittedError` narrows the CORA-side arm; see 

286 it for why the distinction is a subclass rather than a sibling. 

287 """ 

288 

289 def __init__(self, reason: str) -> None: 

290 super().__init__(f"Compute job submission rejected: {reason}") 

291 self.reason = reason

294class ComputeExecutableNotPermittedError(ComputeSubmitRejectedError): 

295 """CORA refused to spawn this executable; no substrate was asked. 

296 

297 Raised by `LocalProcessComputePort.submit` when `command[0]` is 

298 outside the deployment's declared `permitted_executables`. The 

299 grammatical subject separates it from its parent: here the subject 

300 is CORA's own configuration, and the refusal is settled before any 

301 substrate is contacted. A scheduler cannot raise this, because a 

302 scheduler has no concept of CORA's allowlist. 

303 

304 It is a SUBCLASS, not a sibling, and that is load-bearing. The 

305 Conductor catches a closed `_COMPUTE_ERRORS` tuple and the 

306 EdgeConductor an inline one; `except` catches subclasses, so this 

307 class reaches both recorded-failure paths with no edit to either and 

308 no risk of the silent escape a new sibling would invite. It buys the 

309 operator a distinct name to filter on, at no threading cost. 

310 

311 `executable` carries the argv[0] that was refused, so a log line 

312 names the thing to add to the allowlist or the thing to worry about. 

313 """ 

314 

315 def __init__(self, executable: str) -> None: 

316 super().__init__( 

317 f"executable {executable!r} is not in this deployment's " 

318 f"COMPUTE_PERMITTED_EXECUTABLES allowlist" 

319 ) 

320 self.executable = executable

336class ComputeTimeoutError(Exception):

417@runtime_checkable 

418class ComputePort(Protocol): 

419 """Domain-shaped job-submission port for compute substrates. 

420 

421 Substrate-agnostic. Concrete adapters (`InMemoryComputePort`, 

422 `LocalProcessComputePort`, future `SlurmComputePort` / 

423 `GlobusComputePort`) implement the launch + poll + artifact-stat 

424 details. Per [[project_non_determinism_principle]] the conducting 

425 runtime captures the port's effects (job id, terminal status, 

426 artifact ref, actuation kind) into the Run's terminal event at 

427 conduct time, so a replay never re-submits. 

428 

429 The submission model is single-blocking: `submit` then 

430 `await_terminal_state` complete one job within one conduct call. 

431 Fire-and-reconcile submission, a routing registry, mid-job 

432 streaming, and cancel-by-handle are deferred to their own triggers 

433 (see module docstring), keeping this surface to what a local 

434 subprocess genuinely needs. 

435 """ 

436 

437 async def submit(self, job_spec: JobSpec) -> JobId: 

438 """Submit `job_spec` to the substrate and return its job id. 

439 

440 Returns as soon as the substrate accepts the job (a launched 

441 subprocess, an enqueued batch job). Raises 

442 `ComputeSubmitRejectedError` if the substrate refuses the spec 

443 or `ComputeNotAvailableError` if the substrate is unreachable. 

444 """ 

445 ... 

446 

447 async def await_terminal_state(self, job_id: JobId) -> ComputeStatus: 

448 """Block until `job_id` reaches a terminal state, then return it. 

449 

450 Returns one of the four `ComputeStatus` terminals. May raise 

451 `ComputeTimeoutError` if a hard await ceiling elapses before the 

452 substrate reports a terminal state, or `ComputeJobFailedError` 

453 when there is diagnostic detail worth preserving alongside a 

454 `Failed` outcome. 

455 """ 

456 ... 

457 

458 async def fetch_artifact_ref(self, job_id: JobId) -> ArtifactRef: 

459 """Return an `ArtifactRef` for the output of a succeeded `job_id`. 

460 

461 Only valid after `await_terminal_state` returned `Succeeded`. 

462 Raises `ArtifactNotFoundError` if the job's declared output is 

463 not where the adapter expects it. 

464 """ 

465 ... 

466 

467 async def fetch_measurements(self, job_id: JobId) -> tuple[Measurement, ...]: 

468 """Return the structured `Measurement`s a succeeded `job_id` produced. 

469 

470 The value-arm sibling of `fetch_artifact_ref`, consumed by the 

471 Procedure Conductor's ComputeStep (slice 6a). Only valid after 

472 `await_terminal_state` returned `Succeeded`. Raises 

473 `MeasurementNotFoundError` when the job surfaced no structured 

474 value (the in-memory fake has none seeded; a real substrate that 

475 does not read structured values raises rather than returning empty). 

476 """ 

477 ... 

478 

479 def provide_result( 

480 self, 

481 job_id: JobId, 

482 status: ComputeStatus, 

483 artifacts: tuple[ArtifactRef, ...] = (), 

484 measurements: tuple[Measurement, ...] = (), 

485 ) -> ComputeResult: 

486 """Assemble the `ComputeResult` for this job's outputs. 

487 

488 Pure assembly (no IO): the adapter stamps the `ActuationKind` it 

489 is the authority for (`Physical` for a real substrate, `Simulated` 

490 for the fake) onto the captured job id, terminal status, and the 

491 produced outputs. The runtime threads this onto the terminal event 

492 for replay-deterministic provenance. The `artifacts` arm is the 

493 file path a ComputeStep with an `output_uri` drives; the 

494 `measurements` arm is the value path a ComputeStep without one 

495 drives, each from its respective `fetch_*` call. The adapter 

496 stamps the kind onto BOTH arms so a value-producing conduct 

497 carries the same promotion provenance as a file-producing one. 

498 """ 

499 ...

501 async def aclose(self) -> None: 

502 """Release any substrate resources; idempotent. 

503 

504 Provided so composition code can call `aclose()` on any 

505 `ComputePort` without branching on type (mirrors 

506 `ControlPort.aclose`). The in-memory fake is a no-op; a 

507 local-process adapter terminates any straggling subprocesses. 

508 """
