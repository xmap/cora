1"""Reaction: a CampaignClosed -> seal the campaign-bound Active allocation. 

2 

3The paper's close-the-books claim: an allocation whose `campaign_id` 

4references the closed Campaign is sealed automatically at the same 

5instant the experiment's own books close, freezing the final-spend 

6snapshot beside the campaign record. An allocation with no campaign 

7binding (or bound to a different campaign) is untouched: binding is 

8what opts an envelope into the automatic seal, so beamline-total 

9envelopes without a campaign stay under manual `seal_allocation`. 

10 

11## Authz posture: system actor, raw decide + append (not the handler) 

12 

13The seal must carry a principal, and no operator issued this command. 

14Precedents inspected: the LLM subscribers and the kill-switch write 

15as their own SEEDED agent principals (each is a modeled Agent with an 

16Actor and, under real Trust, an operator-granted policy), while 

17seed/bootstrap writes and the enclosure permit monitor stamp 

18`SYSTEM_PRINCIPAL_ID` and run the slice's load -> decide -> append 

19WITHOUT the handler's authorize gate, because `SYSTEM_PRINCIPAL_ID` 

20is deliberately NOT an authz wildcard and a real Trust policy would 

21deny it. This sealer is a deterministic bookkeeping reflex, not an 

22agent with judgment worth modeling, so it mirrors the enclosure 

23monitor: `sealed_by = SYSTEM_PRINCIPAL_ID`, same-BC decider reuse 

24(the Active-only guard in `seal_allocation.decider` is the real 

25gate), no Authorize call. The spend snapshot flows through the SAME 

26`make_ledger_total_spend` reader `wire_budget` binds, so an automatic 

27seal and an operator seal can never disagree about the figure. 

28 

29## Determinism + idempotency 

30 

31The seal's `occurred_at` and its ledger window end are the 

32CampaignClosed event's `occurred_at`, not wall clock, so a replayed 

33delivery derives the same event (the subscribers' determinism rule). 

34The seal event's `event_id` is a UUIDv5 of (trigger event, allocation) 

35and the append is guarded by the loaded stream version. A benign 

36concurrent write (an operator `update_allocation_ceiling` landing 

37between load and append) bumps the version while the envelope is 

38still Active, so instead of forfeiting the automatic seal the sealer 

39re-loads and retries the append at the fresh version (bounded, a few 

40attempts); the deterministic event id keeps the retry idempotent. A 

41re-delivery after a real seal short-circuits on the non-Active fold 

42pre-guard. Skips (no Active envelope, unbound envelope, campaign 

43mismatch, retry exhaustion) advance the bookmark; nothing here may 

44wedge it. 

45 

46## Lookup + fold double-check, and the projection-lag caveat 

47 

48`AllocationLookup.find_active` (projection-backed) finds the 

49candidate cheaply, then the aggregate stream is loaded and folded 

50before deciding: the fold is the truth the optimistic append is 

51versioned against. The double-check guards the stale-POSITIVE 

52direction (projection still shows Active, fold says otherwise) and 

53logs it at WARNING as a real divergence. It cannot guard the 

54stale-NEGATIVE direction: because subscribers run on independent 

55cursors, the summary projection may not yet reflect an 

56`AllocationActivated` that landed just before CampaignClosed, so a 

57`no_active_allocation` or `campaign_mismatch` skip can be a false 

58negative. A missed automatic seal is recovered by the operator's 

59manual `seal_allocation` slice, which reads the stream directly. 

60"""

104"""Bounded reload-and-retry on a lost seal race. A benign concurrent

108realistic burst; beyond it the seal is deferred to the manual slice."""
