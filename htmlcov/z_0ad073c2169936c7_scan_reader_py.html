1"""ScanReader: Data BC's port for reading facts out of a scan file. 

2 

3Used by the ``ingest_scan`` handler to turn one on-disk scan product 

4into the facts the Data BC's registration commands need: frame roles 

5and counts, angles, structural completeness, the acquisition 

6timestamp, and a stat snapshot. The port encapsulates the layout 

7(Data Exchange today, NeXus NXtomo when a deployment selects it); the 

8domain never sees a dataset path. 

9 

10## The axis map 

11 

12Scan ingest separates four independently varying concerns, and this 

13port is exactly one of them: 

14 

15 - layout (THIS PORT): how facts are read out of the file; 

16 - finality: when the file stops changing (a deployment protocol, 

17 not a file property; two beamlines writing the same layout can 

18 differ); 

19 - correlation: whose experiment the file belongs to (a scheduling 

20 derivation, not a file property); 

21 - transport: how CORA reaches the bytes (the locator's meaning). 

22 

23Fusing any of the other three into an adapter here is the mistake the 

24seam exists to prevent. 

25 

26## Roles, not paths 

27 

28The payload speaks a closed frame-role vocabulary 

29{projection, flat, dark, invalid}. Data Exchange separates roles into 

30datasets (``/exchange/data`` + ``data_white`` + ``data_dark``); NXtomo 

31interleaves one stack tagged per-frame by ``image_key`` (0 projection, 

321 flat, 2 dark, 3 invalid). Counts absorb both shapes; paths absorb 

33neither, which is why the payload carries no paths. 

34 

35``invalid_count`` counts frames the layout MARKS unusable. A layout 

36with no marking (Data Exchange) reports 0, meaning none-marked, not 

37all-validated. 

38 

39## Zero versus None on counts 

40 

410 means verified-none; None means the source cannot know. A crashed 

42Data Exchange file has no commanded counts (they are written on clean 

43close), and NXtomo has no commanded counts at all, so 

44``dropped_frame_count`` and the ``commanded_*`` fields are optional 

45rather than defaulted, and a consumer must not read absence as zero. 

46 

47## Discriminated result 

48 

49``Description | Unreadable | Unrecognized``, bare variant names scoped 

50by this module per the ChecksumVerifier precedent 

51(``Match | Mismatch | Unreachable``). ``Unrecognized`` fires only when 

52the one dataset the layout makes mandatory is absent; a missing or 

53empty ROLE dataset is count 0, never Unrecognized (a no-flats scan is 

54a designed acquisition mode, not a malformed file). ``Unreadable`` may 

55be transient: a half-transferred file on the analysis tier is an 

56expected observable, and the caller decides whether to retry. 

57"""

64@dataclass(frozen=True) 

65class Description: 

66 """The facts one readable scan file yields. 

67 

68 ``byte_size`` and ``mtime_ns`` are the stat snapshot taken before 

69 the structural read; the ingest handler compares them against the 

70 digest pass's snapshot to refuse files that changed while being 

71 read (the live-file guard). 

72 

73 ``captured_at`` is parsed ONLY when the file's timestamp string 

74 carries an unambiguous offset; a naive string stays raw in 

75 ``captured_at_raw`` with ``captured_at=None``, because guessing a 

76 timezone would manufacture provenance. The site timezone rule, once 

77 staff confirm it, lands in the adapter and turns those raws into 

78 parsed values. 

79 

80 ``captured_at_source`` names WHICH of the file's timestamps that 

81 came from, and it is not always the obvious one. A layout can offer 

82 several, and a deployment's writer can be wrong about one of them: 

83 2-BM's ``start_date`` is measurably the PREVIOUS scan's end, while 

84 its ``end_date`` is correct to within seconds. So the reader is told 

85 which to believe, and the record carries the answer rather than 

86 leaving a reader to assume. The field is a plain ``str`` so a new 

87 layout can name a timestamp this one has never heard of. 

88 """

129class ScanReader(Protocol): 

130 """Data BC port: read the registration facts out of one scan file.""" 

131 

132 kind: str 

133 """Short adapter-kind label stamped into the recorded evidence as 

134 ``reader_kind``. Forensic provenance: records WHICH layout reader 

135 produced the facts. A class attribute on each adapter.""" 

136 

137 async def describe(self, *, locator_uri: str) -> ScanReadResult: 

138 """Read the facts at ``locator_uri`` without writing anything. 

139 

140 The locator is opaque to callers and interpreted by the 

141 adapter (one-file-one-scan is a 2-BM property, not a port 

142 property; a future layout may address an entry inside a 

143 file). Implementations MUST open read-only without taking 

144 filesystem locks, MUST NOT raise on I/O or layout failures 

145 (return ``Unreadable`` / ``Unrecognized``), and MUST be safe 

146 to point at a file another process is still writing. 

147 """
