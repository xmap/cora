1"""BC-application-layer errors for the Access BC. 

2 

3These errors are raised by application handlers (not domain logic) and 

4mapped to HTTP / MCP responses by the BC's exception handlers in 

5`cora/access/routes.py`. 

6 

7Domain errors (raised by aggregates / deciders) live with their 

8aggregate, for example `aggregates/actor/state.py`. 

9 

10Distinct class from `cora.subject.errors.UnauthorizedError` / 

11`cora.trust.errors.UnauthorizedError`: each BC owns its own 

12application-error namespace so an Access 403 is distinguishable 

13from a Subject or Trust 403 in logs / aggregator filters 

14(documented in CONTRIBUTING.md "BC-application-layer errors"). 

15Cross-BC consumers catching authorization failures import per-BC. 

16""" 

17 

18from typing import ClassVar 

19from uuid import UUID

22class UnauthorizedError(Exception): 

23 """The Authorize port denied the command.""" 

24

26 super().__init__(reason) 

27 self.reason = reason

30class ActorSelfReactivationRefusedError(Exception): 

31 """A principal attempted to reinstate its own deactivated Actor. 

32 

33 Lives here, beside `UnauthorizedError`, rather than in the Actor 

34 aggregate's error block. The `<X>Cannot<Verb>Error` names there are 

35 the 409 state-transition family (`ActorCannotDeactivateError`, 

36 `ActorCannotReactivateError`): they mean the aggregate is in the 

37 wrong state for the command. This one is a 403. The aggregate is in 

38 exactly the right state to be reactivated; what is refused is WHO 

39 asked. Filing it with the transition errors would have put an 

40 authority refusal in the family a reader scans for state conflicts. 

41 

42 Refused structurally rather than by Policy configuration. The gate's 

43 liveness conjunct fails OPEN on a lookup error by design, so without 

44 this the only barrier to self-reinstatement is a check built to 

45 yield under fault. Granting `ReactivateActor` means the power to 

46 reinstate colleagues; self-reinstatement is a different power and 

47 nobody would expect it to ride along. 

48 """ 

49 

50 # Without this the idempotency layer's `classify_error_status` would 

51 # fall through to its 409 default, because the old name was in the 

52 # `<X>Cannot<Verb>Error` state-conflict family and this one matches no 

53 # branch. Inert today (`reactivate_actor` is not idempotency-wrapped), 

54 # declared anyway so wrapping it later cannot quietly downgrade an 

55 # authority refusal into a state conflict. 

56 idempotency_http_status: ClassVar[int] = 403 

57 

58 def __init__(self, actor_id: UUID) -> None: 

59 super().__init__(f"Actor {actor_id} cannot reactivate itself") 

60 self.actor_id = actor_id
