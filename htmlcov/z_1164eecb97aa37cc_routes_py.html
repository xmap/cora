1"""HTTP setup for the Operation BC. 

2 

3`register_operation_routes(app)` includes every slice's router and 

4registers exception handlers that translate the BC's domain / 

5application errors to HTTP status codes. Called once at app 

6construction. 

7 

8JSONResponse is used (not HTTPException) per FastAPI guidance to 

9avoid nested-exception pitfalls. 

10 

11`IdempotencyConflictError`, `IdempotencyClaimLostError`, 

12`CachedHandlerError`, `ConcurrencyError`, and `AssetNotFoundError` 

13(Equipment-BC) are infra-layer / cross-BC errors registered by their 

14owning BC. They produce the same JSON shape regardless of which BC 

15raised them, so Operation does not re-register them. 

16 

17## Loop-collapse pattern 

18 

19Operation owns one aggregate (Procedure) plus its per-step logbook. 

20Five error families share the same response shape and get collapsed 

21via the Trust / Equipment / Supply-style loop pattern: 

22 

23 - 400 (validation): InvalidProcedureName, InvalidProcedureKind, 

24 InvalidProcedureAbortReason, InvalidProcedureTruncateReason, 

25 InvalidProcedureInterruptedAt, InvalidStepKind 

26 - 404 (load miss): ProcedureNotFound 

27 - 409 (defensive guard for AlreadyExists): ProcedureAlreadyExists 

28 - 409 (transition guards): ProcedureCannotStart, 

29 ProcedureCannotComplete, ProcedureCannotAbort, 

30 ProcedureCannotTruncate, ProcedurePlanAssetDecommissioned, 

31 ProcedureStepsLogbookClosed 

32"""

99async def _handle_validation_error(request: Request, exc: Exception) -> JSONResponse: 

100 """Shared 400 handler for every domain validation error. 

101 

102 Covers Invalid<X>NameError / Invalid<X>KindError / 

103 Invalid<X>AbortReasonError. All map to HTTP 400 + 

104 `{"detail": str(exc)}` body. Adding a new validation-style error 

105 is one extra entry in the tuple in `register_operation_routes`. 

106 """ 

107 _ = request 

108 return JSONResponse( 

109 status_code=status.HTTP_400_BAD_REQUEST, 

110 content={"detail": str(exc)}, 

111 )

132async def _handle_already_exists(request: Request, exc: Exception) -> JSONResponse: 

133 """Defensive 409 handler for every aggregate's AlreadyExistsError. 

134

138 this handler closes that gap. 

139 """

164async def _handle_unprocessable(request: Request, exc: Exception) -> JSONResponse: 

165 """Shared 422 handler for parse-shape failures past the Pydantic boundary. 

166 

167 Covers the Recipe-expansion family raised at 

168 register_procedure_from_recipe time: stale-Capability schema drift, 

169 operator-supplied bindings shape failures, and the expansion 

170 overflow cap. The 400 Invalid<X> family is reserved for VO 

171 constructor failures (name / kind); 422 is reserved for 

172 downstream parse-shape or schema-cross-check failures that pass 

173 Pydantic but fail at the cross-aggregate boundary. 

174 """ 

175 _ = request 

176 return JSONResponse( 

177 status_code=status.HTTP_422_UNPROCESSABLE_CONTENT, 

178 content={"detail": str(exc)}, 

179 )

182async def _handle_internal_server_error(request: Request, exc: Exception) -> JSONResponse: 

183 """Shared 500 handler for server-side determinism / port-contract bugs. 

184 

185 Covers RecipeExpansionDeterminismError (expansion port returned 

186 different results for the same `(steps, bindings)` input, 

187 indicating a non-pure expander or a non-canonical bindings dict). 

188 Distinct from operator error: the operator's request is well-formed; 

189 the server-side bug means re-trying with the same payload will 

190 likely fail the same way. Mapped to HTTP 500. 

191 

192 Also covers `PseudoAxisEvaluationFailedError`: the partition-rule 

193 math kernel produced a non-finite result, a NaN, or an unsupported 

194 rule variant. Operator command shape was valid; the server-side 

195 failure is in the evaluator. Per [[project-pseudoaxis-design]] v3 

196 HTTP status map: 500. 

197 """ 

198 _ = request 

199 return JSONResponse( 

200 status_code=status.HTTP_500_INTERNAL_SERVER_ERROR, 

201 content={"detail": str(exc)}, 

202 )
