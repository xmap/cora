1"""Supply aggregate state, value objects, status enum, and domain errors. 

2 

3`Supply` is a continuously-available resource that other aggregates 

4depend on: photon beam, LN2, compressed air, electrical power, 

5cooling water, vacuum, process gases, compute pool, FEL pulses, 

6neutrons. Per the BC map, `Supply` is the Track B intro aggregate, 

7multiple instances at runtime, one per resource. Physical 

8infrastructure delivering the resource (gas cabinets, compressors, 

9mass-flow controllers) stays as `Asset`s; the resource itself is 

10`Supply`. 

11 

12The aggregate is intentionally slim: identity + scope + kind + name 

13+ a single `status` field driving the FSM. The 5-state FSM is locked 

14day one per [[project_supply_design]]: 

15 

16 Unknown -> Available 

17 Unknown -> Degraded 

18 Unknown -> Unavailable 

19 Available -> Degraded 

20 Available -> Unavailable 

21 Degraded -> Available 

22 Degraded -> Unavailable 

23 Unavailable -> Recovering 

24 Recovering -> Available (operator-ack via restore_supply slice) 

25 Recovering -> Degraded 

26 Recovering -> Unavailable 

27 

28`Unknown` is the registration-time initial state per universal 

29precedent (Tango UNKNOWN, EPICS UDF/INVALID, areaDetector 

30ADStatusInitializing, SKA Tango Base INIT, Azure Resource Health 

31Unknown, Kubernetes Pod Pending, Prometheus `up{}` UNKNOWN-before- 

32first-scrape, BACnet out_of_service, PackML STOPPED, PI Pt Created). 

33The optimistic-Available default is an anti-pattern across all three 

34research corpora. 

35 

36## Phase 10a-a + 10a-b scope 

37 

38Minimal Supply: id + scope + kind + name + status (defaults Unknown 

39implicitly via genesis evolver) + registered_at. 10a-a shipped 

40`register_supply` (genesis -> Unknown) and `mark_supply_available` 

41(Unknown -> Available, operator-asserted first observation). 10a-b 

42closed the FSM with `degrade`, `mark_unavailable`, `mark_recovering`, 

43and `restore` (the last is the recovery acknowledgement, distinct 

44from `mark_supply_available`'s first-observation semantics). 

45 

46## Status as enum-in-state, derived-from-event-type-in-evolver 

47 

48`SupplyStatus` is a `StrEnum` so the values serialize naturally as 

49JSON-friendly strings IF carried in an event payload. State holds 

50the enum (typed); evolver derives status from event type 

51(`SupplyRegistered -> UNKNOWN`, `SupplyMarkedAvailable -> AVAILABLE`). 

52Same precedent as `SubjectStatus` / `FamilyStatus` / 

53`AssetLifecycle`. 

54 

55`SupplyScope` enum value DOES travel in event payloads (scope is set 

56at registration and doesn't change). The payload carries the string; 

57the evolver reconstructs via `SupplyScope(payload["scope"])`. Same 

58precedent as `AssetLevel`. 

59 

60## TriggerSource locked 3-value day one 

61 

62`TriggerSource` is locked at three values (`Operator`, `Monitor`, 

63`Auto`) from day one even though only `Operator` is used in 10a-a/b. 

64The forward-compat motivation is in [[project_supply_design]]: when 

65substream-driven `Monitor` slices and timer-based `Auto` recovery 

66land, the enum doesn't need to widen. Carried in transition-event 

67payloads as the trigger discriminator. 

68 

69## Identity: stable opaque + typed address 

70 

71`Supply` carries `id: UUID` (stable opaque handle, survives any 

72operator-driven name changes; survives physical equipment swaps once 

73binding lands per Watch item 6) plus `(scope, kind, name)` typed 

74address. The 4-tuple `(scope, kind, name)` is the operator-readable 

75identity surfaced in REST/MCP and indexed in the projection. The 

76projection-side UNIQUE INDEX on `(scope, kind, name)` catches 

77duplicate registrations at insert time; aggregates cannot enforce 

78cross-stream uniqueness without DCB (per [[project_deferred]]). 

79 

80## Eleventh bounded-name VO 

81 

82`SupplyName` is the eleventh trimmed-bounded-name VO. Uses the 

83shared `validate_bounded_text` helper hoisted in 6e-1 

84(`cora.infrastructure.bounded_text`). 

85 

86## SupplyKind shape — BARE str, not a VO (gate-review iter 1 lock) 

87 

88`kind: str` is bare on the Supply state, NOT a VO. Validated at the 

89decider via `validate_bounded_text` (1-50 chars after trim) and at 

90the API boundary via Pydantic min_length / max_length. Closed 

91StrEnum was rejected universally across all three research corpora 

92(Kubernetes CRD, Crossplane MRD, OpenTelemetry semantic conventions, 

93CloudEvents reverse-DNS; ISA-95 property model; IEC 61850 namespace 

94extensions). 

95 

96The bare-str-not-VO choice was caught by the iter-1 gate review and 

97backed by Khononov 2024 *Balancing Coupling*: wrap a primitive in a 

98VO when the type carries domain *behavior or comparison semantics*, 

99not when it merely needs a length check. Two converging arguments 

100for the bare form here: 

101 

102 1. `kind` will eventually graduate to `SupplyKind: StrEnum` once 

103 pilot vocabulary settles (Watch item 4 in 

104 [[project_supply_design]]). Migration `str -> StrEnum` is a 

105 clean parser change; `SupplyKind(VO) -> SupplyKind(StrEnum)` 

106 would break every type-annotated call site. 

107 2. `AssetPort.signal_type: str` is the in-codebase precedent: 

108 bare-str discriminator with inline-validation, awaiting future 

109 enum promotion. Same shape applies here. 

110 

111Documented starter vocabulary lives in [[project_supply_design]] as 

112guidance, not constraint: PhotonBeam, FELPulses, Neutrons, IonBeam, 

113LiquidNitrogen, LiquidHelium, CompressedAir, CoolingWater, 

114ChilledWater, ElectricalPower, ProcessGas, Vacuum, ComputePool. 

115 

116`SupplyName` and `SupplyReason` STAY as VOs — `SupplyName` is a true 

117free-form display name (will never be an enum), and `SupplyReason` 

118is operator-supplied prose (matches `RunAbortReason` / 

119`RunStopReason` / `RunTruncateReason` precedent exactly). 

120"""

133class SupplyStatus(StrEnum): 

134 """The Supply's availability state. 

135 

136 Five values locked day one per [[project_supply_design]]: 

137 

138 - `Unknown` — registration-time default; no observation yet 

139 - `Available` — resource is up and meeting consumer needs 

140 - `Degraded` — resource is up but below nominal capacity / quality 

141 - `Unavailable` — resource is down (planned or unplanned) 

142 - `Recovering` — resource was Unavailable; observation suggests 

143 it may be coming back; operator must `restore_supply` 

144 to confirm `Recovering -> Available` 

145 

146 Initial `Unknown` is universal industrial + cloud-native consensus 

147 (Tango UNKNOWN, EPICS UDF, Azure Resource Health Unknown, k8s 

148 Pending, Prometheus `up{}` UNKNOWN-before-first-scrape). The 

149 optimistic-Available default is an anti-pattern. 

150 """ 

151 

152 UNKNOWN = "Unknown" 

153 AVAILABLE = "Available" 

154 DEGRADED = "Degraded" 

155 UNAVAILABLE = "Unavailable" 

156 RECOVERING = "Recovering"

161 

162 Three values per APS LMA18-3 LN2 distribution layering and 

163 NeXus NXsource one-source-per-storage-ring precedent: 

164

171 beamline-local vacuum subsystem, beamline-local compute)

174 additive when triggers fire.

418@dataclass(frozen=True) 

419class Supply: 

420 """Aggregate root: a continuously-available resource. 

421 

422 Slim aggregate per [[project_fold_cost_principles]]: identity + 

423 typed address + status + registered_at. Per-transition audit 

424 metadata (timestamps, reasons, triggers) lives in the event 

425 stream itself; the projection denormalizes the latest values for 

426 query-time access. 

427 

428 `id` is the stable opaque handle. `(scope, kind, name)` is the 

429 operator-readable address; the projection enforces cross-stream 

430 uniqueness via UNIQUE INDEX (the aggregate cannot enforce cross- 

431 stream invariants without DCB). 

432 

433 `status` defaults to `SupplyStatus.UNKNOWN`: the registration- 

434 time initial state per universal precedent. The genesis event 

435 `SupplyRegistered` carries no status field; the evolver sets 

436 `UNKNOWN` from the event type (same convention as 

437 `SubjectRegistered -> Received`). 

438 

439 Future additive facets (per Watch items in 

440 [[project_supply_design]]): `bound_asset_id` (physical-equipment 

441 binding, mirrors 4f Subject pattern), `health` (orthogonal 

442 facet, mirrors 5g-b Asset.condition), `auto_clear_after` (per- 

443 kind timer for auto-restore), `capacity` (when first consumer 

444 needs quantity tracking). All land with safe defaults so pre- 

445 extension streams fold cleanly via the additive-state pattern. 

446 """ 

447 

448 id: UUID 

449 scope: SupplyScope 

450 kind: str 

451 name: SupplyName 

452 status: SupplyStatus = SupplyStatus.UNKNOWN
