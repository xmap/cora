1"""AssetLookup port: cross-aggregate query for Equipment BC's Asset projection. 

2 

3Used by cross-BC consumers that hold an `AssetId` from the wire and 

4need to validate the Asset exists (and optionally inspect its tier 

5or lifecycle) before committing a command. First consumer is the 

6Supply BC's `register_supply` handler (Session 5 Slice 7B): it 

7resolves `command.containing_asset_id` to an `AssetLookupResult` at 

8the handler port edge and threads the result into the decider as 

9`asset_lookup_result`. Future Slice 8 consumers (Asset.facility_id 

10back-binding) and potential Safety / Caution BC consumers will 

11also consume this port. 

12 

13## Convention 

14 

15This is a cross-aggregate port (Equipment BC ships the production 

16adapter `PostgresAssetLookup` reading `proj_equipment_asset_summary`; 

17multiple BC handlers consume it). Lives in 

18`cora.infrastructure.ports` per the existing pattern (`Authorize`, 

19`ClearanceLookup`, `CautionLookup`, `SupplyLookup`, `SecretStore`, 

20`CredentialLookup`, `FacilityLookup`). 

21 

22The port is shaped around the CONSUMER's need: cross-BC binding sites 

23need "does this Asset exist and what's its identity + tier + lifecycle" 

24to validate before commit. The decommissioned-Asset binding question 

25is decided per-consumer at the decider boundary (slice 7B Supply 

26follows the slice 6A FacilityLookup precedent: bind anyway, the 

27operator chose to keep the lineage visible). 

28 

29## Modern DDD alignment 

30 

31Per Khononov / Cockburn / Herberto Graca: cross-aggregate integration 

32at command time should go through a port that the consumer shapes, 

33with the implementor providing the adapter. The replicated read 

34model (`proj_equipment_asset_summary`) is the modern recommendation 

35over synchronous replay of the Asset aggregate, because the 

36projection is already a denormalized cross-stream view + already 

37covers the hierarchy + lifecycle FSM. 

38 

39## No BC imports in the port 

40 

41`tier` and `lifecycle` are typed as `str` (not Equipment BC's 

42`AssetTier` / `AssetLifecycle` StrEnums) so this port stays inside 

43`cora.infrastructure`'s `depends_on = []` tach contract. The values 

44match the StrEnum string values; consumer deciders partition by 

45literal comparison (`tier == "Unit"`, `lifecycle == "Active"`) and 

46cast to typed enums at their boundary if they need the discipline. 

47 

48`id` is typed `UUID` (Equipment BC's Asset.id is bare UUID, not a 

49NewType, so no cross-BC NewType to thread). Consumers that care 

50about the typed identity wrap at their BC boundary. 

51"""

57ANCESTOR_WALK_DEPTH_CAP = 50 

58"""Maximum `parent_id` chain depth `ancestors_of` walks before failing. 

59 

60Belt-and-braces against a runaway walk; the load-bearing cycle 

61terminator is the adapter mechanism (Postgres `CYCLE` clause / the 

62in-memory visited-set), this cap is the secondary ceiling. Set well 

63above any legitimate Equipment containment tree (today's 2-BM tree is 

642 deep: Device -> Unit; even a future Device -> hutch -> Unit -> 

65sub-facility nesting stays in single digits). A walk that exceeds 50 

66levels is a cycle or data corruption, not a real tree, and raises 

67`AncestorWalkDepthExceededError`. Defined here (the walk contract's 

68home) and imported by exactly the two `AssetLookup` adapters; an arch 

69fitness test pins that single-definition-site discipline. 

70"""

73@dataclass(frozen=True) 

74class AssetLookupResult: 

75 """Summary row from `proj_equipment_asset_summary` for cross-aggregate checks. 

76 

77 Carries the minimal columns cross-BC consumers need to validate 

78 cross-aggregate invariants before commit. Loaded by the handler 

79 via `AssetLookup.lookup` and handed to the decider in the slice's 

80 context object (mirrors `FacilityLookupResult` shape). 

81 

82 `tier` and `lifecycle` are the StrEnum values as plain strings 

83 (matches the projection's `TEXT` columns); the consumer decider 

84 partitions on the literals it cares about. 

85 

86 `name` is the operator-readable display name (1-200 chars per 

87 `AssetName` VO); useful for surfacing in cross-BC error messages 

88 that name the Asset operators recognize rather than a bare UUID. 

89 

90 `family_affordances` is the union of the closed-enum Affordance 

91 value strings across every Family the Asset belongs to. Typed 

92 `frozenset[str]` (not `frozenset[Affordance]`) so this port stays 

93 inside `cora.infrastructure`'s `depends_on = []` tach contract, 

94 free of any Equipment BC import; consumer deciders compare against 

95 literal value strings (for example `"Capturing" in family_affordances`) 

96 and cast to the typed enum at their boundary if they need the 

97 discipline. Empty when the Asset belongs to no Family or none of 

98 its Families declare any affordance. The Data BC `record_acquisition` 

99 decider gates on `"Capturing"` membership; future cross-BC 

100 affordance-gated consumers read the same set. 

101 

102 `located_in_enclosure_id` is the bare opaque pointer to the 

103 Enclosure (the operational access-gated volume) the Asset is 

104 located in, carried on the snapshot so the enclosure pre-flight 

105 gate can read each ancestor's operational enclosure-zone in one hop 

106 (the gate walks the Asset ancestor closure via `ancestors_of` and 

107 inspects this field per row, never traversing into the Enclosure 

108 BC). `None` when the Asset declared no enclosure at registration. 

109 Typed `UUID | None` (not an Enclosure BC type) so this port stays 

110 inside `cora.infrastructure`'s `depends_on = []` tach contract. 

111 

112 Snapshot columns whose purpose is a one-hop read (for example 

113 `controller_id`, `fixture_id`, `facility_code`, 

114 `located_in_enclosure_id`) can be added additively as cross-BC 

115 consumers need them; the slice 6A 

116 `FacilityLookupResult.trust_anchor_credential_ids` extension is 

117 the precedent. Walk-axis fields go behind walk methods: a field 

118 whose purpose is to TRAVERSE a chain (notably `parent_id`) does 

119 NOT belong on this snapshot row. Parent-chain traversal is the 

120 `ancestors_of` method's job, which reads `parent_id` internally 

121 and returns these same snapshot rows, never exposing the 

122 traversal axis as a result field. 

123 """

126 name: str

133class AncestorWalkDepthExceededError(Exception): 

134 """`ancestors_of` hit a parent_id cycle or exceeded the depth cap. 

135 

136 Raised by every `AssetLookup` adapter's `ancestors_of` when the 

137 parent_id walk either revisits an Asset (a cycle such as A -> B -> 

138 A) or descends past `ANCESTOR_WALK_DEPTH_CAP` levels without 

139 reaching a root. The adapters NEVER truncate-and-return a partial 

140 closure: a partial ancestor set would silently under-scope the 

141 enclosure pre-flight gate (admitting a Run that an unreached 

142 ancestor's Enclosure should refuse), so the walk fails loud 

143 instead. 

144 

145 The message names BOTH the observed depth and the cap so an 

146 operator can distinguish a legitimate-but-deep tree (raise the 

147 cap) from a genuine cycle (fix the parent_id). Cycle detection is 

148 defense-in-depth: the Asset write side does not yet enforce 

149 acyclicity, so the read-time walk must protect itself. 

150 """ 

151 

152 def __init__(self, *, observed_depth: int, cap: int) -> None: 

153 super().__init__( 

154 f"ancestors_of walk exceeded the depth cap (observed_depth=" 

155 f"{observed_depth}, cap={cap}): a parent_id cycle or a tree " 

156 f"deeper than the cap. Fix the cycle, or raise " 

157 f"ANCESTOR_WALK_DEPTH_CAP if the depth is legitimate." 

158 ) 

159 self.observed_depth = observed_depth 

160 self.cap = cap

163class AssetLookup(Protocol): 

164 """Cross-aggregate port: query Equipment's Asset projection by id."""

166 async def lookup(self, asset_id: UUID) -> AssetLookupResult | None: 

167 """Return the projection row for `asset_id`, or None if not found. 

168 

169 Returning None signals "no Asset with that id is visible in 

170 the projection". Callers (`register_supply` containing-Asset 

171 validation today; future Slice 8 Asset.facility_id binding, 

172 future Safety / Caution BC consumers) translate None to the 

173 appropriate domain error at the decider boundary. 

174 

175 Assets in EVERY lifecycle are returned (Commissioned, Active, 

176 Maintenance, Decommissioned); the decider partitions on 

177 `lifecycle` if it needs to distinguish "no Asset at all" from 

178 "Asset exists but Decommissioned". The slice 6A FacilityLookup 

179 precedent is to bind anyway and let the operator keep the 

180 lineage visible. 

181 """

184 async def ancestors_of(self, asset_ids: frozenset[UUID]) -> frozenset[AssetLookupResult]: 

185 """Return the ancestor closure of `asset_ids` (inclusive). 

186 

187 Walks each Asset's `parent_id` chain upward and returns the 

188 union of the input Assets plus every ancestor, as 

189 `AssetLookupResult` rows (the same snapshot shape `lookup` 

190 returns, so consumers partition on `lifecycle` the same way). 

191 The input ids are included in the result; an input id with no 

192 projection row contributes nothing (no row exists to walk 

193 from). 

194 

195 Termination: the walk stops at any Asset whose `parent_id IS 

196 NULL` (a facility-rooted root Asset, the post-AssetLevel- 

197 collapse anchoring where a root binds `facility_code` and has 

198 no Asset parent) and NEVER reads the Federation `Facility` 

199 aggregate. The two structural-scope axes (Equipment 

200 `Asset.parent_id`, Federation `Facility.parent_id`) are joined 

201 by `Asset.facility_code`, never traversed together here. 

202 

203 Cycle / runaway defense: a `parent_id` cycle (A -> B -> A) or 

204 a chain deeper than `ANCESTOR_WALK_DEPTH_CAP` raises 

205 `AncestorWalkDepthExceededError` rather than looping or 

206 silently truncating the closure. Empty input returns the 

207 empty frozenset without touching any store. 

208 

209 The signature is flat positional by design: no keyword-only 

210 filter / depth / edge-type parameters. A federation-spanning 

211 walk that crosses into the Facility axis is a SEPARATE sibling 

212 method (`ancestors_of_across_facilities`), not a parameter 

213 here; the down-chain mirror is a separate `descendants_of` 

214 method, each landing only when its own consumer trigger fires. 

215 """
