1"""Commands a principal an operator switched off may still issue. 

2 

3Sibling of `cora.shared.consequence`: a BC-agnostic set of command names 

4that a gate consults, living in `shared` because the names it holds 

5belong to Operation, Run, and Trust while the gate that reads it lives 

6in Trust. 

7 

8## The question this set answers, which is not the one it was first copied from 

9 

10An earlier version of this set was lifted verbatim from the 

11human-envelope design's closing-and-recording and brake lists. Those 

12lists were written for a WINDOW conjunct, where a twelve-hour scan 

13crosses a beamtime boundary and the principal is entirely legitimate; 

14the clock moved, not the person. Liveness is a different question: an 

15operator deliberately reached for a switch and turned this principal 

16off. 

17 

18The two answers diverge, and `resume_procedure` is where. Letting a 

19scientist resume across a window boundary is obviously right. Letting 

20someone an operator just switched off resume a held Procedure is 

21obviously wrong, because a resumed Procedure walks real setpoints, so 

22the exemption would have handed a revoked principal the power to 

23restart beam motion. That is the inverse of a brake. It was in the 

24inherited list and it is not here. 

25 

26So the set is derived from one question, asked directly: 

27 

28> What may a principal an operator deliberately switched off still do? 

29 

30Two answers, and nothing else: 

31 

32 1. STOP work that is already running. Refusing a brake means an 

33 operator who switches someone off has, in the same act, taken away 

34 that person's ability to halt what they started. The eligible set 

35 for moving the system toward safety must be strictly WIDER than for 

36 routine work, never narrower. 

37 

38 2. RECORD what already happened. The photons already hit the detector. 

39 Refusing the append does not un-run the scan, it only makes CORA's 

40 record wrong, and a wrong record is the one failure a system of 

41 record cannot absorb. Refusing `complete_procedure` additionally 

42 strands the Procedure in Running with its own abort denied by the 

43 same conjunct. 

44 

45Deliberately NOT here, having been considered: 

46 

47 - Anything that STARTS or RESTARTS work, `resume_procedure` included. 

48 - `AbortVisit`, `HoldCampaign`: terminal or organizational, not the 

49 halting of physical work in progress. Their siblings `CancelVisit` 

50 and `CompleteVisit` are not exempt either, and an exemption that 

51 covers one of a family and not the rest reads as an oversight. 

52 

53## Scope limit: no target scoping, and that is deliberate 

54 

55Membership is by COMMAND NAME. A switched-off principal still in a 

56Policy's permitted set may brake or append against ANY Run or Procedure, 

57not only their own. A security review flagged this; the decision is to 

58accept it here and fix the real cause elsewhere, for four reasons. 

59 

60**The gap is Policy's, not this set's.** `Policy` carries 

61`permitted_principal_ids` and `permitted_commands`, both flat, and no 

62target dimension whatsoever. An ACTIVE principal permitted `AbortRun` can 

63already abort any run at the facility. This set inherits that absence; it 

64does not create it, and it grants a switched-off principal nothing they 

65did not have a moment earlier. 

66 

67**Scoping only the switched-off would invent a narrowing that exists for 

68nobody.** What instrument does a facility issue that binds a scientist's 

69brake to their own scans? None. Authoring one here would make a withdrawn 

70principal MORE constrained than a permitted one on the identical command, 

71which is a new asymmetry in the opposite direction rather than a fix for 

72the old one. 

73 

74**The design rule points the other way for brakes.** For commands that 

75move the system toward a safer state the eligible set must be strictly 

76WIDER than for routine work, never narrower. Someone hitting the brake on 

77a runaway scan is the system working, whatever an operator has since done 

78to their account. 

79 

80**The sharpest edge is already blunted.** `StopRun` is the sole member of 

81`COMMANDS_REQUIRING_RATIFICATION`, so the most consequential brake needs a 

82second principal regardless. And since `ActorDeactivated` began cascading 

83into `authority_revocation_holder`, a switched-off principal's OWN runs 

84are held the moment they are withdrawn, so the residual reach is over 

85other people's work only. 

86 

87What stays uncomfortable, honestly: a principal an operator withdrew is 

88likelier to be acting badly than one who was not, so preserving their 

89reach is worse than preserving anyone else's, even though the reach is 

90identical. That argues for giving Policy a target dimension, which would 

91bind every principal at once. It does not argue for a partial fix wired 

92through the liveness door. 

93 

94HAND-MAINTAINED, DELIBERATELY TEMPORARY. When the OperationClass map 

95lands this becomes derived (every Halt-class and Record-class command) 

96and stops being something a new slice can forget to join. 

97""" 

98 

99from typing import Final 

100 

101# Stops work already in progress. See the module docstring for why the 

102# eligible set here must be wider than for routine commands. 

103_BRAKE: Final[frozenset[str]] = frozenset( 

104 { 

105 "StopRun", 

106 "HoldRun", 

107 "AbortRun", 

108 "TruncateRun", 

109 "HoldProcedure", 

110 "AbortProcedure", 

111 "TruncateProcedure", 

112 "HoldVisit", 

113 } 

114) 

115 

116# States what already happened. Refusing these corrupts the record 

117# rather than preventing anything. 

118_RECORDING: Final[frozenset[str]] = frozenset( 

119 { 

120 "CompleteRun", 

121 "CompleteProcedure", 

122 "EndProcedureIteration", 

123 "AppendProcedureActivities", 

124 "AppendProcedureOutcomes", 

125 "AppendProcedureDiagnostics", 

126 "AppendObservations", 

127 } 

128) 

129 

130LIVENESS_EXEMPT_COMMANDS: Final[frozenset[str]] = _BRAKE | _RECORDING 

131 

132 

133def is_liveness_exempt(command_name: str) -> bool: 

134 """True if liveness may never refuse `command_name`.""" 

135 return command_name in LIVENESS_EXEMPT_COMMANDS 

136 

137 

138__all__ = ["LIVENESS_EXEMPT_COMMANDS", "is_liveness_exempt"]
