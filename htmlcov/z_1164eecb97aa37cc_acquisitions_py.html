1"""Substrate-neutral data-acquisition action bodies for the Conductor. 

2 

3The four primitives `collect` / `discrete` / `continuous` / `stream` 

4register as named `ActionBody` callables in the `InMemoryActionRegistry` 

5the `Conductor` consumes. `collect` is the single-detector capture cycle; 

6`discrete` walks a trajectory of axis points and runs a `collect` cycle 

7at each; `continuous` drives the axis from `start` to `stop` while the 

8detector receives external trigger pulses fired by an emitter during 

9motion; `stream` records a DAQ-owned high-rate frame stream to an 

10external file, terminal on a frame count or a wall-clock duration (the 

11event-stream acquisition axis, for XPCS and XFEL per-shot DAQ). 

12 

13See `project_scan_primitives_design` for the design lock and 

14`project_scan_primitives_research` for the corpus that backs the 

15substrate-neutral parameter shapes. 

16 

17## v1 contract: areaDetector ADCore PV convention 

18 

19`collect` integrates with areaDetector's ADCore PV layout. `params.detector` 

20is the areaDetector root prefix (e.g., `"2bma:cam1"`); the body writes 

21to sibling PVs: 

22 

23 - `{detector}:TriggerMode` <- mapped from `trigger_mode` 

24 - `{detector}:AcquireTime` <- `dwell` (seconds) 

25 - `{detector}:ImageMode` <- `"Multiple"`, unconditionally 

26 - `{detector}:NumImages` <- `repetitions` 

27 - `{detector}:Acquire` <- `1` to start 

28 - `{detector}:Acquire_RBV` -> polled until Done 

29 - `{detector}:DetectorState_RBV` -> read once for final-state evidence 

30 

31`ImageMode` is written explicitly rather than inherited from whatever 

32state the camera was last left in: areaDetector's `NumImages` only 

33takes effect under `Multiple` (or is irrelevant under `Single`), and 

34under `Continuous` the detector free-runs and `Acquire_RBV` never 

35returns to Done, so a body that waits for completion must never let 

36`Continuous` stand. `repetitions=None` ("free run") is refused before 

37any PV write (`UnboundedAcquisitionError`) rather than translated to 

38an `ImageMode` this body would then wait on forever; see 

39`_arm_bounded_repetitions`. 

40 

41Trigger-mode value mapping translates the substrate-neutral primitive 

42vocabulary into detector-driver-coded strings via `_TRIGGER_MODE_VALUES`, 

43keyed by `ctx.trigger_dialect` (a DEPLOYMENT fact, `Settings.detector_trigger_dialect`, 

44not a recipe fact): `ExternalEdge` and `ExternalLevel` always collapse to 

45one External value; edge polarity vs level is carried on the trigger 

46EMITTER (PandABox PCOMP, Aerotech PSO, etc.), not the detector. The 

47`ADCore` dialect writes `"Internal"`/`"External"`; the `ADSpinnaker` 

48dialect (APS 2-BM's FLIR camera) writes the INVERTED `"Off"`/`"On"` -- 

49see `_TRIGGER_MODE_VALUES`'s docstring for why. Non-AD detectors will 

50land as their own action bodies; promote a shared shape when 3 detector 

51families exist (rule-of-three). 

52 

53## `Acquire_RBV` is read by index, not by the word "Done" 

54 

55A real areaDetector `Acquire_RBV` is a `bi` record (DBR_ENUM), so it 

56arrives as `kind="Categorical"` carrying a facility/build-authored 

57label, with the index it resolved from on `Measurement.ordinal`. 

58`"Done"` is ADCore's default `ZNAM`, nothing more: a relabelled record, 

59or a build whose defaults differ, produces a value the poll cannot 

60recognise, and the loop then waits forever on a detector that already 

61finished. This is the fourth instance of a defect family fixed three 

62times already this month (the hutch permit, the BLEPS interlock flags, 

63the beam-availability gate): `_acquisition_finished` reads 

64`Measurement.ordinal` via `cora.shared.binary_signal.binary_code`, the 

65same decoder those three use, and treats the conventional label set as 

66the fallback for a reading with no index. 

67 

68The floor is `cora.shared.quality.believable`, not `actionable`, and 

69picking the strict one would recreate the same failure at one remove: a 

70detector carrying a standing `Uncertain` alarm for a reason unrelated to 

71whether it finished (a temperature warning, a nearly-full file-writer 

72disk) would then never be readable as Done, so every acquisition on it 

73would hang instead of finish. An alarm on `Acquire_RBV` says nothing 

74about whether the acquisition is over; only `Bad` (the value itself is 

75untrustworthy) may withhold a conclusion. 

76 

77An unreadable `Acquire_RBV` (unbelievable quality, or a value 

78`binary_code` cannot resolve) does not conclude "still running": it logs 

79once per continuous stretch of unreadability and keeps polling. Silently 

80treating it as "not yet Done" would look identical to a slow detector 

81until someone reads the log, which is the whole point: the wait staying 

82unbounded is a stated v1 choice (see `_POLL_INTERVAL_S`), so the fix 

83here is to stop that choice from making an ordinary label mismatch 

84silent, not to bound the wait. 

85 

86## v1 detector-side / emitter-side split 

87 

88`collect` writes ONLY the detector-side trigger PVs. The `polarity` and 

89`source` fields are validated by Pydantic and recorded in the returned 

90evidence mapping, but they are NOT written to PVs by `collect`. The 

91trigger EMITTER (the device named by `source`) is configured by the 

92caller via setpoint steps that precede the action step in the Procedure, 

93or by a future Capability template that expands trigger configuration 

94into the step list. This split keeps the primitive substrate-neutral on 

95the emitter side, where addressing conventions vary by hardware (PCOMP 

96PV layout differs from PSO PV layout differs from software clock). 

97Revisit at first PandABox-or-Aerotech integration. 

98 

99Because that split leaves the emitter unconfigured by this body, `source` 

100and `polarity` sit in the evidence under `requested_not_applied`, not 

101alongside the values `collect` / `continuous` actually wrote: a reader 

102scanning the top-level evidence keys must not conclude CORA armed the 

103trigger path just because these fields are present. `requested_not_applied` 

104answers "what did the caller ask for on the emitter side" while 

105`detector_settings` (below) answers "what did CORA actually change". 

106 

107## External triggering is refused, not attempted 

108 

109`ExternalEdge` / `ExternalLevel` raise `UnwiredExternalTriggerError` 

110before any PV write, in both `_run_collect_cycle` and `continuous`. This 

111is the same hang shape `UnboundedAcquisitionError` guards against: the 

112emitter split above means CORA never configures the device named by 

113`source`, so setting the detector's `TriggerMode` to `External` and then 

114polling `Acquire_RBV` would wait forever for pulses nothing arranged. 

115`CollectParams` keeps validating all three `trigger_mode` values (a 

116recipe may still declare intent), but only `Internal` reaches a PV 

117write at v1. Revisit once an emitter-configuring step type exists and a 

118deployment actually wires one end to end. 

119 

120## Prior values are read before every configuration write 

121 

122`_run_collect_cycle` and `continuous` read each configuration PV 

123(`TriggerMode`, `AcquireTime`, `ImageMode`, `NumImages`) immediately 

124before writing it, and record both values together under 

125`detector_settings[<PV suffix>] = {"prior": ..., "applied": ...}`. This 

126is what lets the record say what CORA changed rather than only what it 

127set: a PV CORA left untouched in practice (the applied value happens to 

128match what was already there) is indistinguishable from an unread one 

129unless the prior value is captured too. A `Control*Error` on one of 

130these reads propagates unchanged, exactly like the write it precedes; 

131it is not treated differently just because it is a read for evidence 

132rather than a read the body's control flow depends on. 

133"""

161 "ADCore": { 

162 "Internal": "Internal", 

163 "ExternalEdge": "External", 

164 "ExternalLevel": "External",

172"""Substrate-neutral trigger_mode value -> detector-driver TriggerMode string, per dialect. 

173 

174The dialect is a DEPLOYMENT fact (which camera driver is installed), not 

175a recipe fact ("free-running" is true everywhere; "this camera is a 

176FLIR" is true only of this building), so it rides `ActionContext.trigger_dialect` 

177(sourced from `Settings.detector_trigger_dialect`), never a `CollectParams` field. 

178 

179`ADCore` is the plain areaDetector convention: `Internal` stays 

180`"Internal"`, both External modes collapse to `"External"` (edge vs 

181level is carried at the trigger emitter, not the detector). 

182 

183`ADSpinnaker` (the FLIR driver at APS 2-BM) is INVERTED relative to 

184what a reader would guess: `Internal` maps to `"Off"` and both External 

185modes map to `"On"`. This is not a naming quirk to normalise away. 

186ADSpinnaker's `TriggerMode` PV does not ask "is the trigger internal or 

187external"; it asks "is EXTERNAL triggering enabled". CORA's `Internal` 

188(free-running, camera's own clock) is the state where external 

189triggering is disabled, hence `Off`. A future reader who assumes 

190`Internal -> On` "because On sounds like the trigger is active" has it 

191exactly backwards. Confirmed live against `2bmSP1:cam1:TriggerMode` 

192(a two-choice DBF_ENUM, `[0] Off` / `[1] On`, no `"Internal"` string in 

193the set at all) and against the deployed `tomoscan_2bm.py`, which 

194writes `CamTriggerMode='Off'` for its own internal-trigger path. 

195"""

198def _resolve_trigger_mode_value(dialect: str, trigger_mode: str) -> str: 

199 """Look up the detector-driver string for `trigger_mode` under `dialect`. 

200 

201 Raises `UnknownTriggerDialectError` naming the offending dialect and 

202 the known ones, rather than letting an unrecognised 

203 `ctx.trigger_dialect` surface as a bare `KeyError` deep inside a 

204 write call. A wrong dialect must fail loudly: silently falling back 

205 to `ADCore` would write a string the real camera's enum does not 

206 accept, or worse, one it accepts with the inverted meaning. 

207 """ 

208 table = _TRIGGER_MODE_VALUES.get(dialect) 

209 if table is None: 

210 raise UnknownTriggerDialectError(dialect, sorted(_TRIGGER_MODE_VALUES)) 

211 return table[trigger_mode]

214_IMAGE_MODE_MULTIPLE = "Multiple" 

215"""The only `ImageMode` value CORA's v1 acquisition bodies write. 

216 

217Unlike `TriggerMode`, `ImageMode` is NOT routed through 

218`_TRIGGER_MODE_VALUES` / `ctx.trigger_dialect`: its three choices 

219(`Single` / `Multiple` / `Continuous`) are the plain ADCore enum and 

220are identical on ADSpinnaker (confirmed live against 

221`2bmSP1:cam1:ImageMode`), so it needs no per-dialect value table. Do 

222not add one. `Single` is unused at v1 because every write site here 

223counts frames via `NumImages`, which only takes effect under 

224`Multiple`; `Continuous` is never written because it never asserts 

225`Acquire_RBV` Done on its own, and both `collect` and `continuous` 

226wait for Done unconditionally. 

227"""

230def _refuse_unwired_external_trigger(detector: str, trigger_mode: str) -> None: 

231 """Raise `UnwiredExternalTriggerError` for any `trigger_mode` other than `Internal`. 

232 

233 Called first, before any PV write, in both `_run_collect_cycle` and 

234 `continuous`. See the module docstring's "External triggering is 

235 refused, not attempted" section for why: the emitter split leaves 

236 `source` unconfigured by this body, so arming the detector for

244async def _write_recording_prior(ctx: ActionContext, address: str, value: Any) -> Mapping[str, Any]: 

245 """Read `address`'s current value, write `value`, and return `{"prior", "applied"}`. 

246 

247 The read-then-write ordering is deliberate: `prior` must be what the 

248 PV held immediately before this body changed it, not some earlier or 

249 later observation. A `Control*Error` from either the read or the 

250 write propagates unchanged; this helper does not catch anything, so 

251 a failed prior-read fails the action exactly like a failed write 

252 always has. 

253 """ 

254 prior = await ctx.control_port.read(address) 

255 await ctx.control_port.write(address, value) 

256 return {"prior": prior.value, "applied": value}

259async def _arm_bounded_repetitions( 

260 ctx: ActionContext, detector: str, repetitions: int | None 

261) -> Mapping[str, Mapping[str, Any]]: 

262 """Write `ImageMode=Multiple` + `NumImages=repetitions`, refusing an unbounded request. 

263 

264 Shared by `_run_collect_cycle` and `continuous`, both of which wait 

265 on `_await_acquire_done` with no internal timeout. `repetitions=None` 

266 used to mean "free run" and wrote `NumImages=0` while leaving 

267 `ImageMode` at whatever the camera was last set to; at APS 2-BM that 

268 is `Continuous`, under which `Acquire_RBV` never returns to Done, so 

269 the poll loop hangs forever against real hardware and the camera is 

270 left acquiring. Raising here, before either write, keeps a caller 

271 who wants free-running acquisition from partially arming a camera 

272 this action body can then never bring back down. 

273 

274 Returns the `detector_settings` fragment for `ImageMode` and 

275 `NumImages` (prior value read immediately before each write, 

276 alongside the applied value); the caller merges it into its own 

277 fragment for `TriggerMode` / `AcquireTime`. 

278 """ 

279 if repetitions is None: 

280 raise UnboundedAcquisitionError(detector) 

281 image_mode = await _write_recording_prior(ctx, f"{detector}:ImageMode", _IMAGE_MODE_MULTIPLE) 

282 num_images = await _write_recording_prior(ctx, f"{detector}:NumImages", repetitions) 

283 return {"ImageMode": image_mode, "NumImages": num_images}

287"""Poll period between Acquire_RBV reads inside `collect`'s done-loop. 

288 

28950ms balances responsiveness against unnecessary CA / PVA traffic for 

290the typical sub-second to multi-second acquisition durations. The body 

291relies on caller-side cancellation (Procedure abort) for hard timeout; 

292no internal bound is enforced at v1."""

295def _acquisition_finished(reading: Measurement) -> bool | None: 

296 """Has `Acquire_RBV` reached its de-asserted (Done) state? 

297 

298 `None` when the reading cannot settle the question at all: either 

299 the quality floor (`believable`, `Bad` only disqualifies) rejects it, 

300 or `binary_code` cannot resolve `reading.value` / `reading.ordinal` 

301 to 0 or 1. `None` is deliberately distinct from `False` -- "cannot 

302 tell" must never be folded into "still running", because the two 

303 poll loops that call this one treat only `True` as a reason to stop 

304 and treat both `False` and `None` identically (keep polling), so 

305 collapsing them here would cost the caller the ability to log the 

306 difference. 

307 

308 `code == 0` is Done because `Acquire_RBV` is a `bi` record and 0 is 

309 always a `bi`'s de-asserted / false state by construction; see the 

310 module docstring's "`Acquire_RBV` is read by index" section for why 

311 the label itself (`"Done"`, `ZNAM`'s ADCore default) is not trusted. 

312 """ 

313 if not believable(reading.quality): 

314 return None 

315 code = binary_code(reading.value, ordinal=reading.ordinal) 

316 return None if code is None else code == 0

319async def _await_acquire_done(ctx: ActionContext, detector: str) -> None: 

320 """Poll `{detector}:Acquire_RBV` until Done. 

321 

322 Shared by `_run_collect_cycle` and `continuous`: both used to carry 

323 their own copy of this loop, which is how the same undecoded-label 

324 bug ended up needing to be found and fixed twice. `_acquisition_finished` 

325 decides; this function owns only the polling cadence and a log line 

326 for a continuous unreadable stretch, emitted once on entry and once 

327 on exit rather than every 50ms. 

328 

329 An unreadable reading (`_acquisition_finished` returns `None`) is 

330 treated exactly like "not yet Done": the loop keeps polling. The wait 

331 staying unbounded either way is the documented v1 choice at 

332 `_POLL_INTERVAL_S`; what changes here is that the caller can now SEE 

333 the difference between a slow detector and a detector CORA cannot 

334 read, instead of both looking like silence. 

335 """ 

336 reported_unreadable = False 

337 while True: 

338 reading = await ctx.control_port.read(f"{detector}:Acquire_RBV") 

339 finished = _acquisition_finished(reading) 

340 if finished is None: 

341 if not reported_unreadable: 

342 reported_unreadable = True 

343 _log.warning( 

344 "acquisitions.acquire_rbv_unreadable", 

345 detector=detector, 

346 value=repr(reading.value), 

347 kind=reading.kind, 

348 ordinal=reading.ordinal, 

349 quality=reading.quality, 

350 detail=( 

351 "Acquire_RBV not resolvable to Done/Acquiring " 

352 "(unbelievable quality, or an unconventional label " 

353 "with no ordinal); polling continues" 

354 ), 

355 ) 

356 elif reported_unreadable: 

357 reported_unreadable = False 

358 _log.info("acquisitions.acquire_rbv_restored", detector=detector) 

359 if finished: 

360 break 

361 await asyncio.sleep(_POLL_INTERVAL_S)

364def _stream_count_reached(reading: Measurement, target: int) -> bool | None: 

365 """Has `NumCaptured_RBV` reached `target`? `None` when it cannot be told. 

366 

367 `NumCaptured_RBV` is a plain numeric readback (AD `longin`), not an 

368 enum, so there is no label/ordinal question here: the only way this 

369 reading can fail to answer is an unbelievable quality 

370 (`cora.shared.quality.believable`, `Bad` only) or a value that is not 

371 actually numeric. Either way `None`, not `False`: before this guard 

372 existed, a `Bad`-quality reading whose stale value happened to compare 

373 `>= target` would end the stream on a count CORA never actually 

374 confirmed, and a non-numeric value would raise `TypeError` -- not one 

375 of the Conductor's closed `_CONTROL_ERRORS`, so it would escape the 

376 Conductor uncaught rather than being recorded as a step failure. 

377 """ 

378 if not believable(reading.quality): 

379 return None 

380 if not isinstance(reading.value, (int, float)): 

381 return None 

382 return reading.value >= target

385class CollectParams(BaseModel): 

386 """Validated parameters for the `collect` action body. 

387 

388 Substrate-neutral field shape per [[project_scan_primitives_design]]. 

389 The `@model_validator` enforces the three conditional rules that the 

390 JSON-Schema subset cannot express today (per design memo Watch item 3): 

391 

392 - `polarity` is required iff `trigger_mode == "ExternalEdge"` 

393 - `source` is required when `trigger_mode != "Internal"` 

394 - `source` must be `None` when `trigger_mode == "Internal"` 

395 

396 `dwell` carries the canonical `unit: {system, code}` annotation per 

397 [[project_units_design]] (no `_seconds` suffix). `repetitions` has a 

398 `ge=1` floor; `0` collides with the AD `NumImages=0` continuous 

399 sentinel, so `None` is the schema's only way to express an unbounded 

400 request. The action bodies refuse that request at runtime rather 

401 than acting on it: `None` validates here, but `collect` and 

402 `continuous` both raise `UnboundedAcquisitionError` before writing 

403 any PV when they see it, because both wait unconditionally for the 

404 acquisition to finish and a free-running acquisition never does. 

405 See `_arm_bounded_repetitions`. 

406 """ 

407 

408 detector: str 

409 trigger_mode: Literal["Internal", "ExternalEdge", "ExternalLevel"] 

410 polarity: Literal["Rising", "Falling", "Either"] | None = None 

411 source: str | None = None 

412 repetitions: int | None = Field(default=None, ge=1) 

413 dwell: float = Field( 

414 ..., 

415 gt=0, 

416 json_schema_extra={"unit": {"system": "udunits", "code": "s"}}, 

417 ) 

418 

419 @model_validator(mode="after") 

420 def _check_trigger_constraints(self) -> CollectParams: 

421 if self.trigger_mode == "ExternalEdge" and self.polarity is None: 

422 raise ValueError("polarity required when trigger_mode == ExternalEdge") 

423 if self.trigger_mode != "Internal" and self.source is None: 

424 raise ValueError("source required when trigger_mode != Internal") 

425 if self.trigger_mode == "Internal" and self.source is not None: 

426 raise ValueError("source must be None when trigger_mode == Internal") 

427 return self

430async def _run_collect_cycle(ctx: ActionContext, params: CollectParams) -> Mapping[str, Any]: 

431 """One collect cycle: configure detector, arm, poll until Done, read state. 

432 

433 Shared helper used by the `collect` action body and the composing 

434 `discrete` / `continuous` bodies. Takes a validated `CollectParams` 

435 (or any subclass that exposes the same fields, e.g., `DiscreteParams` 

436 inherits all of them), so the callers don't re-validate or re-wrap 

437 `ActionContext` per cycle. 

438 Returns the same evidence Mapping the `collect` action body returns, 

439 so per-point composition stays uniform. 

440 

441 Raises `UnwiredExternalTriggerError` for any `trigger_mode` other 

442 than `Internal`, before any PV write: see the module docstring's 

443 "External triggering is refused, not attempted". `detector_settings` 

444 carries the prior and applied value for each of the four 

445 configuration PVs; `requested_not_applied` carries `polarity` / 

446 `source` under a key that says they were never written by this body. 

447 """ 

448 _refuse_unwired_external_trigger(params.detector, params.trigger_mode) 

449 started_at = ctx.clock.now() 

450 

451 detector_settings: dict[str, Mapping[str, Any]] = {} 

452 detector_settings["TriggerMode"] = await _write_recording_prior( 

453 ctx, 

454 f"{params.detector}:TriggerMode", 

455 _resolve_trigger_mode_value(ctx.trigger_dialect, params.trigger_mode), 

456 ) 

457 detector_settings["AcquireTime"] = await _write_recording_prior( 

458 ctx, f"{params.detector}:AcquireTime", params.dwell 

459 ) 

460 detector_settings.update( 

461 await _arm_bounded_repetitions(ctx, params.detector, params.repetitions) 

462 ) 

463 await ctx.control_port.write(f"{params.detector}:Acquire", 1) 

464 

465 await _await_acquire_done(ctx, params.detector) 

466 

467 stopped_at = ctx.clock.now() 

468 state_reading = await ctx.control_port.read(f"{params.detector}:DetectorState_RBV") 

469 

470 return { 

471 "started_at": started_at.isoformat(), 

472 "stopped_at": stopped_at.isoformat(), 

473 "repetitions_requested": params.repetitions, 

474 "trigger_mode": params.trigger_mode, 

475 "trigger_dialect": ctx.trigger_dialect, 

476 "image_mode": _IMAGE_MODE_MULTIPLE, 

477 "polarity": params.polarity, 

478 "source": params.source, 

479 "detector_state_final": state_reading.value, 

480 "detector_settings": detector_settings, 

481 "requested_not_applied": { 

482 "polarity": params.polarity, 

483 "source": params.source, 

484 }, 

485 }

488async def collect(ctx: ActionContext) -> Mapping[str, Any]: 

489 """Single-detector capture against areaDetector ADCore PV convention. 

490 

491 Writes TriggerMode / AcquireTime / ImageMode / NumImages, starts 

492 Acquire, polls Acquire_RBV until `0` / `"Done"`, reads 

493 DetectorState_RBV for the final-state evidence, returns a Mapping 

494 the Conductor records as the step entry's `result_data`. 

495 

496 `params.repetitions is None` raises `UnboundedAcquisitionError` 

497 before any PV write: this body waits for Acquire_RBV to reach Done 

498 unconditionally, and a free-running acquisition never reaches Done 

499 on its own, so an unbounded request combined with that wait would 

500 hang forever against real hardware. See `_arm_bounded_repetitions`. 

501 

502 `params.trigger_mode != "Internal"` raises `UnwiredExternalTriggerError` 

503 before any PV write, for the same reason: see the module docstring's 

504 "External triggering is refused, not attempted". 

505 

506 `Control*Error` raised by the underlying `ControlPort` propagates 

507 unchanged; the Conductor catches it at the action-dispatch site and 

508 records the step failure per its standard contract. 

509 

510 See module docstring for the AD-convention v1 contract, the 

511 detector-side / emitter-side split that leaves `polarity` and 

512 `source` as evidence-only fields under `requested_not_applied` (the 

513 trigger EMITTER is configured by caller-authored setpoint steps 

514 before this action step, when it is configured at all), and the

583class ContinuousParams(CollectParams): 

584 """Validated parameters for the `continuous` action body. 

585 

586 Extends `CollectParams` with the axis sweep definition (`axis` +

598 loop (detector waits for pulses that never arrive). `rate` is 

599 `gt=0` when present; the axis-dimensional `unit` declaration lives 

600 on the Capability template's outer `parameters_schema` (rate units 

601 vary by axis: deg/s for rotation, eV/s for energy, K/s for 

602 temperature, T/s for field). 

603

605 any axis-rate PV by the body. The substrate-specific rate PV 

606 convention (EPICS motor `.VELO`, ramp-controller setpoint, etc.) 

607 is the caller's responsibility via a `SetpointStep` before this 

608 action step, mirroring the polarity / source emitter-side split 

609 documented for `collect`. 

610 """

624async def continuous(ctx: ActionContext) -> Mapping[str, Any]: 

625 """Continuous-trajectory scan: arm detector, sweep axis, collect on triggers. 

626 

627 Fly-scan ordering: configure detector, move axis to `start` (blocking 

628 so motion completes before arm), arm detector (Acquire=1), start 

629 motion toward `stop` (non-blocking so the trigger emitter sees 

630 motion + arm overlap), then poll Acquire_RBV until the detector has 

631 consumed all expected trigger pulses. The trigger emitter (per 

632 `source`) fires `repetitions` pulses during the sweep, externally 

633 coordinated with the axis motion (Aerotech PSO, PandABox PCOMP, 

634 etc.). 

635 

636 Evidence shape carries the request (`axis_start_requested`, 

637 `axis_stop_requested`, `rate_requested`, `repetitions_requested`) 

638 plus the observed `axis_final_actual` for end-of-sweep verification, 

639 timestamps, trigger config, and the detector's final state. 

640 

641 `params.repetitions is None` raises `UnboundedAcquisitionError` 

642 before any PV write, same as `collect`: see 

643 `_arm_bounded_repetitions`. 

644 

645 `params.trigger_mode != "Internal"` raises `UnwiredExternalTriggerError` 

646 before any PV write, same as `collect`: see the module docstring's 

647 "External triggering is refused, not attempted". `detector_settings` 

648 carries the prior and applied value for each of the four 

649 configuration PVs; `requested_not_applied` carries `polarity` / 

650 `source` under a key that says they were never written by this body. 

651 

652 `Control*Error` from any read or write propagates unchanged; the 

653 Conductor records the failure per its standard contract. The 

654 detector is NOT explicitly stopped on the happy path; the 

655 NumImages=repetitions setting bounds it, so it self-terminates when 

656 all pulses have been consumed. Detector-side overrun handling 

657 (motion completes before pulses arrive) is deferred: surfaces as a 

658 poll-loop hang the caller cancels via Procedure abort. Revisit at 

659 first deployment that exercises the overrun edge. 

660 """ 

661 params = ContinuousParams.model_validate(ctx.params) 

662 _refuse_unwired_external_trigger(params.detector, params.trigger_mode) 

663 started_at = ctx.clock.now() 

664 

665 detector_settings: dict[str, Mapping[str, Any]] = {} 

666 detector_settings["TriggerMode"] = await _write_recording_prior( 

667 ctx, 

668 f"{params.detector}:TriggerMode", 

669 _resolve_trigger_mode_value(ctx.trigger_dialect, params.trigger_mode), 

670 ) 

671 detector_settings["AcquireTime"] = await _write_recording_prior( 

672 ctx, f"{params.detector}:AcquireTime", params.dwell 

673 ) 

674 detector_settings.update( 

675 await _arm_bounded_repetitions(ctx, params.detector, params.repetitions) 

676 ) 

677 

678 await ctx.control_port.write(params.axis, params.start, wait=True) 

679 await ctx.control_port.write(f"{params.detector}:Acquire", 1) 

680 await ctx.control_port.write(params.axis, params.stop, wait=False) 

681 

682 await _await_acquire_done(ctx, params.detector) 

683 

684 stopped_at = ctx.clock.now() 

685 state_reading = await ctx.control_port.read(f"{params.detector}:DetectorState_RBV") 

686 axis_final = await ctx.control_port.read(params.axis) 

687 

688 return { 

689 "started_at": started_at.isoformat(), 

690 "stopped_at": stopped_at.isoformat(), 

691 "axis": params.axis, 

692 "axis_start_requested": params.start, 

693 "axis_stop_requested": params.stop, 

694 "axis_final_actual": axis_final.value, 

695 "rate_requested": params.rate, 

696 "repetitions_requested": params.repetitions, 

697 "trigger_mode": params.trigger_mode, 

698 "trigger_dialect": ctx.trigger_dialect, 

699 "image_mode": _IMAGE_MODE_MULTIPLE, 

700 "polarity": params.polarity, 

701 "source": params.source, 

702 "detector_state_final": state_reading.value, 

703 "detector_settings": detector_settings, 

704 "requested_not_applied": { 

705 "polarity": params.polarity, 

706 "source": params.source,
