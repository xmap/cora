1"""The `ConductProcedure` command -- operator-facing entry for `Conductor.conduct()`. 

2 

3Unlike most slice commands, `ConductProcedure` does not directly write 

4to an aggregate's event stream. It hands control to the 

5`cora.operation.conductor.Conductor` runtime, which orchestrates 

6the full Procedure lifecycle: `start_procedure` -> 

7walk-supplied-steps -> `complete_procedure` (on success) or 

8`abort_procedure` (on step failure). The handler returns a 

9`ConductProcedureResult` summarising the run; failures are encoded in 

10that result, not raised as exceptions, so a single HTTP / MCP 

11response shape covers every outcome the operator needs to triage. 

12 

13`steps` is the caller-supplied sequence the Conductor walks. 

14Substrate-agnostic: setpoint addresses parse inside the routed 

15`ControlPort` adapter, action names look up in the `ActionRegistry`, 

16check criteria evaluate against the read `Measurement.value`. 

17""" 

18 

19from collections.abc import Mapping, Sequence 

20from dataclasses import dataclass, field 

21from uuid import UUID 

22 

23from cora.operation.conductor import ConductorFailure, Step, WriteValue 

24from cora.operation.ports.compute_port import ArtifactRef 

25from cora.operation.ports.measurement import Measurement 

26 

27 

28@dataclass(frozen=True) 

29class ConductProcedure: 

30 """Invoke the Conductor against an existing Procedure + step list.""" 

31 

32 procedure_id: UUID 

33 steps: Sequence[Step] 

34 

35 

36@dataclass(frozen=True) 

37class ConductProcedureResult: 

38 """Summary of a `ConductProcedure` invocation. 

39 

40 Mirrors `ConductorResult` shape verbatim (procedure_id + 

41 completed_count + optional failure) so the wire response stays 

42 decoupled from the in-process Conductor type and the 

43 application-layer slice owns its return-type contract. 

44 

45 `actuation_kind` is the raw `ActuationKind` value (Physical / 

46 Simulated / Hybrid) the Conductor observed across the conduct, or 

47 None when nothing instrumented was actuated (no routing table, or 

48 no control-port write). Surfaced for operator visibility; the same 

49 value is the one the Conductor records on the Procedure terminal 

50 event, where the Data BC reads it back to gate promotion. 

51 

52 `measurements` carries the `Measurement`s every value-arm `ComputeStep` 

53 produced (threaded from `ConductorResult.measurements`), so the caller 

54 reads the produced measurements (a detector pixel size that homes to a 

55 Calibration) without re-parsing the activity log. `artifacts` carries 

56 the `ArtifactRef`s every file-arm `ComputeStep` produced (threaded from 

57 `ConductorResult.artifacts`), so a caller (the Phase-of-Run glue) can 

58 register a volume Dataset against the file a reconstruction wrote. Both 

59 empty on a conduct with no ComputeStep. 

60 

61 `outputs` is the named artifact bus (keyed by `output_ref_name`, threaded 

62 from `ConductorResult.outputs`), so a caller selects the Dataset-of-record 

63 by NAME (e.g. `outputs["recon"]`) rather than by document position. Empty 

64 when no file-arm ComputeStep declared an `output_ref_name`. 

65 """ 

66 

67 procedure_id: UUID 

68 completed_count: int 

69 succeeded: bool 

70 failure: ConductorFailure | None = None 

71 actuation_kind: str | None = None 

72 measurements: tuple[Measurement, ...] = () 

73 artifacts: tuple[ArtifactRef, ...] = () 

74 outputs: Mapping[str, ArtifactRef] = field(default_factory=dict[str, ArtifactRef]) 

75 substrate_writes: Mapping[str, WriteValue] = field(default_factory=dict[str, WriteValue]) 

76 """Every address the conduct wrote, in first-write order, last value. 

77 

78 Threaded from `ConductorResult.substrate_writes`. Includes the Recipe's 

79 closing steps, which run on a real terminal (Completed or Aborted) and 

80 merge their own writes into this ledger. 

81 """ 

82 closing_failures: tuple[ConductorFailure, ...] = () 

83 """Every closing step that failed, threaded from `ConductorResult.closing_failures`. 

84 

85 Isolated from `failure`: a closing failure never flips `succeeded`, and 

86 one closing step failing does not stop the rest of the closing walk. 

87 Empty when the bound Recipe has no closing steps, or every closing step 

88 ran clean. 

89 """
