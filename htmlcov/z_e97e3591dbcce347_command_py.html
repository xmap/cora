1"""The `ConductProcedure` command -- operator-facing entry for `Conductor.conduct()`. 

2 

3Unlike most slice commands, `ConductProcedure` does not directly write 

4to an aggregate's event stream. It hands control to the 

5`cora.operation.conductor.Conductor` runtime, which orchestrates 

6the full Procedure lifecycle: `start_procedure` -> 

7walk-supplied-steps -> `complete_procedure` (on success) or 

8`abort_procedure` (on step failure). The handler returns a 

9`ConductProcedureResult` summarising the run; failures are encoded in 

10that result, not raised as exceptions, so a single HTTP / MCP 

11response shape covers every outcome the operator needs to triage. 

12 

13`steps` is the caller-supplied sequence the Conductor walks. 

14Substrate-agnostic: setpoint addresses parse inside the routed 

15`ControlPort` adapter, action names look up in the `ActionRegistry`, 

16check criteria evaluate against the read `Reading.value`. 

17""" 

18 

19from collections.abc import Sequence 

20from dataclasses import dataclass 

21from uuid import UUID 

22 

23from cora.operation.conductor import ConductorFailure, Step 

24 

25 

26@dataclass(frozen=True) 

27class ConductProcedure: 

28 """Invoke the Conductor against an existing Procedure + step list.""" 

29 

30 procedure_id: UUID 

31 steps: Sequence[Step] 

32 

33 

34@dataclass(frozen=True)

37 

38 Mirrors `ConductorResult` shape verbatim (procedure_id + 

39 completed_count + optional failure) so the wire response stays 

40 decoupled from the in-process Conductor type and the 

41 application-layer slice owns its return-type contract. 

42 """ 

43 

44 procedure_id: UUID 

45 completed_count: int 

46 succeeded: bool 

47 failure: ConductorFailure | None = None
