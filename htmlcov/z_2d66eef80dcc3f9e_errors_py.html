1"""BC-application-layer errors for the Data BC. 

2 

3These errors are raised by application handlers (not domain logic) 

4and mapped to HTTP / MCP responses by the BC's exception handlers in 

5`cora/data/routes.py`. 

6 

7Domain errors (raised by aggregates / deciders) live with their 

8aggregate at `aggregates/dataset/state.py`. 

9 

10Distinct class from other BCs' `UnauthorizedError` namespaces 

11(per-BC log-distinguishability convention; see CONTRIBUTING.md 

12"BC-application-layer errors"). 

13""" 

14 

15from enum import StrEnum

18class ScanFileInvalidReason(StrEnum): 

19 """Why `InvalidScanFileError` refused a scan file, discriminated from 

20 the message text so a caller can branch on cause without parsing a 

21 string or ever touching the path the message may (redacted or not) 

22 embed. 

23 

24 One member per raise site in `ingest_scan.handler`; none merged. 

25 Every pair considered kept a real diagnostic distinction: the two 

26 `captured_at` members have opposite remedies (drop the supplied 

27 value versus supply one); `UNREADABLE` and `DIGEST_UNREACHABLE` are 

28 distinct pipeline stages behind distinct ports, and collapsing them 

29 would lose which pass failed; `LOCATOR_UNRESOLVED` and 

30 `LOCATOR_MISSING_FILENAME` fail for different reasons at different 

31 call sites. 

32 

33 `is_transient` is the machine-readable permanent/transient split: 

34 true when retrying the SAME command unmodified could plausibly 

35 succeed once the file's writer finishes; false when nothing about 

36 the file changing can help, because the fix requires the caller to 

37 change the request, the file, or the configuration. Each 

38 classification below is cited from the code that justifies it, not 

39 from intuition. 

40 

41 - `LOCATOR_UNRESOLVED` (permanent): `resolve_capture_path_locator` 

42 returns `None` only for "malformed locator; no vault row at 

43 all; a row that exists but not at the location the locator 

44 names; filename mismatch" (its own docstring). The sweep's 

45 candidate query only selects vault rows that already exist, so 

46 a failure here is drift or misconfiguration, not a file still 

47 arriving. 

48 - `UNREADABLE` (transient): `ScanReader`'s port docstring: "may be 

49 transient: a half-transferred file on the analysis tier is an 

50 expected observable, and the caller decides whether to retry." 

51 - `UNRECOGNIZED` (permanent): the same `ScanReader` docstring 

52 pointedly withholds the "may be transient" language from this 

53 variant; it fires only when the layout's one mandatory dataset 

54 is entirely absent, a layout verdict rather than an I/O timing 

55 issue. 

56 - `STRUCTURALLY_INCOMPLETE` (permanent): `DataExchangeScanReader` 

57 documents the absent rotation-angle dataset as meaning 

58 post-processing "has not completed (not yet run, failed 

59 permanently... or a scan that produced zero projections)". The 

60 sweep only ever considers terminal runs (`status IN 

61 ('Completed', 'Aborted')`), which narrows but does not fully 

62 eliminate the "not yet run" sub-case this member bundles 

63 together with the two permanent ones; whoever builds the 

64 finality-axis work the port docstring defers should revisit 

65 this member first. 

66 - `DIGEST_UNREACHABLE` (transient): reuses `ChecksumVerifier`'s 

67 `Unreachable`, whose docstring says outright "(transient)". 

68 - `CHANGED_WHILE_READING` (transient): fires only when size or 

69 mtime moved between two stat snapshots taken moments apart, 

70 which by construction means a writer touched the file during 

71 the read window. 

72 - `CAPTURED_AT_AMBIGUOUS` (permanent): the remedy is to drop the 

73 supplied value; the CALLER's request must change, not the file. 

74 - `CAPTURED_AT_MISSING` (permanent): the remedy requires an 

75 operator to supply `captured_at` manually. `CaptureScanIngestor` 

76 (the only automated caller) never passes `captured_at`, so this 

77 can never self-resolve through automated retry. 

78 - `LOCATOR_MISSING_FILENAME` (permanent): the locator names a 

79 directory, not a file; a caller/configuration defect, not a 

80 file-readiness one. 

81 

82 Member name SCREAMING_SNAKE; string value PascalCase, matching 

83 `AttestationKind`'s house style. Values are plain enum labels only 

84 and must never embed, interpolate, or derive from a filesystem 

85 path, so they stay safe to log and persist forever. 

86 """

116class InvalidScanFileError(ValueError): 

117 """The file at the ingest locator cannot be ingested as commanded. 

118 

119 Validation family (`Invalid<X>` -> 400), homed here rather than in 

120 an aggregate's `state.py` because no aggregate's state gates it: the 

121 subject is the FILE, judged before any command composes. Same 

122 handler-tier posture as `ChecksumVerifierUnsupportedSchemeError`. 

123 

124 Covers: the reader refusing the bytes (unreadable, unrecognized 

125 layout, structurally incomplete), the digest pass failing, the file 

126 changing while being read, a missing acquisition timestamp with no 

127 operator-supplied one, and a supplied timestamp alongside a 

128 parseable file value (ambiguous). The message always names the 

129 remedy, because the operator holding it is the only one who can act. 

130 

131 `reason` carries the same cause as a closed, non-PII 

132 `ScanFileInvalidReason` a caller can branch on (whether to keep 

133 retrying, for instance) without parsing `message` or risking a path 

134 it may embed; see that enum for the permanent/transient split. 

135 `message` remains the sole content of `str(exc)`, unchanged, so 

136 every existing catcher that ignores `reason` behaves identically. 

137 

138 Subclasses ValueError so the shared schema validator can raise it 

139 directly for the declared evidence shape. 

140 """ 

141 

142 def __init__(self, message: str, *, reason: ScanFileInvalidReason) -> None: 

143 super().__init__(message) 

144 self.reason = reason
