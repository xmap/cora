1"""An `EventStore` that reads but refuses to append. 

2 

3Wraps the real store when the process booted against a schema it does not 

4expect and an operator explicitly asked for that rather than a refusal 

5(`allow_schema_version_mismatch`, see `schema_version`). Reading a 

6restored database is useful and harmless. Writing to one is neither: the 

7event log is append-only at the role level, so a bad append is history 

8rather than a row to correct. 

9 

10## Why a wrapper and not a flag 

11 

12Same reasoning as `ReadOnlyControlPort`: this refuses at CONSTRUCTION. 

13The composition root decides once, and every call site downstream holds a 

14store that cannot write, rather than one that consults a flag and could 

15be reached on a path that forgets to. There is no compensating action 

16available after a wrong append, so there is no room for a gate that can 

17be talked past. 

18 

19## Completeness 

20 

21`EventStore` has exactly three methods and this covers all three. Nothing 

22in `src/` reaches an event store by `getattr` or narrows one by 

23`isinstance`, so unlike the ControlPort registry (whose `aclose` lookup 

24made a partial wrapper leak connections) there is no attribute a wrapper 

25can hide by omission. `test_read_only_event_store_covers_protocol` pins 

26that: it fails if `EventStore` grows a method this class does not. 

27 

28## Scope: this guards the event log, NOT every write 

29 

30Say this precisely, because the tempting summary ("degraded means writes 

31are off") is not true. Each BC builds its own Postgres-backed stores from 

32`deps.pool` in `wire_<bc>(deps)` (Decision's `InferenceStore`, 

33Operation's `ActivityStore` and `OutcomeStore`, Run's 

34`ObservationStore`, and the projection workers). None of those pass 

35through this wrapper, so a degraded process can still write to them. 

36 

37That is a deliberate ordering rather than an oversight. The event log is 

38the append-only record of truth and cannot be corrected once written; 

39everything listed above is derived state that a rebuild reconstructs from 

40those events. Protecting the irreversible thing first is the whole 

41trade. Widening the guard to those stores means a port each, and the 

42trigger for doing it is a real incident in one of them, not this comment. 

43"""

61class EventWritesDisabledError(RuntimeError): 

62 """An append was attempted on a store that boots read-only. 

63 

64 Mirrors `ControlWritesDisabledError` in shape and intent: named for 

65 the refusal, raised before any substrate is contacted. 

66 """ 

67 

68 def __init__(self, applied: str, expected: str) -> None: 

69 super().__init__( 

70 f"Refusing to write: this process booted against a schema it does " 

71 f"not expect.\n" 

72 f"\n" 

73 f" database is at {applied}\n" 

74 f" this build needs {expected}\n" 

75 f"\n" 

76 f"It started anyway because the mismatch was explicitly allowed, " 

77 f"which permits reading a restored database and nothing else. " 

78 f"Events are append-only, so a write here could not be undone.\n" 

79 f"\n" 

80 f"To write: bring the schema and the image into agreement, then " 

81 f"restart without the override." 

82 ) 

83 self.applied = applied 

84 self.expected = expected

87class ReadOnlyEventStore: 

88 """Delegates `load`, refuses `append` and `append_streams`. 

89 

90 The versions are carried rather than re-read so the refusal can name 

91 both sides of the mismatch. A caller who hits this is usually not the 

92 operator who set the override, and "writes are off" without the two 

93 numbers leaves them guessing at why. 

94 """ 

95 

96 def __init__(self, inner: EventStore, *, applied: str, expected: str) -> None: 

97 self._inner = inner 

98 self._applied = applied 

99 self._expected = expected 

100 

101 async def load( 

102 self, 

103 stream_type: str, 

104 stream_id: UUID, 

105 ) -> tuple[list[StoredEvent], int]:

114 ) -> int:
