1"""Composition-root bridge: drive the capture observer from ControlPort. 

2 

3The Run BC's `CaptureObserver` port is BC-local (`cora.run.ports`) and 

4the `ControlPort` value-IO it needs is Operation-BC-owned 

5(`cora.operation.ports`). tach forbids `cora.run -> cora.operation`, so 

6the adapter that bridges the two lives here at the composition root, 

7mirroring `_enclosure_permit_observer.py` exactly. If a third cross-BC 

8`ControlPort` consumer appears, the rule-of-three move is to hoist 

9`ControlPort` to `cora.infrastructure.ports`. 

10 

11Maps each configured capture code's `status` PV to a 

12`CaptureLifecycleObservation` by looking its decoded text up in the 

13deployment's declared `capture_status_phases` table 

14(`classify_capture_status`); a literal absent from the table 

15classifies `UNRECOGNIZED` rather than being dropped or coerced into a 

16nearby phase. The optional `abort` role layers a direct `ABORTED` 

17claim on top (slice 9); the optional `images_saved` / 

18`images_collected` progress roles (slice 10) each pump their own 

19`CaptureProgressObservation` onto the same merged stream, siblings of 

20the phase pumps. The optional `testing` role (slice 11) pumps its own 

21`CapturePreconditionBypassObservation`: a tri-state reading of whether 

22the substrate is bypassing its own beam preconditions for this capture 

23code, decoded via the same `binary_code` the `abort` role already 

24uses (2-BM's `Testing` PV is the identical `DBR_ENUM` record type as 

25`AbortScan`). The optional `full_file_name` role (slice 13) pumps its 

26own `CapturePathObservation`: a text reading of the areaDetector file 

27plugin's own filename readback (`2bmSP2:HDF1:FullFileName_RBV`, NOT 

28tomoscan's own `FullFileName`, which is written too late relative to 

29CORA's terminal -- see `_run_witness.py`'s "Capture path pairing" 

30section for the full argument). `observed_path` is PERSONAL DATA; this 

31module never logs it, only its length when rejecting a suspect 

32reading. 

33 

34## One deliberate inversion from the Enclosure precedent 

35 

36`ControlPortEnclosureObserver` synthesizes an `Unknown` STATUS CLAIM on 

37disconnect, because a dead permit signal must fail the run-start gate 

38closed rather than leave a stale `Permitted` standing. There is no such 

39gate here, and reading a disconnect as a real observation would 

40fabricate one: it would either assert a phase no substrate reading 

41backs, or, if mapped to `UNRECOGNIZED`, misrepresent a communication 

42failure as a vocabulary problem. So `_unreached` here carries NO status 

43claim at all (`reported_status=None`, `phase=None`), the same shape a 

44probe-only poll tick already uses, exactly mirroring 

45`CaptureLifecycleObservation`'s own port-level contract for the 

46probe-only case. A progress pump has no `_unreached` counterpart at 

47all: `CaptureProgressObservation.value` is a required float with no 

48"no claim" shape, so its disconnect / clean-end simply stops the pump 

49rather than fabricating a reading (see `_pump_progress`). 

50 

51## The bug that would have shipped without checking the real PV, again 

52 

53Slice 9 caught 2-BM's `AbortScan` resolving to the ENUM label `'No'`, 

54not `0`. Slice 10 caught the same class of trap on `ImagesSaved` / 

55`ImagesCollected`: they are `stringout` records at 2-BM, and TomoScan 

56writes `"<done>/<total>"` onto them (`update_status()` in the upstream 

57`decarlof/tomoscan` source), never a bare number. `finite_float`'s 

58first cut assumed a plain float; every real reading would have failed 

59to parse and the feature would have shipped recording nothing on the 

60real beamline, with no error anywhere; a deployment can watch a whole 

61scan complete and never notice the record stayed empty. Caught by 

62checking the upstream source's own write path rather than trusting the 

63`Settings.capture_watch_pvs` docstring's example. `progress_counts` 

64now accepts both shapes and carries both halves onto 

65`CaptureProgressObservation`, per `commanded_total`'s own docstring for 

66why it is carried and what it is NOT: a completeness test. 

67 

68## The denominator is carried, and is not a completeness signal 

69 

70Slice 10 originally discarded the `"<total>"` half of a `"<reached>/ 

71<total>"` reading, reasoning that a consumer needing the commanded 

72count should read the Plan's own parameters instead. That reasoning 

73does not hold on the witnessed path: a witnessed Run's Plan is a 

74configured stand-in (`Settings.capture_watch_plan_id`), not the 

75parameters TomoScan was actually given, so "read the Plan" means 

76guessing at someone else's scan length. The commanded total is now 

77carried through as `commanded_total`, because a witnessed terminal 

78(`record_witnessed_run_outcome`) needs the substrate's own target as 

79evidence when tomoscan reports a clean completion after an abort, 

80camera timeout, or file-overwrite refusal that never reaches 

81`ScanStatus` (see tomography/tomoscan#181). 

82 

83Carrying it does NOT make `value == commanded_total` a valid test. 

84`wait_camera_done()`'s poll loop (upstream `tomoscan.py`) returns on 

85`CamAcquireBusy == 0` BEFORE its final `update_status()` call, so a 

86perfectly healthy scan routinely ends with `value` short of 

87`commanded_total` by roughly one poll interval's worth of frames. See 

88`CaptureProgressSnapshot` (`cora.run.aggregates.run.state`) for how the 

89witnessed terminal records this without asserting a verdict. 

90 

91## Permit probe trail's sibling-poller shape, reused unchanged 

92 

93Same reasoning as the Enclosure adapter: `_poll` is a SIBLING of 

94`_pump`, not nested inside it, because `_pump` returns as soon as its 

95subscription ends and `_drain` only re-subscribes after every pump has 

96returned; a poller living inside `_pump` would die with it and could 

97never observe the PV's recovery. 

98"""

182def binary_code(value: object) -> int | None: 

183 """Resolve a binary-role reading to 1 / 0, or None when it is neither. 

184 

185 Unrecognized resolves to `None`, never a guess: same fail-toward- 

186 silence posture as `_enclosure_permit_observer._binary_code`, whose 

187 docstring documents the production incident (`int('ON')` raising) 

188 that made string-label matching necessary in the first place. 

189 

190 Module-public (not `_`-prefixed): `capture_watch_preflight` calls this 

191 directly to report whether the `abort` role's reading decodes, and 

192 must not carry a second copy of this logic. 

193 """ 

194 if isinstance(value, str): 

195 token = value.strip().upper() 

196 if token in _ASSERTED_LABELS: 

197 return 1 

198 if token in _CLEAR_LABELS: 

199 return 0 

200 return None 

201 try: 

202 code = int(value) # type: ignore[call-overload] 

203 except (TypeError, ValueError): 

204 return None 

205 return code if code in (0, 1) else None

208def finite_float(value: object) -> float | None: 

209 """Coerce a single reading to a finite float, or `None`. 

210 

211 Fail-toward-silence, mirroring `binary_code`: a value that cannot 

212 coerce, or resolves to NaN/Infinity, returns `None` rather than 

213 reaching `append_observations`, which raises 

214 `InvalidObservationValueError` on NaN/Inf and would fail an entire 

215 batch over one bad reading. 

216 """ 

217 try: 

218 result = float(value) # type: ignore[arg-type] 

219 except (TypeError, ValueError): 

220 return None 

221 if math.isnan(result) or math.isinf(result): 

222 return None 

223 return result

226def progress_counts(value: object) -> tuple[float, float | None] | None: 

227 """Split a progress-role reading into `(reached, commanded_total)`. 

228 

229 Two accepted shapes: a bare number, and 2-BM's REAL format, a 

230 `"<reached>/<commanded>"` string. `ImagesSaved` / `ImagesCollected` 

231 are `stringout` records at 2-BM (not numeric ones): TomoScan's 

232 `update_status()` writes `f"{num_saved}/{num_to_save}"` / 

233 `f"{num_collected}/{num_images}"` onto them, confirmed against the 

234 upstream `decarlof/tomoscan` source, `tomoScan.template` (both 

235 declared `record(stringout, ...)`) and `tomoscan.py`'s 

236 `update_status`. A bare-number reading returns `commanded_total` 

237 `None`, for a future substrate or role that IS numeric. 

238 

239 Only the numerator's coercibility gates the whole reading, matching 

240 `finite_float`'s fail-toward-silence posture: a garbled, missing, 

241 or absent denominator (`"2987/"`, `"2987/abc"`, a bare `2987`) still 

242 returns the reached count with `commanded_total=None`, since the 

243 reached count is a true progress fact on its own. Returns `None` 

244 only when the numerator itself does not coerce to a finite float. 

245 

246 Module-public (not `_`-prefixed): `capture_watch_preflight` calls this 

247 directly to report whether a progress role's reading decodes. 

248 """ 

249 numerator: object = value 

250 denominator: object = None 

251 if isinstance(value, str) and "/" in value: 

252 numerator, _, denominator = value.partition("/") 

253 reached = finite_float(numerator) 

254 if reached is None: 

255 return None 

256 # `denominator is None` on a bare-number reading (no "/") is a 

257 # normal, expected shape, not a coercion failure to route through 

258 # `finite_float`'s try/except: skip the call rather than raise and 

259 # catch a `TypeError` on every single bare-number reading. 

260 commanded_total = finite_float(denominator) if denominator is not None else None 

261 return reached, commanded_total

264def classify_capture_status(reported_status: str, status_phases: Mapping[str, str]) -> CapturePhase: 

265 """Classify a decoded status literal against the deployment's declared table. 

266 

267 A literal absent from `status_phases` classifies as 

268 `CapturePhase.UNRECOGNIZED`. This also covers the Bad-quality-reading 

269 case with no special handling needed: an unresolvable or garbled 

270 string is exceedingly unlikely to match a declared literal, so it 

271 naturally falls to UNRECOGNIZED, which is the correct signal ("the 

272 substrate said something CORA cannot classify"), rather than a 

273 fabricated phase. 

274 """ 

275 mapped = status_phases.get(reported_status) 

276 if mapped is None: 

277 return CapturePhase.UNRECOGNIZED 

278 return CapturePhase(mapped)

290class ControlPortCaptureObserver: 

291 """`CaptureObserver` over a `ControlPort` (`status` + optional `abort` + 

292 optional progress PVs per capture code). 

293 

294 `capture_pvs` is code -> role -> PV, matching 

295 `Settings.capture_watch_pvs`. The `status` role is required; a code 

296 whose PV set has no `status` entry cannot be watched and is 

297 silently excluded from scope, mirroring the Enclosure adapter's 

298 `if code in self._permit_pvs` filter. The `abort` role is optional 

299 per code: when declared, a truthy reading on it is a direct 

300 `ABORTED` phase claim, letting a real abort be distinguished from a 

301 successful end even where the `status` PV alone cannot (2-BM's 

302 `fly_scan` writes the identical `'Scan complete'` literal on both). 

303 A code with no `abort` entry watches `status` only, exactly as 

304 before this role existed. The `images_saved` / `images_collected` 

305 progress roles (also optional, independently declared per code) 

306 each pump `CaptureProgressObservation` readings. The `testing` role 

307 (also optional, independently declared per code) pumps 

308 `CapturePreconditionBypassObservation` readings, a tri-state claim 

309 rather than a phase or a counter; see that dataclass's own 

310 docstring. The `full_file_name` role (slice 13, also optional, 

311 independently declared per code) pumps `CapturePathObservation` 

312 readings, a text claim carrying personal data; see that dataclass's 

313 own docstring. 

314 `server_running` stays declared and unread (tool liveness, not 

315 capture progress). 

316 """ 

317

354 async def _drain(self, scope: CaptureObserverScope) -> AsyncGenerator[AnyCaptureObservation]: 

355 pvs = [ 

356 (code, self._status_pvs[code]) 

357 for code in sorted(scope.capture_codes) 

358 if code in self._status_pvs 

359 ] 

360 if not pvs: 

361 return 

362 abort_pvs = [ 

363 (code, self._abort_pvs[code]) 

364 for code in sorted(scope.capture_codes) 

365 if code in self._abort_pvs 

366 ] 

367 testing_pvs = [ 

368 (code, self._testing_pvs[code]) 

369 for code in sorted(scope.capture_codes) 

370 if code in self._testing_pvs 

371 ] 

372 full_file_name_pvs = [ 

373 (code, self._full_file_name_pvs[code]) 

374 for code in sorted(scope.capture_codes) 

375 if code in self._full_file_name_pvs 

376 ] 

377 progress_pvs = [ 

378 (code, role, pv) 

379 for code in sorted(scope.capture_codes) 

380 if code in self._progress_pvs 

381 for role, pv in sorted(self._progress_pvs[code].items())

383 queue: asyncio.Queue[AnyCaptureObservation | _PumpDone] = asyncio.Queue() 

384 pump_tasks = ( 

385 [asyncio.create_task(self._pump(code, pv, queue)) for code, pv in pvs] 

386 + [asyncio.create_task(self._pump_abort(code, pv, queue)) for code, pv in abort_pvs] 

387 + [asyncio.create_task(self._pump_testing(code, pv, queue)) for code, pv in testing_pvs] 

388 + [ 

389 asyncio.create_task(self._pump_full_file_name(code, pv, queue))

391 ] 

392 + [ 

393 asyncio.create_task(self._pump_progress(code, role, pv, queue)) 

394 for code, role, pv in progress_pvs 

395 ] 

396 ) 

397 poll_tasks = ( 

398 [asyncio.create_task(self._poll(code, pv, queue)) for code, pv in pvs] 

399 if self._tick_seconds is not None 

400 else [] 

401 ) 

402 tasks = pump_tasks + poll_tasks 

403 # Only pumps ever signal completion; a poller runs until the 

404 # `finally` below cancels it, so it must not hold this open. 

405 remaining = len(pump_tasks) 

406 try: 

407 while remaining > 0: 

408 item = await queue.get() 

409 if isinstance(item, _PumpDone): 

410 remaining -= 1 

411 continue 

412 yield item 

413 # Every pump has finished, but a still-running poller can have 

414 # enqueued a probe in the same instant the final _PumpDone was 

415 # read. Drain exactly what is ALREADY queued right now, 

416 # synchronously, into a list before yielding any of it: see 

417 # `ControlPortEnclosureObserver._drain` for the full reasoning. 

418 pending = queue.qsize() 

419 leftover = [queue.get_nowait() for _ in range(pending)] 

420 for item in leftover: 420 ↛ 421line 420 didn't jump to line 421 because the loop on line 420 never started

421 if not isinstance(item, _PumpDone): 

422 yield item 

423 finally: 

424 for task in tasks: 

425 task.cancel() 

426 await asyncio.gather(*tasks, return_exceptions=True)

428 async def _pump( 

429 self, 

430 code: str, 

431 pv: str, 

432 queue: asyncio.Queue[AnyCaptureObservation | _PumpDone], 

433 ) -> None: 

434 try: 

435 async for reading in self._control_port.subscribe(pv): 

436 queue.put_nowait(self._from_reading(code, pv, reading)) 

437 # Clean stream end: no status claim, mirroring a disconnect. 

438 queue.put_nowait(self._unreached(code, pv)) 

439 except ControlNotConnectedError: 

440 queue.put_nowait(self._unreached(code, pv)) 

441 finally: 

442 queue.put_nowait(_PUMP_DONE)

462 except ControlNotConnectedError: 

463 queue.put_nowait(self._unreached(code, pv))

520 async def _pump_full_file_name( 

521 self, 

522 code: str, 

523 pv: str, 

524 queue: asyncio.Queue[AnyCaptureObservation | _PumpDone], 

525 ) -> None: 

526 """Sibling pump for the optional `full_file_name` role (slice 13). 

527 

528 Mirrors `_pump_testing` exactly, for the same reason: a 

529 disconnect must not erase the last retained reading, since the 

530 dual-clock guard `RunWitnessRecorder` applies (comparing this 

531 reading's `observed_at` against the Run's own BEGUN time) needs 

532 the last GOOD reading to survive a reconnect, not be replaced by 

533 a synthesized "unreached". Unlike `_pump_abort` / `_pump`, no 

534 `_from_full_file_name_reading` result is dropped for being 

535 "no claim" the way an abort's clear reading is -- it can return 

536 `None` (see that function), but that is a REJECTION (empty 

537 string, suspected truncation, non-str value), not a "nothing 

538 happened" no-op, so it is still correct to enqueue nothing for 

539 it: there is no partial fact to carry. 

540 """ 

541 try: 

542 async for reading in self._control_port.subscribe(pv): 

543 observation = self._from_full_file_name_reading(code, pv, reading) 

544 if observation is not None: 

545 queue.put_nowait(observation) 

546 except ControlNotConnectedError: 

547 pass 

548 finally: 

549 queue.put_nowait(_PUMP_DONE) 

550 

551 async def _poll( 

552 self, 

553 code: str, 

554 pv: str, 

555 queue: asyncio.Queue[AnyCaptureObservation | _PumpDone], 

556 ) -> None: 

557 """Re-affirm reach to `pv` every `_tick_seconds`, independent of push. 

558 

559 Never pushes `_PumpDone`: a sibling of `_pump`, not a stage in 

560 its lifecycle. See `ControlPortEnclosureObserver._poll`. 

561 """ 

562 assert self._tick_seconds is not None 

563 while True: 

564 await asyncio.sleep(self._tick_seconds) 

565 try: 

566 await self._control_port.read(pv) 

567 except Exception: # any read failure is a failed probe, not a bug 

568 queue.put_nowait(self._probe_only(code, pv, ReachTier.UNREACHED)) 

569 else: 

570 queue.put_nowait(self._probe_only(code, pv, ReachTier.RELAYED))

587 def _from_abort_reading( 

588 self, code: str, pv: str, reading: Measurement 

589 ) -> CaptureLifecycleObservation | None: 

590 """An asserted abort-role reading is a direct `ABORTED` claim. 

591 

592 NOT Python truthiness: 2-BM's `AbortScan` is a DBR_ENUM that 

593 resolves to the label `'No'` when idle, and `bool('No')` is 

594 `True`. `binary_code` decodes the conventional EPICS binary 

595 labels (or a raw 0/1 index) instead, so "No" correctly resolves 

596 to clear, not asserted. 

597 

598 A clear or unresolvable reading makes no phase claim: it is not 

599 "the capture is not aborted" so much as "nothing happened on 

600 this PV" (or a label this cannot decode), and reporting it as a 

601 phase would let a stale idle read silently arrive between a 

602 real `Begun` and its `status` transitions. `None` return means 

603 the caller enqueues nothing. 

604 """ 

605 if binary_code(reading.value) != 1: 

606 return None 

607 return CaptureLifecycleObservation( 

608 capture_code=code, 

609 reported_status=str(reading.value), 

610 phase=CapturePhase.ABORTED, 

611 reach_tier=ReachTier.RELAYED, 

612 observed_at=reading.produced_at, 

613 source_kind=_SOURCE_KIND, 

614 source_id=pv, 

615 )

617 def _from_progress_reading( 

618 self, code: str, role: str, pv: str, reading: Measurement 

619 ) -> CaptureProgressObservation | None: 

620 """A progress-role reading, decoded to a finite float plus an 

621 optional commanded total (see `progress_counts`). 

622 

623 `None` return (no coercible reached count) means the caller 

624 enqueues nothing, matching `_from_abort_reading`'s fail-toward- 

625 silence posture: a garbled or non-numeric reading is dropped, 

626 never guessed at. A garbled or absent commanded total does NOT 

627 drop the reading; it enqueues with `commanded_total=None`. 

628 """ 

629 counts = progress_counts(reading.value) 

630 if counts is None: 

631 return None 

632 value, commanded_total = counts 

633 return CaptureProgressObservation( 

634 capture_code=code, 

635 role=role, 

636 value=value, 

637 commanded_total=commanded_total, 

638 reach_tier=ReachTier.RELAYED, 

639 observed_at=reading.produced_at, 

640 source_kind=_SOURCE_KIND, 

641 source_id=pv, 

642 )

644 def _from_testing_reading( 

645 self, code: str, pv: str, reading: Measurement 

646 ) -> CapturePreconditionBypassObservation: 

647 """A `testing`-role reading, decoded via `binary_code` exactly as 

648 the `abort` role's reading is (2-BM's `Testing` PV is the 

649 identical `DBR_ENUM` record type as `AbortScan`): `1` -> `True` 

650 (asserted: bypassing beam preconditions), `0` -> `False` (clear: 

651 a positive claim of a real acquisition), `None` -> `None` 

652 (unresolved). Unlike `_from_abort_reading`, every reading 

653 constructs an observation; there is no reading here that means 

654 "nothing happened". 

655 """ 

656 code_value = binary_code(reading.value) 

657 bypassed = None if code_value is None else code_value == 1 

658 return CapturePreconditionBypassObservation( 

659 capture_code=code, 

660 beam_preconditions_bypassed=bypassed, 

661 reach_tier=ReachTier.RELAYED, 

662 observed_at=reading.produced_at, 

663 source_kind=_SOURCE_KIND, 

664 source_id=pv, 

665 )

667 def _from_full_file_name_reading( 

668 self, code: str, pv: str, reading: Measurement 

669 ) -> CapturePathObservation | None: 

670 """A `full_file_name`-role reading (slice 13), rejected rather 

671 than enqueued for three reasons, in order. 

672 

673 1. Not a string: the adapter's own text-waveform decode 

674 (`text_addresses`) failed to apply or produced something 

675 else. Never coerced; a non-text reading on this role is a 

676 deployment misconfiguration, not a value to guess at. 

677 2. Empty string: the fresh-IOC-boot state (the file plugin has 

678 never opened a file since the IOC started). A fine, ordinary 

679 outcome, not an error -- just nothing to enqueue. 

680 3. Length at or over `FULL_FILE_NAME_TRUNCATION_THRESHOLD`: 

681 indistinguishable from a wire truncation (see that 

682 constant's own docstring). Logs the length only, NEVER the 

683 value -- `observed_path` is personal data. 

684 

685 `None` return means the caller enqueues nothing, matching 

686 `_from_abort_reading` / `_from_progress_reading`'s fail-toward- 

687 silence posture. 

688 """ 

689 value = reading.value 

690 if not isinstance(value, str): 

691 return None 

692 if not value: 

693 return None 

694 if len(value) >= FULL_FILE_NAME_TRUNCATION_THRESHOLD: 

695 _log.warning( 

696 "capture_observer.full_file_name_suspected_truncated", 

697 capture_code=code, 

698 length=len(value), 

699 ) 

700 return None 

701 return CapturePathObservation( 

702 capture_code=code, 

703 observed_path=value, 

704 reach_tier=ReachTier.RELAYED, 

705 observed_at=reading.produced_at, 

706 source_kind=_SOURCE_KIND, 

707 source_id=pv, 

708 )
