1"""BC-application-layer errors for the Operation BC. 

2 

3These errors are raised by application handlers (not domain logic) 

4and mapped to HTTP / MCP responses by the BC's exception handlers in 

5`cora/operation/routes.py`. 

6 

7Domain errors (raised by aggregates / deciders) live with their 

8aggregate, for example `aggregates/procedure/state.py`. 

9 

10Distinct class from each other BC's `UnauthorizedError`: each BC 

11owns its own application-error namespace so an Operation 403 is 

12distinguishable from other BCs' 403s in logs / aggregator filters 

13(documented in CONTRIBUTING.md "BC-application-layer errors"). 

14"""

62class ActionRefusedError(Exception): 

63 """An action body declined the step BEFORE touching the substrate. 

64 

65 The Conductor catches this alongside `_CONTROL_ERRORS` at the 

66 action-dispatch site and gives it the same treatment: a recorded 

67 `result="failed"` step entry plus a `ConductorFailure`, so the 

68 Procedure reaches a terminal state. Without a shared base the 

69 Conductor would need to import each body's private refusal, coupling 

70 the orchestrator to the acquisition bodies; a body signals "I will 

71 not do this" by subclassing, and the Conductor never learns why. 

72 

73 Raising one carries a promise that NOTHING was written yet. That is 

74 what makes it safe to treat as an ordinary recorded failure: a 

75 refusal thrown midway would leave the substrate half-configured 

76 while the record said only that the step failed, which is the 

77 situation the refusals exist to prevent. Subclasses must be raised 

78 before the body's first write, and their tests must assert that no 

79 write occurred. 

80 

81 Distinct from a `Control*Error`, which means the substrate refused 

82 or could not be reached: this means CORA refused, on its own reading 

83 of the request, without asking the substrate anything. 

84 """

87class UnboundedAcquisitionError(ActionRefusedError): 

88 """A detector acquisition body was asked for `repetitions=None` while it waits for completion. 

89 

90 Application-layer, not domain-layer: whether a given action body's 

91 done-poll can tolerate a free-running acquisition is a body-shape 

92 fact, not an aggregate invariant. `collect` and `continuous` both 

93 wait on `Acquire_RBV` reaching Done with no internal timeout 

94 (`cora.operation.acquisitions._await_acquire_done`), and an 

95 unbounded acquisition (areaDetector `ImageMode=Continuous`) never 

96 asserts Done on its own, so combining the two would hang the 

97 caller forever and leave the camera acquiring. Raised before any 

98 PV write so a caller who wants free-running acquisition never 

99 leaves the camera partially configured through this action body. 

100 """ 

101 

102 def __init__(self, detector: str) -> None: 

103 super().__init__( 

104 f"unbounded acquisition on {detector!r} cannot be combined with waiting for " 

105 "completion; a bounded repetitions value is required" 

106 ) 

107 self.detector = detector

112 

113 Application-layer, not domain-layer: whether the trigger EMITTER 

114 (the device named by `source`) is wired into this deployment is a 

115 configuration fact, not an aggregate invariant. `collect` and 

116 `continuous` write only the detector-side PVs (see the module 

117 docstring's "v1 detector-side / emitter-side split" in

123 external triggering never leaves the detector partially armed 

124 through this action body. 

125 """

131 "nobody arranged would hang"

156class ClosingCaptureBeforeBoundaryError(Exception): 

157 """A closing step's `CaptureRef` names a capture only the pre-boundary 

158 main steps declare. 

159 

160 `conduct_from` starts the per-conduct `captures` dict EMPTY: only the 

161 main steps from `boundary` onward re-run and can deposit into it (the 

162 same "fails loud rather than resolving against stale data" contract 

163 `execute_from` already holds for a main-step `CaptureRef`). Closing 

164 steps always run in full regardless of `boundary`, so a closing 

165 `CaptureRef` whose only declaring `CaptureStep` / capturing 

166 `ComputeStep` sits before `boundary` would resolve against nothing 

167 during THIS resume and fail as `UnresolvedCaptureRef` -- but inside 

168 `_run_closing`'s per-step isolation, that failure is recorded and the 

169 walk continues, silently converting a should-be-loud gap into a 

170 recorded-and-continue one. Checked up front instead, so the operator 

171 sees a 422 naming the missing capture and can pick a boundary at or 

172 before the declaring step, rather than a closing_failures entry after 

173 the fact. 

174 """ 

175 

176 def __init__(self, capture_name: str, boundary: int) -> None: 

177 super().__init__( 

178 f"closing step references capture {capture_name!r}, which only a " 

179 f"pre-boundary main step (boundary={boundary}) declares; resume " 

180 "starts captures empty, so this closing step would never see it" 

181 ) 

182 self.capture_name = capture_name 

183 self.boundary = boundary

186class UnsupportedClosingStepsError(Exception): 

187 """A loop-driving conduct slice refuses a closing-bearing Recipe (v1 scope). 

188 

189 `conduct_until_converged` / `conduct_until_advised` / `conduct_until_advised_from` 

190 each re-walk ONE pass block repeatedly (loop-top abort, per-iteration 

191 re-expansion); `_run_closing` runs once, on a real conduct terminal, and 

192 has no defined place in a loop that may never terminate the way `conduct` 

193 /`conduct_or_hold` do. Rather than silently drop the Recipe's closing 

194 steps or guess when to run them, these three slices refuse the request 

195 up front: well-formed, but this Recipe cannot be driven by a loop slice 

196 until closing-in-a-loop is designed. Mapped to HTTP 422 (operator- 

197 correctable: use `conduct` / `conduct_or_hold` for this Recipe, or 

198 author a closing-less variant for loop-driven conduct). 

199 """ 

200 

201 def __init__(self, procedure_id: UUID) -> None: 

202 super().__init__( 

203 f"procedure {procedure_id} is bound to a Recipe with closing_steps, " 

204 "which loop-driving conduct slices do not support" 

205 ) 

206 self.procedure_id = procedure_id
