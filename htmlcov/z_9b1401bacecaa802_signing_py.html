1"""Signature verification + signed-event-type registry. 

2 

3Implementation of Candidate F (signed events) per 

4[[project_signed_events_design]]. Ships the verification path and 

5the closed registry of event types that must be signed at write 

6time; the `Signer` port lives next door at 

7`cora.infrastructure.ports.signer`. 

8 

9No production signer adapter ships in this iteration. The verification 

10function works against any future adapter (Sigstore Fulcio, SPIFFE / SVID, 

11cloud KMS, local keystore) because the signature input is the same DSSE 

12PAE wrapper used by [[project_content_addressed_identity_design]] for 

13content hashing. One canonicalization profile, two consumers. 

14 

15## Algorithm 

16 

17EdDSA over Ed25519. Picked per the corpus survey: modal across 

18modern attestation ecosystems (Sigstore, in-toto, SLSA, age, Tailscale), 

19smaller signatures (64 bytes) than RSA-2048 (256 bytes), faster sign 

20(~50us) and verify (~150us) than RSA at typical CORA append rates. 

21 

22## Signature input 

23 

24`PAE(payload_type, canonical_body_bytes(payload))`, computed via the 

25shared helper in `cora.shared.content_hash`. The payloadType 

26URI binds the event type into the signature so a `DecisionRegistered` 

27signature can never collide with a different Agent-emitted event of a 

28future type even when their bodies happen to serialize to the same 

29bytes. 

30 

31## What is NOT here 

32 

33 - The `Signer` Protocol lives in `cora.infrastructure.ports.signer`. 

34 - Production signing adapters are deferred; iteration 3 lands one. 

35 - The verification function takes an explicit public-key resolver 

36 callable rather than depending on a kernel-wide registry. Resolvers 

37 are call-site-specific (read-time verify can use a different cache 

38 than write-time signing); composition stays explicit. 

39"""

55"""Closed set of event-type names that MUST be signed at write time. 

56 

57Initial set per [[project_signed_events_design]] (errata 2026-05-24): 

58 

59 - `DecisionRegistered`: produced by Agents AND by humans. Per the 

60 design lock the signing requirement applies only to the Agent- 

61 produced rows; the subscriber tier (CautionDrafter and 

62 RunDebriefer today) checks `actor_id` against the Agent BC's 

63 stable-id rule before invoking `Signer.sign`. Human-actor 

64 `DecisionRegistered` rows from the operator-driven 

65 `register_decision` slice stay unsigned. Both AI-agent 

66 subscribers route through this single entry: CautionDrafter 

67 emits `DecisionRegistered` with `context="CautionProposal"` 

68 (the Caution aggregate itself is created later via the 

69 operator-driven `promote_caution_proposal` slice), and 

70 RunDebriefer emits `DecisionRegistered` with its own context. 

71 

72Errata note: an earlier draft listed `CautionProposed` as a separate 

73entry on the assumption that CautionDrafter emitted a dedicated 

74Caution-aggregate event. It does not: the actual Caution-aggregate 

75events are `CautionRegistered`, `CautionSuperseded`, and 

76`CautionRetired`, none of which are AI-emitted directly. The 

77single `DecisionRegistered` entry above covers the CautionDrafter 

78signing case via the Agent-actor discriminator. 

79 

80Future Agent-BC event types land here by default. Expansion to 

81human-actor events requires a deliberate design lock per the 

82scientific-data corpus verdict. 

83"""

86def event_type_to_payload_type(event_type: str) -> str: 

87 """Map an event-type name to its payloadType URI. 

88 

89 `"DecisionRegistered"` -> `"application/vnd.cora.decision-registered+json"`. 

90 

91 Single source of truth shared between sign-side and verify-side so 

92 the PAE input is provably the same bytes on both paths. The 

93 function is event-type-agnostic; any CamelCase event-type name 

94 maps cleanly, including hypothetical future entries to 

95 SIGNED_EVENT_TYPES. 

96 """ 

97 kebab = _camel_to_kebab(event_type) 

98 return f"{EVENT_TYPE_PAYLOAD_TYPE_PREFIX}{kebab}{EVENT_TYPE_PAYLOAD_TYPE_SUFFIX}"

101def _camel_to_kebab(name: str) -> str: 

102 """Convert CamelCase event-type names to kebab-case payloadType slugs. 

103 

104 Internal helper. CORA event-type names are CamelCase by convention 

105 (`DecisionRegistered`, `RunStarted`, etc.); payloadType URIs follow 

106 the IANA media-type kebab-case convention. Acronym-aware: insert 

107 a dash before an uppercase letter when the previous char is 

108 lowercase (CamelCase boundary) OR when the next char is lowercase 

109 and the previous char was uppercase (last-letter-of-acronym 

110 boundary). So `MCPSessionOpened` becomes `mcp-session-opened`, 

111 not `m-c-p-session-opened`. 

112 """ 

113 if not name: 113 ↛ 114line 113 didn't jump to line 114 because the condition on line 113 was never true

114 return "" 

115 out: list[str] = [name[0].lower()] 

116 for i in range(1, len(name)): 

117 ch = name[i] 

118 prev = name[i - 1] 

119 nxt = name[i + 1] if i + 1 < len(name) else "" 

120 if ch.isupper() and (prev.islower() or (nxt != "" and nxt.islower())): 

121 out.append("-") 

122 out.append(ch.lower()) 

123 return "".join(out)

126class SignatureInvalidError(Exception): 

127 """The recorded signature does not verify against the recomputed bytes. 

128 

129 Critical: surfaces tampering, schema-evolution-without-payloadType 

130 bump, or key compromise. Surfaces as HTTP 422 at API boundary 

131 (read-time verify mode) or HTTP 500 in internal audit paths. 

132 """

157async def verify_signature( 

158 *, 

159 event_type: str, 

160 payload: Mapping[str, Any], 

161 signature: bytes, 

162 kid: str, 

163 resolve_public_key: Callable[[str], Awaitable[bytes]], 

164) -> None: 

165 """Verify a signature over an event payload. Raise on failure. 

166 

167 Recomputes the canonical-body-bytes from `payload` via the shared 

168 helper in `content_hash`, wraps in PAE with the payloadType derived 

169 from `event_type`, resolves the public key for `kid`, and verifies 

170 using Ed25519. Same bytes the signer signed; deterministic 

171 canonicalization profile guaranteed by the shared helper. 

172 

173 `resolve_public_key` is an async callable taking the `kid` and 

174 returning the raw 32 bytes of the Ed25519 public key. Call-site 

175 chooses the resolver (in-memory cache for hot verify paths, 

176 JWKS-backed for federated paths, etc.). 

177 

178 Raises: 

179 - `SignatureInvalidError`: signature does not verify 

180 """ 

181 payload_type = event_type_to_payload_type(event_type) 

182 body_bytes = canonical_body_bytes(payload) 

183 pae = pae_bytes(payload_type, body_bytes) 

184 public_key_bytes = await resolve_public_key(kid) 

185 try: 

186 public_key = Ed25519PublicKey.from_public_bytes(public_key_bytes) 

187 except ValueError as exc: 

188 raise SignatureInvalidError(event_type, kid, f"public key malformed: {exc}") from exc 

189 try: 

190 public_key.verify(signature, pae) 

191 except InvalidSignature as exc: 

192 raise SignatureInvalidError(event_type, kid) from exc

195async def verify_stream( 

196 events: Sequence[StoredEvent], 

197 *, 

198 resolve_public_key: Callable[[str], Awaitable[bytes]], 

199 strict: bool = False, 

200) -> None: 

201 """Verify every signed event in a loaded stream. Raise on first failure. 

202 

203 Audit-mode opt-in verification for callers reading from any 

204 `EventStore` adapter. The function takes the loaded sequence and a 

205 public-key resolver and walks the stream in order: 

206 

207 - When `event.signature_kid is not None`, calls `verify_signature` 

208 with the event's payload, signature, and kid. Raises 

209 `SignatureInvalidError` on the first row that fails. 

210 - When `event.signature_kid is None` AND `event.event_type` is in 

211 `SIGNED_EVENT_TYPES` AND `strict=True`, raises 

212 `SignatureMissingError` (audit-mode "no signed event went 

213 unsigned" check). 

214 - When `event.signature_kid is None` and either the event type 

215 is NOT in `SIGNED_EVENT_TYPES` or `strict=False`, the event is 

216 skipped silently. Pre-rollout events and human-actor rows are 

217 legitimately unsigned per the design lock's "AI-agent events 

218 signed, human-actor events not" stance. 

219 

220 The function is event-type-agnostic at the call signature; the 

221 `SIGNED_EVENT_TYPES` check is the registry-lookup that determines 

222 which rows must carry a signature. 

223 

224 Kept as a standalone helper rather than an `EventStore.load` flag 

225 so the port stays signing-unaware. Callers wanting opt-in 

226 verification compose: `events, _ = await store.load(...); 

227 await verify_stream(events, resolve_public_key=...)`. 

228 

229 `strict=True` is the audit-sweep default; production read paths 

230 that just need bytes (projection rebuilds, decider folds) leave it 

231 `False` so they don't pay the verify cost per row. 

232 

233 Raises: 

234 - `SignatureInvalidError`: a signed event's signature failed 

235 verification (tampering, key rotation drift, key compromise). 

236 - `SignatureMissingError`: only with `strict=True`, an event 

237 whose type is in SIGNED_EVENT_TYPES has no signature. 

238 """ 

239 for event in events: 

240 if event.signature_kid is not None: 

241 assert event.signature is not None, ( 

242 "events_signature_kid_consistency CHECK constraint guarantees " 

243 "both-or-neither; signature_kid set implies signature set" 

244 ) 

245 await verify_signature( 

246 event_type=event.event_type, 

247 payload=event.payload, 

248 signature=event.signature, 

249 kid=event.signature_kid, 

250 resolve_public_key=resolve_public_key, 

251 ) 

252 elif strict and event.event_type in SIGNED_EVENT_TYPES: 

253 raise SignatureMissingError(event.event_type)
