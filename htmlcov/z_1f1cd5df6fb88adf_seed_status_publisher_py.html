1"""Bootstrap-time seed for the StatusPublisher Agent. 

2 

3The StatusPublisher identity backs the external status page relay 

4(`cora.api._status_push`): a runtime that pushes a live snapshot of the 

5facility over a websocket to an external relay, since the 2-BM pilot has 

6no inbound reachability for a dashboard to pull from directly. Mirrors 

7`cora.agent.seed_run_witness.seed_run_witness_agent` verbatim except for 

8the per-agent constants below; the shared scaffolding lives in 

9`cora.agent._agent_seed`. 

10 

11 - Pinned UUID continues the numeric-mnemonic range at `4444`, the next 

12 unclaimed block after `3333` (CaptureProgressFeeder); deployment-stable 

13 forever. 

14 - DETERMINISTIC agent (rule-based, NOT LLM): no prompt template 

15 (`prompt_template_id=None`) and a Rule brain 

16 (`BrainRef.for_rule("StatusPublisher:v1")`). Never used to build an LLM: the runtime 

17 is a read-and-relay loop, not an LLM subscriber. 

18 - Authorization: `_status_push.py` reads across nine BCs to assemble the 

19 snapshot it relays: `ListPlans` (Recipe), `ListRuns` and 

20 `GetRunHistory` (Run), `ListSubjects` (Subject), `ListCampaigns` 

21 (Campaign), `ListDatasets` (Data), `ListProcedures` (Operation), 

22 `ListClearances` (Safety), `ListEnclosures` and `GetEnclosureHistory` 

23 (Enclosure), and `ListDecisions` (Decision). This identity only seeds 

24 the Agent record; `_status_push.py` still issues every one of those 

25 reads as `SYSTEM_PRINCIPAL_ID` and does not yet act as this agent. 

26 Switching it over, and granting this principal the eleven commands 

27 above under a real `TrustAuthorize` Policy, is separate follow-up 

28 work, not part of this seed. 

29"""
