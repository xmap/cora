1"""ConsequenceLookup port: cross-BC query for Trust BC's ratification-coverage 

2projection (consequence gate, Gate IV). 

3 

4Used by Run BC's `stop_run` handler to gate a consequence-classed command on the 

5presence of a GRANTED Ratification covering this action's scope 

6`(run_id, command_name)`. A second, independent principal must have granted the 

7co-signature before the action is admitted; absent that, the gate refuses and the 

8run is placed in the shared hold pending the co-sign. 

9 

10## Convention 

11 

12Mirrors `ClearanceLookup` exactly: one implementor (Trust BC ships 

13`PostgresConsequenceLookup` reading `proj_trust_ratification_coverage`), one 

14consumer today (Run's `stop_run`; more in-scope commands later). Lives in 

15`cora.infrastructure.ports` for neutral cross-BC access. The port is shaped around 

16the CONSUMER's need ("is this action co-signed?"), not Trust's domain language; 

17the adapter translates the projection's columns to this shape. 

18 

19## Coverage semantics 

20 

21"Covered" means: a Ratification exists with `status = 'Granted'`, `run_id = <the 

22run>`, and `command_name = <the gated command>`. The consequence-class trigger 

23(which commands require co-sign) is a static allowlist on the Run side 

24(`COMMANDS_REQUIRING_RATIFICATION`); this port answers ONLY the coverage question, 

25keeping the trigger and the lookup orthogonal. A log-folded first-of-kind 

26refinement of the trigger is a documented follow-up and does not change this 

27port's contract. 

28""" 

29
