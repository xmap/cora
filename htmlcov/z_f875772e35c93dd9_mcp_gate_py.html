1"""MCP write-tool gate for the post-review hardening Phase A.1. 

2 

3The MCP 2025-11-25 spec defines OAuth 2.1 at the transport layer 

4but does NOT propagate a verified principal to tool handlers 

5(the python-sdk's `@server.call_tool()` receives only name + 

6arguments; verified token / principal is not surfaced via the 

7session context). Every MCP write-tool in CORA therefore falls 

8back to `SYSTEM_PRINCIPAL_ID`, which collapses CORA's 

9operator-in-the-loop audit invariant for any MCP caller. 

10 

11Until the MCP TokenVerifier integration ships (Phase 8f-d), this 

12module **fail-closes** every MCP write-tool when the deployment 

13runs with `require_authenticated_principal=True` (the prod-only 

14posture enforced by `_enforce_production_principal_policy` in 

15`api.main`). In that mode the MCP surface still serves read-only 

16tools (audit + operator dashboards) but every write tool is 

17deregistered at server-build time, so it never appears in 

18`tools/list` and cannot be called. 

19 

20In dev / test (`require_authenticated_principal=False`), all 

21tools register normally because the SYSTEM-fallback principal is 

22already the documented dev / test posture for REST as well; MCP 

23and REST share the same auth posture. 

24 

25## Read-only classification 

26 

27A tool is read-only if its name starts with `get_` or `list_` OR 

28appears in `_EXPLICIT_READS`. The prefix convention covers 34 of 

2936 read-only tools; the explicit set carries the remaining 

30exceptions (today: `evaluate_policy`, a Trust BC query that does 

31not write events). 

32 

33A future tool that does NOT match either rule is treated as a 

34write and gated off in prod. To add a new read-only tool, either 

35name it with a read prefix OR extend `_EXPLICIT_READS`. 

36 

37## Sources 

38 

39 - MCP 2025-11-25 Authorization spec: 

40 https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization.md 

41 - Python MCP SDK README: 

42 https://github.com/modelcontextprotocol/python-sdk 

43 - OWASP Secure Coding Practices (fail-closed for unauth'd writes) 

44 - NIST SP 800-204 (microservices security; default-deny) 

45 

46## Lifecycle 

47 

48Once MCP TokenVerifier integration lands (Phase 8f-d), each 

49tool's `register(...)` will extract a real principal from the 

50session context, the SYSTEM-fallback path disappears, and this 

51module becomes obsolete. Delete it then; do not keep it as 

52defense-in-depth (that would silently mask future MCP-auth bugs). 

53"""

79def is_read_only_tool(name: str) -> bool: 

80 """True iff the MCP tool with this name is a read-only query.""" 

81 return name in _EXPLICIT_READS or name.startswith(_READ_ONLY_PREFIXES)

84def gate_mcp_write_tools(mcp: FastMCP, settings: Settings) -> None: 

85 """Deregister every MCP write-tool when MCP-auth is not yet wired. 

86 

87 The gate fires when `require_authenticated_principal` is True 

88 (the prod-only posture). In that mode every non-read-only tool 

89 is removed from the FastMCP server's tool manager so it never 

90 appears in `tools/list` and cannot be invoked. 

91 

92 Uses `mcp._tool_manager.list_tools()` (sync) rather than 

93 `await mcp.list_tools()` (async) so the gate can run inside 

94 `create_app()`'s sync construction path. ToolManager is the 

95 public MCP SDK class behind FastMCP's facade; the private- 

96 attribute access is acceptable here because this whole module 

97 is a hardening shim slated for deletion at Phase 8f-d. 

98 

99 Idempotent and safe to call once after all `register_*_tools` 

100 calls have completed; no-op when `require_authenticated_principal` 

101 is False (dev / test). 

102 """ 

103 if not settings.require_authenticated_principal: 

104 return 

105 

106 tools = mcp._tool_manager.list_tools() # pyright: ignore[reportPrivateUsage] 

107 removed: list[str] = [] 

108 for tool in tools: 

109 if not is_read_only_tool(tool.name): 

110 mcp.remove_tool(tool.name) 

111 removed.append(tool.name)

117 "require_authenticated_principal=True but MCP TokenVerifier " 

118 "integration not yet wired; write-tools fail-closed until " 

119 "Phase 8f-d. Use REST endpoints for write operations." 

120 ), 

121 count=len(removed), 

122 tools=sorted(removed), 

123 )
