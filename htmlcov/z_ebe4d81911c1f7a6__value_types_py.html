1"""Equipment-BC-aggregate-shared relational-ref NewType aliases. 

2 

3Mirrors `cora.federation.aggregates._value_types` (CredentialId, 

4FacilityId). Equipment's first entry is `RoleId`, the relational 

5reference between the new Role aggregate (Layer 3 of 

6[[project-role-aggregate-design]]) and downstream consumers 

7(Family.presents_as, Assembly.presents_as, RoleRequirement.role_kind, 

8Capability.suggested_roles). RoleId lives here, not at 

9`cora.shared.identity`, for the same reason CredentialId does: the 

10fold-symmetry fitness test consumes `cora.shared.identity` as its 

11attribution-NewType allowlist, and a relational-ref NewType placed 

12there would pollute the test's semantics (the test would demand a 

13paired `*_at` timestamp for every `*_by` field, which is wrong for a 

14ref that is not a who-claims-a-fact attribution). 

15 

16NewType is preferred over `TypeAlias` because the wrapper is a true 

17distinct type at type-check time (pyright rejects `UUID -> RoleId` 

18without an explicit `RoleId(uuid)` call) while remaining a zero-cost 

19identity function at runtime. 

20 

21Future hoist trigger: when a second Equipment-BC relational-ref 

22NewType lands (rule-of-three relative to the Federation precedent's 

232-entry seed; Equipment is at 1 today), the module name `_value_types` 

24already matches the established convention and no rename is needed. 

25"""
