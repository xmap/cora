1"""The record exporter's operator command (S5d). 

2 

3`python -m cora.api.record_bundle_export DESTINATION` produces, from ONE 

4database snapshot, both bundles a record export can be: the full, 

5unredacted bundle under `DESTINATION/full/`, and the published, 

6redacted projection under `DESTINATION/published/`. It replaces the 

7ad-hoc script that produced the only bundle pair ever built from a live 

8database (still on the pilot host at 

9`/home/beams0/2BMB/dgursoy/cora-postdeploy-verify/{full,published}`), 

10whose two-bundle shape this command keeps but whose hand-wiring and 

11lack of a shared snapshot it does not. 

12 

13## Why both, always 

14 

15`_shell.export_bundle` produces only the full, unredacted bundle: it 

16calls `build_manifest(record, git_commit=...)` with no `redaction`, so 

17H3 (`published_record_hash`) is `None` and nothing is tokenized or 

18dropped. A command that could produce only that bundle, under a name an 

19operator reads as "make the record," is a disclosure hazard: nothing 

20about running it would tell a future operator that what they hold is 

21not publishable. This command removes the failure mode structurally 

22rather than flagging it after the fact -- there is no flag that selects 

23"just the full bundle," so there is nothing to default to accidentally. 

24Both bundles land at fixed, distinctly named paths every run. 

25 

26## Why one snapshot 

27 

28`full/` and `published/` are the same underlying rows under two 

29projections (H1 over the raw record, H3 over the redacted one). If they 

30came from two different `export_record` calls, "the published bundle is 

31a redaction of the full bundle" would not be true of the pair on disk, 

32and H1-versus-H3 comparison would stop meaning anything. This command 

33therefore calls `export_record` exactly once, inside one `REPEATABLE 

34READ READ ONLY` transaction, and builds both manifests and both bundles 

35from that single in-memory `ExportedRecord` after the transaction 

36closes -- the same reason `_shell.export_bundle`'s transaction cannot 

37live inside `export_record` itself: `capture_git_commit` shells out to 

38git and `write_bundle` does blocking multi-file disk I/O, and holding a 

39`REPEATABLE READ` snapshot open across either pins the database's xmin 

40horizon and blocks autovacuum cluster-wide for as long as they take. 

41 

42## Refusals, not tracebacks 

43 

44Three conditions are operator mistakes, not bugs, and are reported as a 

45clean refusal with no bundle written and no traceback: 

46 

47 - `BundleDestinationNotEmptyError`: `DESTINATION/full/` or 

48 `DESTINATION/published/` already holds something. Checked for BOTH 

49 slots before the database is touched at all, so a mistake on one 

50 slot is caught before the other slot's write, or the export itself, 

51 ever starts. 

52 - `EmptyExportError`: the database has zero events below the captured 

53 watermark. 

54 - `RedactionProfileMismatchError`: this checkout's disposition table 

55 does not hash to what `redact_record` was told to expect. Reachable 

56 only if a future caller stops self-supplying `hash_redaction_profile()` 

57 as its own expectation (see `export_record_bundles`'s body); handled 

58 here defensively regardless, per 

59 `project_record_completeness_design.md`'s S5d traps. 

60 

61All three are checked before EITHER `write_bundle` call runs (the two 

62destination checks before the pool even opens; `EmptyExportError` and 

63`RedactionProfileMismatchError` both fire while only manifests, not 

64bundles, exist), so "no bundle written" holds for all three without 

65needing the two writes themselves to be atomic as a pair. 

66 

67Any other exception (a database connectivity failure, a coding defect) 

68is not caught here and surfaces as a traceback: only operator-shaped 

69conditions are softened. `LogbookKindRowCountMismatchError` (S2b, raised 

70from inside `build_manifest`) is deliberately NOT a fourth refusal: an 

71`included` kind's independent row count disagreeing with what the 

72traversal actually exported is not an operator mistake like the three 

73conditions above, so it is not softened into a "refused" line the same 

74way. It still fires before either `write_bundle` call (both manifests 

75are built up front), so "no bundle written" holds for it too. Unlike the 

76three refusals, though, this is not always evidence of a code defect: 

77`capture_source_row_count_by_logbook_kind`'s own docstring names a 

78benign, concurrency-driven cause specific to envelope-scoped kinds (a 

79straggling transaction elsewhere pinning the stream walk's xmin 

80watermark below this export's own snapshot), which a plain retry -- a fresh 

81watermark against a fresh snapshot -- will usually not reproduce. A 

82divergence that reproduces across a retry is the one worth escalating as 

83a real omission; treat one occurrence as "retry once, then look closer," 

84not as an incident on its own. Residual worth naming: if `write_bundle` ever 

85raised `ManifestRecordMismatchError` on the SECOND call (`published/`), 

86after the first call (`full/`) already succeeded, this function would 

87propagate that traceback with `full/` already complete on disk and 

88`published/` absent. Today that pairing cannot actually disagree -- 

89`full_manifest` and `published_manifest` are both built from the same 

90`record` in the same call, immediately before each write -- so this is 

91a structural guarantee, not a runtime check, and it would take a future 

92edit that decouples manifest-building from record-being-written to 

93reopen it. A crash with a visible traceback is not the disclosure 

94hazard this command exists to close either way: nothing about a lone, 

95plainly-named `full/` directory and a stack trace reads as "here is 

96your publishable bundle." 

97 

98## The report is a measurement, not a fourth argument 

99 

100Three consecutive slices (S5a, S5b, S5c) argued that a single-round-trip 

101unscoped read was acceptable without ever running one against a 

102populated database. The report this command prints states, per 

103registered logbook kind, its `extent` status, its exported row count, its 

104independent source row count (S2b's `source_row_count`; the two can only 

105ever agree by the time either reaches this report, since `build_manifest` 

106raises before printing anything if they don't), and the wall-clock time 

107`export_record` spent reading it (`ExportedRecord.read_seconds_by_logbook_kind`, 

108added in `_export.py` for S5d: it is the only place with a seam onto each 

109individual `spec.reader` / `spec.unscoped_reader` call), plus each 

110bundle's total byte count and the command's total elapsed time. Counts 

111and timings only: no row contents are printed. 

112 

113## Exit codes 

114 

115 - `0`: both bundles written. 

116 - `2`: refused. One of the three conditions above; the message printed 

117 names which. 

118 

119Nothing else is defined; an uncaught exception exits via Python's own 

120non-zero status, not one of these two. 

121"""

167@dataclass(frozen=True, slots=True) 

168class _KindLine: 

169 """One `extent_by_logbook_kind` row of the printed report.""" 

170 

171 kind: str 

172 status: str 

173 exported_row_count: int 

174 source_row_count: int | None 

175 """The independent unscoped `count(*)` (S2b), or `None` for a kind 

176 whose status left it absent from `source_row_count_by_logbook_kind` -- see 

177 `LogbookKindExtent.source_row_count`. An `included` kind reaching this 

178 report already agrees with `exported_row_count`: `build_manifest` 

179 raises `LogbookKindRowCountMismatchError` before either bundle is written 

180 if the two disagree, so a divergence never reaches a printed report.""" 

181 read_seconds: float | None 

182 """`None` for a kind never read this export (`untraversed`, or an 

183 `included` envelope-driven kind whose envelope never occurred, which 

184 is a genuine zero read rather than an unknown one -- see 

185 `_kind_lines`). Otherwise the summed wall-clock time 

186 `export_record` spent reading it.""" 

187 

188 def render(self) -> str: 

189 read = "n/a" if self.read_seconds is None else f"{self.read_seconds:.3f}s" 

190 source = "n/a" if self.source_row_count is None else str(self.source_row_count) 

191 return ( 

192 f" {self.kind:<15} status={self.status:<11} " 

193 f"rows={self.exported_row_count:<8} source={source:<8} read={read}" 

194 )

197@dataclass(frozen=True, slots=True) 

198class _Report: 

199 git_commit: str 

200 watermark: int 

201 kinds: tuple[_KindLine, ...] 

202 full_destination: Path 

203 published_destination: Path 

204 full_bundle_bytes: int 

205 published_bundle_bytes: int 

206 elapsed_seconds: float 

207 

208 def render(self) -> str: 

209 lines = [ 

210 "record bundle export", 

211 f" git_commit={self.git_commit} watermark={self.watermark}", 

212 *(line.render() for line in self.kinds), 

213 f" full bundle: {self.full_destination} ({self.full_bundle_bytes} bytes)", 

214 f" published bundle: {self.published_destination} " 

215 f"({self.published_bundle_bytes} bytes)", 

216 f" elapsed: {self.elapsed_seconds:.3f}s", 

217 ] 

218 return "\n".join(lines)

221def _refuse_if_occupied(destination: Path) -> None: 

222 """Mirrors `write_bundle`'s own non-empty-destination check, run for 

223 one bundle slot. Called for BOTH slots before either write, and 

224 before the database is touched, so an operator mistake on one slot 

225 never costs a real export attempt.""" 

226 destination.mkdir(parents=True, exist_ok=True) 

227 if any(destination.iterdir()): 

228 raise BundleDestinationNotEmptyError(destination)

231def _bundle_bytes(destination: Path) -> int: 

232 return sum(path.stat().st_size for path in destination.rglob("*") if path.is_file())

235def _kind_lines(record: ExportedRecord, manifest: Manifest) -> tuple[_KindLine, ...]: 

236 """`exported_row_count` and `source_row_count` come straight off the 

237 manifest's own `extent_by_logbook_kind` rather than being recomputed 

238 from `record` here: the manifest already carries both (S2b), and 

239 `record` is only still needed for `read_seconds_by_logbook_kind`, which 

240 has no manifest-side home.""" 

241 lines: list[_KindLine] = [] 

242 for kind in sorted(manifest.extent_by_logbook_kind): 

243 extent = manifest.extent_by_logbook_kind[kind] 

244 read_seconds = ( 

245 record.read_seconds_by_logbook_kind.get(kind, 0.0) 

246 if extent.status == LogbookKindExtentStatus.INCLUDED 

247 else None 

248 ) 

249 lines.append( 

250 _KindLine( 

251 kind=kind, 

252 status=extent.status.value, 

253 exported_row_count=extent.exported_row_count, 

254 source_row_count=extent.source_row_count, 

255 read_seconds=read_seconds, 

256 ) 

257 ) 

258 return tuple(lines)

261async def export_record_bundles(*, destination: Path, database_url: str | None = None) -> int: 

262 """Run the command. `database_url` overrides the Settings value so 

263 the integration tier can point a run at its per-test database; the 

264 CLI always uses the deployment's own configuration. 

265 

266 See the module docstring for the one-snapshot, both-bundles, 

267 refuse-cleanly design this function implements. 

268 """ 

269 full_dir = destination / FULL_DIRNAME 

270 published_dir = destination / PUBLISHED_DIRNAME 

271 try: 

272 _refuse_if_occupied(full_dir) 

273 _refuse_if_occupied(published_dir) 

274 except _REFUSAL_ERRORS as exc: 

275 print(f"refused: {exc}") 

276 return _EXIT_REFUSED 

277 

278 settings = Settings() 

279 pool = await create_pool( 

280 database_url if database_url is not None else settings.database_url, 

281 min_size=1, 

282 max_size=4, 

283 ) 

284 started = time.perf_counter() 

285 try: 

286 try: 

287 async with pool.acquire() as conn: 

288 pg_conn: asyncpg.Connection = conn # type: ignore[assignment] 

289 async with pg_conn.transaction(isolation="repeatable_read", readonly=True): 

290 record = await export_record(pg_conn) 

291 source_row_count_by_logbook_kind = ( 

292 await capture_source_row_count_by_logbook_kind(pg_conn) 

293 ) 

294 

295 git_commit = capture_git_commit() 

296 full_manifest = build_manifest( 

297 record, 

298 git_commit=git_commit, 

299 source_row_count_by_logbook_kind=source_row_count_by_logbook_kind, 

300 ) 

301 redaction = redact_record( 

302 record, expected_redaction_profile_hash=hash_redaction_profile() 

303 ) 

304 published_manifest = build_manifest( 

305 record, 

306 git_commit=git_commit, 

307 source_row_count_by_logbook_kind=source_row_count_by_logbook_kind, 

308 redaction=redaction, 

309 ) 

310 

311 write_bundle(record, full_manifest, full_dir) 

312 write_bundle(redaction.redacted_record, published_manifest, published_dir) 

313 except _REFUSAL_ERRORS as exc: 

314 print(f"refused: {exc}") 

315 return _EXIT_REFUSED 

316 finally: 

317 await pool.close() 

318 

319 report = _Report( 

320 git_commit=git_commit, 

321 watermark=record.watermark, 

322 kinds=_kind_lines(record, full_manifest), 

323 full_destination=full_dir, 

324 published_destination=published_dir, 

325 full_bundle_bytes=_bundle_bytes(full_dir), 

326 published_bundle_bytes=_bundle_bytes(published_dir), 

327 elapsed_seconds=time.perf_counter() - started, 

328 ) 

329 print(report.render()) 

330 return _EXIT_CLEAN

333def build_parser() -> argparse.ArgumentParser: 

334 """The CLI surface, separate from `main` so tests can pin the 

335 destination without touching a database.""" 

336 parser = argparse.ArgumentParser( 

337 prog="python -m cora.api.record_bundle_export", 

338 description=( 

339 "Export CORA's record as two bundles from one database " 

340 f"snapshot: an unredacted bundle under DESTINATION/{FULL_DIRNAME}/ " 

341 f"and the published, redacted projection under " 

342 f"DESTINATION/{PUBLISHED_DIRNAME}/. Always writes both, so which " 

343 "one an operator has is never a guess. Refuses cleanly, writing " 

344 "nothing, if either subdirectory already holds anything, if " 

345 "the database has nothing to export, or if this checkout's " 

346 "redaction disposition table does not hash to what it expects." 

347 ), 

348 ) 

349 parser.add_argument( 

350 "destination", 

351 type=Path, 

352 help=f"Directory to hold {FULL_DIRNAME}/ and {PUBLISHED_DIRNAME}/.", 

353 ) 

354 return parser
