1"""TransferPort: CORA's domain-shaped seam for moving a dataset's bytes. 

2 

3`TransferPort` is the async Protocol the conducting engine uses to begin a 

4bulk byte movement, observe its progress, and cancel it. It is owned and 

5shaped by CORA, from what CORA's own domain needs: the engine has to start a 

6move, watch a possibly long-running move toward a terminal, and learn whether 

7every byte arrived so the Data BC can mark the landed `Distribution` verified. 

8Concrete substrates (a Globus transfer task, the APS Data Management DAQ 

9service, an S3 copy) are OUTSIDE adapters that get tested against this shape 

10later; they do not define it. An adapter translates the substrate's wire 

11vocabulary into the CORA-owned value types below, the same ACL posture the 

12control and compute adapters take. 

13 

14This is the data-movement member of CORA's actuation seam, alongside 

15`ControlPort` (drive hardware) and `ComputePort` (drive a compute job). All 

16three are seams the engine reaches across to actuate the outside world; per 

17the seam model, moving bytes through Globus is the same posture as driving a 

18motor through EPICS, not a competition with it. The three are siblings in 

19role, not copies in shape: a transfer is neither value-IO nor a single job, 

20so its surface is its own. 

21 

22## Earned, not minted 

23 

24There is no production consumer yet. This port exists to finalize the design 

25triage (is a transfer a step the conductor walks, or a long-running edge job 

26with its own lifecycle?), and ships with a test double only. A real adapter 

27(Globus first) and the executing aggregate land when the build trigger fires: 

28a promote or publish rule that blocks on a transfer outcome, an in-path 

29substrate with a native partial terminal, or a custody chain the existing 

30`Attestation` path cannot carry. Until then this is a spike, not a merge. 

31 

32## Why `begin` / `observe` / `cancel`, not blocking submit-and-await 

33 

34`ComputePort` blocks (`submit` then `await_terminal_state`) because a compute 

35job is bounded: a reconstruction runs for minutes and the engine can hold the 

36call open. A transfer is different in kind. It can be large, slow, and partial: 

37a sync of an experiment directory may move for hours, may stall waiting for a 

38credential to be renewed, and may finish with most files moved but a few 

39failed. So the engine does not block on a transfer; it begins one, gets back 

40an opaque handle, and observes that handle on its own cadence until the 

41progress reports a terminal state. That non-blocking begin-then-observe shape 

42is the whole reason a transfer wants a long-running edge job rather than a 

43synchronous step. 

44 

45## Out of scope (deferred, each with its trigger) 

46 

47- A routing registry / multi-substrate dispatch. Triggers at the second real 

48 adapter, exactly as ControlPort earned its registry from a third substrate. 

49- A `PartiallyFailed` terminal state. The first real substrate (Globus) has no 

50 native partial terminal: a sync that skips unchanged files still ends 

51 succeeded, and a genuine partial appears only as a failed terminal carrying 

52 a non-zero failed-file count. So partial-ness is carried on `TransferProgress` 

53 (a terminal `Failed` with `files_failed > 0` and `files_moved > 0`), not as 

54 an enum value, until an adapter with a native partial terminal earns it. 

55- Resume of an interrupted transfer. Does not generalize across substrates 

56 (a directory sync re-derives its own delta; a single-file move restarts); 

57 capability-flagged when a substrate needs it. 

58 

59## Actuation kind 

60 

61`ActuationKind` (Physical / Simulated / Hybrid) is deliberately NOT on this 

62surface. It is a property of the ROUTE a move is dispatched to, not of the 

63port, so the engine observes it from the routing table the same way the 

64control path does, never from the transfer adapter class. A rehearsal move on 

65a simulated route taints its output exactly as a simulated control episode 

66does. 

67 

68## Integrity 

69 

70`verify_on_arrival` asks the substrate to self-check that the bytes that 

71landed match the source and re-move on mismatch. It is a convenience that 

72fails a bad move early. It does NOT replace CORA's authoritative custody 

73record: the landed `Distribution` becomes verified only through the Data BC's 

74`Attestation` path (`ChecksumVerifier`), which walks the bytes CORA can see. 

75 

76## Exceptions 

77 

78Six exception families describe the move's failure modes. `TransferPort` is 

79not REST-accessible; the executing edge job captures these as event-payload 

80metadata per the non-determinism principle, never as HTTP errors. 

81"""

89TransferHandle = NewType("TransferHandle", str) 

90"""Opaque substrate handle to one begun move, returned by `begin`. 

91 

92The substrate mints it (a Globus task id, a DM DAQ directory key, an S3 copy 

93token); the engine treats it as an opaque correlation key it passes back to 

94`observe` and `cancel`, and snapshots onto the edge job's event for audit. A 

95separate CORA-supplied `idempotency_key` on the request (not this handle) is 

96what makes a retried `begin` safe. 

97"""

100class TransferState(StrEnum): 

101 """The coarse lifecycle of one move, as CORA needs to drive its edge job. 

102 

103 Adapters MAP a substrate's own statuses into these; the set is CORA's, not 

104 any substrate's. There is one in-flight value, one intervention value, and 

105 three terminals. 

106 

107 `Pending`: begun and accepted, not yet observed moving. 

108 `Active`: bytes are moving. 

109 `Suspended`: stalled and will not continue without intervention (the 

110 canonical cause is an expired credential on a long sync). NOT a 

111 terminal: a renewed credential returns it to `Active`. 

112 `Succeeded`: the move finished and every in-scope byte arrived. A sync that 

113 skipped unchanged files still ends here. 

114 `Failed`: the move reached a terminal without full success. This carries 

115 BOTH the total-failure case (`files_moved == 0`) and the partial case 

116 (`files_moved > 0` and `files_failed > 0`); the counts on 

117 `TransferProgress` tell them apart. A caller-issued `cancel` also lands 

118 here unless the substrate distinguishes it (see `Cancelled`). 

119 `Cancelled`: the move stopped because the engine asked it to. Distinct from 

120 `Failed` so an operator reads "we stopped this" differently from "this 

121 broke," for substrates that report the difference. 

122 """ 

123 

124 PENDING = "Pending" 

125 ACTIVE = "Active" 

126 SUSPENDED = "Suspended" 

127 SUCCEEDED = "Succeeded" 

128 FAILED = "Failed" 

129 CANCELLED = "Cancelled" 

130 

131 @property 

132 def is_terminal(self) -> bool: 

133 """True for the three end states; False for Pending / Active / Suspended. 

134 

135 Suspended is explicitly non-terminal: it is the long-sync intervention 

136 state the engine waits through, not an end the edge job folds on. 

137 """ 

138 return self in {TransferState.SUCCEEDED, TransferState.FAILED, TransferState.CANCELLED}

141@dataclass(frozen=True) 

142class TransferRequest: 

143 """What CORA asks a substrate to move, in CORA's own vocabulary. 

144 

145 `source` and `destination` are CORA location strings the routed adapter 

146 parses (a Globus `endpoint_id:/path`, a DM `@host:/path`, an `s3://` 

147 URI); at v1 they are plain strings, promoted to a typed location sum at 

148 the second-substrate trigger, the same path `ControlPort.address` reserves. 

149 `recursive` declares the source is a directory tree, not a single file. 

150 `skip_unchanged` asks the substrate not to re-move bytes already present and 

151 identical at the destination (a re-sync of an experiment directory). 

152 `verify_on_arrival` asks the substrate to self-check integrity and re-move 

153 on mismatch (see module docstring: this does not replace the Attestation 

154 record). `label` is an operator-facing name for the move. `idempotency_key` 

155 is a CORA-minted key that lets a retried `begin` dedupe at the substrate 

156 instead of starting a duplicate move, so a replay stays deterministic. 

157 """ 

158 

159 source: str 

160 destination: str 

161 recursive: bool = False 

162 skip_unchanged: bool = False 

163 verify_on_arrival: bool = False 

164 label: str | None = None 

165 idempotency_key: str | None = None

168@dataclass(frozen=True) 

169class TransferProgress: 

170 """A snapshot of one move, returned by `observe`. 

171 

172 Carries the lifecycle `state` plus the coarse counts CORA needs to fold 

173 onto its edge job and show an operator. `files_total` is None until the 

174 substrate has finished scanning (it can grow as a recursive move discovers 

175 directories). `files_skipped` counts unchanged files a `skip_unchanged` 

176 move did not re-move. `files_failed` is the partial signal: on a terminal 

177 `Failed` state, `files_failed > 0` with `files_moved > 0` is a partial 

178 move, while `files_moved == 0` is a total failure. `detail` carries the 

179 substrate's human-readable sub-status (a stall reason, a fatal-error 

180 summary) for the operator-facing record. 

181 """ 

182 

183 state: TransferState 

184 bytes_moved: int = 0 

185 files_total: int | None = None 

186 files_moved: int = 0 

187 files_skipped: int = 0 

188 files_failed: int = 0 

189 detail: str | None = None 

190 

191 @property 

192 def is_partial(self) -> bool: 

193 """True for a terminal `Failed` that nonetheless moved some files. 

194 

195 The carried-on-counts stand-in for a native `PartiallyFailed` terminal 

196 (deferred until a substrate reports one). Lets a consumer separate 

197 "moved most of it, some failed" from "moved nothing." 

198 """ 

199 return self.state is TransferState.FAILED and self.files_moved > 0 and self.files_failed > 0

282@runtime_checkable 

283class TransferPort(Protocol): 

284 """CORA-owned seam for moving a dataset's bytes across a substrate. 

285 

286 Substrate-agnostic. Concrete adapters (a future `GlobusTransferPort`, 

287 `DmDaqTransferPort`, `S3TransferPort`) implement the wire details and map 

288 their statuses into `TransferState`; the engine never touches a 

289 substrate-specific symbol. Non-blocking by design: `begin` returns a handle 

290 and the engine `observe`s it to a terminal on its own cadence, because a 

291 transfer can be long-running, can suspend mid-flight, and can finish 

292 partially. A routing registry, a native partial terminal, and resume are 

293 deferred to their own triggers (see module docstring). 

294 """ 

295 

296 async def begin(self, request: TransferRequest) -> TransferHandle: 

297 """Begin the move described by `request` and return its handle. 

298 

299 Returns as soon as the substrate accepts the move (a submitted task, a 

300 started sync). Raises `TransferRejectedError` if the substrate refuses 

301 the request, `TransferEndpointUnreachableError` if a substrate is 

302 unreachable, `TransferAccessDeniedError` on a permission denial, or 

303 `NoRouteForLocationError` if no adapter route matches a location. 

304 """ 

305 ... 

306 

307 async def observe(self, handle: TransferHandle) -> TransferProgress: 

308 """Return a current `TransferProgress` snapshot for `handle`. 

309 

310 Non-blocking: reports wherever the move is now (`Pending` / `Active` / 

311 `Suspended` or a terminal), so the engine polls on its own cadence 

312 rather than holding a call open. Raises 

313 `TransferEndpointUnreachableError` or `TransferAccessDeniedError` if the 

314 status cannot be read, `TransferTimeoutError` if the adapter's status 

315 call itself times out, or `TransferIntegrityError` when the substrate 

316 definitively reports a verify-on-arrival mismatch. 

317 """ 

318 ... 

319 

320 async def cancel(self, handle: TransferHandle) -> None: 

321 """Ask the substrate to stop the move identified by `handle`. 

322 

323 Best-effort and idempotent: cancelling an already-terminal move is a 

324 no-op. A successfully cancelled move is observed as `Cancelled` (or 

325 `Failed` on a substrate that does not distinguish the two). 

326 """ 

327 ... 

328 

329 async def aclose(self) -> None: 

330 """Release any substrate resources; idempotent. 

331 

332 Provided so composition code can `aclose()` any `TransferPort` without 

333 branching on type, the same affordance the control and compute ports 

334 offer. A dict-backed test double is a no-op. 

335 """
