1"""SupplyLookup port: cross-BC query for Supply BC's status projection. 

2 

3Used by Run BC's `start_run` handler and Operation BC's 

4`start_procedure` handler to gate Run / Procedure start on the 

5presence of at least one AVAILABLE Supply for every kind that the 

6governing Method declared in its `needed_supplies` field. 

7 

8## Convention 

9 

10Third cross-BC port (after `Authorize` and `ClearanceLookup`, 

11mirrored by `CautionLookup`): one implementor (Supply BC ships 

12`PostgresSupplyLookup` reading `proj_supply_summary`), multiple 

13consumers (Run today; Operation alongside). Lives in 

14`cora.infrastructure.ports` per the existing pattern. Shaped around 

15the consumer's need (the start-time gate needs "which Supplies of 

16each requested kind are registered, and in what status?"); the 

17adapter translates Supply BC's projection columns to this shape. 

18 

19## Available-only semantics 

20 

21The decider, not this port, gates on `status == SupplyStatus.AVAILABLE`. 

22The port returns every matching Supply regardless of status so the 

23decider can produce a useful diagnostic ("LiquidNitrogen has a 

24Supply but it's Unavailable") distinct from absence ("no LN2 Supply 

25registered at all"). Decommissioned rows are filtered at the query 

26layer per [[project_deregister_supply_design]] (tombstones should 

27not count toward gate satisfaction). See 

28[[project_supply_preflight_gate_design]] for the shared decision. 

29"""

38class SupplyLookupResult: 

39 """Summary row from `proj_supply_summary` for cross-BC consumers. 

40 

41 Carries the minimal columns the cross-BC consumers (Run / Operation 

42 pre-flight gate; Data BC register_distribution + default-storage-supply 

43 bootstrap; future Trust BC credential rotation) need to make their 

44 decisions and produce diagnostics. Loaded by the handler via 

45 `SupplyLookup.find_supplies_by_kind` (grouped query), 

46 `SupplyLookup.lookup` (single-id query), or 

47 `SupplyLookup.find_supplies_by_name` (by natural-key attributes) and 

48 handed to the consumer's decider. 

49 

50 `status` is the StrEnum value as a plain string (matches the 

51 projection's `TEXT` column); consumers treat it opaquely and 

52 partition on `"Available"` (pre-flight gate) or pass it through 

53 (register_distribution status-agnostic bind). 

54 

55 `kind` is the bare-str Supply.kind value (today; future closed-StrEnum 

56 move per Supply BC's own roadmap). Distribution's register decider 

57 gates on `kind == "Storage"`. 

58 

59 `facility_code` carries the resolved Facility code of the Supply's 

60 owning Facility (added for the Data BC register_distribution 

61 consumer + future federation use cases). Bare str on the wire per 

62 [[project-facility-aggregate-design]] convention. 

63 

64 `supply_id` is typed `UUID` for cross-port symmetry with 

65 `ClearanceLookupResult.clearance_id` and `CautionLookupResult.caution_id`. 

66 """

83 """Return Supplies grouped by kind for every requested kind. 

84 

85 The returned mapping is keyed by kind string and contains 

86 ONLY the kinds for which at least one non-Decommissioned 

87 Supply is registered. Kinds with no registered Supply are 

88 absent from the mapping (the decider treats absence as a 

89 missing-kind rejection distinct from a no-Available 

90 rejection). 

91 

92 Decommissioned Supplies are filtered out at the query layer: 

93 tombstones do not count toward satisfaction. Operators who 

94 deregister a typo-Supply do not see that row contributing to 

95 a satisfied gate. 

96 

97 Empty input (`kinds = frozenset()`) returns an empty 

98 mapping; the handler should short-circuit before calling the 

99 port for Methods with no `needed_supplies`.

103 async def lookup(self, supply_id: UUID) -> SupplyLookupResult | None: 

104 """Return the projection row for `supply_id`, or `None` if not found. 

105 

106 Consumers needing to validate a specific supply (the Data BC 

107 register_distribution handler being the first such consumer) 

108 use this single-id query in preference to the grouped 

109 find_supplies_by_kind interface. 

110 

111 Supplies in EVERY status are returned (Available, Degraded, 

112 Unavailable, Recovering, Decommissioned); the consumer 

113 decider partitions on `status` if it needs to distinguish 

114 "no Supply at all" from "Supply exists but in non-Available 

115 state". register_distribution intentionally accepts every 

116 status because a Distribution can legitimately be registered 

117 against a Decommissioned Supply for archival completeness; 

118 only `kind` is gated. 

119 

120 Mirrors `AssetLookup.lookup` shape one-for-one for cross-port 

121 symmetry. 

122 """

149class AllSatisfiedSupplyLookup: 

150 """Test-default stub: returns ONE synthetic Available Supply per requested kind. 

151 

152 Mirrors `AlwaysCoveredClearanceLookup`'s role for `ClearanceLookup`: 

153 tests that don't care about the Supply gate get this stub from 

154 `build_postgres_deps` defaults, so existing Run / Procedure tests 

155 don't have to seed real Supplies. Tests that exercise the gate 

156 explicitly override with the real adapter (`PostgresSupplyLookup`) 

157 and seed Supplies via `register_supply` + `mark_supply_available`. 

158 

159 The synthetic Supply has `status="Available"` so every kind 

160 requested by Method.needed_supplies satisfies the decider's 

161 gate. Tests that need to assert the missing-kind or no-Available 

162 rejection paths MUST use the real `PostgresSupplyLookup` 

163 adapter, not this stub. 

164 

165 `lookup(supply_id)` returns `None` by default; tests that exercise 

166 Distribution's register flow against this stub will see the 

167 `DistributionSupplyNotFoundError` rejection path, which is the 

168 correct conservative default for a not-explicitly-seeded stub.
