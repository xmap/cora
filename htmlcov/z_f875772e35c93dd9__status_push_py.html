1"""StatusPush runtime: pushes a live, read-only snapshot outbound to an 

2external relay, for a status page served from a host outside this 

3deployment's own network. 

4 

5## Why this exists, and why it is not a `list_*` consumer over HTTP 

6 

72-BM's deployment runs on a host with no inbound reachability from outside 

8its own controls network (see docs/deployments/2-bm's serving design). A 

9status page that should be viewable from elsewhere therefore cannot be 

10served FROM this host; instead this host must PUSH state OUT to a relay on 

11a host that does have reach, over a connection this host itself opens. That 

12asymmetry, push rather than serve, is the entire reason this module exists 

13alongside the `list_*` REST/MCP surfaces rather than instead of them. 

14 

15## Why this is a bespoke loop, not `_flag_watcher.flag_watcher_lifespan` 

16 

17Every other composition-root watcher in this package (`_calibration_watcher`, 

18`_clearance_watcher`, `_procedure_watcher`, `_campaign_watcher`) does one 

19self-contained unit of work per tick: drain a query, compare against a rule, 

20maybe append one Decision. `flag_watcher_lifespan` is built for exactly that 

21shape. This module instead holds one PERSISTENT outbound connection across 

22many ticks (reopening it every 1-2 seconds would be pure handshake overhead 

23for a live feed), and reconnects with backoff when the relay is unreachable 

24rather than treating each drop as an isolated tick failure. That is closer 

25to `_run_witness.py`'s hand-rolled shape than to the flag-watcher family. 

26 

27## Current scope 

28 

29Each tick reads and pushes: 

30 

31 - open Runs (`Running` + `Held`), each with `progress` from 

32 `RunWitnessRecorder.progress_readings()` (`{}` when unavailable; see 

33 `_render_progress`) 

34 - open Subjects (`Received` / `Mounted` / `Measured` / `Removed`; 

35 `Returned` / `Stored` / `Discarded` are terminal and dropped) 

36 - open Campaigns (`Planned` / `Active` / `Held`; `Closed` / `Abandoned` 

37 are terminal and dropped) 

38 - Datasets produced by an on-screen Run (bounded by the open-run count, 

39 not a separate unbounded drain) 

40 - Active Clearances (the safety-gate status a viewer most wants: is 

41 something required to start a run currently in force) 

42 - Active Enclosures (permit status: the most direct "is it safe right 

43 now" answer CORA records) 

44 - the most recent Decisions since this process started, tail-followed 

45 (see `_DecisionTail`) rather than paged from the beginning, since 

46 Decisions have no "open" status to filter on and the table is 

47 unbounded 

48 

49The payload is a full snapshot every push, never a delta: a fresh viewer, 

50a reconnecting viewer, and a restarted relay are all served by "here is 

51the current one". 

52 

53Deliberately reads ONLY the in-memory `RunWitnessRecorder` for progress, 

54not the Postgres-durable `entries_run_observations` fallback 

55`PostgresRunChannelLookup` would offer for a run whose capture is not open 

56in this process: that path is capped at `capture_progress_flush_tick_seconds` 

57(10s by default) and never carries `commanded_total` (dropped at the 

58`ObservationInput` boundary), so it would not feel live and would silently 

59lack the "of M" figure. Revisit if this ever runs against a Run witnessed 

60by a different process than the one pushing. 

61 

62## Principal identity: the widening trigger has now fired 

63 

64Every other watcher here authenticates as its own seeded Agent (a real 

65Actor with its own grant set, so a missing grant is auditable per-agent). 

66This module still uses `SYSTEM_PRINCIPAL_ID` for every read: the read scope 

67has now widened past the single `ListRuns` command this module started 

68with, to seven commands across seven BCs, which is exactly the trigger this 

69docstring named for standing up a dedicated seeded identity (mirroring 

70`agent/seed_calibration_watcher.py`). That identity is NOT built in this 

71change; doing so is a follow-up, tracked so the deferral is visible rather 

72than silently indefinite. Until then, a Trust Policy that denies any of the 

73seven read commands to `SYSTEM_PRINCIPAL_ID` blinds this feature for that 

74domain only (each drain is independently try/except-guarded; see 

75`_push_loop`), never the others. 

76"""

163async def _drain_all(call: Callable[[str | None], Awaitable[Any]]) -> list[Any]: 

164 """Page through a list_* handler call until `next_cursor` is `None`. 

165 

166 `call` closes over everything but the cursor (the query's other 

167 filters, the handler, the principal), so this stays generic across 

168 every domain's distinct item shape. 

169 """ 

170 items: list[Any] = [] 

171 cursor: str | None = None 

172 while True: 

173 page = await call(cursor) 

174 items.extend(page.items) 

175 if page.next_cursor is None: 175 ↛ 177line 175 didn't jump to line 177 because the condition on line 175 was always true

176 break 

177 cursor = page.next_cursor 

178 return items

181def _render_progress(run_id: UUID, witness_recorder: RunWitnessRecorder | None) -> dict[str, Any]: 

182 """The run's progress readings, JSON-safe, or `{}` when unavailable. 

183 

184 `{}` covers three cases alike, deliberately not distinguished on the 

185 wire: witnessing is disabled entirely (`witness_recorder is None`), the 

186 capture behind this run is not open in this process, and the capture is 

187 open but has not produced a reading yet. All three mean the viewer has 

188 no progress number to show; none of them is an error. 

189 """ 

190 if witness_recorder is None: 

191 return {} 

192 readings = witness_recorder.progress_readings().get(run_id) 

193 if not readings: 

194 return {} 

195 return { 

196 role: { 

197 "value": observation.value, 

198 "commanded_total": observation.commanded_total, 

199 "observed_at": render_value(observation.observed_at), 

200 } 

201 for role, observation in readings.items() 

202 }

358class _DecisionTail: 

359 """Tail-follows `list_decisions` since this instance was created, 

360 keeping only the most recent `_DECISION_RING_SIZE`. 

361 

362 Decisions carry no "open" status to filter on and the table is 

363 unbounded, so re-draining from the beginning every tick (the shape 

364 every other domain in this module uses) is both wrong and slow: it 

365 would replay the facility's entire decision history into memory once 

366 per tick, forever. Instead this holds a cursor forward across ticks 

367 (and across reconnects: one instance lives for the whole `_push_loop` 

368 call, not per-connection) and only ever asks for what is new. 

369 

370 The cursor starts at "now" rather than the beginning of the stream, so 

371 the ring is genuinely empty on construction and only ever fills with 

372 Decisions made after this process started; there is no cheap way to 

373 seek a keyset cursor to "the last N rows" without a descending query, 

374 which `list_decisions` does not offer. 

375 """ 

376 

377 def __init__(self, *, started_at_cursor: str) -> None: 

378 self._cursor: str | None = started_at_cursor 

379 self._ring: deque[dict[str, Any]] = deque(maxlen=_DECISION_RING_SIZE) 

380 

381 async def poll( 

382 self, list_decisions: ListDecisionsHandler, deps: Kernel 

383 ) -> list[dict[str, Any]]: 

384 cursor = self._cursor 

385 newest_cursor = cursor 

386 while True: 

387 page = await list_decisions( 

388 ListDecisions(cursor=cursor, limit=_PAGE_LIMIT), 

389 principal_id=SYSTEM_PRINCIPAL_ID, 

390 correlation_id=deps.id_generator.new_id(), 

391 surface_id=NIL_SENTINEL_ID, 

392 ) 

393 for item in page.items: 

394 self._ring.append( 

395 { 

396 "decision_id": render_value(item.decision_id), 

397 "decided_by": render_value(item.decided_by), 

398 "choice": item.choice, 

399 "confidence_band": item.confidence_band, 

400 "created_at": render_value(item.created_at), 

401 } 

402 ) 

403 if page.next_cursor is None: 403 ↛ 405line 403 didn't jump to line 405 because the condition on line 403 was always true

404 break 

405 newest_cursor = page.next_cursor 

406 cursor = page.next_cursor 

407 self._cursor = newest_cursor 

408 return list(self._ring)

411def _content_hash(payload: dict[str, Any]) -> str: 

412 """Stable hash over the change-relevant payload, excluding generated_at 

413 and sequence, so an unchanged tick can be told apart from a real change.""" 

414 canonical = json.dumps(payload, sort_keys=True, separators=(",", ":")) 

415 return hashlib.sha256(canonical.encode()).hexdigest()

477async def _push_loop( 

478 deps: Kernel, 

479 *, 

480 list_runs: ListRunsHandler, 

481 list_subjects: ListSubjectsHandler, 

482 list_campaigns: ListCampaignsHandler, 

483 list_datasets: ListDatasetsHandler, 

484 list_clearances: ListClearancesHandler, 

485 list_enclosures: ListEnclosuresHandler, 

486 list_decisions: ListDecisionsHandler, 

487 producer_id: str, 

488 url: str, 

489 witness_recorder: RunWitnessRecorder | None, 

490) -> None: 

491 """Reconnect-with-backoff outer loop; one open connection sends many 

492 ticks. `websockets`' own `InvalidStatus` (bad token) and `ConnectionClosed` 

493 (relay restarted, network blip) both fall through to a fresh backoff 

494 reconnect; nothing here distinguishes them further, since v1's only 

495 remedy for either is "try again". 

496 

497 `decision_tail` is constructed ONCE, outside the reconnect loop below, 

498 so "recent decisions" means since this process started, not since the 

499 last successful connection. 

500 """ 

501 token = deps.settings.status_push_token 

502 headers = {"Authorization": f"Bearer {token.get_secret_value()}"} if token is not None else {} 

503 

504 decision_tail = _DecisionTail( 

505 started_at_cursor=encode_cursor(created_at=deps.clock.now(), item_id=_MIN_UUID) 

506 ) 

507 

508 backoff = _RECONNECT_INITIAL_SECONDS 

509 sequence = 0 

510 last_hash: str | None = None 

511 tick_seconds = deps.settings.status_push_tick_seconds 

512 

513 while True: 

514 try: 

515 async with connect(url, additional_headers=headers) as sock: 

516 _log.info(f"{_LOG_PREFIX}.connected", url=url) 

517 backoff = _RECONNECT_INITIAL_SECONDS 

518 last_hash = None # force one full push right after (re)connect 

519 ticks_since_push = _HEARTBEAT_TICKS # push immediately on connect 

520 while True: 

521 fields = await _build_payload_fields( 

522 deps, 

523 list_runs=list_runs, 

524 list_subjects=list_subjects, 

525 list_campaigns=list_campaigns, 

526 list_datasets=list_datasets, 

527 list_clearances=list_clearances, 

528 list_enclosures=list_enclosures, 

529 decision_tail=decision_tail, 

530 list_decisions=list_decisions, 

531 witness_recorder=witness_recorder, 

532 ) 

533 content_hash = _content_hash(fields) 

534 changed = content_hash != last_hash 

535 heartbeat_due = ticks_since_push >= _HEARTBEAT_TICKS 

536 if changed or heartbeat_due: 

537 sequence += 1 

538 snapshot = build_snapshot( 

539 sequence=sequence, 

540 generated_at=deps.clock.now().isoformat(), 

541 producer_id=producer_id, 

542 **fields, 

543 ) 

544 await sock.send(json.dumps(snapshot)) 

545 last_hash = content_hash 

546 ticks_since_push = 0 

547 else: 

548 ticks_since_push += 1 

549 await asyncio.sleep(tick_seconds) 

550 except asyncio.CancelledError: 

551 raise 

552 except _UNAUTHORIZED_ERRORS: 

553 _log.exception(f"{_LOG_PREFIX}.read_unauthorized") 

554 await asyncio.sleep(tick_seconds) 

555 except (ConnectionClosed, InvalidStatus, OSError) as err: 

556 _log.warning(f"{_LOG_PREFIX}.disconnected", reason=str(err), retry_in=backoff) 

557 await asyncio.sleep(backoff) 

558 backoff = min(backoff * 2, _RECONNECT_MAX_SECONDS)

573) -> AsyncGenerator[None]: 

574 """Spawn the StatusPush loop for the duration of the context. 

575 

576 No-op unless `settings.status_push_enabled` is True (default off) AND 

577 `settings.status_push_url` is configured; the latter mirrors the 

578 `LLM_ENABLED`-without-a-key posture elsewhere in this file, log once and 

579 stand down rather than crash the app over a deployment that has not 

580 finished configuring this feature. `producer_id` is drawn from 

581 `deps.id_generator` lazily, here, rather than accepted as a caller-supplied 

582 parameter, so booting the app with this feature off (the default, and 

583 every test's `create_app()`) never consumes an id from a test's 

584 `FixedIdGenerator` queue. 

585 

586 `witness_recorder` is `run_witness_lifespan`'s own yielded value, so the 

587 caller must enter that context manager first and bind it (`main.py` 

588 does this by ordering `run_witness_lifespan(...) as witness_recorder` 

589 before this call in the same `async with` group). `None` is a normal 

590 state, not a misconfiguration: it means witnessing is off, or shadow-only 

591 with no recorder built; either way progress is simply absent from every 

592 pushed run, per `_render_progress`. 

593 """ 

594 if not deps.settings.status_push_enabled: 

595 _log.info(f"{_LOG_PREFIX}.skipped", reason="disabled") 

596 yield 

597 return 

598 url = deps.settings.status_push_url 

599 if not url: 

600 _log.warning(f"{_LOG_PREFIX}.skipped", reason="no_url_configured") 

601 yield 

602 return 

603 

604 producer_id = str(deps.id_generator.new_id()) 

605 _log.info( 

606 f"{_LOG_PREFIX}.started", 

607 tick_seconds=deps.settings.status_push_tick_seconds, 

608 ) 

609 task = asyncio.create_task( 

610 _push_loop( 

611 deps, 

612 list_runs=list_runs, 

613 list_subjects=list_subjects, 

614 list_campaigns=list_campaigns, 

615 list_datasets=list_datasets, 

616 list_clearances=list_clearances, 

617 list_enclosures=list_enclosures, 

618 list_decisions=list_decisions, 

619 producer_id=producer_id, 

620 url=url, 

621 witness_recorder=witness_recorder, 

622 ), 

623 name="status-push", 

624 ) 

625 try: 

626 yield 

627 finally: 

628 task.cancel() 

629 with contextlib.suppress(asyncio.CancelledError): 

630 await task 

631 _log.info(f"{_LOG_PREFIX}.stopped")
