1"""State, status enum, reason enum and errors for the Shortfall aggregate. 

2 

3A Shortfall is the recorded fact that a capture PRODUCED SOMETHING THAT 

4CAN NEVER BECOME A DATASET. It is not a re-judgement of the act: the 

5Run's own terminal stands untouched, faithfully transcribing what the 

6substrate reported. This records a fact about the PRODUCT. 

7 

8## Why this exists 

9 

10Before this aggregate, CORA's record could not distinguish "no scan 

11ran" from "a scan ran and produced nothing". Both looked identical: a 

12terminated Run with no Dataset naming it. Three real 2-BM Runs hold 

13HDF5 files carrying 1 projection of a commanded 1541 and no 

14`/exchange/theta`, and the sweep retried them 387 times in one recent 

15log window, at a measured 6.3s per attempt, writing nothing each time. 

16The reader had already computed the frame counts and discarded them at 

17the refusal, so CORA threw away its only non-substrate evidence 

18precisely when that evidence DISAGREED with the substrate. See 

19tomoscan#181 for why "Scan complete" is reported on every exit path, 

20and therefore why a `Completed` Run is a faithful transcript and a 

21false record at the same time. 

22 

23## Terminal at genesis 

24 

25Same fact-chain shape as `Acquisition` and `Attestation`: one stream per 

26Shortfall, exactly one `ShortfallRecorded` event ever, no lifecycle and 

27no transition arm. A capture that is later ingested by hand does NOT 

28retract this: both facts stand, because both are true. The file really 

29did lack its rotation angles when CORA looked, and a human really did 

30supply what was missing afterwards. 

31 

32## Finality is what makes the claim safe to make 

33 

34"Can never become a Dataset" is unfalsifiable unless the record says 

35how it was reached, so the state and the event carry BOTH sides of the 

36judgement (`file_modified_at`, `run_ended_at`) rather than only the 

37verdict. A reader can re-derive the verdict from the payload without 

38going back to the file, which matters because the file sits on a 

39detector control PC that may not exist in five years, and because this 

40row can never be erased. 

41 

42## Personal data 

43 

44`capture_path_id` is the surrogate key of the `run_capture_path` vault 

45row, NOT the path. `host` and `root` are the facility-level storage 

46tier (`tomdet`, `/local1/2BM`), which is provenance a reader benefits 

47from and which `capture_path_locator` already argues is safe to carry 

48in the clear. Everything strictly between the root and the filename, 

49which at 2-BM embeds `{UserLastName}-{ProposalNumber}`, never reaches 

50this aggregate at all. 

51 

52Both land as `drop:text` in the generated redaction table, because they 

53are bare `str` and the generator cannot tell a storage tier from free 

54text. That is not a defect to work around: the same already holds for 

55`AttestationRecorded.kind` / `.outcome`, and dropping a facility's 

56internal hostname from the PUBLISHED record is the right default even 

57though carrying it on the internal event is safe. Anyone tempted to add 

58an override should have a reason to publish them, not just a wish for 

59symmetry. 

60"""

81class ShortfallReason(StrEnum): 

82 """Why this capture can never become a Dataset. 

83 

84 A CLOSED enum, deliberately: the free-text refusal messages 

85 `InvalidScanFileError` carries embed the opened path verbatim (they 

86 are built from `os.stat` / h5py error strings), and this row is 

87 unerasable. A closed enum cannot carry a path by construction, 

88 which is the whole reason the payload names a member here instead 

89 of a rendered message. 

90 

91 One member today, and the space is deliberately unfilled rather 

92 than overlooked. `ScanFileInvalidReason` marks several of its nine 

93 members permanent, but only this one has ever been OBSERVED, and 

94 only this one can supply the frame counts that make the record 

95 worth writing: an `Unrecognized` file yields no `Description` at 

96 all, so a Shortfall for it would carry a verdict and no evidence. 

97 Adding that member is a modelling decision about what a countless 

98 Shortfall means, not a mechanical widening, so it waits for a real 

99 instance to reason from. 

100 """ 

101 

102 STRUCTURALLY_INCOMPLETE = "StructurallyIncomplete"

105@dataclass(frozen=True) 

106class Shortfall: 

107 """Aggregate root: one capture that can never become a Dataset. 

108 

109 `capture_path_id` identifies the observation this verdict is about, 

110 and is what the stream is keyed on, so a Run observed under two 

111 storage locations can carry a separate verdict per location. That 

112 matches `ScanIngestCandidateLookup`'s own `exclude` key, which is 

113 scoped the same way and for the same reason. 

114 

115 `projection_count` is what the file actually holds; 

116 `commanded_projection_count` is what the scan was told to collect, 

117 and is `None` when the file does not record it. The pair is the 

118 substance of the fact: 1 of a commanded 1541 is the shape that 

119 motivated this aggregate. `dropped_frame_count` is the detector's 

120 own count of frames it discarded, again `None` when absent, and is 

121 a SEPARATE fact from the shortfall between the other two: a scan 

122 can fall short with zero drops (it stopped early) or drop frames 

123 and still meet its total. 

124 

125 `file_modified_at` and `run_ended_at` are the two sides of the 

126 finality judgement, kept so the verdict stays checkable. See the 

127 module docstring. 

128 """ 

129 

130 id: UUID 

131 producing_run_id: UUID 

132 capture_path_id: UUID 

133 host: str 

134 root: str 

135 projection_count: int 

136 commanded_projection_count: int | None 

137 dropped_frame_count: int | None 

138 reason: ShortfallReason 

139 file_modified_at: datetime 

140 run_ended_at: datetime 

141 recorded_at: datetime 

142 recorded_by: ActorId 

143 status: ShortfallStatus = ShortfallStatus.RECORDED
