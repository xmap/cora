1"""Shared start-safety-envelope check (Run aggregate kernel). 

2 

3The four cross-BC live-signal gates a Run must pass to begin, 

4clearance, supply, enclosure, and beam, are the same gates that must 

5still hold for a held Run to be safely resumed. Living in the aggregate 

6kernel (mirroring `plan.wires_validation.validate_wire_endpoints`) lets 

7the `start_run` decider, the RunSupervisor's pre-resume re-check, AND the 

8witnessed-genesis decider import one definition, so a change to any gate 

9applies to every consumer. Slice-to-slice sharing through a feature 

10module is banned (cross-slice independence), so this is the correct home. 

11 

12Pure: no I/O. The caller (the `start_run` handler, the supervisor runtime 

13for resume, or the witnessed-genesis handler) loads the cross-aggregate 

14state and passes it in. 

15 

16## Two entry points, four shared gates 

17 

18`check_safety_envelope` raises the first failing gate, in the fixed order 

19clearance, supply, enclosure, beam; unchanged from before this module had 

20a second entry point. `witness_safety_envelope` is the witnessed-genesis 

21counterpart: per the roadmap's rule ("refuse on what CORA can fix, witness 

22what CORA cannot"), clearance and supply are CORA's own aggregates, so 

23they still RAISE on the witnessed path exactly as they do on the driven 

24path. Only enclosure and beam, the two genuinely external live facility 

25signals, become a recorded `SafetyEnvelopeVerdict` instead of a refusal. 

26 

27Both entry points call the same four gate functions below, `check_*` for 

28the two that always raise and `*_gate_refusal` for the two that may 

29instead be witnessed. There is no third copy of any gate's logic: a 

30change to, say, the enclosure rule changes what both paths see by 

31construction, not by two authors remembering to keep two copies in sync. 

32 

33The structural start-genesis validations (Plan-deprecated, Subject 

34status, Asset-decommissioned, capability re-validation, wire endpoints, 

35Campaign membership, name) deliberately stay in each decider: they are 

36genesis invariants, not live-signal gates, and a resume must NOT re-run 

37them (resume continues a Run that already passed them), and the witnessed 

38path's decider re-runs them exactly as the driven decider does (per the 

39roadmap: CORA-side data faults stay refusals on both paths). 

40"""

63def clearance_gate_check( 

64 *, 

65 run_id: UUID, 

66 referencing_clearances: tuple[ClearanceLookupResult, ...], 

67) -> None: 

68 """Raise unless at least one Safety Clearance is Active AND references 

69 this Run's scope. The caller pre-loaded every clearance whose bindings 

70 reference the Run/Subject/Asset ids. Partition on status == "Active" 

71 to distinguish "no clearance at all" (RunRequiresActiveClearanceError) 

72 from "clearance exists but none Active" (RunClearanceCoverageMismatchError). 

73 Modern DDD consensus (Khononov / Dudycz / Herberto Graca 2024-2025): 

74 cross-context gating queries a replicated read model (here: 

75 proj_safety_clearance_summary), not the upstream aggregate. 

76 

77 Always raises, never witnesses: a Clearance is a human authorization, 

78 not a live facility reading, per the roadmap's rule. This keeps the 

79 cross-port invariant fail-closed for EVERY Run, including a compute 

80 Run whose empty Asset scope makes the enclosure / beam gates below 

81 vacuous, and including a witnessed Run (see `test_compute_shaped_scope_ 

82 still_requires_active_clearance`; any future split must not exempt 

83 either). 

84 """ 

85 if not referencing_clearances: 

86 raise RunRequiresActiveClearanceError(run_id) 

87 active_clearances = [c for c in referencing_clearances if c.status == "Active"] 

88 if not active_clearances: 

89 raise RunClearanceCoverageMismatchError( 

90 run_id, 

91 referencing_clearance_count=len(referencing_clearances), 

92 )

95def supply_gate_check( 

96 *, 

97 run_id: UUID, 

98 needed_supplies_snapshot: frozenset[str], 

99 needed_supplies_satisfaction: Mapping[str, tuple[SupplyLookupResult, ...]], 

100) -> None: 

101 """Raise unless, for every kind in Method.needed_supplies, at least one 

102 registered Supply of that kind is in status=Available, per 

103 [[project_supply_preflight_gate_design]]. Default-strict: Degraded 

104 does NOT pass; operators with override authority use 

105 mark_supply_available to declare a Supply Available before starting. 

106 Mirrors `clearance_gate_check`'s two-error pair pattern. 

107 

108 Always raises, never witnesses, for the same reason as 

109 `clearance_gate_check`: Supply is CORA's own aggregate, not a live 

110 facility reading. 

111 """ 

112 for kind in sorted(needed_supplies_snapshot): 

113 candidates = needed_supplies_satisfaction.get(kind, ()) 

114 if not candidates: 

115 raise RunRequiresAvailableSupplyError(run_id, kind) 

116 if not any(s.status == "Available" for s in candidates): 

117 raise RunSupplyCoverageMismatchError( 

118 run_id, 

119 kind, 

120 frozenset((s.supply_id, s.status) for s in candidates), 

121 )

124def enclosure_gate_refusal( 

125 *, 

126 run_id: UUID, 

127 referencing_enclosures: tuple[EnclosureLookupResult, ...], 

128) -> RunRequiresPermittedEnclosureError | RunEnclosureCoverageMismatchError | None: 

129 """Return the enclosure-gate refusal this Run would face, or None when 

130 the gate holds. Per [[project_enclosure_stage1_design]], every 

131 referencing Enclosure row must be `permit_status == "Permitted"` AND 

132 `lifecycle == "Active"`. Per L-pre-1 (always-derive-from-Asset-chain), 

133 the scope set is derived by the caller by collecting each scoped 

134 Asset's (and ancestor's) `located_in_enclosure_id` and loading them 

135 via `EnclosureLookup.find_by_ids`; an empty `referencing_enclosures` 

136 is Permit-by-default (no scoped Asset is located in any Enclosure). 

137 The returned error carries `enclosure_status_summary`, the 

138 `(enclosure_id, "permit_status|lifecycle")` tuple for every failing 

139 Enclosure, so a 409 built from it names each blocker. Default-strict: 

140 NotPermitted / Unknown / Decommissioned all fail (the adapter excludes 

141 most Decommissioned rows at the read layer; this treats any 

142 non-"Active" non-"Permitted" row as a fail defensively). 

143 

144 Returns rather than raises: this is a live facility signal, so 

145 `check_safety_envelope` raises the return value while 

146 `witness_safety_envelope` records only whether it was None. 

147 """ 

148 failing_rows = tuple( 

149 e 

150 for e in referencing_enclosures 

151 if not (e.permit_status == "Permitted" and e.lifecycle == "Active") 

152 ) 

153 if not failing_rows: 

154 return None 

155 # Build the user-facing summary as a frozenset (dedupes on 

156 # (id, label) for noise reduction in the 409 message). The branch 

157 # decision uses raw tuple lengths so a future adapter that returns 

158 # duplicate rows still classifies correctly. 

159 failing_summary = frozenset( 

160 (e.enclosure_id, f"{e.permit_status}|{e.lifecycle}") for e in failing_rows 

161 ) 

162 if len(failing_rows) == len(referencing_enclosures): 

163 # Every referencing Enclosure failed the gate. 

164 return RunRequiresPermittedEnclosureError(run_id, failing_summary) 

165 # Mixed: at least one passed, at least one failed. 

166 return RunEnclosureCoverageMismatchError(run_id, failing_summary)

169def beam_gate_refusal( 

170 *, 

171 run_id: UUID, 

172 beam_availability: BeamAvailabilityLookupResult | None, 

173) -> RunBeamAvailabilityUnknownError | RunRequiresOpenBeamShuttersError | None: 

174 """Return the beam-gate refusal this Run would face, or None when the 

175 gate holds. Per BEAM-1: when the deployment configures beam PVs the 

176 caller reads the live front-end + station shutter states 

177 (BeamBlockingM, inverted polarity: 0 == open) and the ACIS FES-permit 

178 composite and passes the BeamAvailabilityLookupResult here. None means 

179 the deployment configures no beam PVs (beam-by-default). Fail-closed: 

180 a read whose quality is not Good (disconnected / bad PV) refuses 

181 rather than assume beam is open. Distinct axis from the Enclosure 

182 SecureM permit above: beam-open cycles per-scan, the enclosure permit 

183 is access-state. 

184 

185 Returns rather than raises, same reason as `enclosure_gate_refusal`. 

186 """ 

187 if beam_availability is None: 

188 return None 

189 if not beam_availability.quality_ok: 

190 return RunBeamAvailabilityUnknownError(run_id) 

191 blocking = frozenset( 

192 flag 

193 for flag, ok in ( 

194 ("fes_open", beam_availability.fes_open), 

195 ("sbs_open", beam_availability.sbs_open), 

196 ("fes_permit", beam_availability.fes_permit), 

197 ) 

198 if not ok 

199 ) 

200 if blocking: 

201 return RunRequiresOpenBeamShuttersError(run_id, blocking) 

202 return None

205def check_safety_envelope( 

206 *, 

207 run_id: UUID, 

208 referencing_clearances: tuple[ClearanceLookupResult, ...], 

209 needed_supplies_snapshot: frozenset[str], 

210 needed_supplies_satisfaction: Mapping[str, tuple[SupplyLookupResult, ...]], 

211 referencing_enclosures: tuple[EnclosureLookupResult, ...], 

212 beam_availability: BeamAvailabilityLookupResult | None, 

213 beam_requirement: BeamRequirement = BeamRequirement.REQUIRED, 

214) -> None: 

215 """Raise the first failing start-safety gate; return None if all pass. 

216 

217 `run_id` is carried on each raised error (the new id at start_run, 

218 the existing run id at resume or at a witnessed genesis). Composed from 

219 the four gate functions above. 

220 

221 `beam_requirement` gates ONLY the beam arm, and only its refusal. It 

222 defaults to `REQUIRED`, so a caller that does not pass it gets the 

223 pre-existing behaviour exactly. `NOT_REQUIRED` skips the beam 

224 refusal for executions where beam availability is irrelevant (a 

225 dark-field capture, a maintenance task, off-beam commissioning). 

226 

227 It deliberately does NOT touch the clearance, supply or enclosure 

228 gates. Those hold regardless of beam: an unsearched hutch or a 

229 missing clearance is no less disqualifying because the work happens 

230 to need no beam. 

231 """ 

232 clearance_gate_check(run_id=run_id, referencing_clearances=referencing_clearances) 

233 supply_gate_check( 

234 run_id=run_id, 

235 needed_supplies_snapshot=needed_supplies_snapshot, 

236 needed_supplies_satisfaction=needed_supplies_satisfaction, 

237 ) 

238 enclosure_refusal = enclosure_gate_refusal( 

239 run_id=run_id, referencing_enclosures=referencing_enclosures 

240 ) 

241 if enclosure_refusal is not None: 

242 raise enclosure_refusal 

243 if beam_requirement is BeamRequirement.REQUIRED: 

244 beam_refusal = beam_gate_refusal(run_id=run_id, beam_availability=beam_availability) 

245 if beam_refusal is not None: 

246 raise beam_refusal

249def witness_safety_envelope( 

250 *, 

251 run_id: UUID, 

252 referencing_clearances: tuple[ClearanceLookupResult, ...], 

253 needed_supplies_snapshot: frozenset[str], 

254 needed_supplies_satisfaction: Mapping[str, tuple[SupplyLookupResult, ...]], 

255 referencing_enclosures: tuple[EnclosureLookupResult, ...], 

256 beam_availability: BeamAvailabilityLookupResult | None, 

257) -> SafetyEnvelopeVerdict: 

258 """Record a verdict on the two live facility signals instead of 

259 enforcing them; used only by the witnessed-genesis decider. 

260 

261 Same six inputs and same clearance/supply behaviour as 

262 `check_safety_envelope`: both still raise on those two gates, because 

263 they are CORA-side data, not something RunWitness can observe from 

264 the floor. Only enclosure and beam, evaluated by the exact same 

265 `enclosure_gate_refusal` / `beam_gate_refusal` functions 

266 `check_safety_envelope` uses, are converted to a bool instead of 

267 raised. This is what makes "both paths provably call the same 

268 predicates" a structural fact rather than a claim to trust. 

269 """ 

270 clearance_gate_check(run_id=run_id, referencing_clearances=referencing_clearances) 

271 supply_gate_check( 

272 run_id=run_id, 

273 needed_supplies_snapshot=needed_supplies_snapshot, 

274 needed_supplies_satisfaction=needed_supplies_satisfaction, 

275 ) 

276 return SafetyEnvelopeVerdict( 

277 enclosure_permitted=enclosure_gate_refusal( 

278 run_id=run_id, referencing_enclosures=referencing_enclosures 

279 ) 

280 is None, 

281 beam_available=beam_gate_refusal(run_id=run_id, beam_availability=beam_availability) 

282 is None, 

283 )
