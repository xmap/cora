1"""Clearance aggregate state, value objects, status enum, bindings, and errors. 

2 

3`Clearance` wraps a facility safety form (APS ESAF, NSLS-II SAF, 

4ESRF A-form / SAF, MAX IV DUO / ESRA, DLS ERA / PLHD, DESY DOOR, 

5ALS ESAF, SLAC BTR, SPring-8 Form 9). One unified aggregate carries 

6form data + lifecycle state + multi-step review chain + the polymorphic 

7set of CORA aggregates and external IDs the form binds to. 

8 

9Per [[project_safety_clearance_design]], the design locks: 

10 

11 - 8-state FSM: `Defined -> Submitted -> UnderReview -> Approved 

12 -> Active -> Expired | Rejected | Superseded` 

13 - `template_id` foreign key into the `ClearanceTemplate` aggregate 

14 (template-tier; auto-seeded per facility per 

15 [[project_slice9_design]] L8). Form-type identity is carried by 

16 the template's `(facility_code, code)` pair, not a closed enum 

17 on Clearance. 

18 - Multi-binding `frozenset[ClearanceBinding]` covering Subject / 

19 Asset / Run / Procedure + ExternalRefBinding(ref=Identifier) for 

20 upstream-deferred refs (Proposal / BTR / LabVisit / Session per 

21 BC-map line 111 anti-corruption pattern) 

22 - Multi-step review chain via `review_steps: tuple[ReviewStep, ...]` 

23 field (NOT additional FSM states) 

24 - Discriminated-union `HazardClassification` VO at 

25 `cora.safety.aggregates.clearance.hazard_classification` 

26 

27 

28State + ClearanceStatus StrEnum + ClearanceTitle VO + 

29ClearanceBinding union + HazardDeclaration + ReviewStep + 7 errors. 

30Genesis decider only (`register_clearance`); transition slices land in 

3111a-b. 

32 

33## Status as enum-in-state, derived-from-event-type-in-evolver 

34 

35`ClearanceStatus` is a `StrEnum` mirroring the cross-aggregate convention 

36(`SubjectStatus`, `FamilyStatus`, `AssetLifecycle`, `SupplyStatus`, 

37`ProcedureStatus`). State holds the typed enum; evolver derives status 

38from event type (`ClearanceRegistered -> DEFINED`). 

39 

40Form-type identity is now carried by `template_id` (FK into the 

41`ClearanceTemplate` aggregate). The earlier closed-enum 

42`ClearanceKind` was retired in favour of an aggregate so future 

43per-facility schema-validation + template-versioning can land 

44additively (see [[project_slice9_design]] L11). 

45 

46## Bindings: multi (frozenset), polymorphic (5 typed arms + ExternalRefBinding) 

47 

48The `bindings` field on Clearance is a `frozenset[ClearanceBinding]` 

49because one ESAF covers samples + user equipment + the Run + the 

50external proposal -- all at once. Single-binding shape would force one 

51Clearance per binding (artificial); multi-binding is the natural shape. 

52 

53The 5 typed arms cover CORA-modeled aggregates (Subject / Asset / Run / 

54Procedure) plus the anti-corruption escape hatch (ExternalRefBinding) 

55for upstream-deferred refs CORA does NOT model: Proposal (BC map line 

56111 defers), BeamtimeRequest, LabVisit (DLS-specific), Session. When 

57CORA later models any of these as aggregates, ExternalRefBinding 

58becomes a typed binding additively. 

59 

60## Reviewers tuple, NOT additional FSM states 

61 

62Per the cross-facility portability research: DESY DOOR has a 3-step 

63review chain (Local Contact -> Beamline Sci+Coordinator -> Safety 

64Group); NSLS-II has ERC-mediated changes; APS has dual gating 

65(beamline + ESRB). All fit one `UnderReview` FSM state with each 

66reviewer step appended to the `review_steps: tuple[ReviewStep, ...]` 

67tuple. The FSM stays clean (8 states); the chain length varies per 

68facility. This keeps the FSM legible and the audit chain expressive. 

69 

70## Thirteenth bounded-name VO 

71 

72`ClearanceTitle` is the 13th occurrence of the trimmed-bounded-name 

73VO pattern (after SubjectName, AssetName, FamilyName, RunName, 

74SupplyName, ProcedureName, RecipeName/MethodName/PracticeName/ 

75PlanName, etc.). Uses the shared `validate_bounded_text` helper. 

76"""

104class ClearanceStatus(StrEnum): 

105 """The Clearance's lifecycle state. 

106 

107 Eight values locked day one per [[project_safety_clearance_design]]: 

108 

109 - `Defined` -- registered, not yet submitted 

110 - `Submitted` -- awaiting first reviewer pickup 

111 - `UnderReview` -- >=1 reviewer step recorded but not terminal 

112 - `Approved` -- all required reviewers approved; not yet effective 

113 - `Active` -- currently in force; gates Run.start / Procedure.start 

114 - `Expired` -- validity window passed OR explicit expire_clearance 

115 - `Rejected` -- terminal-bad 

116 - `Superseded` -- replaced by amended child (parent_id link) 

117 

118 Compresses the union of all 9 surveyed facility-form lifecycles per 

119 the cross-facility portability research (v3 pass). Multi-step review 

120 rolls up into UnderReview + the `review_steps: tuple[...]` field; no 

121 facility introduces states outside this set. 

122 """ 

123

127 APPROVED = "Approved"

558@dataclass(frozen=True) 

559class HazardDeclaration: 

560 """A hazard claim (intrinsic descriptor + mitigations) against a binding target. 

561 

562 Each declaration scopes its claim to ONE of the Clearance's bindings 

563 (the target). `classifications` is the frozenset of typed 

564 `HazardClassification` VOs (NFPA704Rating / RiskBand / GHSPictogram / 

565 SchemeCode -- see `cora.safety.aggregates.clearance.hazard_classification`). 

566 

567 `mitigations` is a frozenset of free-form ref strings (PPE codes, 

568 training cert refs, procedure IDs); typed mitigations are deferred 

569 to the [gap] watch item for separate Mitigation aggregate (the 

570 four-primitive split's bottom half). 

571 

572 `notes` is operator-supplied prose, 0-2000 chars (optional). 

573 """ 

574 

575 target: ClearanceBinding 

576 classifications: frozenset[HazardClassification] = field( 

577 default_factory=frozenset[HazardClassification] 

578 ) 

579 mitigations: frozenset[str] = field(default_factory=frozenset[str]) 

580 notes: str | None = None 

581 

582 def __post_init__(self) -> None: 

583 for ref in self.mitigations: 

584 trimmed = ref.strip() 

585 if not trimmed or len(trimmed) > CLEARANCE_MITIGATION_REF_MAX_LENGTH: 

586 raise InvalidClearanceMitigationRefError(ref) 

587 if self.notes is not None: 

588 notes_trimmed = self.notes.strip() 

589 if len(notes_trimmed) > CLEARANCE_HAZARD_NOTES_MAX_LENGTH: 

590 raise InvalidClearanceHazardNotesError(self.notes) 

591 object.__setattr__(self, "notes", notes_trimmed if notes_trimmed else None)

629@dataclass(frozen=True) 

630class Clearance: 

631 """Aggregate root: a facility safety-form clearance. 

632 

633 Slim aggregate per [[project_fold_cost_principles]]: identity + 

634 typed kind + title + bindings + declarations + risk_band + 

635 review chain + status + lazy parent / validity / review-cycle 

636 timestamps. Per-step audit metadata (decided_at, role, decision) 

637 lives on ReviewStep tuple entries. 

638 

639 Per the cross-facility portability research, this single aggregate 

640 shape is portable across all 9 surveyed facilities (split-form 

641 facilities like ESRF / MAX IV / DLS get multiple Clearance instances 

642 per Run, each with its own bindings, NOT a polymorphic Clearance 

643 aggregate type). 

644 

645 `id` is the stable opaque CORA UUID. `external_id` is the facility- 

646 minted regulatory ID (ESAF-12345, SAF-67890, etc.); set lazily once 

647 the facility approves and assigns. Mirrors PID landscape internal- 

648 opaque + lazy-external-mint pattern. 

649 

650 The Defined-only FSM is the genesis surface; transition events 

651 declared in events.py reach via the FSM-closure slices. 

652 """ 

653 

654 id: UUID 

655 template_id: ClearanceTemplateId # FK to ClearanceTemplate; auto-seeded per facility 

656 facility_code: FacilityCode # Federation Facility's cross-deployment convergent slug 

657 title: ClearanceTitle 

658 bindings: frozenset[ClearanceBinding] 

659 declarations: frozenset[HazardDeclaration] = field(default_factory=frozenset[HazardDeclaration]) 

660 risk_band: RiskBand | None = None 

661 review_steps: tuple[ReviewStep, ...] = () 

662 status: ClearanceStatus = ClearanceStatus.DEFINED 

663 external_id: str | None = None 

664 parent_id: UUID | None = None 

665 valid_from: datetime | None = None 

666 valid_until: datetime | None = None 

667 next_review_due_at: datetime | None = None
