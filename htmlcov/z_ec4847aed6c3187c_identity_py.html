1"""Cross-BC identity NewType aliases for fact-act attribution. 

2 

3Per [[project_fold_symmetry_design]], the Pass 1 fitness test detects 

4attribution fields by type rather than by name: a state field is 

5classified as an ATTRIBUTION field when its annotation is `ActorId`, 

6`ActorId | None`, `AgentId`, `AgentId | None`, or the trigger-aware 

7discriminated union `ActorId | MonitorSourceId | SchedulerTickId`. 

8Bare `UUID` annotations are skipped. Identity-ref cross-aggregate UUIDs 

9(Asset refs, Subject refs, Calibration target refs, and so on) carry 

10their own per-aggregate NewType in the same spirit and are skipped by 

11the same predicate. This shifts the discipline burden from 

12"exhaustively enumerate every attribution field name" to "always use 

13the right NewType at the annotation site", which is what makes the 

14fold-symmetry detection robust. 

15 

16Four NewType aliases ship in this module: 

17 

18 - `ActorId` -- a UUID that identifies a principal in Access BC's 

19 Actor stream (humans, agents, service accounts). 

20 Folded onto state by the `<verb>_by` attribution 

21 field whenever the act was performed by an Actor. 

22 - `AgentId` -- a UUID that identifies an autonomous agent in Agent 

23 BC's Agent stream. Per [[project_agent_bc_design]], 

24 every Agent shares its `id` with the co-registered 

25 Actor (`AgentId == ActorId` value-wise), but the 

26 typing distinction lets a slice that explicitly 

27 wants an Agent (not any Actor) reject bare Actor 

28 inputs at type-check time. 

29 - `MonitorSourceId` -- a UUID that identifies a Monitor-driven 

30 transition source (substream observation, EPICS PV, 

31 file watcher). Appears in Supply's trigger-aware 

32 union when no human performed the act. 

33 - `SchedulerTickId` -- a UUID that identifies an Auto-driven 

34 timer / scheduler tick. Appears in Supply's 

35 trigger-aware union when an automated periodic 

36 process performed the act. 

37 

38NewType is preferred over `TypeAlias` because the wrapper is a true 

39distinct type at type-check time (pyright rejects `UUID -> ActorId` 

40without an explicit `ActorId(uuid)` call) while remaining a zero-cost 

41identity function at runtime (no boxing, no isinstance overhead). This 

42gives the fitness test a load-bearing structural signal without 

43imposing a runtime tax. 

44 

45Per-slice migration order is documented in 

46[[project_fold_symmetry_design]]; this module is the Pre-work slice 

47that lands the aliases as a no-op (no existing field annotations 

48change in the same slice). The per-BC rename + add-missing-half 

49slices follow and re-annotate fields field-by-field. 

50""" 

51 

52from typing import NewType 

53from uuid import UUID 

54 

55ActorId = NewType("ActorId", UUID) 

56AgentId = NewType("AgentId", UUID) 

57MonitorSourceId = NewType("MonitorSourceId", UUID) 

58SchedulerTickId = NewType("SchedulerTickId", UUID) 

59 

60 

61__all__ = [ 

62 "ActorId", 

63 "AgentId", 

64 "MonitorSourceId", 

65 "SchedulerTickId", 

66]
