1"""Cross-aggregate context the `start_run` decider validates against. 

2 

3`RunStartContext` is built by the `start_run` handler from 

4`load_plan` + `load_subject` (if subject_id given) + `load_asset` 

5calls before reaching the pure decider. The decider treats these 

6loaded entities as opaque domain data and validates the Run-start 

7preconditions without performing any I/O. 

8 

9Per gate-review Q2 / Q5: this is the canonical pattern for cross- 

10aggregate validation in CORA, mirroring `PlanBindingContext` from 

116e-1 (the first decider that took cross-aggregate state as input). 

12Documented in CONTRIBUTING.md as the cross-aggregate-validation 

13idiom for any future cross-validating decider. 

14 

15Slice-local module by design: only `start_run` uses it today. 

16 

17## Field semantics 

18 

19 - `plan`: the Plan being executed. Decider rejects if Deprecated. 

20 - `subject`: the Subject being measured, or None for dark-field / 

21 flat-field calibration runs (per beamline-domain convention). 

22 Decider rejects if non-None and not in Mounted | Measured. 

23 - `assets`: dict keyed by asset_id, loaded from `plan.asset_ids`. 

24 Decider rejects if any is Decommissioned, and re-validates 

25 capability superset against current Asset state (drift since 

26 Plan-bind is real; Run is the last gate). 

27 - `referencing_clearances`: every Safety clearance 

28 whose bindings reference this Run's scope (run_id, subject_id, 

29 asset_ids), regardless of status. Loaded by the handler via 

30 `deps.clearance_lookup.find_referencing_run(...)` against the 

31 `proj_safety_clearance_summary` projection. Decider partitions 

32 on `status == "Active"` to distinguish "no clearance at all" 

33 (`RunRequiresActiveClearanceError`) from "clearance exists but 

34 none Active" (`RunClearanceCoverageMismatchError`). 

35 - `active_cautions`: every Active Caution whose 

36 target references the Run's scope (asset_ids + a future 

37 procedure_ids when a procedure-driven run shape lands). Loaded 

38 by the handler via 

39 `deps.caution_lookup.find_active_for_run(...)` against the 

40 `proj_caution_summary` projection. NON-BLOCKING by construction: 

41 the decider does NOT partition on this field; it only threads 

42 the snapshot into the `RunStarted` event payload as 

43 `acknowledged_cautions`. Distinct from 

44 `referencing_clearances` which IS a gate. 

45 

46Naming: `assets` (not `bound_assets`) matches `PlanBindingContext` 

47precedent. The "bound" qualifier was meaningful at Plan-bind time 

48(Plan was doing the binding); at Run-start, Run isn't binding 

49anything new. 

50"""

67@dataclass(frozen=True) 

68class RunStartContext: 

69 """Snapshot of upstream aggregate state at Run-start time. 

70 

71 `subject` is None when the Run has no Subject (calibration / 

72 dark-field run). `assets` is loaded from `plan.asset_ids`. 

73 `referencing_clearances` carries every Safety clearance that 

74 references the Run's scope (Run/Subject/Asset bindings) at any 

75 status; the decider applies the Active-coverage check. 

76 `active_cautions` carries every Active Caution attached to the 

77 Run's scope; the decider does NOT gate on this field, only 

78 embeds it on the `RunStarted` event payload. 

79 

80 `needed_supplies_satisfaction` is a mapping keyed by `Supply.kind` 

81 string carrying every non-Decommissioned Supply of each required 

82 kind from the governing Method's `needed_supplies` (loaded by the 

83 handler via `deps.supply_lookup.find_supplies_by_kind`). The 

84 decider gates on at-least-one-AVAILABLE per required kind per 

85 [[project_supply_preflight_gate_design]]: kinds absent from the 

86 mapping raise `RunRequiresAvailableSupplyError`; kinds present 

87 but with no Available entry raise `RunSupplyCoverageMismatchError`. 

88 Empty mapping is the natural state for Methods with empty 

89 `needed_supplies` (the handler skips the lookup). 

90 

91 `campaign` is None unless `StartRun.campaign_id` was 

92 provided. When non-None the decider gates on `campaign.status` 

93 being in `{Planned, Active, Held}` (else 

94 `RunCannotJoinCampaignError`) and embeds the campaign_id on the 

95 `RunStarted` event payload. The handler additionally writes the 

96 inverse `CampaignRunAdded` event to the Campaign stream atomically 

97 via `EventStore.append_streams`. 

98 """ 

99 

100 plan: Plan 

101 subject: Subject | None 

102 assets: dict[UUID, Asset] 

103 referencing_clearances: tuple[ClearanceLookupResult, ...] 

104 active_cautions: tuple[CautionLookupResult, ...] = () 

105 needed_supplies_satisfaction: Mapping[str, tuple[SupplyLookupResult, ...]] = field( 

106 default_factory=lambda: cast("Mapping[str, tuple[SupplyLookupResult, ...]]", {}) 

107 ) 

108 referencing_enclosures: tuple[EnclosureLookupResult, ...] = () 

109 """Every Active Enclosure whose `containing_asset_id` traces to any 

110 of the Run's scoped Asset ids. Loaded by the handler via 

111 `deps.enclosure_lookup.find_for_assets(asset_ids=scoped_asset_ids)`. 

112 

113 Empty tuple is Permit-by-default per the EnclosureLookup port 

114 docstring: an Asset that no Enclosure contains has no enclosure- 

115 permit gate. The decider partitions each row on 

116 `permit_status == "Permitted" AND lifecycle == "Active"`; 

117 failing rows raise the appropriate cross-BC enclosure error per 

118 [[project_enclosure_stage1_design]] L-pre-1 (always-derive-from- 

119 Asset-chain). Methods do NOT declare a `needed_enclosure_permits` 

120 field; the chain IS the declaration.""" 

121 campaign: Campaign | None = None
