1"""Allocation aggregate state, VOs, enum, and domain errors. 

2 

3`Allocation` is the spending envelope a holder receives and spends: 

4v1's holder is the deployment's own beamline (one CORA instance, one 

5beamline at the pilot), with an optional `campaign_id` reference that 

6binds the award window to a Campaign's lifecycle. Design lock: 

7[[project_allocation_design]]. 

8 

9Balance is never stored: it folds from the same inference ledger every 

10other spend tier sums, so this aggregate carries only the envelope's 

11declared shape (ceiling, note, window timestamps) and its FSM. 

12 

13Per [[project_lifecycle_status_naming]] the FSM is a single axis, 

14`AllocationStatus`: 

15 

16 Granted -> Active -> Sealed 

17 {Granted, Active} -> Voided 

18 

19`Granted` is the award's dormant phase (granted at approval, dormant 

20until work starts); `Active` opens the spend window (`activated_at`); 

21`Sealed` closes the books with a final-spend snapshot 

22(`spent_usd_at_seal`), the normal terminal; `Voided` is the operator 

23withdrawing a mistaken grant, terminal without a spend snapshot. The 

24two terminals stay distinct because they answer different audit 

25questions (did this envelope's books close, or did the award never 

26stand?). 

27 

28## Window 

29 

30The allocation's own lifecycle IS the award window: `activated_at` 

31opens it and `sealed_at` closes it. No calendar arithmetic lives here; 

32the calendar case stays the per-agent caps' territory. 

33 

34## Ceiling 

35 

36`ceiling_usd` is USD-only at v1 (facility-unit accounting waits for 

37the first in-house GPU pool). It must be finite and strictly positive: 

38a zero or negative ceiling would make every envelope check refuse 

39unconditionally, and a non-finite one would never refuse, so both are 

40construction-time errors rather than representable states. 

41"""

56class AllocationStatus(StrEnum): 

57 """The allocation envelope's lifecycle state. 

58 

59 - `Granted` -- awarded but dormant; the spend window has not 

60 opened and the envelope check does not arm. 

61 - `Active` -- the spend window is open (`activated_at`); the 

62 gate stack refuses spend that would breach 

63 `ceiling_usd`. 

64 - `Sealed` -- books closed with a final-spend snapshot 

65 (`spent_usd_at_seal`). Terminal. 

66 - `Voided` -- the operator withdrew a mistaken grant; no spend 

67 snapshot because the award never stood. Terminal. 

68 """ 

69 

70 GRANTED = "Granted" 

71 ACTIVE = "Active" 

72 SEALED = "Sealed" 

73 VOIDED = "Voided"

81class InvalidAllocationCeilingError(ValueError): 

82 """The supplied ceiling is not a finite, strictly positive USD amount. 

83 

84 Zero and negative ceilings would refuse all spend unconditionally; 

85 NaN and infinity would never refuse. Both poison the envelope 

86 check, so they fail at the decider rather than folding into state. 

87 """ 

88 

89 def __init__(self, value: float) -> None: 

90 super().__init__( 

91 f"Allocation ceiling must be a finite USD amount greater than 0 (got {value!r})" 

92 ) 

93 self.value = value

141class AllocationCannotActivateError(Exception): 

142 """Attempted `activate_allocation` from a disqualifying status. 

143 

144 Source set is `{Granted}` only: activation opens the spend window 

145 exactly once, and re-activating an Active, Sealed, or Voided 

146 envelope would silently reset or resurrect the window the seal's 

147 spend snapshot depends on. 

148 """ 

149 

150 def __init__(self, allocation_id: UUID, current_status: "AllocationStatus") -> None: 

151 super().__init__( 

152 f"Allocation {allocation_id} cannot be activated: currently in status " 

153 f"{current_status.value}, activate_allocation requires " 

154 f"{AllocationStatus.GRANTED.value}" 

155 ) 

156 self.allocation_id = allocation_id 

157 self.current_status = current_status

160class AllocationAlreadyActiveError(Exception): 

161 """Attempted to activate a second envelope while one is already Active. 

162 

163 Best-effort single-writer guard on the deployment's one instrument 

164 envelope: the gates enforce a single Active allocation's ceiling and 

165 the sealer closes a single Active allocation on CampaignClosed, so a 

166 second Active envelope would silently reset the spend window (older 

167 ceiling stops being enforced) and orphan the first (its auto-seal 

168 would never fire). The active allocation must be sealed or voided 

169 before another is activated. The check reads the projection, so a 

170 tight concurrent race is possible and accepted; the invariant is a 

171 guard, not a lock. 

172 """ 

173 

174 def __init__(self, allocation_id: UUID, active_allocation_id: UUID) -> None: 

175 super().__init__( 

176 f"Allocation {allocation_id} cannot be activated: allocation " 

177 f"{active_allocation_id} is already Active; seal or void it first" 

178 ) 

179 self.allocation_id = allocation_id 

180 self.active_allocation_id = active_allocation_id

280def validate_allocation_ceiling(value: float) -> None: 

281 """Reject a ceiling that is not finite and strictly positive. 

282 

283 Shared by the grant and update deciders so both entry points to 

284 `ceiling_usd` enforce one rule; a bare float (not a VO) because 

285 the ceiling participates in arithmetic at the gate and a wrapper 

286 would be unwrapped at every comparison site. 

287 """ 

288 if not isfinite(value) or value <= 0.0: 

289 raise InvalidAllocationCeilingError(value)

297@dataclass(frozen=True) 

298class Allocation: 

299 """Aggregate root: one spending envelope for the deployment's beamline. 

300 

301 Slim per [[project_fold_cost_principles]]: identity + declared 

302 shape + status + window timestamps + closing metadata. The 

303 `(granted_at, granted_by)` / `(activated_at, activated_by)` / 

304 `(sealed_at, sealed_by)` pairs are the fold-symmetric fact-act 

305 records per [[project_fold_symmetry_design]]. `spent_usd_at_seal` 

306 is the closing-the-books snapshot (None until sealed); 

307 `end_reason` carries whichever reason ended the envelope (the 

308 seal's optional note or the void's required reason). 

309 """ 

310 

311 id: UUID 

312 ceiling_usd: float 

313 note: AllocationNote 

314 campaign_id: UUID | None 

315 granted_at: datetime 

316 granted_by: ActorId 

317 status: AllocationStatus = AllocationStatus.GRANTED 

318 activated_at: datetime | None = None 

319 activated_by: ActorId | None = None 

320 sealed_at: datetime | None = None 

321 sealed_by: ActorId | None = None 

322 spent_usd_at_seal: float | None = None 

323 end_reason: str | None = None
