1"""binary_code: resolve a two-state substrate reading to 0 / 1, or neither. 

2 

3Originated in `cora.api._enclosure_permit_observer._binary_code` 

4(2026-08-09, fixing a production incident where `int('ON')` raised and 

5a correctly secured hutch read as `Unknown` forever). Copied verbatim 

6into `cora.operation.adapters.control_port_beam_availability_lookup` 

7(2026-08-18, the identical defect on the beam-permit PVs) and into 

8`cora.api._capture_observer` as the module-public `binary_code` 

9(`capture_watch_preflight` needed to call it directly). That third 

10occurrence's docstring already said a fourth should hoist rather than 

11copy again; the BLEPS supply observer is that fourth, so this module 

12is the hoist. 

13 

14## The ordinal is the portable half, and it comes first 

15 

16The three incidents above share one shape: a facility spelled its enum 

17labels differently and CORA read nothing. That kept being fixed by 

18widening the label set, which cannot converge. `ZNAM` / `ONAM` (EPICS), 

19`enum_labels` (Tango) and `value.choices` (PVA) are free text one 

20engineer chose at one facility, constrained by nothing, so no label set 

21is ever complete. 2-BM's BLEPS proved it in the field: its flags read 

22`NO_FAULT` / `TRIP`, and its comms flag reads the EMPTY STRING for 

23healthy, neither of which any conventional set would contain. 

24 

25The index behind those labels is not free text. It is 0 / 1 on every 

26substrate CORA speaks, and every adapter already holds it at the moment 

27it picks a label (see `Measurement.ordinal`). So `ordinal` decides when 

28the adapter supplied one, and the label vocabulary below is the 

29FALLBACK, kept for readings that carry no ordinal: a genuine string 

30record, an adapter that resolved no index, or a test constructing a 

31reading by hand. 

32 

33## What preferring the index gives up 

34 

35Deliberate, accepted 2026-08-23, and worth stating plainly because the 

36loss is invisible from the passing tests. An unconventional label used 

37to resolve to `None`, so a consumer pointed at the WRONG record often 

38failed closed by accident: a beam gate misconfigured onto a 

39`Closed` / `Open` shutter readback got `binary_code("Closed") -> None` 

40and blocked. That same reading now carries index 0 and is believed, and 

41on the polarity-inverted shutters 0 means OPEN. 

42 

43The old behavior was a coincidence rather than a check. It fired only 

44when the wrong record happened to carry unconventional labels, missed 

45every wrong record whose labels were conventional, and REJECTED correct 

46records whose labels were not, which is the defect this module exists 

47to close. Trading an inconsistent filter for a consistent decode is the 

48right trade, but it is a trade and not a free win. 

49 

50What remains catches strictly less than that: the out-of-range check 

51below fires only if the wrong record happens to be resting outside 

520 / 1 when it is read, so the same mis-pointed `mbbi` sitting in state 0 

53is trusted with full confidence. Whether a deployment is pointed at the 

54right address is not a question this module can answer. A real check 

55needs information it does not have, for instance an adapter publishing 

56the record's state COUNT so a two-state question could refuse a 

57sixteen-state record. That is deliberately NOT built here: it would 

58couple the ordinal to label resolution, and the ordinal's independence 

59from the label cache is what makes it correct on a cold first read. 

60 

61`ordinal` is a REQUIRED keyword rather than a defaulted one on purpose. 

62A caller that forgets it would silently fall back to label matching and 

63re-open exactly the defect this module exists to close, and that failure 

64is invisible until a facility with unconventional labels deploys. 

65Required means pyright counts the CONSUMER sites instead of a reviewer. 

66 

67That guarantee covers one side only. `Measurement.ordinal` itself 

68defaults to `None`, so any PRODUCER (a new adapter, a serializer that 

69rebuilds a reading, a test double) can omit it in silence and every 

70consumer of that reading quietly reverts to label matching. Nothing 

71type-checks that away; `tests/unit/operation/test_enum_ordinal_mapping.py` 

72is the drift catcher that does, and a new adapter belongs in it. 

73 

74`cora.shared` has no dependencies of its own (tach), so this module 

75cannot import `Measurement` and takes the two fields it needs as plain 

76arguments. Any BC or composition-root adapter may use it without adding 

77a cross-BC edge. 

78""" 

79 

80from __future__ import annotations 

81 

82# Conventional EPICS binary state labels, the FALLBACK path only. A 

83# DBR_ENUM reading (a `bi` / `mbbi` record) reaches a ControlPort adapter 

84# as its resolved FORMAT_CTRL label; `CaprotoControlPort`, by contrast, 

85# leaves the raw integer unresolved, which the `int(value)` arm covers. 

86# Neither is consulted when the caller supplies an ordinal. 

87_ONE_LABELS = frozenset({"1", "ON", "TRUE", "YES"}) 

88_ZERO_LABELS = frozenset({"0", "OFF", "FALSE", "NO"}) 

89 

90 

91def binary_code(value: object, *, ordinal: int | None) -> int | None: 

92 """Resolve a two-state reading to 1 / 0, or `None` when it is neither. 

93 

94 Pass `Measurement.ordinal` and `Measurement.value` from the same 

95 reading. The ordinal wins whenever it is present, because it is the 

96 substrate's own answer rather than the facility's wording of it; 

97 `value` is consulted only when `ordinal` is `None`. 

98 

99 Polarity is NOT decided here: this only turns a reading into 0 / 1. 

100 The caller applies whatever the signal's own polarity means 

101 (open/closed, permitted/not, tripped/clear, ...). 

102 

103 Unrecognized resolves to `None`, never a guess: mapping a label this 

104 function does not recognize to 0 or 1 would be inventing a fact about 

105 a record nobody here has read. A reading outside {0, 1} (a stray 2, or 

106 an ordinal pointing at the third state of an `mbbi`) also resolves to 

107 `None`, not to its raw value: the caller asked a two-state question, 

108 so an out-of-range answer is not a third state to interpret, it is a 

109 signal that the caller is pointed at the wrong record, and that should 

110 fail closed like any other unbelievable reading. 

111 """ 

112 if ordinal is not None: 

113 return ordinal if ordinal in (0, 1) else None 

114 if isinstance(value, str): 

115 token = value.strip().upper() 

116 if token in _ONE_LABELS: 

117 return 1 

118 if token in _ZERO_LABELS: 

119 return 0 

120 return None 

121 if isinstance(value, float) and not value.is_integer(): 

122 # `int(0.4)` truncates to 0, and 0 is a CONFIRMED state to every 

123 # caller: on the polarity-inverted beam shutters it means "open". 

124 # A fractional reading on a two-state signal says the caller is 

125 # not looking at a flag, so it fails closed rather than rounding 

126 # toward whichever answer the truncation happens to give. 

127 # `control_port_beam_availability_lookup` has guarded this at its 

128 # own call site since the beam gate shipped; the guard belongs 

129 # here now that four other consumers share this decoder, and it 

130 # stays there as belt-and-braces. 

131 return None 

132 try: 

133 code = int(value) # type: ignore[call-overload] 

134 except (TypeError, ValueError): 

135 return None 

136 return code if code in (0, 1) else None 

137 

138 

139__all__ = ["binary_code"]
