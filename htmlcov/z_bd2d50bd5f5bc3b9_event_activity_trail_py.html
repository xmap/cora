1"""`EventActivityTrail`: a bounded, cursor-following read over the global 

2`events` table, event metadata only. 

3 

4Lives here rather than BC-local (contrast `run.ports.run_observation_trail`) 

5because its data source is the whole `events` table across every stream 

6type by construction, not one BC's own stream. It has exactly one consumer 

7today (the live status push's flowing-mode activity tail, constructed 

8directly inside `cora.api._status_push`), so it is not a `Kernel` field: 

9promoting a single-consumer port to the shared kernel would be the reverse 

10of the rule-of-three this codebase applies to new cross-cutting primitives. 

11 

12Ships `event_id`, `stream_type`, `stream_id`, `event_type`, `occurred_at`, 

13`recorded_at`, `correlation_id`, `causation_id` and `cause_occurred_at` only. 

14NEVER `payload`. `test_run_events_carry_no_pii.py` (and its Access-BC sibling) are 

15the only two fitness tests that guard event field names against personal 

16data, and they cover exactly two of the twenty-five stream types this port's 

17data spans; shipping raw payloads across every BC would carry that guarantee 

18somewhere it does not hold. A lane needs to know THAT something happened and 

19WHAT KIND, never the values inside it. 

20 

21The three relationship columns do not weaken that. They are opaque 

22identifiers and one timestamp drawn from the envelope, never from 

23`payload`, so no BC's field names ride out on them and the guarantee the two 

24fitness tests actually make is unchanged. They answer "which events belong to 

25one operator action" and "which event caused this one", both of which are 

26structure, not content. Anything requiring a VALUE from inside an event still 

27has to come from a domain-specific read, not from here. 

28 

29Cursor discipline mirrors `cora.infrastructure.ports.event_store`'s own 

30documented rule: `position` alone is unsafe (sequences advance on rollback, 

31and a later-started transaction can commit before an earlier one), so the 

32lexicographic `(transaction_id, position)` tuple with an in-flight 

33`pg_snapshot_xmin` exclusion is the only safe advance predicate. Copy the 

34query shape from `cora.infrastructure.projection.worker`'s `_ADVANCE_SQL`, 

35not the stream-load query. 

36 

37Two methods, not one `read_since(cursor: Cursor | None, ...)`: `head()` 

38answers "start tailing from now, without replaying history" (the same 

39posture `_DecisionTail` takes by seeding its cursor at construction time), 

40so a caller establishing a fresh baseline never has to special-case a 

41`None` cursor inside the read path. 

42""" 

43

50@dataclass(frozen=True) 

51class EventActivityCursor: 

52 """Opaque advance position: the `(transaction_id, position)` tuple. 

53 `transaction_id` is carried as `str` (the DB's own `xid8::text` cast) 

54 since Python has no native 64-bit-unsigned-with-no-wraparound type 

55 mapping asyncpg trusts uniformly across both adapters."""

58 position: int

61@dataclass(frozen=True) 

62class EventActivityRow: 

63 event_id: UUID 

64 """This event's own identity, and the thing a `causation_id` points AT. 

65 Without it a consumer holds a cause it can never resolve: it can tell that 

66 an event was caused, but not by which of the events it already has.""" 

67 

68 stream_type: str 

69 stream_id: UUID 

70 event_type: str 

71 occurred_at: datetime 

72 recorded_at: datetime 

73 correlation_id: UUID 

74 causation_id: UUID | None 

75 cause_occurred_at: datetime | None 

76 """When the causing event happened, resolved by the query rather than left 

77 to the reader. A consumer holding a bounded window cannot resolve a 

78 `causation_id` older than that window, and without this it can only say 

79 "no cause" for an event that certainly had one. Carrying the time turns an 

80 unresolvable parent into "caused by something at 14:31:30, before this 

81 window" instead of silence. `None` only when `causation_id` is."""
