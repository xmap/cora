1"""FacilityLookup port: cross-aggregate query for Federation BC's Facility projection. 

2 

3Used by Federation BC's `register_facility` handler to validate 

4parent.kind=Site at cross-stream boundary (Slice 6 closes the 

5Slice 5 deferral), Slice 6 Sub-Slice B's 

6`add_facility_trust_anchor_credential` decider for parent-existence 

7+ tier-membership checks, and Slice 7 cross-BC consumers 

8(`register_supply` resolves `command.facility_code` to a 

9`FacilityLookupResult` via the `lookup_by_code` arm) for 

10cross-deployment convergent-identity binding. 

11 

12## Convention 

13 

14This is a cross-aggregate port (within Federation BC; second after 

15`CredentialLookup` if counted by Federation-internal consumers): 

16one implementor (Federation BC ships `PostgresFacilityLookup` reading 

17`proj_federation_facility_summary` from Slice 5 Sub-Slice B), many 

18consumers (`register_facility` parent validation, 

19`add_facility_trust_anchor_credential` decider, and cross-BC 

20Supply / Asset / Safety binding in slices 7-9). Lives in 

21`cora.infrastructure.ports` per the existing pattern (`Authorize`, 

22`ClearanceLookup`, `CautionLookup`, `SupplyLookup`, `SecretStore`, 

23`CredentialLookup`). 

24 

25## Two access methods 

26 

27`lookup(facility_id)` keys by the internal-opaque UUID and serves 

28Federation BC's intra-BC parent-validation arms. `lookup_by_code` 

29keys by the cross-deployment convergent slug and serves cross-BC 

30binding sites where the consumer carries the bare-str slug across 

31the wire (Slice 7+; Permit / Credential / Seal aggregate state 

32already keys on `FacilityCode`). Both return the same 

33`FacilityLookupResult` shape with the full projection row; callers 

34partition on `kind` or `status` as needed. 

35 

36## Modern DDD alignment 

37 

38Per Khononov / Cockburn / Herberto Graca: cross-aggregate integration 

39at command time should go through a port that the consumer shapes, 

40with the implementor providing the adapter. The replicated read model 

41(`proj_federation_facility_summary`) is the modern recommendation over 

42synchronous replay of the Facility aggregate, because the projection 

43is already a denormalized cross-stream view + already covers the 

44two-tier identity (id + code). 

45 

46## No BC imports in the port 

47 

48`kind` and `status` are typed as `str` (not the Federation BC's 

49`FacilityKind` / `FacilityStatus` StrEnums) so this port stays 

50inside `cora.infrastructure`'s `depends_on = []` tach contract. The 

51values match the StrEnum string values; deciders partition by literal 

52comparison (`kind == "Site"`, `status == "Active"`). 

53 

54`trust_anchor_credential_ids` is typed `frozenset[UUID]` (not 

55`frozenset[CredentialId]`) for the same tach reason; Federation BC 

56callers cast at the boundary if they want the NewType discipline. 

57 

58`id` is typed `UUID` not `FacilityId` for the same reason; consumers 

59cast at the Federation BC boundary. 

60 

61`code` is typed `FacilityCode` per the locked two-tier facility 

62identity design: `FacilityCode` lives in `cora.infrastructure` 

63itself (post Slice 3 hoist) and is the cross-deployment convergent 

64identity. The adapter constructs it from the raw `TEXT` column. 

65"""

75@dataclass(frozen=True) 

76class FacilityLookupResult: 

77 """Summary row from `proj_federation_facility_summary` for cross-aggregate checks. 

78 

79 Carries the minimal columns the Federation deciders need to validate 

80 cross-aggregate invariants before commit. Loaded by the handler via 

81 `FacilityLookup.lookup` and handed to the decider in the slice's 

82 context object (mirrors `CredentialLookupResult` shape). 

83 

84 `kind` and `status` are the StrEnum values as plain strings (matches 

85 the projection's `TEXT` columns); the decider partitions on 

86 `kind == "Site"` / `"Area"` and `status == "Active"`. 

87 

88 `code` is a `FacilityCode` value object per the two-tier 

89 facility-identity design; the adapter constructs the VO from the raw 

90 `TEXT` column. A malformed code at the projection-row tier raises 

91 `InvalidFacilityCodeError` at adapter construction time, which 

92 surfaces upstream as a port-level integrity error. 

93 

94 `trust_anchor_credential_ids` is the projection's JSONB array of 

95 credential id strings, materialized as a `frozenset[UUID]`. Empty 

96 for `kind=Area` Facilities (Area inherits the parent Site's trust 

97 posture). 

98 """

107class FacilityLookup(Protocol): 

108 """Cross-aggregate port: query Federation's facility projection by id.""" 

109 

110 async def lookup(self, facility_id: UUID) -> FacilityLookupResult | None: 

111 """Return the projection row for `facility_id`, or None if not found. 

112 

113 Returning None signals "no Facility with that id is visible in 

114 the projection". Callers (`register_facility` parent-validation, 

115 `add_facility_trust_anchor_credential` decider) translate None 

116 to the appropriate domain error (`FacilityParentNotFoundError` 

117 per the start_run -> PlanNotFoundError precedent) at the decider 

118 boundary. 

119 

120 Facilities in EVERY status are returned (Active, Decommissioned); 

121 the decider partitions on `status` to distinguish "no facility 

122 at all" from "facility exists but Decommissioned". 

123 """ 

124 ... 

125 

126 async def lookup_by_code(self, code: FacilityCode) -> FacilityLookupResult | None: 

127 """Return the projection row for `code`, or None if not found. 

128 

129 Cross-deployment convergent-identity arm: callers carry the 

130 bare-str slug across the wire (Slice 7 `register_supply` is 

131 the first cross-BC consumer) and resolve it to the full 

132 projection row before threading into the decider. Same 

133 None-on-missing + every-status-returned contract as `lookup`. 

134 Code uniqueness is enforced by the projection's UNIQUE INDEX 

135 on `code`, so at most one row matches; the adapter applies 

136 `LIMIT 1` defensively. 

137 """ 

138 ... 

139 

140 async def list_active(self) -> Sequence[FacilityLookupResult]: 

141 """Return every Active facility (status='Active'). 

142 

143 Used by lifespan-time seeding hooks (Safety BC's 

144 `seed_clearance_templates` iterates one template-per-form-type 

145 per Active facility). Decommissioned facilities are filtered out: 

146 seeds are pre-flight gates, not historical replays. Order is 

147 implementation-defined; callers must not rely on it. 

148 

149 Returns an empty Sequence when no Active facilities are 

150 registered (consistent with `lookup` returning None on miss -- 

151 the seed hook short-circuits naturally). 

152 """
