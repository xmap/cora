1"""Domain events emitted by the Procedure aggregate, plus the discriminated union. 

2 

3Mirrors the locked event-module shape: event classes, discriminated 

4union, `event_type_name`, `to_payload`, `from_stored`. The 

5persistence-envelope construction (`NewEvent`) lives at 

6`cora.infrastructure.event_envelope.to_new_event`. 

7 

8Phase 10c-a shipped `ProcedureRegistered`. Phase 10c-b adds the 

9three FSM-closure transition events: 

10 - `ProcedureStarted` -- single-source genesis transition (Defined -> 

11 Running). Slim payload: procedure_id + occurred_at. Mirrors 

12 `RunStarted`'s no-status convention; the start fact is what the 

13 event encodes. 

14 - `ProcedureCompleted` -- happy-path terminal (Running -> Completed). 

15 Slim payload by design; substantive completion summary (step count, 

16 duration, final check pass-rate) deferred until the step logbook 

17 has accreted real consumer signal. 

18 - `ProcedureAborted` -- emergency-exit terminal (Running -> Aborted). 

19 Payload carries `procedure_id` + free-form `reason: str` (1-500 

20 chars after trimming) + `occurred_at`. Mirrors RunAborted's reason 

21 shape exactly (free-form by design; structured taxonomy future- 

22 additive on the same triggers documented at 

23 `InvalidProcedureAbortReasonError`). 

24 

25Phase 10c-b also adds `ProcedureStepsLogbookOpened` (lazy envelope 

26event for the per-step logbook table). Phase 10c-c adds 

27`ProcedureTruncated` (mirrors RunTruncated from 6f-4) and possibly 

28`ProcedureHeld / ProcedureResumed` if pilot needs surface. 

29 

30## Payload conventions 

31 

32`target_asset_ids` is stored as `list[UUID]` in payloads (events 

33carry primitives; lists JSON-serialize cleanly). The evolver 

34converts to `frozenset` when folding into Procedure state. The list 

35is sorted by string form in `to_payload` so the same logical Asset 

36set serializes deterministically -- important for hash-based 

37idempotency. Same precedent as Method's needed_capabilities (6a) and 

38Plan's asset_ids (6e-1). 

39 

40`parent_run_id` is stored as `str | None` in payloads (UUID 

41serialized via `str()` when present). Optional binding: standalone 

42procedures (bakeouts, calibration sweeps between Runs) have None; 

43Phase-of-Run procedures have the parent Run's id. 

44 

45Status is NOT carried in event payloads -- the event type itself 

46encodes the state change. Same precedent as `RunStarted` / 

47`SupplyRegistered` / `SubjectMounted`. 

48"""

62 

63 Status is implicit (`Defined`) -- the evolver sets it.

65 `target_asset_ids` carries the Asset ids the procedure acts on; 

66 eventual-consistency stance, no cross-aggregate verification at

68 happens at start_procedure time in 10c-b via

117@dataclass(frozen=True) 

118class ProcedureStepsLogbookOpened: 

119 """A steps logbook was attached to this Procedure (Phase 10c-b iter 2). 

120 

121 Naming note: this event carries the entry-noun (`Steps`) in its name, 

122 vs. Conduit/Decision's bare `<Aggregate>LogbookOpened`. Same rationale 

123 as Run BC's `RunReadingLogbookOpened`: Procedure is planned to host 

124 multiple logbook kinds in the future (operator-action audit, hazard 

125 observations are likely future additions), so the event name carries 

126 the entry-noun discriminator upfront. Per 

127 [[project_logbook_entry_storage]] cross-BC family table. 

128 

129 Lazy open-on-first-write: emitted by the `append_procedure_step` 

130 handler the first time a step is appended for this Procedure, NOT by 

131 `start_procedure` (mirrors Decision BC's 8c-b precedent for 

132 `DecisionLogbookOpened` and Run BC's 6f-5b precedent for 

133 `RunReadingLogbookOpened`). Subsequent appends find the logbook 

134 already attached and skip the open-event emission. 

135 

136 `kind` discriminates the logbook category. Today only 

137 `LOGBOOK_KIND_STEPS` from state.py; future per-Procedure logbook 

138 kinds (operator-action audit, hazard) would use distinct constants 

139 and distinct state fields, not additional values for `kind` here. 

140 

141 `schema` declares the row shape of `entries_operation_procedure_steps`, 

142 documenting the polymorphic `(step_kind, payload, sampled_at, 

143 occurred_at, recorded_at)` shape for downstream projections. 

144 

145 No `ProcedureStepsLogbookClosed` event today: Procedure.status 

146 terminals (Completed | Aborted | Truncated) are the implicit close 

147 signal; `append_procedure_step` rejects writes when status is not 

148 Running via `ProcedureStepsLogbookClosedError`. Audit fidelity is 

149 preserved: the open event timestamps the logbook lifecycle start; 

150 the terminal ProcedureCompleted / ProcedureAborted / etc. event 

151 timestamps the lifecycle end. 

152 """ 

153 

154 procedure_id: UUID 

155 logbook_id: UUID 

156 kind: str 

157 schema: LogbookSchema 

158 occurred_at: datetime

161@dataclass(frozen=True) 

162class ProcedureTruncated: 

163 """A Procedure reached its partial-data terminal (Running -> Truncated, 10c-c). 

164 

165 Cleanup terminal for a Procedure that became de-facto dead through 

166 interruption (power loss, process crash, hardware fault, weekend 

167 interruption) and is being closed retroactively by an operator. 

168 The Procedure was already over before the operator could mark it; 

169 truncation captures that fact. 

170 

171 `reason` is a free-form string (1-500 chars after trimming), 

172 captured verbatim from the operator. Same shape and future-additive 

173 structured-taxonomy posture as ProcedureAborted's reason. 

174 

175 `interrupted_at` is the operator's best guess at when the actual 

176 interruption occurred (None when unknown). Distinct from 

177 `occurred_at`, which is when the truncate command was processed. 

178 The two timestamps can be hours or days apart for weekend / 

179 overnight interruptions; the explicit field saves auditors from 

180 parsing the free-text reason for a date. 

181 

182 Truncated vs Aborted (lifecycle-layer distinction): Aborted is an 

183 emergency exit while the system is still responsive; Truncated is 

184 a cleanup mechanism for known-dead Procedures. The system itself 

185 does not detect de-facto-dead Procedures (separate liveness 

186 concern, out of scope for 10c-c); operators must invoke truncate 

187 explicitly. Mirrors `RunTruncated` from Run BC's 6f-4. 

188 """ 

189 

190 procedure_id: UUID 

191 reason: str 

192 interrupted_at: datetime | None 

193 occurred_at: datetime

234def to_payload(event: ProcedureEvent) -> dict[str, Any]: 

235 """Serialize a Procedure event to a JSON-friendly dict for jsonb storage. 

236 

237 `target_asset_ids` is sorted by UUID string form so the persisted 

238 payload is deterministic -- same logical Asset set, same payload 

239 bytes, same idempotency hash. Same precedent as Method's 

240 PolicyDefined / MethodDefined. 

241 """ 

242 match event: 

243 case ProcedureRegistered( 

244 procedure_id=procedure_id, 

245 name=name, 

246 kind=kind, 

247 target_asset_ids=target_asset_ids, 

248 parent_run_id=parent_run_id, 

249 occurred_at=occurred_at, 

250 ): 

251 return { 

252 "procedure_id": str(procedure_id), 

253 "name": name, 

254 "kind": kind, 

255 "target_asset_ids": sorted(str(a) for a in target_asset_ids), 

256 "parent_run_id": str(parent_run_id) if parent_run_id is not None else None, 

257 "occurred_at": occurred_at.isoformat(), 

258 } 

259 case ProcedureStarted(procedure_id=procedure_id, occurred_at=occurred_at): 

260 return { 

261 "procedure_id": str(procedure_id), 

262 "occurred_at": occurred_at.isoformat(), 

263 } 

264 case ProcedureCompleted(procedure_id=procedure_id, occurred_at=occurred_at): 

265 return { 

266 "procedure_id": str(procedure_id), 

267 "occurred_at": occurred_at.isoformat(), 

268 } 

269 case ProcedureAborted(procedure_id=procedure_id, reason=reason, occurred_at=occurred_at): 

270 return { 

271 "procedure_id": str(procedure_id), 

272 "reason": reason, 

273 "occurred_at": occurred_at.isoformat(), 

274 } 

275 case ProcedureTruncated( 

276 procedure_id=procedure_id, 

277 reason=reason, 

278 interrupted_at=interrupted_at, 

279 occurred_at=occurred_at, 

280 ): 

281 interrupted_at_iso = interrupted_at.isoformat() if interrupted_at is not None else None 

282 return { 

283 "procedure_id": str(procedure_id), 

284 "reason": reason, 

285 "interrupted_at": interrupted_at_iso, 

286 "occurred_at": occurred_at.isoformat(), 

287 } 

288 case ProcedureStepsLogbookOpened( 

289 procedure_id=procedure_id, 

290 logbook_id=logbook_id, 

291 kind=kind, 

292 schema=schema, 

293 occurred_at=occurred_at, 

294 ): 

295 return { 

296 "procedure_id": str(procedure_id), 

297 "logbook_id": str(logbook_id), 

298 "kind": kind, 

299 "schema": schema.to_dict(), 

300 "occurred_at": occurred_at.isoformat(), 

301 } 

302 case _: # pragma: no cover # exhaustiveness guard 

303 assert_never(event)

306def from_stored(stored: StoredEvent) -> ProcedureEvent: 

307 """Rebuild a Procedure event from a StoredEvent loaded from the event store. 

308 

309 Dispatches on `stored.event_type`; raises ValueError on unknown 

310 discriminators so a stream contaminated with foreign event types 

311 fails loud rather than silently being dropped by the evolver. 

312 

313 NOTE: 10c-a uses strict `payload[...]` indexing because every key 

314 in `ProcedureRegistered` is required at the schema level. When 10c-b 

315 adds optional facets to the genesis payload (for example 

316 `expected_step_count`, `triggered_by`, `requested_supply_kinds`), 

317 those new keys MUST use `payload.get("k", default)` so pre-10c-b 

318 streams fold cleanly without backfill. Same additive-evolution 

319 pattern as `recipe/aggregates/method/events.py:from_stored` 

320 (`needed_supplies` added in 10b). 

321 """ 

322 payload = stored.payload 

323 match stored.event_type: 

324 case "ProcedureRegistered": 

325 raw_parent = payload["parent_run_id"] 

326 return ProcedureRegistered( 

327 procedure_id=UUID(payload["procedure_id"]), 

328 name=payload["name"], 

329 kind=payload["kind"], 

330 target_asset_ids=[UUID(a) for a in payload["target_asset_ids"]], 

331 parent_run_id=UUID(raw_parent) if raw_parent is not None else None, 

332 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

333 ) 

334 case "ProcedureStarted": 

335 return ProcedureStarted( 

336 procedure_id=UUID(payload["procedure_id"]), 

337 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

338 ) 

339 case "ProcedureCompleted": 

340 return ProcedureCompleted( 

341 procedure_id=UUID(payload["procedure_id"]), 

342 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

343 ) 

344 case "ProcedureAborted": 

345 return ProcedureAborted( 

346 procedure_id=UUID(payload["procedure_id"]), 

347 reason=payload["reason"], 

348 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

349 ) 

350 case "ProcedureTruncated": 

351 raw_interrupted_at = payload["interrupted_at"] 

352 return ProcedureTruncated( 

353 procedure_id=UUID(payload["procedure_id"]), 

354 reason=payload["reason"], 

355 interrupted_at=( 

356 datetime.fromisoformat(raw_interrupted_at) 

357 if raw_interrupted_at is not None 

358 else None 

359 ), 

360 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

361 ) 

362 case "ProcedureStepsLogbookOpened": 

363 return ProcedureStepsLogbookOpened( 

364 procedure_id=UUID(payload["procedure_id"]), 

365 logbook_id=UUID(payload["logbook_id"]), 

366 kind=payload["kind"], 

367 schema=LogbookSchema.from_dict(payload["schema"]), 

368 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

369 ) 

370 case _: 

371 msg = f"Unknown ProcedureEvent event_type: {stored.event_type!r}" 

372 raise ValueError(msg)
