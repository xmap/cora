1"""Domain events emitted by the Procedure aggregate, plus the discriminated union. 

2 

3Mirrors the locked event-module shape: event classes, discriminated 

4union, `event_type_name`, `to_payload`, `from_stored`. The 

5persistence-envelope construction (`NewEvent`) lives at 

6`cora.infrastructure.event_envelope.to_new_event`. 

7 

8`ProcedureRegistered` is the genesis event. FSM-closure transitions: 

9 - `ProcedureStarted` -- single-source genesis transition (Defined -> 

10 Running). Slim payload: procedure_id + occurred_at. Mirrors 

11 `RunStarted`'s no-status convention; the start fact is what the 

12 event encodes. 

13 - `ProcedureCompleted` -- happy-path terminal (Running -> Completed). 

14 Slim payload by design; substantive completion summary (step count, 

15 duration, final check pass-rate) deferred until the step logbook 

16 has accreted real consumer signal. 

17 - `ProcedureAborted` -- emergency-exit terminal (Running -> Aborted). 

18 Payload carries `procedure_id` + free-form `reason: str` (1-500 

19 chars after trimming) + `occurred_at`. Mirrors RunAborted's reason 

20 shape exactly (free-form by design; structured taxonomy future- 

21 additive on the same triggers documented at 

22 `InvalidProcedureAbortReasonError`). 

23 

24`ProcedureStepsLogbookOpened` is the lazy envelope event for the 

25per-step logbook table. `ProcedureTruncated` mirrors RunTruncated. 

26`ProcedureHeld` / `ProcedureResumed` are deferred until the pilot 

27needs the surface. 

28 

29## Payload conventions 

30 

31`target_asset_ids` is stored as `tuple[UUID, ...]` in payloads (events 

32carry primitives; tuples JSON-serialize cleanly and are immutable 

33so the fold step can't alias a mutable list into state). The evolver 

34converts to `frozenset` when folding into Procedure state. The values 

35are sorted by string form in `to_payload` so the same logical Asset 

36set serializes deterministically -- important for hash-based 

37idempotency. Same precedent as Method's needed_family_ids and Plan's 

38asset_ids. 

39 

40`parent_run_id` is stored as `str | None` in payloads (UUID 

41serialized via `str()` when present). Optional binding: standalone 

42procedures (bakeouts, calibration sweeps between Runs) have None; 

43Phase-of-Run procedures have the parent Run's id. 

44 

45Status is NOT carried in event payloads -- the event type itself 

46encodes the state change. Same precedent as `RunStarted` / 

47`SupplyRegistered` / `SubjectMounted`. 

48"""

63@dataclass(frozen=True) 

64class ProcedureRegistered: 

65 """A new procedure was registered (lands in `Defined`). 

66 

67 Status is implicit (`Defined`) -- the evolver sets it. 

68 

69 `target_asset_ids` carries the Asset ids the procedure acts on; 

70 eventual-consistency stance, no cross-aggregate verification at 

71 register time. Existence + Decommissioned-lifecycle gating 

72 happens at start_procedure time via `ProcedureStartContext`. 

73 

74 `parent_run_id` carries the optional Run binding (None for 

75 standalone procedures, set for Phase-of-Run procedures). 

76 

77 `capability_id` is the optional cross-BC binding to the universal 

78 Capability template (Recipe BC) this Procedure realizes as a 

79 Procedure-shaped executor. None for legacy Procedures and for 

80 ceremony Procedures with no template binding. Same additive shape 

81 as Method.capability_id. 

82 

83 `recipe_id` is the optional cross-BC binding to the Recipe whose 

84 steps were expanded into this Procedure via the 

85 `register_procedure_from_recipe` slice. None for legacy Procedures 

86 (registered via `register_procedure` with inline steps) and for 

87 ceremony Procedures with no Recipe binding. When set, 

88 `capability_id` carries the Recipe's `capability_id` as a denorm 

89 for audit-by-Capability read paths without requiring a Recipe 

90 join. Additive payload field; pre-rewrite streams fold via 

91 `payload.get("recipe_id")` -> None. 

92 """ 

93 

94 procedure_id: UUID 

95 name: str 

96 kind: str 

97 target_asset_ids: tuple[UUID, ...] 

98 parent_run_id: UUID | None 

99 occurred_at: datetime 

100 capability_id: UUID | None = None 

101 recipe_id: UUID | None = None

104@dataclass(frozen=True) 

105class RecipeExpansionRecorded: 

106 """Provenance event: a Recipe's steps were expanded into this Procedure. 

107 

108 Emitted alongside `ProcedureRegistered` by the 

109 `register_procedure_from_recipe` slice, NOT by `register_procedure`. 

110 Captures the template-invocation grain provenance per the design 

111 lock ([[project-recipe-aggregate-design]]): one event per Recipe 

112 invocation, NOT one per expanded step. Per-step records live in 

113 `entries_operation_procedure_steps` via the existing 

114 `append_procedure_steps` handler; this event lifts the binding 

115 context above the per-step granularity so PROV-O / 21 CFR Part 11 

116 audit trails point at the activity that produced the entity, not 

117 at every intermediate state. 

118 

119 `recipe_id` is the Recipe whose steps were expanded. `recipe_version` 

120 pins which Recipe-version's steps were active at expansion time 

121 (without this, replay after a `version_recipe` call would resolve 

122 to different steps and lose determinism). 

123 

124 `capability_id` + `capability_version` are denormalized for 

125 audit-by-Capability read paths (find all Procedures expanded from 

126 this Capability) without requiring a Recipe join. Recipe.capability_id 

127 is the source of truth; the denorm here mirrors the Procedure 

128 aggregate state pin per anti-hook 15 of [[project-recipe-aggregate-design]]. 

129 

130 `bindings` carries the operator-supplied parameter values verbatim 

131 for replay (serialized via `json.dumps(..., sort_keys=True)` for 

132 canonical-JSON content hashing). `expansion_port_version` records 

133 which expander emitted the steps (the design memo's "non-determinism 

134 captured via port injection" principle). `steps_hash` (renamed from 

135 the worktree's `template_hash`) + `bindings_hash` are content-hashes 

136 enabling cheap equality checks at projection time; `step_count` is 

137 the number of expanded Steps the slice paginated through. 

138 

139 Provenance-only: the evolver leaves `Procedure` state unchanged 

140 when this event arrives. Replay of `(recipe_id, recipe_version, 

141 bindings, expansion_port_version)` reconstructs the step sequence 

142 deterministically by re-loading Recipe at the recorded version and 

143 re-running expand. 

144 """ 

145 

146 procedure_id: UUID 

147 recipe_id: UUID 

148 recipe_version: str | None 

149 capability_id: UUID 

150 capability_version: str | None 

151 bindings: Mapping[str, Any] 

152 expansion_port_version: str 

153 steps_hash: str 

154 bindings_hash: str 

155 step_count: int 

156 occurred_at: datetime

193@dataclass(frozen=True) 

194class ProcedureStepsLogbookOpened: 

195 """A steps logbook was attached to this Procedure. 

196 

197 Naming note: this event carries the entry-noun (`Steps`) in its name, 

198 vs. Conduit/Decision's bare `<Aggregate>LogbookOpened`. Same rationale 

199 as Run BC's `RunReadingLogbookOpened`: Procedure is planned to host 

200 multiple logbook kinds in the future (operator-action audit, hazard 

201 observations are likely future additions), so the event name carries 

202 the entry-noun discriminator upfront. Per 

203 [[project_logbook_entry_storage]] cross-BC family table. 

204 

205 Lazy open-on-first-write: emitted by the `append_procedure_steps` 

206 handler the first time a step is appended for this Procedure, NOT by 

207 `start_procedure` (mirrors Decision BC's precedent for 

208 `DecisionLogbookOpened` and Run BC's precedent for 

209 `RunReadingLogbookOpened`). Subsequent appends find the logbook 

210 already attached and skip the open-event emission. 

211 

212 `kind` discriminates the logbook category. Today only 

213 `LOGBOOK_KIND_STEPS` from state.py; future per-Procedure logbook 

214 kinds (operator-action audit, hazard) would use distinct constants 

215 and distinct state fields, not additional values for `kind` here. 

216 

217 `schema` declares the row shape of `entries_operation_procedure_steps`, 

218 documenting the polymorphic `(step_kind, payload, sampled_at, 

219 occurred_at, recorded_at)` shape for downstream projections. 

220 

221 No `ProcedureStepsLogbookClosed` event today: Procedure.status 

222 terminals (Completed | Aborted | Truncated) are the implicit close 

223 signal; `append_procedure_steps` rejects writes when status is not 

224 Running via `ProcedureStepsLogbookClosedError`. Audit fidelity is 

225 preserved: the open event timestamps the logbook lifecycle start; 

226 the terminal ProcedureCompleted / ProcedureAborted / etc. event 

227 timestamps the lifecycle end. 

228 """ 

229 

230 procedure_id: UUID 

231 logbook_id: UUID 

232 kind: str 

233 schema: LogbookSchema 

234 occurred_at: datetime

237@dataclass(frozen=True) 

238class ProcedureTruncated: 

239 """A Procedure reached its partial-data terminal (Running -> Truncated, 10c-c). 

240 

241 Cleanup terminal for a Procedure that became de-facto dead through 

242 interruption (power loss, process crash, hardware fault, weekend 

243 interruption) and is being closed retroactively by an operator. 

244 The Procedure was already over before the operator could mark it; 

245 truncation captures that fact. 

246 

247 `reason` is a free-form string (1-500 chars after trimming), 

248 captured verbatim from the operator. Same shape and future-additive 

249 structured-taxonomy posture as ProcedureAborted's reason. 

250 

251 `interrupted_at` is the operator's best guess at when the actual 

252 interruption occurred (None when unknown). Distinct from 

253 `occurred_at`, which is when the truncate command was processed. 

254 The two timestamps can be hours or days apart for weekend / 

255 overnight interruptions; the explicit field saves auditors from 

256 parsing the free-text reason for a date. 

257 

258 Truncated vs Aborted (lifecycle-layer distinction): Aborted is an 

259 emergency exit while the system is still responsive; Truncated is 

260 a cleanup mechanism for known-dead Procedures. The system itself 

261 does not detect de-facto-dead Procedures (separate liveness 

262 concern, out of scope for 10c-c); operators must invoke truncate 

263 explicitly. Mirrors `RunTruncated` from Run BC's 6f-4. 

264 """ 

265 

266 procedure_id: UUID 

267 reason: str 

268 interrupted_at: datetime | None 

269 occurred_at: datetime

311def to_payload(event: ProcedureEvent) -> dict[str, Any]: 

312 """Serialize a Procedure event to a JSON-friendly dict for jsonb storage. 

313 

314 `target_asset_ids` is sorted by UUID string form so the persisted 

315 payload is deterministic -- same logical Asset set, same payload 

316 bytes, same idempotency hash. Same precedent as Method's 

317 PolicyDefined / MethodDefined. 

318 """ 

319 match event: 

320 case ProcedureRegistered( 

321 procedure_id=procedure_id, 

322 name=name, 

323 kind=kind, 

324 target_asset_ids=target_asset_ids, 

325 parent_run_id=parent_run_id, 

326 occurred_at=occurred_at, 

327 capability_id=capability_id, 

328 recipe_id=recipe_id, 

329 ): 

330 return { 

331 "procedure_id": str(procedure_id), 

332 "name": name, 

333 "kind": kind, 

334 "target_asset_ids": sorted(str(a) for a in target_asset_ids), 

335 "parent_run_id": str(parent_run_id) if parent_run_id is not None else None, 

336 # None when register_procedure omits capability_id. 

337 # Pre-10d streams fold via `.get("capability_id")` in 

338 # from_stored. Mirrors Method.capability_id (6l-additive). 

339 "capability_id": str(capability_id) if capability_id is not None else None, 

340 # None when register_procedure (legacy slice) omits 

341 # recipe_id. register_procedure_from_recipe sets both 

342 # `recipe_id` and the denorm `capability_id` to the 

343 # Recipe's capability_id. Pre-rewrite streams fold via 

344 # `.get("recipe_id")` in from_stored. 

345 "recipe_id": str(recipe_id) if recipe_id is not None else None, 

346 "occurred_at": occurred_at.isoformat(), 

347 } 

348 case ProcedureStarted(procedure_id=procedure_id, occurred_at=occurred_at): 

349 return { 

350 "procedure_id": str(procedure_id), 

351 "occurred_at": occurred_at.isoformat(), 

352 } 

353 case ProcedureCompleted(procedure_id=procedure_id, occurred_at=occurred_at): 

354 return { 

355 "procedure_id": str(procedure_id), 

356 "occurred_at": occurred_at.isoformat(), 

357 } 

358 case ProcedureAborted(procedure_id=procedure_id, reason=reason, occurred_at=occurred_at): 

359 return { 

360 "procedure_id": str(procedure_id), 

361 "reason": reason, 

362 "occurred_at": occurred_at.isoformat(), 

363 } 

364 case ProcedureTruncated( 

365 procedure_id=procedure_id, 

366 reason=reason, 

367 interrupted_at=interrupted_at, 

368 occurred_at=occurred_at, 

369 ): 

370 interrupted_at_iso = interrupted_at.isoformat() if interrupted_at is not None else None 

371 return { 

372 "procedure_id": str(procedure_id), 

373 "reason": reason, 

374 "interrupted_at": interrupted_at_iso, 

375 "occurred_at": occurred_at.isoformat(), 

376 } 

377 case ProcedureStepsLogbookOpened( 

378 procedure_id=procedure_id, 

379 logbook_id=logbook_id, 

380 kind=kind, 

381 schema=schema, 

382 occurred_at=occurred_at, 

383 ): 

384 return { 

385 "procedure_id": str(procedure_id), 

386 "logbook_id": str(logbook_id), 

387 "kind": kind, 

388 "schema": schema.to_dict(), 

389 "occurred_at": occurred_at.isoformat(), 

390 } 

391 case RecipeExpansionRecorded( 

392 procedure_id=procedure_id, 

393 recipe_id=recipe_id, 

394 recipe_version=recipe_version, 

395 capability_id=capability_id, 

396 capability_version=capability_version, 

397 bindings=bindings, 

398 expansion_port_version=expansion_port_version, 

399 steps_hash=steps_hash, 

400 bindings_hash=bindings_hash, 

401 step_count=step_count, 

402 occurred_at=occurred_at, 

403 ): 

404 # Canonical-JSON bytes via the shared `canonical_json_bytes` 

405 # helper, then `json.loads` to keep the persisted `bindings` 

406 # field a dict (matches `from_stored`'s `dict(payload['bindings'])` 

407 # consumer at line 528). The single-source canonicalizer keeps 

408 # `sha256(payload['bindings'])` reproducible against the 

409 # decider's at-write `bindings_hash`. Recipe.steps wire-format 

410 # is JSON-friendly by construction (no UUID values inside). 

411 return { 

412 "procedure_id": str(procedure_id), 

413 "recipe_id": str(recipe_id), 

414 "recipe_version": recipe_version, 

415 "capability_id": str(capability_id), 

416 "capability_version": capability_version, 

417 "bindings": json.loads(canonical_json_bytes(dict(bindings))), 

418 "expansion_port_version": expansion_port_version, 

419 "steps_hash": steps_hash, 

420 "bindings_hash": bindings_hash, 

421 "step_count": step_count, 

422 "occurred_at": occurred_at.isoformat(), 

423 } 

424 case _: # pragma: no cover # exhaustiveness guard 

425 assert_never(event)

428def from_stored(stored: StoredEvent) -> ProcedureEvent: 

429 """Rebuild a Procedure event from a StoredEvent loaded from the event store. 

430 

431 Dispatches on `stored.event_type`; raises ValueError on unknown 

432 discriminators so a stream contaminated with foreign event types 

433 fails loud rather than silently being dropped by the evolver. 

434 

435 NOTE: today this uses strict `payload[...]` indexing because every 

436 key in `ProcedureRegistered` is required at the schema level. When 

437 future iterations add optional facets to the genesis payload (for 

438 example `expected_step_count`, `trigger_source`, 

439 `requested_supply_kinds`), those new keys MUST use 

440 `payload.get("k", default)` so legacy streams fold cleanly without 

441 backfill. Same additive-evolution pattern as 

442 `recipe/aggregates/method/events.py:from_stored` 

443 (`needed_supplies` was added that way). 

444 """ 

445 payload = stored.payload 

446 match stored.event_type: 

447 case "ProcedureRegistered": 

448 

449 def _build_registered() -> ProcedureRegistered: 

450 raw_parent = payload["parent_run_id"] 

451 # capability_id and recipe_id are OPTIONAL on the payload. 

452 # Pre-binding streams omit capability_id; pre-Recipe-rewrite 

453 # streams omit recipe_id. Fold via `.get` -> None default. 

454 # Mirrors Method.capability_id additive-evolution pattern. 

455 raw_capability = payload.get("capability_id") 

456 raw_recipe = payload.get("recipe_id") 

457 return ProcedureRegistered( 

458 procedure_id=UUID(payload["procedure_id"]), 

459 name=payload["name"], 

460 kind=payload["kind"], 

461 target_asset_ids=tuple(UUID(a) for a in payload["target_asset_ids"]), 

462 parent_run_id=UUID(raw_parent) if raw_parent is not None else None, 

463 capability_id=UUID(raw_capability) if raw_capability is not None else None, 

464 recipe_id=UUID(raw_recipe) if raw_recipe is not None else None, 

465 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

466 ) 

467 

468 return deserialize_or_raise("ProcedureRegistered", _build_registered) 

469 case "ProcedureStarted": 

470 return deserialize_or_raise( 

471 "ProcedureStarted", 

472 lambda: ProcedureStarted( 

473 procedure_id=UUID(payload["procedure_id"]), 

474 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

475 ), 

476 ) 

477 case "ProcedureCompleted": 

478 return deserialize_or_raise( 

479 "ProcedureCompleted", 

480 lambda: ProcedureCompleted( 

481 procedure_id=UUID(payload["procedure_id"]), 

482 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

483 ), 

484 ) 

485 case "ProcedureAborted": 

486 return deserialize_or_raise( 

487 "ProcedureAborted", 

488 lambda: ProcedureAborted( 

489 procedure_id=UUID(payload["procedure_id"]), 

490 reason=payload["reason"], 

491 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

492 ), 

493 ) 

494 case "ProcedureTruncated": 

495 

496 def _build_truncated() -> ProcedureTruncated: 

497 raw_interrupted_at = payload["interrupted_at"] 

498 return ProcedureTruncated( 

499 procedure_id=UUID(payload["procedure_id"]), 

500 reason=payload["reason"], 

501 interrupted_at=( 

502 datetime.fromisoformat(raw_interrupted_at) 

503 if raw_interrupted_at is not None 

504 else None 

505 ), 

506 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

507 ) 

508 

509 return deserialize_or_raise("ProcedureTruncated", _build_truncated) 

510 case "ProcedureStepsLogbookOpened": 

511 return deserialize_or_raise( 

512 "ProcedureStepsLogbookOpened", 

513 lambda: ProcedureStepsLogbookOpened( 

514 procedure_id=UUID(payload["procedure_id"]), 

515 logbook_id=UUID(payload["logbook_id"]), 

516 kind=payload["kind"], 

517 schema=LogbookSchema.from_dict(payload["schema"]), 

518 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

519 ), 

520 ) 

521 case "RecipeExpansionRecorded": 

522 return deserialize_or_raise( 

523 "RecipeExpansionRecorded", 

524 lambda: RecipeExpansionRecorded( 

525 procedure_id=UUID(payload["procedure_id"]), 

526 recipe_id=UUID(payload["recipe_id"]), 

527 recipe_version=payload.get("recipe_version"), 

528 capability_id=UUID(payload["capability_id"]), 

529 capability_version=payload.get("capability_version"), 

530 bindings=dict(payload["bindings"]), 

531 expansion_port_version=payload["expansion_port_version"], 

532 steps_hash=payload["steps_hash"], 

533 bindings_hash=payload["bindings_hash"], 

534 step_count=int(payload["step_count"]), 

535 occurred_at=datetime.fromisoformat(payload["occurred_at"]), 

536 ), 

537 extra=(ValueError,), 

538 ) 

539 case _: 

540 msg = f"Unknown ProcedureEvent event_type: {stored.event_type!r}" 

541 raise ValueError(msg)
